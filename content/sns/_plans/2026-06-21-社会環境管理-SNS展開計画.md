# 総監標準テキスト 5管理 → 図解SVG（記事＋SNS両用）展開計画

> 方針: md の各概念を **サイト図版スタイルの「1枚の図」SVG** にする。**記事埋め込み（`<ArticleImage>`）と SNS の両用（一石二鳥）**。
> スタイル真実源: `.claude/skills/authoring/create-svg/SKILL.md` + `.claude/knowledge/design-system/svg-tokens.json` + `.claude/knowledge/design-system/design-system.md`
> 策定: 2026-06-21（方針転換: カルーセル → 図解SVG）

## 0. 方針転換の経緯

- 当初: Instagram カルーセル（notebook デザイン・複数スライド）で検討 → **不採用**（文字小・余白大・余計な情報・低品質）。
- 転換: **md の内容を1枚の明快な図(SVG)で表現**。サイト記事に既存の115本と同系統（例: 4E対策の2×2カード、ハインリッヒのピラミッド）。
- 利点: **記事とSNSで同一SVGを使い回せる**。SVG=ベクタなので両サイズで鮮明、著作権クリーン、修正容易。

## 1. 単位（粒度）

```
各管理md
 └─ 図解候補（概念）= 1概念 → 1枚のSVG（= 記事figure かつ SNS画像）
```

図にすべきか判定は image-policy の判定フロー:
- 概念・仕組み・工程・関係（フロー/マトリクス/比較/順位） → **SVG 化**
- 実機外観・現場 → 写真（CC/PD）
- 数式・単純表で足りる → 図にしない（本文で表現）

## 2. パイロット（完了）

- **循環型社会の5段階**（§2-(1)）→ `circular-society-basic-act/img/figure-1.svg`
  - 縦5段の優先度ラダー（発生抑制→再使用→再生利用→熱回収→適正処分）、緑→赤の優先度勾配、2R・第7条注記。
  - 機械監査 HIGH=0、4.5KB。記事スタイル合致を確認。
  - → このスタイル・粒度を全管理の基準とする。

## 3. エージェント分業

| 工程 | 担当 | 種別 | 出力 |
|---|---|---|---|
| 図解候補の抽出（管理ごと） | 親 or decomposer agent | Generator | 候補リスト(JSON): concept / mdRange / sendToSlug / 既存SVG有無 / layoutパターン / 要素・ラベル |
| SVG 作成（概念ごと） | create-svg 準拠 generator | Generator | `content/site/{sendToSlug}/img/figure-N.svg` |
| 機械監査（必須ゲート） | `audit.mjs --fail-on=HIGH` | — | HIGH=0 |
| 意味監査 | `svg-figure-auditor` | Evaluator | 4軸スコア＋指摘 |
| 修正 | `svg-figure-rewriter` | Generator | 外科的修正後の SVG |
| 記事埋め込み | `<ArticleImage>` を該当 article.mdx へ | — | MDX 編集 |
| SNS 用 PNG | `.claude/scripts/sns/lib/svg-to-png.mjs` + フレーム | — | 1080×1350 PNG |

- Generator/Evaluator 分離を堅持。**並行は2本まで**（feedback/workflow-concurrency）。
- 既存SVGがある概念は重複作成しない（115本実在）。新規・不足分のみ。
- writer/QA が md の不足・誤りに気づいたら `content/sns/instagram/_keyword-findings.md` へ（MDX直接編集しない）。

## 4. フェーズ計画

### Phase 1: パイロット ✓ 完了（循環型社会5段階）
### Phase 2: 図解候補の分解（5管理並列）
- 各 md → 「図にすべき概念」リスト＋既存SVG有無＋layoutパターン案。Workflow で並列。
### Phase 3: SVG 生成 + 監査（pipeline）
- 候補ごと: 作成 → audit.mjs(HIGH=0) → svg-figure-auditor → 必要なら rewriter。2本並列。
### Phase 4: 記事埋め込み + commit
- 各 SVG を sendToSlug の article.mdx に `<ArticleImage>` で配置 → refresh-indexes → commit。R2 は main push 時 CI 同期。
### Phase 5: SNS 用 PNG 化
- 同一 SVG を 1080×1350 にフレーム化 → IG/X/YT サムネへ。Reels/Shorts は図の連結 or ナレーション化（派生）。

## 5. SSOT 規律

- **SVG = 単一ソース**（記事 figure と SNS 画像の両方がこれ由来）。
- 色は svg-tokens.json の allowlist のみ（brand/positive/warn/danger/ink/surface）。
- ファクトは textbook md に忠実（数値・法令名・条番号、推測補完しない）。
- SVG 内に「図N.N」「※イメージ」等のメタを書かない（create-svg Step3 セルフチェック）。
- 記事の CTA/送客は note ファネル L3（既存規律）。
