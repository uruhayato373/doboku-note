1. こんな方へ（悩みの言葉で 3 行。例: P3「解決策が一般論で終わる」「発注者が何を見ているか分からない」）
2. お届けするもの（赤入れ・総評・直す順番の 3 点。P4 は施策ごとの 600 字の判定、P5 は上水道／下水道の別）

## 6. 進め方（承認後）

1. P1 を ¥2,000・対象部門に上下水道を追加（`npm run product -- set`・`coconala-edit --fields price`・本文の対応部門）
2. P2〜P5 を正本に `draft` で入れ、表紙を Codex で生成・照合。**新規出品は 1 日 4 件まで**（2026-09-23 に 5 件目以降が通らなかった）なので、P3・P4 → 翌日 P5 → P2（1 月中旬）の順に出す

4. 指標: 2026-12-15 と 2027-01-31 に、各出品の閲覧・お気に入り・受注・評価を `npm run coconala-analytics` で読む。評価 5 件（2027-03 まで・[22 §6](../../docs/strategy/22_チャネル別商品設計2026-11.md)）に届かない出品は、7 月の筆記のあとに休止を判断する

## 判断の契約

- 読者の課題: 筆記・口頭・申込のそれぞれで、自分の答案と経歴を合格者に直してほしい（本人の文章なので無料記事や教材では解決しない）
- HARM: A（資格・成長）
- 支払う理由: 合格者の赤入れは note では手に入らない。価格は競合の中央値に合わせ、部門を名乗って選ばれやすくする
- 需要の証拠: 上の表（論文 33 出品・評価 259、口頭 35・86、業務経歴 16・56、上下水道 9・66）。当社の技術士の出品は評価 0・受注 0（P1 は 11/7 時点で閲覧 12）
- 次の検証: ¥2,000〜4,000 で評価が付くか（2027-01-31 に判定）。運営者の作業時間（1 件あたりの分）は受注 1 件目で記録する
