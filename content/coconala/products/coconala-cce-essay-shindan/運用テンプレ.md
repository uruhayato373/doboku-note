# コンクリート主任技士 小論文 診断（coconala-cce-essay-shindan）運用テンプレ

> [!note]
> ココナラ商品 `coconala-cce-essay-shindan` の受注から評価までの型。価格・受付枠・状態は `config/products.json`（生成物 `src/lib/coconala-services.ts`）、出品文は `config/coconala-listings.json` が真実源（ここに価格を書かない）。
> 観点表と受領時の確認は添削と共通で、[添削テンプレ](../../../note/コンクリート主任技士/小論文-添削テンプレ.md) の §1・§2 を使う。診断は**書き換え例文を出さない**ところだけが添削と違う。土木の添削エージェント（`civil-keiken-tensaku-drafter` / `-qa`）は経験記述専用なので使わない。

## 1. 守ること

- 出品文の約束は「A/B/C 判定・減点の大きい箇所の指摘・観点別のひとこと」まで。**NG→OK の書き換え案と書き直しの確認は出さない**（添削の範囲）。直し方の方向は一言まで
- 事実は答案と課題文からだけ取る。答案に無い業務・数値を足さない。読めない行は推測せず質問する
- 納品文に URL・note・サイト名を書かない（外部誘導禁止）。合格保証・出題予想の断定を書かない。採点者を名乗らない
- 11/25（水）までに受け取った答案は本試験（11/29）前に返す（出品文の約束）
- 顧客の答案と下書きはリポジトリに置かず `.tmp/coconala/talkrooms/{id}/` に保存する

## 2. 購入直後に送る文

```
ご購入ありがとうございます。小論文の診断を担当いたします。
次の2点をこのトークルームでお送りください。届いた時点から48時間以内にお返しします。

1. 課題文（受験予定の年度の過去問・予想課題など、診断の基準にする課題。うろ覚えなら要旨で構いません）
2. ご自身で書いた小論文1本（テキスト、または文字が読める画像）

お預かりした答案は本サービスの診断にのみ使い、第三者に開示しません。
```

## 3. 納品文の型（トークルーム貼付用）

```
お待たせしました。小論文の診断結果をお返しします。

【判定】〇（A: このままでも戦える / B: 要修正 / C: 書き直し推奨）
（判定の理由を2〜3行。良い点を1つ入れる）

【減点の大きい箇所】
1. 該当箇所：「（原文の引用）」
   → なぜ減点されやすいか：（理由。技術的な指摘は規格名・示方書の章を添える）
2. （同上。2〜4点、減点の大きい順）

【観点別のひとこと】
・題意への応答：〇　（一言）
・技術的な正確さ：〇　（一言）
・実務経験の具体性：〇　（一言）
・構成：〇　（一言）
・字数と表現：〇　（約〇〇字／一言）

【次の一歩】
（最初に直すべき1点を一言。書き換え例文は書かない）

本サービスは診断までです。書き換え案と書き直し1回の確認が必要でしたら、添削サービスへ進めます。購入済みの額を調整したお見積もりをこのトークルームでご案内しますので、お気軽にお知らせください。

内容をご確認のうえ、問題なければ取引の完了をお願いします。
完了後に評価をいただけると、今後の診断の改善に役立てます。
本番での健闘をお祈りしています。
```

- 観点の 〇 は A/B/C。判定の目安は添削テンプレ §2 の「C になる典型」を使う
- 減点箇所は引用と理由だけを書く。「こう書けばよい」という文は入れない（入れたくなったら添削の案内に回す）
- 評価のお願いは上の一文だけにし、星の数の指定・特典との交換はしない

## 4. 送信前の自己点検

- 判定と5観点すべてに A/B/C と理由がある
- 書き換え例文が入っていない。答案に無い事実・数値を書いていない
- URL・note・サイト名・合格保証・AI 下書きの注記が残っていない
- 返信文は運営者が読み、トークルームへ送る（エージェントは送信しない）

## 5. 記録と評価

- 受注は `data/coconala/orders.json` に追記する（`/coconala-order`）。`tensakuMinutes` に診断の所要時間を書き、2〜3件で週枠（3名）と価格を見直す
- 取引は評価まで終えて完了。購入者への評価は `scripts/coconala-rate-buyer.mjs`（送信は `--submit`）で、未送信と期限は `npm run check-coconala-orders` が拾う
- 添削へ進んだ場合は、添削の受注として別に記録する
