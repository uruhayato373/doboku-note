## なぜこのクラスターか（戦略）

土木側は**有料マガジンは整備済みだが、それへ送客する無料集客記事が空白**だった。総監側には公務員クラスター8本＋単発無料16本があり、無料記事→有料マガジンの回遊が機能している。土木側にも同型の集客層を作る。

立ち上がり期の doboku-note（サイト）は新規ドメインで順位確立に時間がかかるため、**被リンク・DA のある note を踏み台に検索流入と売上を先に作る**（[総監 noteコンテンツ計画 Red Line #4（2026-06-03 改訂）](../../技術士総監/noteコンテンツ計画.md) の「立ち上がり期の踏み台運用」に準拠）。サイトが育つにつれ重心はサイトへ移す。

## Red Line 整合（最重要）

- **verbatim 重複の禁止／角度を変えれば両載可**（Red Line #4 再定義）。本クラスターは全記事を**運営者（元自治体土木職＝発注者・1級土木保有）の一人称体験・添削視点・意思決定の角度**で書く。サイト（中立・体系・スペック）とはクエリ意図が割れるため両立する。
- **形式スペック・留意事項一覧・記入例はサイトへリンク委譲**する。note 記事内に同じ表・チェックリストを再掲しない。
  - サイト: [施工経験記述 出題傾向と対策](https://doboku-note.com/docs/civil-construction-2-secondary-experience-writing-guide) / [施工経験記述 改善例](https://doboku-note.com/docs/civil-construction-2-secondary-experience-writing-examples)
- **経験記述は「自分が経験した工事」が大前提・捏造は失格**。商品も記事も「模範解答」ではなく「**改変前提テンプレ**」として打ち出す（2級プラン Red Line #3 継承）。

## 第1バッチ（A層・施工経験記述ピンポイント＝BOFU・購入直結）

全記事 `content/note/2級土木/{記事dir}/article.md`。送客主軸＝**2級 完成答案集**。

| # | 記事dir | 角度（サイトとの差別化） | 主CTA |
|---|---|---|---|
| A1 | `施工経験記述で落ちる答案` | 発注者・添削する側から見た「落ちる答案の共通パターン」（site=書き方の型／note=失敗の構造） | 完成答案集 |
| A2 | `工事概要の書き方` | 工事概要欄の減点に特化。発注者が本文との矛盾を見抜く視点（site=記入注意点の一覧／note=なぜ減点されるかの体験論） | 完成答案集 |
| A3 | `経験記述R6新形式` | 令和6年・2テーマ必答への「準備の変え方・心構え」（形式スペックはサイトへ委譲） | 完成答案集 |
| A4 | `経験記述テーマ選び` | 安全・品質・工程のどれで書くか＝題材選びで半分決まる（総監・道路担当記事の土木版） | 完成答案集 |
| A5 | `経験記述を自分の現場に置換` | 完成答案集・テンプレを「改変前提」で自分の経験に落とす手順＝丸写し失格の回避 | 完成答案集（直接） |

各記事末尾に二方向リンクを必須配線：**サイト**（技術深掘り）＋**完成答案集**（フル答案）。`notePricing: free` / `noteStatus: draft`（note 公開時に URL 投入 → published）。

## note記事の完了定義（DoD）— 全バッチ共通

**note記事1本の完成物＝3点セット**。article.md だけでは公開不可。新規記事は着手時に下記3つをまとめて成果物とする（第1バッチで本DoD未定義によりカバー・タグの生成漏れが発生したため明記）。

1. `article.md`（本文＋frontmatter。`cover:` ブロック必須＝カバー生成の入力）
2. `img/cover.png`（`node scripts/generate-note-covers.mjs "<記事dir>"` で生成。frontmatter の `cover:` を入力にする）
3. `hashtags.txt`（記事固有タグ先頭5-6＋ベース群、計70-90個。note多タグ運用。級整合: 2級=`#主任技術者`／`#監理技術者`は1級用で除外）

検証: U+FFFD 0・全LF・note-lint OK・カバー目視（テキスト溢れ無）・有効アイコン名（pen/clock/doc/edit/calendar/chart/check/target/book/layers/bulb/flag/yen/map）。

**本文図版（任意の肉付け）**: スペック表・枠組みは `img/figure-*.png` として再掲してよい（SVG→PNG＝テキスト重複インデックスされず Red Line #4 と両立、視覚的権威付け）。note-svg-policy.md 準拠（W=1200・本文 font 22+・余白40/24・右下ブランド）。生成器は `scripts/render-figure-2c-essay-cluster.mjs`（A層）/ `scripts/render-figure-2c-entry-cluster.mjs`（B層）。**2026-06-03 に A1-A5・B1-B5 全10本へ図版1枚ずつ追加し、具体例＋発注者知見で肉付け済み**。

## 着手順と検証ゲート

```
第1バッチ A1-A5 執筆（draft）→ U+FFFD/CRLF/サイト重複チェック
  → note 公開（ユーザー作業）→ 各 article.md に noteUrl 投入・published 化
  → 完成答案集マガジンへの回遊 CTR を確認（検証ゲート）
        ▼ 回遊が立ち上がれば
B層（入口拡大）展開 ＋ 1級完成答案集 執筆と 1級向けクラスター横展開
```

**検証指標**: note 各記事の閲覧数 / 完成答案集マガジンの参照元 note 比率 / マガジン販売数の増分。総監クラスターの実績（無料→有料回遊）を参照ベンチにする。
