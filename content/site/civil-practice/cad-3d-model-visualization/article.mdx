橋台の修正設計で、発注者から2次元の図面データと3次元モデルが一緒に届きました。図面は線の太さもレイヤの名前も作成者ごとにばらばらで、モデルは色がきれいについて見栄えがよい。ところが、モデルの橋台の幅が、図面の寸法と合っているのかどうかは、画面を眺めただけではわかりません。

迷いどころは三つに分かれます。図面データをどの決まりで作り、どこまでそろえて渡すのか。きれいに見えるモデルと図面が合っていることを、何で確かめるのか。画面の見え方は、どこまで信じてよいのか。国土交通省のCAD製図基準とBIM/CIMの要領を物差しにして、順に見ていきましょう。

3次元モデルの詳細度や属性、データ交換形式の中身はBIM/CIMの要領と[BIM/CIMの現場実務](/practice/bim-cim-site-practice)に任せます。SXFへの変換で欠ける要素の点検や、設計データの照査の流れは[ICT施工の実務ワークフロー](/practice/ict-construction-workflow)が扱っています。

点群は[3次元計測の選び方](/practice/3d-measurement-selection)に譲り、この記事は図面の決まりとモデルの見せ方に絞った内容です。

## 図面データは、国のCAD製図基準で形をそろえる

最初に確かめるのは、そのCADデータがどの基準で作られたかです。国土交通省の「CAD製図基準」は、土木設計業務の詳細設計の成果図面、土木工事の発注図、完成図のCADデータを作るときに適用するものです（[CAD製図基準](https://www.cals-ed.go.jp/mg/wp-content/uploads/cad8.pdf) 1-1 p.2）。

対象は国土交通省直轄事業の34工種で、道路から下水道の管路までが含まれます（1-2）。

現行は令和7年12月版で、改定履歴には「土木 202512-01」の初版発行とあります。

この記号は、図面管理項目の「適用要領基準」に書き込む内容でもあり、受け取った図面の管理項目を見れば、作成時の基準の版を読み取れます。令和8年4月1日以降に契約した業務・工事に適用され、それ以前の契約でも受発注者の協議で適用できます（公開元の[CALS/ECのCAD製図基準の案内](https://www.cals-ed.go.jp/cri_point/)）。

自治体や民間の発注で同じ基準を使うかどうかは、発注者の要領と特記仕様書しだいです。直轄の基準を準用する場合も、版が古いまま運用されていないか、公開元の最新版と照らして確かめておきましょう。基準はときどき改定されます。

## 納品の形式とファイル名は、決まりで読める

保存形式は、SXF（P21）形式が対象です。電子納品では、これを圧縮したSXF（P2Z）形式も対象に含まれます（1-5-1 p.5）。圧縮はZIP方式で、拡張子を「P2Z」とします（1-5-5）。SXFの成り立ちと変換後の点検は、[ICT施工の実務ワークフロー](/practice/ict-construction-workflow)にあります。

ファイル名は、段階と図面の種類が読める並びです（1-5-2 p.5）。

| 区切り | 内容 |
|---|---|
| 図面番号 | 半角数字3文字。表題欄の番号と合わせる |
| ライフサイクル | 1文字。S測量・D設計・C施工・M維持管理 |
| 整理番号 | 1文字。細かく区分したいときに使う |
| 図面種類 | 半角英大文字2文字。平面図ならPL |
| 改訂履歴 | 1文字。0〜9、A〜Yの順で、最終成果はZ |
| ユーザ定義領域 | 先頭にハイフン。図面名などを日本語で書ける |

基準の例では、「001D0PL1-○○区間平面図.P21」が、設計段階の平面図で、1回の改訂があったことを表します。文字数は全体で64文字以下です。

<Callout type="warn" title="P2Zに入れると、ファイル名の決まりは外れる">
圧縮前のファイルの名称は、P2Zの場合、この命名規則の適用を受けません（1-5-6 p.8）。P2Zで受け取ると、中身のファイル名が規則と違っていても、基準違反とは言えません。名前で段階や版を読む運用なら、納品物の一覧を別に作ってもらいます。
</Callout>

改訂履歴の「Z」は、最終成果の印です。納品前の最終データなのに、改訂履歴が数字のままになっていれば、版の取り違いを疑う手がかりになります。

## レイヤ名は、責任主体・図面オブジェクト・任意名の順で読む

レイヤ名は、責任主体（S・D・C・M）、図面オブジェクト（半角英大文字3文字）、ユーザ定義領域を、ハイフンでつなぎます。全体で半角256文字以内です（1-5-7 p.8）。例は「D-STR-A1橋台」で、設計段階の主構造物のうち、A1橋台の図形が入っていることを示します。ユーザ定義領域は省略でき、「D-STR」だけでも構いません。

図面オブジェクトは、図面に描く内容の分類です（表1-4 p.9）。

| 図面オブジェクト | 入る内容 |
|---|---|
| TTL | 外枠、表題欄、罫線、文字 |
| BGD | 主計曲線、現況地物、既設構造物 |
| BMK | 基準点、測量ポイント、中心線、幅杭 |
| STR | その図面で表す構造物 |
| BYP | 主構造物から派生する構造物 |
| MTR | 切盛土、コンクリート、鉄筋加工、数量 |
| DCR | ハッチ、シンボル、塗りつぶし、記号 |
| DOC | 説明事項、指示事項、参照事項の文章 |
| SUV | 地形図など、改変しない測量成果 |
| ORD | 発注図に描く注記、旗上げ |

発注図に使う発注用レイヤだけは別扱いで、図面オブジェクトを「ORD」、責任主体を「C」に固定します。発注者が発注図に書いた注記や旗上げは、このORDレイヤに入っているということです。工事の受注者が図面を修正するときは、構造物の図形とは別のレイヤにある、発注者の注記を消したり、描き直したりしないようにします。

## 線・文字・寸法は、JISの製図規格に合わせる

線、文字、寸法の表し方は、JISの製図規格に準じます（1-5-10〜1-5-12 pp.10-11）。

- 線: 線種はJIS Z 8312に定める15種類。太さは細線・太線・極太線の3種類
- 文字: JIS Z 8313に基づく。高さは1.8、2.5、3.5、5、7、10、14、20mmから選ぶ
- 図形と寸法: JIS Z 8316、Z 8317、Z 8318、引出線はZ 8322に準ずる

線の太さは、図面の大きさごとに標準が決まっています（表1-7 p.11）。

| 図面の大きさ | 細線・太線・極太線（mm） |
|---|---|
| A0 | 0.35・0.7・1.4 |
| A1 | 0.25・0.5・1 |
| A2 | 0.18・0.35・0.7 |
| A3 | 0.13・0.25・0.5 |

寸法線と引出線は、どの大きさでも0.13mm、輪郭線はA0の2mmからA3の0.7mmまでです。色は黒、赤、緑、青など16色を基本とします（1-5-9）。

地形データを含む図面、たとえば位置図や平面図には、測量座標系である平面直角座標系を設定するのが標準です（1-5-13）。座標系の選び方と、成果の測地系の確かめ方は[座標系と測地系の基礎](/practice/coordinate-systems-geodetic-datum)にまとめています。

## 3次元モデルは、2次元図面と整合させるのが原則

ここから、3次元モデルに話を移します。直轄土木工事の詳細設計では、令和5年度からBIM/CIMの原則適用が始まり、3次元モデルの納品が義務づけられました。今後は2次元図面に加えて3次元モデルを工事契約図書とし、積算や施工への活用を広げる方針です。

ところが、現状では2次元図面を作ってから3次元モデルを別に作るケースが多いと、国土交通省は認めています。設計段階で図面を直しても、モデルに反映されなければ、両者の形が食い違います。

そのため、BIM/CIM取扱要領（令和8年3月）の2-3-1は、モデルと図面の整合を原則とし、当面は詳細度300以上で作る主要構造物から確認を進める扱いとなっています（[BIM/CIM取扱要領](https://www.mlit.go.jp/tec/content/001990086.pdf) 2-3-1 pp.19-20）。

確認の方法は、附属資料2「設計段階における3次元モデルと2次元図面の整合確認方法（案）」にあります。案の段階の資料なので、確定したかどうかは最新の公表で確かめてください。

### 作り方によっては、整合確認は要らない

附属資料2は、次のどちらかを満たし、その根拠が確認できる場合は、整合確認を不要とします（[附属資料2](https://www.mlit.go.jp/tec/content/001990089.pdf) 2(1) p.附2-2）。

- 納品する3次元モデルから、2次元図面を切り出して作っている
- 同一のソフトウェアで、同一の入力情報から、3次元形状と2次元図面を自動で生成している

図面とモデルの食い違いは、別々の入力から作るところで生まれます。出どころが一つなら、食い違う余地がないという考え方です。「根拠が確認できる場合」という条件が付いていますが、根拠の示し方に決まりはありません。引継書や打合せ記録で、どちらの作り方かを聞いておきましょう。

### 別々に作ったなら、外形線を重ねて確かめる

図面を先に作り、モデルを別に作るなら、整合を確かめる作業が要ります。主要構造物の数量算出に使うモデルでは、次の手順が例として示されています（附属資料2 3(1) pp.附2-5〜附2-6）。

1. 2次元図面の構造物外形線をソフトウェアに取り込み、3次元モデルを作る。このとき、外形線をモデル上に残す
2. 納品の前に、残した外形線を2次元CADへ取り込み、納品する図面の外形線と一致するか見る
3. 一致しなければ、納品する図面の外形線を取り込み直し、それに合わせてモデルを直す

トンネルや擁壁のような線形構造物は、曲線区間などを考え、形状の根拠になる平面図と基準断面の外形線を残して、同じ確認を行います。

土工の線形データをICT施工の元データにするときは、J-LandXML形式の中心線形を、平面図と縦断図に照らして各測点の位置を見ます。照合の相手は、納品する図面と合った線形計算書の座標値で、この方法は推奨として示されたものです。なお、ダム・砂防堰堤など中心線の定義が困難な土工は、対象外とされています（3(2) pp.附2-7〜附2-8）。

数値の確認では、図面に書かれた寸法の単位と有効数字で合わせます。寸法がmm単位の整数で書かれている図面なら、原則として1mm単位での一致を見ます（2(5) p.附2-4）。

<Callout type="note" title="何のために合わせるか">
確認の目標は、主要構造物のモデルの体積が設計数量に使えること、土工の3次元線形がICT施工のデータに使えることです。出来上がりイメージの確認だけのモデルなど、この水準を要しないものは、確認の方法と要否を受発注者で協議します（2(3)(4) pp.附2-3〜附2-4）。
</Callout>

### 3次元に付けた注記は、交換形式で落ちる恐れがある

もう一つの落とし穴が、注記です。BIM/CIM取扱要領は、IFCとJ-LandXMLでは、文字列と引出線の交換が定義されていないと述べています（2-3-1 p.20）。モデルの中に書き込んだ注記や引出線は、別のソフトウェアへ渡すと消えるかもしれません。そのため、渡したい注記は2次元図面と3次元モデル作成引継書シートで確実に伝えます。

整合確認を行った場合は、「3次元モデル照査時チェックシート」にその旨を書き、「3次元モデル作成引継書シート」に、確認した図面の名前と選んだ理由を書きます。確認をしていない箇所があれば、その箇所と理由も引継書に書く決まりです（附属資料2 2(6)(7) p.附2-4）。

## ワイヤ・面・立体で、モデルが持つ情報が違う

同じ橋脚でも、モデルの作り方によって、持っている情報が違います。3次元モデル表記標準（案）は、モデリングの手法としてソリッドモデル、サーフェスモデル、ワイヤーフレームモデルを挙げています（[3次元モデル表記標準（案）](https://www.mlit.go.jp/common/001289109.pdf) 令和元年5月版 第1編 2-2 p.11）。

この標準は、BIM/CIM取扱要領（令和8年3月）p.5で、内容が更新済み、または取組が終了した資料に分類されています。令和2年3月版と読み比べると、ここで引く補足幾何形状・平行投影・保存ビュー・色の記述は同じ内容ですが、頁は1頁ずつずれ、平行投影の図の名称は「3DA面図」に変わっています。現行の定めではなく、考え方の参考として読んでください。

受け取ったモデルを、数量に使えるかという判断の順に見ます。

- 数量に使うなら: 体積が定まる立体（ソリッド）か。内部が詰まっていれば、体積を求められる
- 面だけのモデル（サーフェス）なら: 面が閉じているか。曲面の形や面積は読めるが、閉じていなければ体積は定まらない
- 線だけのモデル（ワイヤーフレーム）なら: 形の確認用と割り切る。面を持たないので、体積は出せない

整合確認の目標が「モデルの体積を設計数量に使うこと」なので、数量に使うモデルは、体積が定まる立体であることが前提になります。画面でなめらかに見えるモデルでも、面だけで作られていれば、数量には使えません。どの手法で作られているかは、属性や作成者の説明で確かめます。

もう一つ、形状モデルには、モデルの形そのものに加えて、補足幾何形状という要素があります。道路中心線、堤防法線、測量法線、計画高水位、建築限界線などで、設計の要求を正確に伝えるために補足的に作られた点・線・面です。見た目には目立たない線が、設計の条件を担っていることがあります。

詳細度とモデル化の範囲の決め方は、[BIM/CIMの現場実務](/practice/bim-cim-site-practice)で扱っています。

## 寸法を読む図は、平行投影で切り出す

3次元のモデルを、紙や画面の2次元に写すのが投影です。投影には、投影の中心を無限の遠くに置く平行投影と、有限の距離に置く透視投影があります（表記標準 令和元年5月版 第1編 2-5 p.18）。令和元年5月版の表記標準は、モデルから切り出す平面図（3DA平面図）の作成に、平行投影を使うよう求めています。

  width={400}

違いは、辺の見え方に現れます。平行投影では、平行な辺は平行なまま描かれ、投影面に平行な辺は実長で表れるのが特徴です。一方、透視投影では、遠い辺が近い辺より小さく、平行な辺は先へ向けて寄っていきます。人の目に近い見え方なので完成のイメージには向く反面、画面上の長さをそのまま寸法として読むことはできません。

寸法を読む図は、投影面に正対させた平行投影（3DA平面図）にします。斜め上から見るビューは、平行投影でも辺が縮んで見えるので、寸法の根拠にしません。

全体のイメージを伝える図は透視投影、という使い分けになります。切り出す位置は、CAD製図基準で定められた図面の位置が基本です。投影法の規格としては、JIS Z 8315「製図−投影法」があり、正投影、軸測投影、中心投影の三つを扱います。CAD製図基準は、図形の表し方をJIS Z 8316に準ずるとしています（1-5-12）。

表記標準は、3DA平面図をモデルからの切り出しを標準とし、別の設計ソフトウェアで作った2次元図面データを使ってもよいとしています。後者を使うなら、図面の寸法とモデルの形に差が出ないようにする、という条件が付きます（2-5、2-7）。前の節の整合確認とつながる話です。

## 見る向きと表示状態は、保存ビューで固定して渡す

モデルは、回して見られるのが長所ですが、見る人によって向きも表示も違ってしまうのが短所です。そこで、見る向きと表示の状態を保存しておく仕組みが、保存ビューです。表記標準は、保存ビューに次の状態を組み合わせて保存できるとしています（第1編 2-6 p.21）。

<ArticleImage src="/posts/civil-practice/cad-3d-model-visualization/img/photo-model-review-desk.webp" alt="机の2台のモニターに、橋脚の3次元モデルと同じ橋脚の2次元図面を並べて表示した様子" width={960} height={720} />

- 形状モデルを見る特定の向きと倍率
- 構造特性や補足幾何形状などの情報の表示と非表示
- 表示の状態。ソリッド、ワイヤーフレーム、断面表示など

設定できるビューの種類は、従来の正面図・側面図に当たる正投影ビュー、各断面図に当たる断面ビュー、斜め上から見る3次元投影ビュー、回しても正対して表示される固定ビューです。作成者以外の人が成果を確認するとき、注記が見やすい位置に置かれ、読めるように設定するのが保存ビューの趣旨です。断面ビューを設けるなら、視線の位置と向きの明示も求められます。

発注者の立場なら、保存ビューの一覧がモデルに付いているかを見ましょう。一覧があれば、誰が開いても同じ向きで同じ表示を確かめられて、図面との見比べもしやすくなります。

## 色・陰影・テクスチャは見た目の道具で、寸法の根拠にしない

BIM/CIM取扱要領は、可視化の目的を、全体のイメージの共有、景観の検討、2次元では難しい特定部の確認と整理しています（表-7 p.15）。どれも、見て理解するための使い方です。出来上がりイメージの確認だけを目的とするモデルは、整合確認の要否を受発注者で協議する、と附属資料2も述べています（2(4) p.附2-4）。

色の決まりも、見分けやすさのためのものです。表記標準は、単一の部材に使う色を可能な限り1部材1色とし、背景の色と明瞭に区別できる色にするとしています（2-8 p.23）。設計変更の箇所を示すときだけ、複数の色を使い分けてもよいとされています。色の違いは、部材の区別や変更箇所の目印であって、材質や強度の情報とは別のものです。

陰影も同じです。陰影は、光の当たる向きを仮定して、面の明暗を付けた表示で、同じモデルでも光源の向きを変えれば明暗が変わります。面の傾きの違いは分かりやすくなる一方、勾配や寸法の値は、陰影から読めません。値は属性と図面から読み、画面は形を理解する助けに使います。

<Callout type="warn" title="貼った写真は、形ではない">
テクスチャは、面の上に貼る画像です。石積みの写真を貼った壁面は、石積みに見えても、凹凸や目地の深さをモデルが持っているとは限りません。仕上げや材質は、属性と図面で確かめます。
</Callout>

### テクスチャ画像は、大きさと解像度で表示が重くなる

テクスチャを使うと、画像のぶんだけデータが増え、表示が重くなります。3D都市モデルの標準製品仕様書（第5.0版）は、テクスチャ画像の決まりを定めています（[標準製品仕様書 第5.0版](https://www.mlit.go.jp/plateau/file/libraries/doc/plateau_doc_0001_ver05.pdf) 9.4 pp.1354-1355）。

- 画像の辺は2の累乗で、2048ピクセル以下が基本
- 解像度は10cm/pixel以下（1ピクセルが10cm以内に収まる細かさ）が基本
- 複数の地物の画像を1枚にまとめるアトラス化を推奨
- 面への貼り付けは、UV座標で行う

画像の枚数が多いと、読み込みの回数も増えます。1枚にまとめるアトラス化が推奨されているのは、そのためと考えられます。この仕様は都市モデルのものですが、構造物のモデルに写真を貼るときの目安にはなるでしょう。

標準製品仕様書は第5.1版も公表されているため、使う版の本文で値を確かめてください。都市モデルの入手は、[公開されている地理空間データの使い方](/practice/open-geospatial-data)で扱っています。

## VR/ARは見せる道具で、判定は計測値で行う

VRとARは、モデルを現地の目線で見せる手段です。BIM/CIM取扱要領の附属資料1は、視覚化による効果の活用項目としてAR・VRなどを挙げ、詳細度200〜400での活用を挙げて、費用対効果を意識するよう求めています（附属資料1 pp.附1-2〜附1-3）。

位置合わせの手段や、施工前の合意形成での使い方は、[BIM/CIMの現場実務](/practice/bim-cim-site-practice)に整理してあります。

ここで確かめておきたいのは、位置づけです。VRやARの画面で、構造物の位置が現場とぴったり重なって見えても、それは見え方の話です。

出来形の合否は、計測した値と規格値の比較で決めます。出来形管理に使う計測の要求精度は[3次元計測の選び方](/practice/3d-measurement-selection)に、工事の流れの中での位置づけは[ICT施工の実務ワークフロー](/practice/ict-construction-workflow)にあります。

## 受け取ったときの確かめ順

最後に、2次元図面と3次元モデルを一緒に受け取ったときの確かめ順を並べます。

1. 図面管理項目の「適用要領基準」で、どの版のCAD製図基準かを見る
2. 保存形式（P21かP2Z）、ファイル名の並び、改訂履歴のZを見る
3. レイヤ名が責任主体・図面オブジェクトの形か、発注者の注記がORDに入っているかを見る
4. モデルの作り方（切り出し、同一生成、別々に作成）を聞き、別々なら外形線の重ね合わせの結果を引継書で見る
5. 注記や引出線が、モデルだけに入っていないかを見る
6. 保存ビューの一覧を開き、寸法を読む図が正対した平行投影かを見る
7. 色、陰影、テクスチャ、VR/ARの画面を、寸法や合否の根拠にしていないかを見る

どれも、特別な道具を使わずに確かめられる点です。見え方が整っているほど、確かめる手順を省きたくなりますが、整合の根拠は図面と計測値の側にあります。
