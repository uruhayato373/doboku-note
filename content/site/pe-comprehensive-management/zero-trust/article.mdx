## ゼロトラストとは

ゼロトラストとは、ネットワークの内部・外部を問わず**すべてのアクセスを信頼しない**ことを前提とし、あらゆる通信に対して認証・認可・検査を行うセキュリティモデルである。

従来の**境界型防御**（ペリメタセキュリティ）は、社内ネットワークを「信頼できる領域」、社外を「信頼できない領域」として境界線で防御する考え方であった。

しかし、クラウドサービスの普及やリモートワークの増加により、社内外の境界が曖昧になり、境界型防御だけではサイバー攻撃の脅威を防ぎきれない状況が顕在化してきた。

ゼロトラストは、この課題に対応するため2010 年頃に提唱され、2020 年に米国国立標準技術研究所（NIST）が「NIST SP800-207 Zero Trust Architecture」を発行したことで、国際的な標準概念として定着した。

## 境界型防御との比較

境界型防御とゼロトラストは、防御の起点と脅威の想定範囲において本質的に異なる。以下に主要な観点を示す。

- **基本思想**: 境界型防御 = 内部は信頼、外部は遮断 — ゼロトラスト = すべてを信頼しない
- **防御の起点**: 境界型防御 = ネットワーク境界（ファイアウォール等） — ゼロトラスト = 個々のアクセスリクエスト
- **内部からの脅威**: 境界型防御 = 想定が弱い — ゼロトラスト = 内部も検証対象
- **クラウド対応**: 境界型防御 = 境界の外にあるため防御が困難 — ゼロトラスト = リソースの場所に依存しない
- **代表的手段**: 境界型防御 = [ファイアウォール](/docs/pe-comprehensive-management-firewall-ids)・[VPN](/docs/pe-comprehensive-management-vpn)・[DMZ](/docs/pe-comprehensive-management-dmz) — ゼロトラスト = 多要素認証・マイクロセグメンテーション・最小権限の原則

両者の決定的な違いは「どこで・何回検証するか」にある。境界型防御は境界で一度認証すれば内部を信頼領域として扱うのに対し、ゼロトラストは信頼領域そのものを設けず、アクセスのたびに検証を繰り返す。

## ゼロトラストの基本原則

NIST SP800-207では、ゼロトラストアーキテクチャの基本的な考え方として以下を示している。

- **すべてのリソースへのアクセスを動的に検証する** — アクセスのたびに認証・認可を行う
- **通信はすべて暗号化する** — ネットワークの場所に関係なく通信の安全性を確保する
- **最小権限の原則** — 必要最小限のアクセス権のみを付与する
- **リソースへのアクセスはセッションごとに判断する** — 過去の認証結果を無条件に信頼しない

## 主要な実現技術

ゼロトラストは単一の製品ではなく、認証・分割・監視・制御を担う複数の技術を組み合わせて実現する。

| 技術 | 役割 |
|---|---|
| [多要素認証（MFA）](/docs/pe-comprehensive-management-multi-factor-authentication) | 記憶・所持・生体の複数要素で本人確認 |
| マイクロセグメンテーション | ネットワークを細分化し、セグメント間の通信を制御 |
| EDR（Endpoint Detection and Response） | 端末ごとの脅威検知と対応 |
| SASE（Secure Access Service Edge） | ネットワーク機能とセキュリティ機能をクラウドで統合 |
| [アクセス制御](/docs/pe-comprehensive-management-access-control) | リソースごとのきめ細かなアクセス権限管理 |
