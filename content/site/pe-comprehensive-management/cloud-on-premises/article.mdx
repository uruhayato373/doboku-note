## クラウドコンピューティングとは

クラウドコンピューティングとは、サーバ・ストレージ・ネットワークなどのITリソースを、インターネット経由でオンデマンドに利用できるサービス形態である。

利用者は自らハードウェアを保有・管理する必要がなく、必要な分だけリソースを確保し、従量課金で利用できる。

NIST（米国国立標準技術研究所）の定義では、クラウドの本質的特徴として、オンデマンド・セルフサービス、幅広いネットワークアクセス、リソースプーリング、迅速な弾力性、計測されたサービスの5 つが挙げられている。

### クラウドのサービスモデル

クラウドのサービスモデルは、事業者がインフラ・実行環境・アプリケーションのどこまでを提供するかによって 3 つに大別される。

- **IaaS（Infrastructure as a Service）**: 仮想マシン・ストレージ等のインフラを提供 — 利用者は OS 以上すべてを管理 — 代表例: AWS EC2、Azure VM
- **PaaS（Platform as a Service）**: アプリ実行環境・開発基盤を提供 — 利用者はアプリケーションとデータを管理 — 代表例: AWS Lambda、Azure App Service
- **SaaS（Software as a Service）**: 完成したアプリケーションを提供 — 利用者はデータと設定のみ管理 — 代表例: Microsoft 365、Google Workspace

<Callout type="warn" title="PaaS と SaaS を混同しない">
過去問 [R03 Ⅰ-1-23](/docs/pe-comprehensive-management-r03-primary#1-23) では「PaaS は電子メール・グループウェアなどのアプリケーション機能をネットワーク経由で提供する」という記述が **誤答** として出題された。アプリケーション機能の提供は **SaaS**。PaaS が提供するのはアプリケーションの開発・実行プラットフォームである。
</Callout>

3 つのサービスモデルは、アプリケーションからハードウェアまでの各層を「利用者と事業者のどちらが管理するか」で整理すると違いが明確になる。SaaS に近いほど事業者の管理範囲が広く、利用者の負担は小さくなる。

### クラウドの配置モデル

配置モデルは、クラウド資源を自組織専用とするか他社と共用するかで分かれる。専用性が高いほどセキュリティは高まるがコストも増し、複数の形態を組み合わせる選択肢もある。

| 配置モデル | 概要 | 特徴 |
|---|---|---|
| **パブリッククラウド** | クラウド事業者が一般に提供 | 低コスト・高い拡張性 |
| **プライベートクラウド** | 特定組織専用に構築 | セキュリティ・カスタマイズ性が高い |
| **ハイブリッドクラウド** | パブリック＋プライベートの組み合わせ | 柔軟な使い分けが可能 |
| **マルチクラウド** | 複数のパブリッククラウドを併用 | ベンダーロックイン回避 |

### オンプレミスとの比較

オンプレミスとは、サーバやネットワーク機器を自組織内に設置・運用する従来型の方式である。クラウドが資源を「借りる」のに対し、オンプレミスは資源を「持つ」。この所有形態の違いが、コスト構造から災害対策まで両者の特性を分ける。

| 評価項目 | クラウド | オンプレミス |
|---|---|---|
| **初期コスト** | 低い（従量課金） | 高い（設備投資が必要） |
| **運用コスト** | 利用量に応じて変動 | 固定費中心（人件費・保守費） |
| **拡張性** | 需要に応じて即座にスケール | 物理的な増設が必要 |
| **カスタマイズ性** | サービス仕様の制約あり | 自由度が高い |
| **セキュリティ統制** | 事業者のポリシーに依存 | 自組織で完全管理 |
| **データ所在** | 事業者のデータセンター | 自組織内に保管 |
| **災害対策** | 地理的冗長化が容易 | 自前でDR環境を構築 |

### クラウド移行の判断基準

クラウドとオンプレミスの選択にあたっては、以下の観点から総合的に判断する。

**クラウドが適する場合**: 需要変動が大きい、初期投資を抑えたい、迅速なサービス立ち上げが必要、グローバル展開を想定している。

**オンプレミスが適する場合**: 機密性の極めて高いデータを扱う、既存システムとの密結合がある、通信遅延が許容できない、法規制上データの国内保管が必須である。

## 総合技術監理における位置づけ

総合技術監理キーワード集では[**4.4 情報通信技術動向**](/docs/pe-comprehensive-management-keyword-2026#44-情報通信技術動向)に位置づけられる。

クラウドとオンプレミスの選択は、集中化と分散化の設計方針と密接に関わり、RASIS指標（特に可用性・安全性）による定量評価が判断根拠となる。東日本大震災以降は、地理的冗長化が容易なクラウドが[事業継続計画（BCP）](/docs/pe-comprehensive-management-business-continuity-plan)の手段として採用を広げた。

政府調達の分野では、2021 年策定の「政府情報システムのためのセキュリティ評価制度（ISMAP）」により、政府が利用するクラウドサービスのセキュリティ評価が制度化され、官公庁のクラウド移行に制度的根拠が与えられた。
