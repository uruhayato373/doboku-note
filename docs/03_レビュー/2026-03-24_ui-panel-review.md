# UI パネルレビュー: doboku-note サイト全体

対象: `src/app/`, `src/components/layout/`, `src/styles/globals.css`, `tailwind.config.ts`
実施日: 2026-03-24

---

## UX デザイナー

このサイトのジョブは「土木技術者が設計式や基準を素早く参照する」こと。目次（ToC）の IntersectionObserver による追従は良い。しかし **トップページが致命的に弱い**。h1「doboku-note」とカード4枚だけで、検索流入ユーザーに「何が載っていて、自分の探しているものがあるか」を3秒で伝えられない。港湾・環境カテゴリがトップページの features に含まれていないのも問題。サイドバーの `text-xs`（約11px）は情報密度は高いが、50以上の項目がある漁港編では視認性が厳しい。

## ビジュアルデザイナー

**h2 の黒ベタ背景が重すぎる**。box-shadow で二重枠を作っている意図はわかるが、スクロール中に「黒い壁」が連続して現れる印象で、ページ全体が暗く感じる。h3 の左ボーダーは悪くないが、h2 との落差が大きい。色のパレットが `#333` 系のグレー一色で、アクセントカラーが事実上存在しない。リンク色 `#0066cc` だけが唯一の色彩だが、`primary: #333` と衝突している。Tailwind の `text-primary` がグレーになるのは混乱の元。余白は概ね適切だが、トップページのカードに border も shadow もなく、カードに見えない。

## フロントエンドエンジニア

CSS 設計に問題がある。`globals.css` でカスタムクラス（`.markdown > h2` 等）を書きつつ、Tailwind も使っている**二重管理**状態。mdx-components.tsx の table が `<div className="table-wrapper">` で囲むが、globals.css の `.table-wrapper` は `display: flex; justify-content: center` で、Markdown テーブルの `min-w-full` と矛盾する場面がある。KaTeX CSS を `layout.tsx` の `<head>` で CDN 読み込みしつつ `globals.css` でも `@import "katex/dist/katex.min.css"` していて**二重読み込み**。Font Awesome も `@import` で全量読み込みしているがアイコンは h4 の1種類しか使っていない。バンドルが無駄に大きい。

## アクセシビリティ専門家

サイドバーに `<nav aria-label>` がない。`<aside>` だけではスクリーンリーダーが「これがナビゲーションだ」と判別しにくい。目次の見出し `<h4>` がセクション見出しのような使い方だが、コンテンツ側の h4 と同じ depth で競合する。テーブルの `<th>` に `scope` 属性がない（mdx-components.tsx:33）。モバイルメニューのフォーカストラップがない — メニューを開いた状態で Tab キーを押すと背面要素にフォーカスが移る。前後ナビの `&larr;` `&rarr;` は装飾的だがスクリーンリーダーには「left arrow, right arrow」と読まれる。

## テクニカルライター

**最大の問題は、文書の出典情報が弱い**こと。SourceCard コンポーネントがあるが、MDX の frontmatter に `source` がないページでは何の文書のどの版を見ているかわからない。漁港ガイドラインの MDX を見ると、通知番号や改正年月日は本文内に埋もれている。節番号の体系も文書間で統一されていない。図の番号体系（`p14.png`, `p15.png`）はページ番号であって図番号ではなく、本文中の「図1」「図2」との対応がとれない。印刷時の CSS が一切定義されていない。

## モバイル UI 専門家

サイドバーが `hidden lg:block` で 1024px 未満では完全に消える。**モバイルでのサイドバーナビゲーションが存在しない**。Navbar にカテゴリリンクはあるが、そこからサイドバーの詳細な目次構造にアクセスする手段がない。数式は `scroll-equation` で横スクロール対応しているが、ユーザーにスクロール可能であることを示すインジケーターがない。本文 14px はモバイルでは小さい。ToC は `hidden xl:block` で 1280px 未満で消えるが、長い技術文書でページ内ナビがないのは厳しい。

## SEO/コンテンツ戦略家

`generateMetadata` は適切に動作している。ただし構造化データ（JSON-LD）が一切ない。技術文書は `TechArticle` スキーマとの相性が良い。`robots.txt` や canonical URL の設定を確認すべき。トップページの h1 が「doboku-note」というブランド名のみで、「土木工学 技術資料」のような検索意図に一致するテキストが title にも description にも H タグにも不足。内部リンクが前後ナビのみで、関連ページへのクロスリンクが弱い。

## 一般ユーザー代表（土木技術者）

トップページを開いたが、**何のサイトか説明がない**。「doboku-note」というタイトルの下に説明文がなく、カード4枚が並んでいるだけ。「港湾」カテゴリはどこ？ 検索から漁港の設計基準のページに飛んだが、サイドバーの文字が小さくて、30以上ある編のどこに自分がいるかわかりにくい。スマホで見たら目次がないので、長い数式のページで迷子になった。前のページ/次のページのリンクは助かるが、「一覧に戻る」ボタンがほしい。

## 競合分析の専門家

国総研の技術資料PDFと比較して、このサイトの優位性は「検索性」と「モバイル対応」のはず。だが現状、モバイルでサイドバーが消えて検索性が失われている。e-Gov の法令データベースと比べると、法律コンテンツの構造化が弱い。一方、設計式が KaTeX でレンダリングされ、図がインラインで表示される点は PDF に対する明確な優位。**サイト内検索（Algolia）がナビバーにない**のが致命的 — 技術者がこのサイトに来る主な行動は「特定の式を検索する」はず。

## 教育デザイナー

各ページに「学習目標」や「前提知識」の明示がない。漁港ガイドラインの参考資料3前半などは専門的で、初学者は「何を理解すべきか」がわからないまま読み進めることになる。ただしこれは原典忠実の方針との兼ね合い。より実現可能な改善は、**ページ冒頭にパンくずリスト + ページの位置づけを示すこと**。現在のパンくずは存在しない。長い技術文書でも「見出しから数式に飛ぶ」ためのアンカーリンクは機能しているが、「戻る」導線がない。

## パネル総括

### 致命的な問題（すぐ直すべき）

- **モバイルでサイドバーナビゲーションが完全に欠落** — 全ページでページ内目次もカテゴリ目次もアクセス不能
- **KaTeX CSS の二重読み込み** — CDN (`layout.tsx`) と npm (`globals.css`) で同じCSSを2回ロード
- **サイト内検索が UI 上に存在しない** — Algolia を導入済みだがナビバーに検索窓がない
- **サイドバーに `<nav aria-label>` がない** — アクセシビリティ違反

### 改善提案（優先度順）

1. **モバイルサイドバー/ドロワー** — ハンバーガーメニューでサイドバー目次を表示可能にする
2. **検索窓をナビバーに追加** — 技術者の主要ユースケースに直結
3. **h2 スタイルの見直し** — 黒ベタ → 左ボーダー + 太字 or 薄い背景色に変更し、ページの重さを軽減
4. **primary カラーの再設計** — `#333`（グレー）をプライマリとするのではなく、アクセントカラーを別途定義
5. **パンくずリスト** — 現在位置の把握と上位階層への遷移
6. **Font Awesome の削除** — h4 アイコン1つのために全量ロードは過剰。CSS `::before` + Unicode か SVG に置換
7. **トップページの改善** — サイト説明文、全カテゴリの掲載、コンテンツ数の表示
8. **`<th scope="col">` の付与** — mdx-components.tsx で一括対応可能
9. **図の命名を図番号ベースに** — `p14.png` → `fig-2-2-1.png` のような意味のある名前
10. **印刷用 CSS** — `@media print` でヘッダー/フッター/サイドバーを非表示にし、本文のみ印刷

### 良い点（維持すべき）

- ToC の IntersectionObserver による追従 — 技術文書で非常に有用
- KaTeX による数式レンダリング — PDF に対する明確な優位
- 前後ナビゲーション — 連続する章を順番に読む導線
- サイドバーの折りたたみ構造 — 大量のコンテンツを整理
- MDX によるコンテンツ管理 — 構造化されたコンテンツ
- Mermaid 対応 — 図表のテキストベース管理
