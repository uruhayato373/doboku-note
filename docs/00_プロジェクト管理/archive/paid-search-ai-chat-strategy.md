# 国の機関文書 Markdown 化 × 有料検索・AI Chat 販売戦略

作成日: 2026-03-24

## エグゼクティブサマリー

国土交通省・環境省等が公開する技術基準・設計便覧・施工管理基準等の公的 PDF 文書を構造化 Markdown（MDX）に変換し、以下を有料販売する:

1. **高精度全文検索** — 横断的キーワード検索・フィルタリング・条文ジャンプ
2. **AI 技術チャット** — RAG ベースの質問応答（出典付き回答）

現在の doboku-note は 501 ファイル（21 万行）の MDX コンテンツを保有しており、これを **無料閲覧（広告収益）+ 有料検索・AI Chat（サブスク収益）** のハイブリッドモデルで収益化する。

---

## 1. ビジネスモデル

### 1.1 フリーミアム構成

| 層 | 提供内容 | 価格 |
|---|---|---|
| **Free** | 全ページ閲覧、基本サイト内検索（Algolia 既存）、広告表示 | ¥0 |
| **Pro** | 高精度横断検索、AI チャット（月 50 回）、広告非表示、ブックマーク同期 | ¥980/月 or ¥9,800/年 |
| **Team** | Pro 全機能 + 複数ユーザー管理、質問履歴共有、API アクセス、AI チャット無制限 | ¥2,980/ユーザー/月 |

### 1.2 なぜこの価格か

- **¥980/月**: 技術書 1 冊（¥3,000〜5,000）の月割り以下。「基準書を買うより安い」と感じさせる水準
- **¥9,800/年**: 月額の 10 ヶ月分。年額ディスカウントで LTV を確保（解約率低減）
- **Team ¥2,980**: 法人の経費精算範囲（月 3,000 円未満は多くの企業で部門決裁可能）

### 1.3 コンテンツの無料公開が前提

**重要: MDX コンテンツ自体は全て無料公開する。** 理由:

1. SEO 流入が全ての基盤（NSM = 月間オーガニック検索流入ユーザー数）
2. 公的文書をペイウォールで囲むと信頼性・被リンク獲得が損なわれる
3. 無料ユーザーの広告収益 + 有料転換の両取りが最も効率的
4. 競合（施工管理ドットコム等）が無料で提供している以上、閲覧課金は成立しない

有料化するのは **「検索・AI という付加価値レイヤー」** のみ。

## 3. プロダクト設計

### 3.1 有料検索機能

#### 基本検索（Free）
- Algolia DocSearch（既存）
- タイトル・見出しレベルの検索
- 10 件/ページ

#### 高精度検索（Pro）
- **全文横断検索**: 全 MDX コンテンツの本文・表・数式を含む全文検索
- **ファセット検索**: カテゴリ、文書種別、発行年、キーワードでフィルタ
- **条文ジャンプ**: 検索結果から該当箇所にダイレクトリンク
- **検索履歴**: 過去の検索を保存・再利用
- **類似文書**: 閲覧中のページに関連する他の基準書を自動表示
- **差分表示**: 基準改定時の変更箇所ハイライト（将来機能）

### 3.2 AI 技術チャット

#### 基本動作
```
ユーザー: 「盛土の締固め度の基準値は？」

AI: 「土木工事共通仕様書 第3編 第2章によると、
盛土の締固め度は以下の基準を満たす必要があります:

- 路体: 締固め度 90% 以上
- 路床: 締固め度 95% 以上

出典: content/general/common-specs/03-02-construction-02a.mdx
      第2章 第3節 盛土工 表3-2-1」
```

## 7. RAG パイプライン設計

### 7.1 インデックス構築

```
MDX ファイル（501 ファイル）
    │
    ▼
チャンキング（見出し単位 + オーバーラップ）
    │  - h2/h3 見出し単位で分割
    │  - 各チャンク 500〜1000 tokens
    │  - 前後 100 tokens のオーバーラップ
    │  - メタデータ: ファイルパス、見出し階層、カテゴリ
    ▼
Embedding 生成（Cloudflare Workers AI / bge-m3）
    │
    ▼
Cloudflare Vectorize に格納
    │  - 推定ベクトル数: 5,000〜10,000 個
    │  - 次元数: 1024
    ▼
インデックス完了
```

### 7.2 クエリフロー

```
ユーザー質問
    │
    ▼
質問を Embedding 化
    │
    ▼
Vectorize で類似チャンク検索（top-k = 5）
    │
    ▼
リランキング（オプション: Cohere Rerank）
    │
    ▼
プロンプト構築:
    │  - システムプロンプト（土木技術者ペルソナ）
    │  - 取得チャンク（出典情報付き）
    │  - ユーザー質問
    ▼
LLM 呼び出し（Claude Haiku / Sonnet）
    │
    ▼
回答 + 出典リンク をユーザーに返却
```

### 7.3 ハルシネーション対策

| 対策 | 実装方法 |
|---|---|
| **出典強制** | プロンプトで「取得チャンクの情報のみで回答せよ」を指示 |
| **出典リンク表示** | 回答に使用したチャンクのファイルパス・見出しを常に表示 |
| **回答不能の明示** | 該当情報がない場合は「この質問に対応する基準は見つかりませんでした」と返す |
| **信頼度スコア** | ベクトル類似度が閾値以下の場合は警告を表示 |
| **免責表示** | 「本回答は参考情報です。正式な判断は原典をご確認ください」を常時表示 |

## 9. リスクと対策

### 9.1 ビジネスリスク

| リスク | 影響度 | 発生確率 | 対策 |
|---|---|---|---|
| 有料転換率が想定以下 | 高 | 中 | Free の AI Chat 回数を絞る（月 3 回）/ 価格改定 |
| 競合の出現（同様のサービス） | 高 | 低〜中 | コンテンツ量と変換品質で先行者優位を確保 |
| 公的文書の著作権問題 | 高 | 低 | 著作権法 13 条（法令・通達は著作権なし）を確認、独自の構造化・注釈は著作物として保護 |
| LLM API コスト高騰 | 中 | 低 | モデル切替の柔軟性を確保、キャッシュ戦略 |

### 9.2 技術リスク

| リスク | 影響度 | 発生確率 | 対策 |
|---|---|---|---|
| AI のハルシネーション | 高 | 中 | 出典強制 + 免責表示 + 信頼度スコア |
| Cloudflare Vectorize の制限 | 中 | 低 | Supabase pgvector をバックアップ選択肢に |
| 日本語 Embedding 精度不足 | 中 | 中 | bge-m3 で検証、不足なら OpenAI embedding に切替 |
| スケール時のレイテンシ | 中 | 低 | Edge computing（Cloudflare Workers）で対応 |

### 9.3 著作権に関する整理

| 文書種別 | 著作権 | 根拠 |
|---|---|---|
| 法律・政令・省令 | **なし** | 著作権法 13 条 1 号 |
| 告示・訓令・通達 | **なし** | 著作権法 13 条 2 号 |
| 技術基準（国交省策定） | **グレー** | 国が作成した報告書は著作物だが、広く利用を想定。利用規約を要確認 |
| 設計便覧（地方整備局） | **グレー** | 同上。引用（著作権法 32 条）の範囲で利用可能 |

**対策**: 各文書の利用規約を確認し、「引用」として出典を明示。構造化・検索・AI 回答は「付加価値サービス」として独自性を主張。
