# 画像運用設計

サイト、OGP、note カバーなどの画像を、何で作り、どこで管理し、どう改善するかの設計。読者が「図で理解し、過去問で確かめる」ことを助ける画像だけを作り、見た目が AI の量産品に見えないことを保つ。

> [!important] 設計の前提（運営者の決定・2026-11-06）
> - 画像は基本的に Codex で作る。プログラムで描くのは、やむを得ない部分だけにする
> - Codex で作っても、AI っぽく見えない仕組みを持つ
> - 画像の効果と修正は継続して分析し、改善する
> - 考え方、作り方、指示文は正本で管理し、同じ内容を複数の場所に書かない

## 1. 見せ方の分類

記事や要素ごとに、次の順で問う。

1. 文字そのものが情報か（年度、資格名、問題数、商品名）。そうなら文字で見せる
2. 関係、流れ、数値を示すか。そうなら図（SVG）で見せる。誤ると学習に支障が出るので AI の絵に任せない
3. 見て分かる実物があるか（構造物、機械、現場の作業）。そうなら絵で見せる
4. どれでもない抽象的な内容は、絵に無理にせず、文字と分野の図柄で見せる

| 類型 | 主な記事 | 件数の目安 | 見せ方 |
|---|---|---|---|
| A 実物がある | 土木実務、教科書 | 約260 | ページの場面の写真 |
| B 文字が本体 | 過去問、年度別の問題 | 約300 | 分野の場面の写真＋年度の帯 |
| C 概念や用語 | 総監キーワード、法令 | 約720 | 総監は写真にしない（OGP の縮小のまま）。法令は現場の場面の写真 |
| D 読み物 | 勉強法、年収、転職、制度 | 約190 | ページの場面の写真 |

pillar の5件は個別に作る。総監は 2026-11-13 に 10 件を試作し、写真だけでは概念が伝わりにくいものがあったので、運営者の決定で写真にしないことにした（正本は `config/site-thumbnails.json` の `excluded`）。件数は 2026-11-06 時点の公開1,475記事を group から数えた概算で、A と D には他の類型が混ざる。

## 2. Codex とプログラムの分担

**既定は Codex。** プログラムで描いてよいのは次の3つだけとする。

| プログラムを使う場面 | 理由 | 例 |
|---|---|---|
| 並べて使う文字 | カードの一覧では、字体と大きさが揃わないと統一感が出ない | サムネイルの下帯 |
| 正確さが必要な図 | 数値、手順、関係は絵の雰囲気で示せない | 記事内の SVG 図 |
| 全記事へ自動で届ける合成 | 記事が増えるたびに人の確認を待てない | OGP の文字載せ |

絵、背景、人物は Codex で作る。少数の主力画像に限り、文字まで Codex で描いてよい。その場合は文字の全数監査を必須にする。

## 3. 画像の種類

OGP とサイト内サムネイルは目的が違うので分ける。共通にするのは、資格の色、生成経路、記事の原稿である。

| 種類 | 目的 | 画像 | 文字 | 対象 |
|---|---|---|---|---|
| サイト内サムネイル | サイト内の回遊 | Codex のページ別の写真調の画像 | HTML の下帯 | 全記事 |
| OGP（標準） | 共有からの流入 | ページ別の写真（サムネイルと同じ原寸） | プログラムで大きく白で載せる | 全記事（写真の無いページは資格別の背景） |
| OGP（主力） | 共有からの流入 | Codex の全面の絵 | Codex（全数監査） | 実際に共有する記事 |
| note カバー（標準） | note 内の発見 | Codex の背景と人物 | プログラムで載せる | 記事とマガジン |
| note カバー（主力） | 販売 | Codex の全面の絵 | Codex（全数監査） | 売れ筋 |

### サイト内サムネイルの型

カードに並べるので、全ページで同じ型にする。

- 画像は写真調の場面で、文字を含めない。OGP と同じ 1.91:1 の構図をそのまま使い、主題を下端の約 15% と左右の端に置かない
- 文字は写真の下端に重ねる帯に、サイトのフォントで載せる。画像に焼き込まないので、文字を直しても画像の作り直しが要らず、字体と大きさも揃う
- 帯の色は資格の色（`note-cover-tokens.json`）を使う。資格の色を持たないカテゴリ（土木実務・法令・建築など）は共通の色にする
- 絵がまだ無いページは OGP の縮小へ戻す。絵の無いページのために共通画像は持たない

写真調は、太線のイラストと比べた結果で選んだ。実務の教材らしい本物感があり、量産の絵に見えにくい。その分、実物との違いが目立つので、人物と機械の監査を外さない。

### 明暗（ダークモード）

明暗で別の画像を作らない（運営者の決定・2026-11-12）。2 枚にすると枚数と監査が倍になり、昼と夕方の版で機械や人物の中身がずれる。崩れやすいのは文字と縁なので、そこを次の形で受け持つ。

| | サイト内サムネイル | OGP |
|---|---|---|
| 明暗を決めるのは | サイト | 表示する側（X・LINE・note など）。こちらでは選べない |
| 画像 | 写真 1 枚。ダーク時だけ CSS で明るさを少し落とす | 写真 1 枚を端まで敷く。白や透明の縁を作らない |
| 文字 | HTML の帯（資格の色・白文字） | 写真の左側に暗いグラデーションを重ね、白文字で載せる（`photo-scrim`） |

写真の指示に「空や白い面などの明るい面を画面の 3 割以上にしない」を入れ、ダークの一覧で写真が浮かないようにする（画風の版 3）。

### 枚数と OGP への流用

ページごとに 1 回生成し、原寸の `site-photo.webp`（1200×630）を作る。カード用の `site-thumb.webp`（640×336）は原寸を縮めるだけにし、OGP とカードで写真の見え方を同じにする（2026-11-13 に 640×245 から改めた）。どちらも R2 から配信し、版（`version`）は原寸の sha で両方を指す。OGP の srcHash は、写真があるページだけ写真の版を入力に含める。写真を作り直すと OGP も作り直しの対象になる。

### 規格と検査

規格の値（寸法・容量・閾値）と目の監査の基準は `config/site-thumbnails.json` の `spec` と `review.criteria` だけが持つ。生成、機械の検査、Codex と Claude の監査、CI のテストが同じ値を読む。

| 検査 | 何を止めるか | いつ・どこで |
|---|---|---|
| 生の出力の比率 | 縦長・正方形に近い出力（切り出しで主題が欠ける） | 生成のとき。採用せず作り直す |
| 明るさ | 明るい面が 3 割超・暗すぎ・明るすぎ（ダークモードで浮く） | 生成のとき。指摘を題材へ足して作り直す |
| 寸法と容量 | 原寸 1200×630・カード 640×336 と容量の上限 | `site-thumbs` の機械検査 |
| 同一・似た画像 | 同じ画像（止める）、dHash が近い画像（二次監査へ） | `site-thumbs` の機械検査。全資格の写真と比べる |
| 似た題材 | 絵の指示が近い組（二次監査へ） | `site-thumbs` の機械検査 |
| 目の監査 | `review.criteria` の 8 項目（題材・土木・安全・人物・文字・AI っぽさ・切り出し・明るさ） | Codex が全件、Claude が絞った分（二次監査の不合格は指摘を題材へ足して作り直す） |
| 記録の整合 | 版と AI 台帳の sha、判定 ok、測った値が規格内、帯の文字の幅、帯の色のコントラスト比 4.5 以上 | CI（`tests/site-thumbnails-pipeline.test.mjs`）。画像は Git に無いので、生成のときに測って台帳に残した値を見る |
| 表示 | カードと OGP が明暗の両方で崩れない | 資格ごとに代表のページを撮って確かめる（`/site-visual-review`） |

## 4. AI っぽく見せない仕組み

個人の注意に頼らず、作る前、作るとき、作った後の工程に組み込む。

**作る前**

- 種類ごとに、運営者が承認した見本で画風を決める。写真調は参照画像を使わず、指示文の部品で固定する
- 不採用の見本も理由つきで残す。「光沢が強い」「現場に実在しない機材」などの理由を、次の指示文の禁止事項へ戻す
- 構図の型を複数持ち、同じ構図、ポーズ、背景が一覧で続かないように割り当てる

**作るとき**

- 共通の禁止事項を指示文へ必ず入れる。過剰な光沢、意味のない光の筋、不自然な左右対称、読めない看板文字、崩れた手指などである
- 日本の土木現場の実物に寄せる。機材の種類、保護具、標識、舗装や型枠の質感を具体的に指定する
- 現場の細部は運営者の経験を指示文の部品にする。一般的な「建設現場」では描かせない

**作った後**

- 文字は実フォントで載せることを基本にする。崩れた文字が最も AI っぽく見えるためである
- 独立監査に「AI っぽさ」の観点を足す。内容の正しさとは別に判定し、不合格の理由を台帳へ残す
- 採用前に、実際の表示の大きさ（一覧、カード、帯）で確認する。全体を原寸だけで見て判定しない

機械では判定しきれないので、合否の基準は言葉と見本で持ち、最終の基準は運営者の承認見本とする。

> [!warning] 内容の誤りは AI っぽさとは別の問題
> 2026-11-06 の試作では、絵の出来は良いが、斜めシュートから生コンを流し込む描写が教材として不適切な可能性があった。図解に近い絵は、土木の内容の確認を監査に含める。

## 5. 管理の正本

| 管理するもの | 正本 | 持つ内容 |
|---|---|---|
| 考え方 | 本書 | 分類、分担、管理の設計 |
| 作業の規則 | `image-policy.md` | 作業時の判定と手順。媒体別の文書は寸法と安全域だけを持つ |
| 共通の作り方 | `config/image-generation.json` | AI っぽさの部品、生成経路の一覧 |
| サムネイルの台帳 | `config/site-thumbnails.json` | 画風、ページごとの帯の文字と絵の題材、監査の絞り込みの基準 |
| 1枚の記録 | `.claude/state/quality/ai-image-review-ledger.json` | ハッシュ、指示文のハッシュ、画風の版、判定、理由、判定者 |
| 効果 | `data/business/experiments.json` | 比べた版、期間、指標、結論 |

指示文の全文は画像ごとに複製しない。台帳の題材と画風の版から再現し、ハッシュで照合する。画像の実体は Git に入れず、`config/asset-storage.json` の `site-thumbnails` で R2 へ供給する。

### 入口

生成の入口は `scripts/lib/codex-image.mjs` の1か所のまま保つ。並列で動かすので、Codex に画像を探させず、実行の `thread_id` から自分の画像だけを取る。加えて、**採用の入口を1つにする。** Codex の自動生成も、手作業の Codex や ChatGPT の画像も、採用時に同じ登録を通して記録する。

サムネイルの版と台帳の一致、判定が ok であることは、テストで止める。

### 三段の分担

トークンを抑えるため、できるだけ Codex に任せ、Claude は絞った分だけを見る。入口は `npm run site-thumbs`（途中で止まっても再実行で続きから動く）。

| 段 | 担当 | 内容 |
|---|---|---|
| 台帳、生成 | Codex | 帯の文字、絵の題材、画像 |
| 機械検査 | スクリプト | 同一の画像、似た題材 |
| 一次監査 | Codex | 全件。不合格は指摘を題材へ戻して作り直す（`--fix-fails`） |
| 二次監査 | Claude | Codex の指摘、機械や手順が主題の絵、似た題材、20% の抜き取り |

Codex の一次監査は、安全と手順の指摘に強く、機械の配置や題材の合致に弱い（2026-11-07 に、Claude の精査で指摘が出た17枚を含む50枚で検出7件）。Codex だけで全件を通すことはしない。Claude の指摘は Codex を通した後の103枚で不合格1枚だったので、絞り込みの語は実績を見て調整する。

描きにくい題材（特殊な機械の細部、墜落防止具の掛かり方、分かれ道の比喩など）は、指示を足すより場面を単純にする。

### 整理の対象

- 指示文は `config/image-generation.json` の `prompts` に集めた（記事の写真・OGP の背景。サムネイルの画風は `config/site-thumbnails.json`）。来歴を書くコードは `image-origin.mjs` の `aiProvenance()`・`recordAiImage()` に集めた。Codex の直接起動は `check-image-rules` が止める（いずれも 2026-11-13 に完了）
- `note-cover-clarity-v3.md` と `note-cover-crop-safe-v4.md` は、今も有効な内容を現行の文書へ移して廃止する
- 手作業の POP、ブランド写真、キャラクター素材も採用の登録に揃える

## 6. 効果の分析と改善

画像1枚ごとの効果は、流入の規模では測れない。種類または版の単位で比べる。

| 対象 | 指標 | 計測の現状 |
|---|---|---|
| サイト内サムネイル | カードの表示あたりのクリック、1訪問あたりの閲覧数 | サムネイルのある全面で、カードの表示（`internal_nav_impression`）とクリック（`internal_nav_click`）を、面のラベルと `cta_placement`（`thumb-photo` / `thumb-ogp`）つきで送る（2026-11-13） |
| OGP | SNS からの流入 | 流入元で見る。7月時点で全体の1%未満 |
| note カバー | 記事の閲覧数、購入数 | note の管理画面。カバー単位の表示回数は見られない |

比較は、同じ資格や分野で半分だけ替えて行う。note は時期で売上が動くので、前後比較だけで結論を出さない。差が見えなかった結論も実験台帳へ残し、不明を効果なしと読み替えない。

改善は月次レビューで読む。変える単位は1枚ではなく種類の設定で、指示文の部品や参照見本を直して版を上げ、対象を再生成する。修正の理由は不採用の見本へ残し、§4 の工程へ戻す。
