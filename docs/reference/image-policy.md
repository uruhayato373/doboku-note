# 画像出典ポリシー

doboku-note の記事に図・写真を載せるときのルール集。PDF スキャン画像からの脱却と、著作権クリーンな画像運用を両立するための判定フローと許容ソースを定める。

**いつ読むか**: textbook 記事のリライト時、新規 keyword ページに図を追加するとき、既存 PNG スキャンを置き換えるとき。

**関連文書**:
- 図版作成スキル: `.claude/skills/authoring/create-svg/SKILL.md`
- 画像配信フロー: `docs/reference/content-authoring.md` § 画像配信
- デザイン原則: `docs/design-system/design-system.md`

## 判定フロー

図を載せようとするときは、まず以下のフローで種別を決める。

```
1. 本文の理解に図が必要か？
   ├─ No → 図を載せない（装飾目的は禁止）
   └─ Yes → 2 へ
2. 何を示すのか？
   ├─ 概念・仕組み・工程・関係（フロー/マトリクス/比較）
   │    → SVG 新規作成（create-svg スキルを使う）
   ├─ 実機の外観・現場の雰囲気・器材の使用場面
   │    → 写真（§ 許容ソース から CC/PD 素材を取得）
   └─ 数式・表で表せる内容
        → 図にせず、本文内で表・箇条書き・数式で表現
```

## SVG 優先の原則

以下のいずれかに該当する場合、写真ではなく **SVG** を優先する。

- **構造を示す**（機械の部品構成、建物の断面）
- **工程を示す**（PDCA、施工手順、ネットワーク工程）
- **比較を示す**（Before/After、方式比較、トレードオフ）
- **関係を示す**（組織図、力の釣り合い、熱移動）
- **抽象概念を可視化する**（リスク分布、指標の位置関係）

SVG の方が写真より優れる理由:
1. **著作権リスクゼロ**（自前制作）
2. **モバイルで鮮明**（ベクタ、拡大しても劣化しない）
3. **学習効果が高い**（本質だけ抽出できる、ノイズが入らない）
4. **後からの修正が容易**（テキスト・色・レイアウトをファイル直編集）

SVG 制作は `create-svg` スキルに従う。モバイル 400px viewBox、デザイントークン（brand/positive/warn/danger）、4 つのレイアウトパターンを適用する。

## 許容ソース（写真を使う場合）

写真が本質的に必要な場面（建設機械の外観、現場の雰囲気など）では、以下のソースから取得する。**ライセンス条件を必ず確認**し、商用利用可・改変可のものだけを採用する。

### 推奨ソース（優先順）

| ソース | ライセンス | 用途 | 備考 |
|---|---|---|---|
| **Wikimedia Commons** | CC-BY / CC-BY-SA / CC0 / Public Domain | 最優先。建設機械・測量器材・構造物外観が豊富 | 画像ページでライセンス種別を必ず確認 |
| **国交省・省庁系画像ライブラリ** | 政府標準利用規約（ほぼ商用 OK） | 公共工事・災害事例・法令解説 | 出典表記必須、加工可の旨を確認 |
| **Unsplash / Pexels / Pixabay** | 各サイトライセンス（商用可・出典任意が多い） | 汎用的な風景・作業風景 | 素材が建設特化でない点に注意 |
| **メーカー公式画像** | 各社利用規約次第 | 特定製品の説明に限定的に | **事前に商用利用可を確認したもののみ**。グレーな場合は使わない |
| **自前撮影** | 著者に帰属 | 現場写真が必要だが上記で入手不可な場合 | 人物・私有地の写り込みに注意 |

### 禁止ソース

- **Google 画像検索の無差別利用** — 出典不明・ライセンス未確認のまま使わない
- **他社書籍・教材のスキャン** — 既存の PDF スキャン PNG も、ライセンス不明なものは置換対象
- **SNS（Twitter/X、Instagram 等）投稿画像** — 個人の著作物
- **ストックフォトの有料版を無許諾で利用** — 透かし除去・トリミングによる回避は違法

> [!note]
> **政府機関由来の図の扱い（2026-07-02 更新）**: 原典が国土交通省等の政府機関（白書・年報・統計・省庁HP）の図・グラフは、政府標準利用規約により出典明記のうえクロップ等の加工・商用利用が可。使う場合は画像直前に `{/* source: 国土交通省「…」, 政府標準利用規約 */}` ＋ caption に短い出典を付す。
>
> **運営者権利保有書籍の例外（2026-07-03 再々確定）**: 技術士建設部門『論文対策キーワード』は**運営者が著作権に問題がない（権利を保有する）ことを明言**しており、同書のスキャン図（`docs/textbook/技術士（建設部門）/論文対策キーワード/img/figNN.png`）は**クロップして `*-ronbun-keyword` 記事へ埋込可**（本書に限る例外。一般の「他社書籍・教材のスキャン」禁止は不変）。埋込時は `{/* source: ... */}` コメント＋出典 caption を付す。
>
> **経緯**: 2026-06-22 に本例外を設け 02(iji-kanri) で実施 → 2026-07-02 いったん撤回（クロップ図撤去・原典直接取得のみ可へ） → **2026-07-03 運営者判断（著作権問題なし）で例外を復活**。逐語本文の活用可否も同判断で許可。真実源＝`docs/textbook/技術士（建設部門）/論文対策キーワード/README.md`。

## 禁止事項: 写真の "参考 SVG 化"

既存写真を参考にして SVG（線画トレース・構図模倣）を作ることは **原則禁止**。

**理由**: 日本著作権法・米国著作権法ともに、特徴的な構図・配置の模倣は「翻案権侵害」と判定されるリスクがある。「参考にしただけ」は抗弁として弱い。

**許容される再構成**:
- 機械部品の **一般的な名称と配置** を示す SVG（例: ブーム・フック・ワイヤの関係図）は、技術的事実の可視化であって特定写真の模倣ではないため OK
- 力学的な関係図（例: 土圧の方向ベクトル）も同様に OK

**NG 例**:
- 特定メーカーの特定機種のシルエットを SVG 化
- 特定教科書の図版レイアウトをそのまま SVG で再現

判断がつかない場合は「削除して本文のみ」または「別ソースから写真取得」を選ぶ。

## 出典表記フォーマット

CC/PD 写真を使うときは、**画像直前の MDX コメント** で出典を明記する。grep 検出と将来の監査を容易にするため、以下の固定フォーマットで書く。

### 写真（CC/PD ソース）

```mdx
{/* source: Wikimedia Commons, CC-BY-SA 4.0, https://commons.wikimedia.org/wiki/File:Example.jpg */}
<img
  src="/posts/civil-construction-1/textbook-crane/img/crane-external.jpg"
  alt="オールテレーンクレーンの外観"
  loading="lazy"
/>
```

### 写真（政府機関画像ライブラリ）

```mdx
{/* source: 国土交通省, 政府標準利用規約 2.0, https://www.mlit.go.jp/... */}
<img ... />
```

### 写真（自前撮影）

```mdx
{/* source: own photograph, taken 2026-MM-DD */}
<img ... />
```

### SVG（自前制作）

SVG は自前制作が前提のため、出典コメントは不要。代わりに SVG ファイル内の先頭に `<!-- Created by doboku-note, <YYYY-MM-DD> -->` を付けておく（任意）。

## 推奨コンポーネント: `<ArticleImage>`

**新規記事は `<ArticleImage>` を使う**（`src/components/ui/ArticleImage/ArticleImage.tsx`）。`<figure>` セマンティクスを自動で付与し、Next.js `<Image>` の最適化も効く。

### caption の使い方

**真実源**: [docs/reference/content-principles.md §8](../content-principles.md) L146

> `<ArticleImage>` の caption は「図の説明」には使わない。ただし、**出典・著作権帰属・機種名などの短い帰属情報**（目安 60 字以内）は caption に書いてよい。

- **NG**: caption で図の内容・構造・関係を説明する（本文と重複する）
- **OK**: caption で **出典（Wikimedia Commons, CC BY-SA 4.0 等）・機種名（Leica TC305 等）** を短く示す

`alt` には簡潔な識別情報（60〜80 字以内）を入れる。機種の詳細説明・図の読み方は **本文** に書く。

### 良い例

```mdx
#### クローラクレーン

クローラ式走行体で不整地走破性に優れるクレーン。日立 CX900HD のように
ラチス構造のブームと全油圧駆動が主流。

{/* source: Wikimedia Commons, CC0, https://commons.wikimedia.org/wiki/File:Hitachi_CX900HD_crawler_crane_at_IJmuiden,_pic1.JPG */}
<ArticleImage
  src="/posts/civil-construction-1/textbook-crane/img/crawler-crane.jpg"
  alt="クローラクレーン（日立 CX900HD）"
  caption="Wikimedia Commons, CC0"
  width={960}
  height={720}
/>
```

### 悪い例（caption で詳細説明）

```mdx
{/* 本文が薄く、caption に図の内容を詰め込んでいる */}
<ArticleImage
  src="..."
  alt="..."
  caption="日立 CX900HD。ラチス構造のブームとクローラ式走行体が特徴で、不整地走破性に優れる。Wikimedia Commons, CC0"
/>
```

### 過去問図の caption / alt — 問題文に無い情報を絶対に追加しない

**真実源**: 本セクション（2026-04-26 追加、Issue #128 起因）

過去問（`*-primary` / `*-secondary` カテゴリ）の図版を反映する際は、**問題文に書かれている語句のみを caption / alt に使う**。問題文に無い情報（構造の説明、関係の解釈、答えに直結する記述）を加えると **受験者の判断材料を奪う / 答えを漏らす** ことになる。

#### 厳格ルール

1. **caption は問題文の関連箇所をそのまま引用** するか、**省略する**（出典がなければ caption 不要）。
2. **alt は問題文の図番号・タイトルをそのまま使う**（例: 「下図のシステム」→ alt="問題文に示されたシステム"）。
3. **構造・関係・分類などの判断情報を絶対に書かない**（特に組合せ問題・空欄補充問題で答えに直結する）。
4. 図の出典（指針名・規格名・白書名など）が問題文中に明示されている場合のみ caption に書いてよい。
5. **図そのものの描画にも解答情報を入れない**（過去問図を新規 SVG 等で再作図する場合）。クリティカルパスの色強調・正答・工期/余裕日数の集計・「最長経路＝○○日」等のサマリーは、設問を見た瞬間に答えが分かるため禁止。問題図は原則 PDF（過去問/問題集）からのクロップ（原図のまま）。解答補助図が有用なら**別図として解説 `<details>` 内へ**置く（2026-06-21 追加、1級土木 primary 工程表図の再発防止）。

#### NG / OK の具体例

**Ⅰ-1-30: 信頼性ブロック図問題**（並列か直列かを受験者が判断する）

```mdx
{/* 問題文: 「下図のシステムにおいて、ユニット1からの信頼度はR1=R2=R3=0.9である。」 */}

{/* NG: 「並列＋直列構成」と書いて答えを漏らす */}
<ArticleImage
  alt="ユニット1〜4の信頼性ブロック図（並列＋直列構成）"
  caption="図: ユニット 1+2 の直列とユニット 3+4 の直列を並列接続した信頼性ブロック図"
/>

{/* OK: 問題文の語句のみ */}
<ArticleImage
  alt="問題文に示されたユニット1〜4からなるシステム"
  caption="図: 信頼度 R₁=R₂=R₃=0.9 の 4 ユニットからなるシステム"
/>
```

**Ⅰ-1-29: OSHMS 概要図問題**（空欄補充）

```mdx
{/* 問題文: 「下図は、労働安全衛生マネジメントシステム（OSHMS）の概要について…」 */}

{/* NG: 「事業者による安全衛生方針の表明から PDCA サイクル、見直しまで」は問題文に無い */}
<ArticleImage
  caption="図: OSHMS の概要（事業者による安全衛生方針の表明から PDCA サイクル、見直しまで）"
/>

{/* OK: 問題文の語句のみ */}
<ArticleImage
  caption="図: 労働安全衛生マネジメントシステム（OSHMS）の概要"
/>
```

#### チェックリスト

過去問図に `<ArticleImage>` を追加する前に必ず確認:

- [ ] caption / alt の **すべての語句が問題文に存在する** か（または出典である指針名・規格名のみ）
- [ ] 図の **構造・関係・分類** を解釈して書いていないか（受験者が判断すべき情報）
- [ ] 「並列」「直列」「PDCA」「Plan-Do-Check-Act」など、図中ラベルや問題文に無い専門用語を補足していないか
- [ ] 不安なら caption を省略する（caption は必須ではない）

### 既存 `<img>` との棲み分け

- **新規記事・新規画像**: `<ArticleImage>` で統一
- **既存の生 `<img>` 記事**: リライト時に順次 `<ArticleImage>` へ移行（互換性維持）
- `{/* source: */}` コメントは両者とも必須（CC/PD 写真の場合）

## 実装ガイドライン

### ファイル配置

```
.local/r2/posts/{slug}/img/
  figure-{n}.svg          # SVG 図版
  photo-{name}.jpg        # CC 写真（元ファイル名は変えず、ライセンス可読性のため英数字スラグに）
  photo-{name}.png        # PNG が必要なケースのみ
```

### 推奨ファイル形式

| 用途 | 形式 | 理由 |
|---|---|---|
| 概念・構造・工程図 | **SVG** | ベクタ、モバイル鮮明、修正容易 |
| 実機外観・現場写真 | **JPG** | 写真圧縮が効率的 |
| スクリーンショット・UI 図 | **PNG** | 文字エッジがくっきり |

### ファイルサイズ目安

- SVG: 10KB 以内（過度な装飾を避ける）
- JPG: 200KB 以内（モバイル回線で 2 秒以内に読める）
- PNG: 100KB 以内（重い PNG は WebP 変換も検討）

## 図クロップの機械検査（`check-figure-crop`）

スキャン過去問・教材から切り出した図クロップ（`.local/r2/posts/**/img/`）の**画素ジオメトリ**を検査する機械ゲート。既存の図監査は OCR ベース（`audit-figure-text` = 答え/本文テキスト、`build-figure-provenance` = 鮮明度・出所）で「テキストの内容」しか見ないため、クロップ縁の切断・隣接図の写り込みを取りこぼしていた（例: `r07-a-fig-04` 下端に隣接図のルビ写り込みが `textStatus:clean` で素通り）。本ゲートが画素で補完する。

実行: `npm run check-figure-crop`（全走査＋`.claude/state/quality/figure-crop-report.json` 出力）/ `check-figure-crop:ci`（baseline 比の新規のみ exit 1）/ `--file <img>`（1枚検査・figure-recrop の自己検証用）。写真（白率<50%）は自動スキップ。

| ルール | 扱い | 意味 |
|---|---|---|
| **STRAY_SLIVER** | **CI ブロッキング（HIGH）** | 上下端の**極薄インク島**（≤6px かつ ≤1%H）が白ギャップで本体から分離＝**隣接図の切れ端＝写り込み**。フルハイトの正当ラベル/軸と分離できる唯一の高精度シグナル（実測 precision ≈ 8/10） |
| EDGE_CUT / EDGE_LINE / EDGE_TIGHT | 情報のみ | 縁接触の分類。finished 図では tight-crop（正当な密着・実測 538/643 が該当）と切断を幾何で判別できないため gate にしない |
| STRAY_LABEL / THIN_MARGIN | 情報のみ | 厚めの分離島（小見出し/軸/写り込みのいずれか・要目視）/ 極薄マージン |

**運用**: content-quality-ratchet と同方式。既存債務は `--update-baseline` で `figure-crop-baseline.json` に棚卸し登録し、`--ci` は baseline に無い**新規 STRAY_SLIVER のみ** fail。是正したら再度 `--update-baseline` で刈り込む。CI では `quality:audit:ci` の `figure-crop-integrity` チェックが 0 件を enforce。

**既知の限界と予防**: 旧 `figure-recrop.mjs` は切断後に白 border を付加するため、「切断済み＋白枠」の legacy 図（`r07-a-fig-02`「収縮限界」欠け型）は画素が失われており機械では高精度検出できない。対策は**予防側**＝`figure-recrop.mjs` が border 付加**前**の生クロップに `analyzeImage()` の EDGE_CUT/STRAY_SLIVER 検査を掛け、切りすぎた時点で `crop_warnings` を返す（生クロップでは切断=縁接触が確実に成立）。「切れた文字」の意味判定は機械ゲートに入れず、視覚監査（`civil-exam-figure-auditor`）の守備範囲とする。

## 既存 PNG スキャンの扱い

`.local/r2/posts/**/img/` に現存する PNG スキャン（PDF 由来）は、**順次リライトで置換する方針**だが、以下のルールで段階的に移行する。

1. リライト対象記事の PNG スキャン → SVG または CC 写真に **完全置換**
2. リライト未対象の記事は **現状維持**（段階展開の途中で放置する）
3. PNG スキャンを残す場合も、著作権侵害の疑いが濃いものは **即削除**（本文のみで理解可能なら削除可）

### 置換履歴の追跡

置換作業の所要時間・CC ヒット率・削除比率は、パイロット記事（textbook-network-schedule / textbook-crane / textbook-leveling）で実測し、全体展開計画の判断材料とする。

## 政府系サイト（go.jp）の画像を利用する場合

**国や地方公共団体のウェブサイトから画像を転載する場合**、以下を満たす必要がある。

### ライセンス確認

- **デフォルト**: 「公共データ利用規約（第 1.0 版）」（PDL 1.0、CC BY 4.0 互換）が適用されることが多い
- **個別規約の確認**: `{domain}/copyright.html` または親省庁の利用規約ページを必ず参照
  - 国交省本体: <https://www.mlit.go.jp/link.html>
  - 環境省: <https://www.env.go.jp/guide/copyright.html>
  - 各地方整備局・独立行政法人は別ポリシーの場合あり

### 運用ルール

1. **ホットリンク禁止**: `src` に相手サイトの URL を直接書かず、画像は自リポジトリ（`.local/r2/posts/{slug}/img/`）にダウンロードして配置する
   - 相手サーバー負荷回避
   - URL 変更による表示破損回避
   - R2 経由で高速配信
2. **出典明示は caption で**: `<ArticleImage caption="出典：{機関名}（公共データ利用規約 1.0）" />` の形式（60 字以内）
3. **編集・加工時は明記**: 一部切り取り・翻訳・再描画した場合は caption に加工の旨を含める
4. **参考資料にも元ページへのリンクを併記**: 転載元の原ページを「参考資料」セクションでもリンクし、読者が最新版・詳細版にアクセスできるようにする

### 事例

`.local/r2/posts/pe-comprehensive-management/environmental-impact-assessment/img/eia-procedure-flow.gif`:
