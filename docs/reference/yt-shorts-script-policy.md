# YouTube Shorts 台本品質ポリシー

技術士総監キーワードの YouTube Shorts（縦型 30〜60 秒）の台本品質基準。`storyboard.json`（SSOT）の各スライドの `data` と `script` を執筆・評価するときの真実源。Generator（執筆）と Evaluator（採点）の両方がこの文書を参照する。

## 背景

旧パイプラインは MDX から機械抽出した断片をそのまま読み上げていたため、`<ExamPoint>` の体言止め暗記フレーズが「試験ポイント1。直接費 : 間接費 ≒ 1 : 4」のように箇条書きの棒読みになり、解説として成立していなかった。本ポリシーは「**読み上げて自然な、独立した解説**」へ引き上げるための基準。

## storyboard.json の構造

```
slides[] = [cover, definition, examPoint, examPoint, cta]   // 5 枚固定
各 slide = { type, data, script }
  data   … スライド画像（PNG）に表示される要素。短く、画面で読める分量
  script … ナレーション（TTS 読み上げ＝字幕）。完全な話し言葉の文
```

`data` と `script` は役割が違う。`data` は画面表示用に簡潔（体言止め可）、`script` は耳で聞いて分かる完全文。両者の内容は矛盾してはならない。

## 5 軸ルーブリック（各 1〜5 点・合格ライン平均 4.0 以上かつ全軸 3 以上）

| 軸 | 観点 | 5 点 | 1 点 |
|---|---|---|---|
| 1. 文の完結性 | script が主語・述語のある完全文か | 全 slide が自然な文。体言止め断片なし | 用語の羅列・体言止めの棒読み |
| 2. 解説の実質 | examPoint が「なぜ・何を意味するか」を説明しているか | 数値や法則の意味・含意まで踏み込む | 用語や数値を提示するだけ |
| 3. 口語適性 | TTS で読んで自然か | 記号を言葉に開き、読点で息継ぎできる | `：≒・` 等の記号を多用し読めない |
| 4. 尺の適正 | 1 slide の script 長 | cover 約 25〜45 字／definition・examPoint 約 60〜100 字／cta 定型 | 極端に長い（120 字超）or 短い |
| 5. 試験的正確性 | MDX の事実に忠実か | 数値・法則名・定義が MDX と一致 | 誤りや MDX にない断定 |

## スライド別の執筆指針

### cover（表紙）
- `data`: `title`（キーワード名）・`label`・`management` は既存値を維持。
- `script`: キーワード名 ＋ 関心を引く一言。例「災害コスト。労働災害の"見えないコスト"を解説します。」
- 固定接尾辞「技術士総合技術監理部門の重要キーワードです」だけで終わらせない。

### definition（定義）
- `data.body`: 画面表示用の簡潔な定義（40 字以内目安・体言止め可）。
- `script`: 「○○とは、〜である。」の完全文。**frontmatter の description（「〜を解説。」調）を流用しない** — MDX 本文の定義文（「○○とは〜である」）を真実源にする。
- 80 字ハード切りで文を途中で切らない。長ければ要約して 1 文にまとめる。

### examPoint ×2（試験ポイント）
- `data.body`: 画面表示用のキーフレーズ（体言止め可・MDX の `<ExamPoint>` を流用してよい）。
- `script`: そのポイントを**解説する完全文**。`<ExamPoint>` の体言止めをそのまま読まない。
  - 悪い例: 「試験ポイント1。直接費 : 間接費 ≒ 1 : 4（ハインリッヒの法則）」
  - 良い例: 「災害コストには、保険でまかなえる直接費と、その裏に隠れた間接費があります。ハインリッヒによれば、その比率はおよそ1対4。見えない損失のほうが大きいのです。」
- 記号は言葉に開く（`：`→「対」、`≒`→「およそ」、`・`→読点や「、」）。
- 2 枚は別々の論点を扱い、内容を重複させない。

### cta（誘導）
- `script`: `SNS_CONFIG.narration.cta` の定型文を使用（変更不要）。

## 全体の制約

- 5 slide 合計の読み上げが概ね 30〜60 秒に収まる（1 slide 平均 8〜12 秒）。
- 「である」調か「です・ます」調か、動画内で統一する（examPoint は「です・ます」推奨＝親しみやすさ）。
- MDX に書かれていない数値・固有名詞を新たに作らない。不確かなら MDX の表現に寄せる。
- 字幕の改行はパイプラインが budoux で自動処理するため、`script` に手動改行（`\n`）は入れない。

## ワークフロー

1. **Generator** — MDX（`.local/r2/posts/{category}/{slug}/article.mdx`）と既存 `storyboard.json` を読み、本ポリシーに沿って各 slide の `data`・`script` を書き直し、`storyboard.json` を上書き保存する。
2. **Evaluator** — MDX と書き直し後の `storyboard.json` を突合し、5 軸で採点。合格ライン未満なら具体的な修正指示を返し、Generator が再執筆する。
3. **動画再生成** — 合格した `storyboard.json` をもとに、ffmpeg + VOICEVOX 環境で `yt-shorts-create.mjs`（`--reset` なし＝SSOT 優先）を実行して mp4 を再生成する。
