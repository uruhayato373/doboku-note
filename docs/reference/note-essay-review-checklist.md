# note 模範論文（総監記述式）レビュー手順書

`docs/note/magazines/総監模範論文-*/` および `docs/note/magazines/総監記述式-R8予想問題集/` 配下のフル模範論文を公開レベルに引き上げるための実施手順。`docs/reference/content-principles.md`「note 模範論文の品質原則」と対をなす。

## 目的

模範論文を**本番再現可能な字数（各施策600字以内）**かつ**読者がそのまま参考にできる品質**で公開する。試行錯誤の繰り返しを避けるため、評価軸を **字数 → 散文性 → 監理可能性 → 専門度 → 白書根拠** の順で固定する。

## 前提

- レビュー対象記事と同ペルソナ・同年度の R7 過去問模範論文がベンチマーク
- 比較対象: `docs/note/magazines/総監模範論文-{persona}/R07/article.md`
- 字数評価は本ファイルの「Step 2」スクリプトを使用

---

## Step 1: ベンチマーク確定（R7 過去問の Read）

該当ペルソナの R7 過去問模範論文を Read し、以下を把握する。

- 設問(1)・(2)・(3) の各施策の**文字数**
- 立場ラベル（道路維持課 課長補佐 等）
- 設問(2) 各施策のトレードオフ軸の組み合わせ（情×安、経×人 等）
- 設問(3) で扱う国家施策の語彙レベル

これが**自施記事の到達目標**となる。R7 が 600 字を多少超えていれば、同水準が許容ライン。

## Step 2: 字数実測（最優先・決定論ツール）

**真実源ツール**: `scripts/essay-shisaku-charcount.mjs`（施策ブロックの CJK 字数を計測し 600 字超過を検出する決定論ゲート）。

```bash
node scripts/essay-shisaku-charcount.mjs "総監模範論文-{persona}" --detail   # ブロック別明細
node scripts/essay-shisaku-charcount.mjs "総監模範論文-{persona}" --strict    # 超過1件で exit 1（ゲート）
```

- 施策見出しは **`### 施策N:` / `### 方法N` / `### 戦略N`** で統一する（R08 予想等で `**施策N:**` 太字インラインにすると 2 施策が 1 ブロックに合算され誤計上する。必ず `###` 見出しにする）。
- ブロックは `##`/`###` のどちらでも区切られる（修正済み）。設問1（2 枚＝1200 字枠）は別枠。

**判定基準**：

| 字数 | 判定 |
|---|---|
| 585〜600 字 | ✅ 本番再現可能・マージンも確保 |
| 575 字未満 | △ 余白が大きい（内容追加の余地あり） |
| 601 字以上 | ❌ **必ず圧縮**（許容範囲なし） |

**「答案用紙 1 枚以内」は厳密な上限**。R7 A案も 618〜657 字で超過しているが、R7 を「同水準＝許容」の基準にしてはならない。**601 字以上は無条件で圧縮対象**。超過があれば最初に「内容議論より先に圧縮」と順序宣言。

## Step 3: 散文性チェック（答案は必ず散文）

```
grep -nE "^- \*\*(内容|根拠|効果|障害|課題|方法|利活用|リスク|克服)" article.md
```

**答案本文（設問1〜3 のフル解答）は流れる散文段落で書く**。`- **効果**: …` `- **障害**（A × B）: …` のような箇条書き化は**禁止**（本番答案は散文で書くため）。検出したら 道路担当（基準）と同じ散文段落へ統合する。トレードオフの分野名（経済性管理 × 社会環境管理 等）は**散文の中に**明示する（箇条書きラベルにしない）。

**修正前**:
```markdown
- **内容**: ...
- **根拠**: ...
- **効果**: ...
```

**修正後**:
```markdown
内容として〜。〜することで〜（根拠）。効果として〜（経済性管理）、〜（情報管理）。
```

**修正前**:
```markdown
- **内容**: ...
- **根拠**: ...
- **効果**: ...
```

**修正後**:
```markdown
内容として〜。〜することで〜（根拠）。効果として〜（経済性管理）、〜（情報管理）。
```

## Step 4: 監理可能性チェック

設問(2) 各施策で、ペルソナの立場（例: 道路維持課 課長補佐）が**自前で実施できる範囲**に収まっているか確認。

**越権施策の典型例**：
- ゼロトラスト移行（CIO 部局所掌）
- 庁内ネットワーク全面整備（情報政策課所掌）
- AI モデル・ベンダーの選定（情報政策課・契約検査課所掌）
- 共同調達のリード（契約検査課所掌）

該当する場合は、「**情報政策課と連携のうえ協議に参画する位置づけ**」のように所掌調整の枠組みに書き換える。**立場ラベルに「(情報化・DX 担当)」などの兼務付与をして越権を正当化することは禁止**。

## Step 5: 専門度チェック

設問(3) の用語をスキャンする：

```
grep -nE "EU AI Act|SBOM|AI-SBOM|第三者認証|リスクベース規制|認証要件法制化|基盤モデル|サプライチェーンリスク評価" article.md
```

**NG リスト**（撤去対象）：
- EU AI Act、AI-SBOM、ソフトウェア SBOM 国際標準
- 第三者認証制度、認証要件法制化、認証機関
- リスクベース規制、用途別認証制度
- 基盤モデル、サプライチェーンリスク評価、SBOM

**OK リスト**（推奨語彙）：
- リスクに応じた規制、定期見直し条項、監督権限の集約
- 人材育成、社会受容性、代替チャネル、救済制度、透明化
- 既存政府指針、AI 関連法、所管集約、分野横断統括機関

NG 用語が混在していれば、OK 語彙へ書き換える。**規制側 1 施策＋人材／社会受容性側 1 施策**で構成を整える。

## Step 6: 白書根拠チェック

「なぜ R8 でこのテーマが出題されると予想するか」セクションの白書言及を、WebSearch で章構成・原表現と照合する。

**検証対象**：
- 白書名・特集タイトル・章番号・章タイトル
- 引用している用語が原文・公的サマリーに登場するか

**確認できない用語は撤回または広い概念語へ置換**：
- ハルシネーション → 偽・誤情報の流通
- 生成 AI 悪用 → 巧妙化・高度化するサイバー攻撃
- ランサムウェア（情報通信白書由来として書く場合は原文確認必須）

「予想問題本文」中の白書引用は出題者風の再構成が許されるが、根拠説明セクションは厳密に。

## Step 6b: 引用記号（blockquote）の濫用チェック

```
grep -nc "^> " article.md
```

**導入の枠組み文（「本記事の構成」「本論文はテンプレートとして…」「A案/B案の対象者注記」等）を blockquote `>` で書かない**。これらは著者自身の説明文であり「引用」ではないため、引用記号は意味的に不適切。**通常の段落**で書く（強調したい行は `**太字**` の通常段落、注意喚起は `<Callout>` でなく素の段落で可）。blockquote は「外部の規程・白書原文・設問前文の引用」など真に引用である箇所のみに限定する。

## Step 6c: 記事ごとアセット（カバー・ハッシュタグ）必須

各記事（`{persona}/{RXX}/`）に以下が**揃っているか**確認する。マガジン単位の `_cover.png`/`hashtags.txt` とは別に、**記事ごと**に必要：

- `img/cover.png`（＋ `cover.svg`）: `node scripts/generate-note-covers.mjs "{persona}"` で生成（部分一致で当該マガジン配下を一括生成）
- `hashtags.txt`: `/note-hashtags` スキルで生成（記事の論点に沿った 80〜90 個・単一行 space 区切り。本文には入れない＝[[feedback_note_prepublish_verify_not_proxy]] の SoT 規約）

```
ls docs/note/技術士総監/magazines/総監模範論文-{persona}/{RXX}/img/cover.png
ls docs/note/技術士総監/magazines/総監模範論文-{persona}/{RXX}/hashtags.txt
```

未生成なら公開不可。新規ペルソナ作成時は **6 記事すべて**に対して生成する。

## Step 7: 修正方針の提示とユーザー承認

Step 2〜6 で検出した問題を一覧化し、**修正方針を提示してユーザーの承認を得てから着手**する。試行錯誤を避けるため、複数論点を抱えるなら案 α/β を比較表で出してから選んでもらう。

承認後、Edit ツールで一括修正。

## Step 8: 修正後の再計測

Step 2 のスクリプトで字数を再計測し、各施策が 600 字 ±50 字以内に収まっているか確認。

## Step 9: commit

1 記事ごとに独立 commit する（5 記事一括 commit は禁止 — 後で問題があった記事だけ revert できなくなる）。

```
content(note): {theme}/article.md を公開レベルに引き上げ（字数圧縮・散文化・専門度調整）
```
