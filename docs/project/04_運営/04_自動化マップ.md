# 自動化マップ（2026-08-03 現在）

doboku-note で稼働中・計画中のすべての自動化を一覧にまとめる。

---

## 自動化タイプと使い分け基準

| タイプ | 向いている用途 | 例 |
|---|---|---|
| **GitHub Actions** | ログイン済みGUIや意味判断が不要な取得・検査・配布・デプロイ | PSI / note public API / 競合公開データ / R2 / deploy |
| **Claude スキル（手動）** | 意味判断・文章生成・承認・公開修復 | `/quality-cycle` `/weekly-review` `/competitor-review` |
| **Claude Cron** | GitHub Actionsで代替できない定期エージェント判断 | weekly PDCA の判断部分のみ |
| **npm scripts** | Actions とローカル手動の共通実装 | `refresh-indexes` `audit-note-funnel` |

> [!important]
> 機械的に完結する処理の実行主体は GitHub Actions を正とする。ローカル／クラウドルーティンに残すのは、本人ログインセッション、CAPTCHA/2FA、意味判断、ユーザー承認、公開先への破壊的変更のいずれかが必要な処理だけ。

## Claude Cron（クラウドルーティン）

GitHub Actionsへ移せない意味判断だけを残す。

| ルーティン | 発火 | 残す責務 | CIへ移した責務 |
|---|---|---|---|
| `doboku-note weekly PDCA` | 月曜 | 計測結果の解釈、週次レビュー/計画の文章化、優先順位判断 | 計測取得、機械ゲート、期限surfacer |
| ~~`doboku-note GSC auto review`~~ | — | **退役（2026-08-06・`enabled:false`）**。記録層は `gsc-auto-review.yml` が引き継ぎ自走を確認済み | 記録層ごと `.github/workflows/gsc-auto-review.yml` へ |
| `doboku-note note-funnel monthly audit` | 月次 | なし。意味監査はオンデマンドで実行 | D1-D6 の機械監査を `r2-audit.yml` / `note-live-audit.yml` へ移管 |

> [!note] GSC auto review の設計意図と CI 移行（2026-08-06）
> データ取得は CI で全自動だったが**分析と記録が手動**で、7/1・8/1 の月次カバレッジ 2 回分が
> 無記録のまま indexed_ratio が 81.6%→71.7% に低下していた。「計測 → 記録」のループを
> 人手なしで閉じる。実験の start・タスク起票はせず**推奨まで**（実行判断は人）。
>
> **実行主体はクラウドルーティン → GitHub Actions へ移す**。理由は本表の原則そのもの＝
> クラウドルーティンは設定も実行履歴も repo から見えず、**本機能を作った動機（沈黙が見えない）を
> 実行基盤自身が再現してしまう**。`claude-code-action` で意味判断も CI 実行できるため、
> 「意味判断はクラウドに残す」例外を本件には適用しない。
>
> **移行完了（2026-08-06）**。`CLAUDE_CODE_OAUTH_TOKEN` を登録し、CI で自走を確認したうえで
> クラウドルーティンを `enabled:false` にした。オーケストレータは `claude-fable-5`、重い JSON 走査は
> `.claude/agents/*.md` の frontmatter で sonnet に固定されたサブエージェント（metrics-analyzer /
> gsc-index-auditor）が担う。詳細な分業は
> [gsc-management.md](../../../.claude/knowledge/reference/gsc-management.md)。
>
> **CI で Claude を動かすときの落とし穴**（同種の自動化を作るときに再発しやすい・実測）:
> ①workflow_dispatch も cron も**デフォルトブランチ版**で動く ②`gh secret set` の隠し入力に
> 貼り付けが効かず**値が空**で登録されることがある（run ログの env が `TOKEN: ***` か `TOKEN: ` かで判る）
> ③`id-token: write` が必須 ④claude-code-action は workflow が**デフォルトブランチと同一内容**で
> ないと実行をスキップ ⑤**CI は非対話＝turn 終了でセッションも終了**（サブエージェントを待って
> turn を終えると記録が永久に失われる）⑥**`.claude/**` への Write は sensitive file として一律拒否**
> （allowlist 不可。よって Claude は `/tmp` に断片を出し、反映と commit は bash が行う）
> ⑦action は step 終了時に自身の app token を revoke するため、後続の push は `GITHUB_TOKEN` で
> remote を貼り直す。
>
> **設計の要点**: 「Claude が成功終了しても記録が増えていなければ成功ではない」を workflow 自身の
> ゲートにした（実行前後の gates を突合し、週次が未記録なら赤）。可視化（実行ログの artifact 化）を
> 先に入れたから、上の ⑤⑥⑦ を順に特定できた。**緑を信じる前に「何件記録されたか」を見る。**

> [!warning]
> クラウドルーティンの状態は repo に存在しない。旧 note-funnel routine は `/routines`（list-first）で確認し、[Claude Code Routines](https://claude.ai/code/routines) から削除する。週次 PDCA は残し、機械取得や public API 監査を本文から外して判断・文書化だけに絞る。

## CI/CDへ移さない処理

| 処理 | 残す場所 | CI化しない理由 |
|---|---|---|
| X 競合取得 / 投稿 / 予約確認 | ローカル手動 | 個人・投稿アカウントのログイン済みセッションと凍結安全弁が必要 |
| Instagram 投稿 / 公開状態照合 | Business Suite + ローカル | 本人セッション、Planner GUI、投稿前の目視が必要 |
| note / Brain / ココナラ / KDP の公開・修復 | ローカル手動 | ログイン、CAPTCHA/2FA、価格・規約・公開の承認が必要 |
| GSC/GA4 管理画面、Indexing request | ローカル Playwright | Google本人セッションが必要。サービスアカウントAPIで取れない情報を扱う |
| weekly PDCA / 競合意味評価 / note導線意味監査 | 対話エージェント | 優先順位・文章・関連性の判断が必要 |
| `.claude/hooks` / git hooks | ローカル補助 | 編集直後のフィードバックとセッション固有の警告。マージ可否の機械ゲートはCI側でも実行 |

## npm scripts（ビルドフロー組み込み）

ビルド・デプロイに自動で呼ばれるスクリプト群。単発でも実行可能。

| コマンド | タイミング | 処理 |
|---|---|---|
| `npm run refresh-indexes` | **コンテンツ編集完了後に必須** | backlinks・cross-exam・タグ インデックスを再生成 |
| `npm run generate-webp` | `npm run build` の prebuild で自動実行 | PNG/JPG → WebP 変換 |
| `npm run quality:audit` | 手動（月次棚卸し）/ `:ci` は ci.yml で自動実行 | コード・記事・画像/SVG の機械チェックを横断実行→レポート |
| `npm run validate-mdx` | CI（ci.yml）で `quality:audit:ci` 経由 | MDX 構文バリデーション |
| `npm run type-check` | CI（ci.yml）で `quality:audit:ci` 経由 | TypeScript 型チェック |
| `npm run upload-images-r2` | `r2-sync.yml` から自動実行 | R2 へ画像アップロード |
| `npm run check-ogp-coverage` | `r2-audit.yml` から自動実行 / 手動 | published 記事の `ogp.png` 欠落を検知（欠落で exit 1） |
| `npm run check-figure-crop` | `quality:audit:ci`（ci.yml）経由 / 手動 | 図クロップの画素検査（隣接図の切れ端 STRAY_SLIVER を baseline 比の新規のみ gate）。詳細 → [image-policy.md](../../reference/image-policy.md) |
| `npm run build-backlinks` | 手動 or `refresh-indexes` 経由 | バックリンクインデックス再構築 |

## 自動化の継続的改善ループ

```
[毎日]  psi-audit / uptime-ping
[週次]  fetch-metrics / link-audit / r2-audit / note-live-audit
[月次]  index-coverage
[四半期] competitor-scan（note / IG / ココナラの機械取得）
          ↓
[週次]  /weekly-review → CI成果物を解釈
[週次]  /weekly-plan → 優先タスクを整理
[四半期] /competitor-review → snapshotを意味評価
          ↓
[随時]  /improve-article / /quality-cycle → コンテンツ改善
[随時]  /deploy → 本番反映 → post-deploy curl 検証
          ↓
[翌日]  psi-audit で効果測定
```
