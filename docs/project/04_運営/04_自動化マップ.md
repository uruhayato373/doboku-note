## 自動化タイプと使い分け基準

| タイプ | 向いている用途 | 例 |
|---|---|---|
| **GitHub Actions** | 人間不要・定時実行・CI/CD | PSI 計測・R2 同期・デプロイ |

## Claude Cron（クラウドルーティン）

常駐ルーティンは**週次 PDCA（`/weekly-review`）1 本のみ**（金 20:00 JST 稼働）。他の週次スキルはコスト最小化のため on-demand 運用に統一し、定期ルーティンは持たない（真実源: memory `cloud-routines-minimized`、2026-06-27 棚卸し）。

| ルーティン | スケジュール（JST） | 状態 |
|---|---|---|
| `/weekly-review`（週次 PDCA） | 金 20:00 | 稼働中（唯一の常駐ルーティン） |

**登録/確認**: ルーティン新設は `/schedule`（RemoteTrigger）。作成前に必ず `/routines` で既存を確認し、重複・cron 衝突を防ぐ。

## npm scripts（ビルドフロー組み込み）

ビルド・デプロイに自動で呼ばれるスクリプト群。単発でも実行可能。

| コマンド | タイミング | 処理 |
|---|---|---|
| `npm run refresh-indexes` | **コンテンツ編集完了後に必須** | backlinks・cross-exam・タグ インデックスを再生成 |
| `npm run generate-webp` | `npm run build` の prebuild で自動実行 | PNG/JPG → WebP 変換 |
| `npm run quality:audit` | 手動（月次棚卸し）/ `:ci` は ci.yml で自動実行 | コード・記事・画像/SVG の機械チェックを横断実行→レポート |
| `npm run validate-mdx` | CI（ci.yml）で `quality:audit:ci` 経由 | MDX 構文バリデーション |
| `npm run type-check` | CI（ci.yml）で `quality:audit:ci` 経由 | TypeScript 型チェック |
| `npm run upload-images-r2` | `r2-sync.yml` から自動実行 | R2 へ画像アップロード |
| `npm run check-ogp-coverage` | `r2-audit.yml` から自動実行 / 手動 | published 記事の `ogp.png` 欠落を検知（欠落で exit 1） |
| `npm run build-backlinks` | 手動 or `refresh-indexes` 経由 | バックリンクインデックス再構築 |

## 自動化の継続的改善ループ

```
[毎日]  psi-audit → task-queue.json に違反追記
[毎日]  uptime-ping → SSR 壊れ検知 → task-queue.json
[週次]  fetch-metrics（金 06:00 JST）→ GSC/GA4 データ蓄積
[週次]  link-audit（金 07:00 JST）→ 内部リンク監査
          ↓
[週次]  /weekly-review（金 PM、同日）→ PSI/品質/学習を集計 → [PDCA] ドキュメント更新
[週次]  /weekly-plan（金 PM、連続実行）→ 優先タスクを整理
          ↓
[随時]  /improve-article / /quality-cycle → コンテンツ改善
[随時]  /deploy → 本番反映 → post-deploy curl 検証
          ↓
[翌日]  psi-audit で効果測定
```
