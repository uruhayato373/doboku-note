## 4. UTM 統一フォーマット

### 設計原則

1. **全外部リンクに UTM を付与**：手動運用の X 含めて例外なし
2. **`utm_source` はチャネル名・`utm_medium` は配信形式・`utm_campaign` は施策名**
3. **`utm_content` で個別投稿を識別**（A/B テストや週次レビュー時の粒度）
4. **生成は自動化**：各スキル（social-post / yt-shorts-create / ig-post-create）から自動付与

### チャネル別フォーマット

| チャネル | utm_source | utm_medium | utm_campaign | utm_content（任意） |
|---|---|---|---|---|
| **X 投稿** | `x` | `organic` | キャンペーン名（例: `exam-2026-jul`） | tweet ID 末尾 |
| **X 固定ポスト** | `x` | `pinned` | `pinned-post` | post 更新日 |
| **YouTube Shorts 概要欄** | `youtube` | `shorts` | キーワード slug | video ID |
| **YouTube 標準動画概要欄** | `youtube` | `longform` | テーマ slug | video ID |
| **IG Reels キャプション** | `instagram` | `reel` | キーワード slug | post ID |
| **IG Carousel キャプション** | `instagram` | `carousel` | 型 ID（`type1` / `type3` 等） | post ID |
| **IG bio link** | `instagram` | `bio` | `bio-link` | （Linktree 経由なら Linktree 側で再付与） |
| **IG Stories link sticker** | `instagram` | `story` | キャンペーン名 | story 投稿日 |
| **note 記事内リンク** | `note` | `article` | 商品 ID（`E-1` 等） | note URL slug |
| **サイト → note**（`buildMagazineUrl`） | `doboku-note` | `referral` | `note-magazine` | 配置識別子（例: `keyword-2026-sidebar`） |
| **note 記事 → サイト deep link**（`add-note-utm`） | `note` | `referral` | 記事の `utmCampaign`（例: `civil-keiken-leadmagnet`） | 送客先識別子（任意・例: `guide-civil-1`） |

> **なぜ `utm_medium=referral` か（2026-07-03 確定）**: `referral` は GA4 が標準で「Referral」チャネルに分類する medium。`inline`/`banner` のような非標準値は GA4 デフォルトで「Unassigned」に落ち、note 流入のチャネル分類が壊れる。link 形式（インライン/バナー/カード）の区別は medium ではなく **`utm_content`** で持つ。過去に土木系 note が `inline`・総監系が `referral` とドリフトしていたのを referral へ統一（114 箇所/53 ファイル移行済）。機械検証は `check-note-site-utm` が `utm_medium=referral` を強制する。
>
> **note のリンクカードと UTM の使い分け**: note のリンクカード（OGP プレビュー）は UTM 付き URL だと安定して生成されないため、**サイトへの送客リンクは UTM 付きのインライン（テキスト）リンク**で張る。リンクカードは note 内部 CTA（有料マガジン・もくじ）に限定し UTM は付けない（内部リンクは note 管理画面のクリック統計で足りる・doboku-note の GA4 は note.com を見ない）。カード表示と UTM 計測を両立したい場合のみ、`public/_redirects` のクリーン URL → 302（UTM 付与）方式を使う（未実装＝計測基盤ロードマップ Tier 3 #15）。**注意**: 送客 URL を**単独行の生 URL** で置くと `/note-publish` が自動でリンクカード化し UTM が落ちる。サイト送客リンクは必ず**アンカー文言付きインライン** `[テキスト](url?utm…)` で本文に畳み込む。
>
> **機械検証**: `npm run check-note-site-utm`（pre-commit は `--staged`）が `docs/note/**` の `doboku-note.com/docs/` 送客リンクを検査し、生 URL（カード化で UTM 消失）と `utm_source=note` 欠落を検出する。既存違反のバーンダウン中は `SKIP_NOTE_UTM=1` で一時回避。

## 7. 動線設計の弱点と橋渡し提案

### 弱点 1: SNS 流入の計測ブラックホール

**現状**: 全チャネル UTM 未統一。流入してきても「どの SNS 投稿が効いたか」が分からない。

**橋渡し**:
- §4 の UTM 統一フォーマットを `.claude/config/utm-templates.json` に実装
- 各スキルから自動付与する仕組みを `lib/utm-builder.mjs` で共通化
- GA4 で「SNS 経由ユーザー」のカスタムレポート作成

### 弱点 2: bio link 着地点の未決

**現状**: IG MVP 着手目前なのに「Linktree か直リンクか」が未決（Instagram 運用設計の未決事項）。

**橋渡し**（Phase 別決定）:
- **Phase 1（〜2026-08）**: bio link = `doboku-note.com` 直接
  - 理由: シンプル、ブランド形成優先、商品が E-1 のみのため分岐不要
  - サイトトップに「IG から来た方へ」歓迎導線（任意）
- **Phase 2（2026-09〜）**: Linktree 化
  - 理由: E-1〜E-4 + 他 SNS が並ぶため集約が必要
  - 構成案: 🏠 サイト / 📘 E-1 / ✍️ E-2 / 📝 E-3 / 🎯 E-4 / 📺 YouTube / 🐦 X
- **Phase 3（合格後 2027-Q1〜）**: DM 自動応答（ManyChat 等）でリードマグネット型
  - PDF 制作 + 自動応答インフラ + 特商法確認が前提

### 弱点 3: note ↔ サイトの検索競合（Red Line #5）

**現状**: note のドメインパワー > サイトのため、同一技術解説を両方に置くと Google が note を正答視 → サイト SEO 低評価化のリスク。運用ルールが未確立（[../../note/技術士総監/noteコンテンツ計画.md](./../../note/技術士総監/noteコンテンツ計画.md) の Red Line #5）。

**橋渡し**:
- **境界ルールの定式化**:
  - ✅ サイト = 体系解説（694 キーワード、680 過去問、無料）
  - ✅ note = 体験談・要約・受験記（E-1〜E-4 / P-01〜P-07、有料）
  - ❌ note でオリジナル技術解説は書かない（必ずサイトへ誘導）
- **チェックスキル新設**: `/check-content-redline`（Generator 用、note 下書き scan + サイト内同等解説検出）

### 弱点 4: iOS 着手判断と Web ファネルの未連携

**現状**: 着手条件「Web 月収 ¥15k + 筆記合格」だが、現状の note 売上を計測する仕組みがない。

**橋渡し**:
- note 売上の週次トラッキング: `.claude/state/note-sales/weekly-{YYYY-WW}.json`
- iOS 着手判断ダッシュボード: `/check-ios-readiness` スキル化（Web 月収 / 筆記合格 / その他条件を一覧）

### 弱点 5: 季節調整の散発化

**現状**: 受験は年サイクルだが、各チャネルでピーク戦略が散発的に書かれているだけ。

**橋渡し**:
- 本書 §6 の「季節 × チャネルマトリクス」を真実源とする
- 各 SNS スキル（social-post / yt-shorts-create / ig-post-create）が `.claude/config/seasonal-matrix.json` を参照して投稿テーマを自動切替できる仕組みを Phase 2 で実装
