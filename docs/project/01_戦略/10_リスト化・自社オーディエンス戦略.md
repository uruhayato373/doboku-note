# リスト化・自社オーディエンス戦略

検索流入（借り物のトラフィック）に依存せず、**メール / LINE / アプリ会員などの「自社で直接届けられるオーディエンス（リスト）」を資産化する**ための方針。リストがあれば note 有料マガジン等の自社商品を直接届けられ、Google アルゴリズム変更のリスクを下げられる。本書は「どうやってリスト化するか／何をしてはいけないか」の横断方針。価格・商品の実行は各 `docs/note/{資格}/noteコンテンツ計画.md`、収益チャネル全体は [04_収益化戦略.md](./04_収益化戦略.md) を参照。

> [!important] 結論（2026-06-27 決定）
> **過去問解説などの SEO コンテンツを「会員登録ゲートで囲う」のは採用しない。**
> 代わりに **「無料で母数を最大化 → おまけ（リードマグネット）で囲う」** を採る。
> リスト化の本丸の会員登録は **PWA 過去問アプリ**（ログインが自然な面）で行う。
> 自社商品（note）はリストへ配信可。**A8 アフィリ（ビルドジョブ等）は LINE・個人メール・SNS DM では配信不可、A8 登録メルマガなら可**（A8 公式規約・2026-06-27 確認・[Red Line](#red-line-やってはいけないこと) 参照）。

## なぜリスト化したいか（狙いは正しい）

- Google 検索流入は **借り物のトラフィック**。アルゴリズム変更 1 つで消える。
- メール / LINE / アプリ会員は **自社資産**。何度でも・直接・無料で届けられる。
- リストがあれば note 有料マガジンの新刊告知、受験期の直前案内、再訪促進などを能動的に打てる。

→ **オーディエンスの資産化という発想自体は正しい。** 論点は「方法」だけ。

## なぜ「SEO コンテンツのハードゲート」は今は不採用か

「やったら不可避に壊れる」ではなく、**現フェーズでは得失が見合わない**というのが正確な論拠。堅い理由は次の 3 点。

| # | 堅い論拠 | 内容 |
|---|---|---|
| 1 | **時期尚早（母数が小さい）** | カテゴリページ流入は 28 日で 17〜157 ユーザー規模（2026-06 GSC/GA4）。囲って得るリストが小さすぎ、潰す成長エンジンに見合わない。**まず母数、囲うのは後**。 |
| 2 | **PV・AdSense・検索評価の下押し（確実なマイナス）** | 無料 PV 減＝AdSense 減。ゲートは CTR/エンゲージメントも下げやすく検索評価にも不利に働きやすい。 |
| 3 | **実装コスト・複雑さ・法令対応** | 認証/会員管理の追加は設計思想の DB レス方針（[data-storage-decision.md](../../reference/data-storage-decision.md) の D1 不採用）からの逸脱＋個人情報保護法・特定電子メール法対応を伴う。現フェーズの労力対効果に合わない。 |

> [!warning] 断定しない論点（過度に誇張しないための注記）
> 初稿で「SEO崩壊／静的構成と矛盾／アフィリのメール配信は一律禁止」と**断定しすぎた**ため、正確には次のとおり:
> - **SEO**: Google は **paywall/会員コンテンツのインデックスを公式サポート**（構造化データ）。ただし静的サイトでは「サーバー側で本当に隠す → Googlebot からも隠れ deindex」「HTML に残す → index は保てるが view-source で回避可能」のジレンマがあり、いずれも評価/CTR は下がりやすい。＝**“崩壊確定”ではなく“リスク大・実装難”**。
> - **静的構成**: 会員登録は SaaS（Cloudflare Access / Clerk / Supabase、メール収集だけなら Mailchimp/ConvertKit のフォーム埋め込み）で実現可能。＝**“不可能”ではなく“設計思想からの逸脱・追加コスト”**。
> - **A8 アフィリのメール配信**: 一律禁止ではない。**A8 にメルマガをメディア登録すれば掲載可**（一方で LINE・個人メール・SNS DM は明確に禁止。詳細は下の [Red Line](#red-line-やってはいけないこと)・A8 公式規約で確認済み）。
> - **摩擦離脱**: 量は減るが「意図の高い層を濾す」トレードオフでもある（純粋なマイナスではない）。

## 採用する方法（ファネルを殺さずリスト化）

| 方法 | 概要 | 優先 |
|---|---|---|
| **A. リードマグネット** | 記事は無料・クロール可のまま、**+α をメール/LINE 登録で配布**（印刷用 PDF・予想問題・直前チェックリスト・暗記カード等）。記事＝SEO 維持、特典＝登録動機。 | ◎ 即着手 |
| **B. LINE 公式アカウント** | この受験層に最適（開封率高・特電法の負担軽）。**ノーコード＝アプリ開発不要**（LINE Official Account Manager の管理画面であいさつメッセージ／応答／ステップ配信を設定）。友だち追加 CTA は摩擦が低い。**ただし A8 アフィリは LINE 配信禁止（規約名指し）＝LINE は note・自社コンテンツの配信に使う**。料金は無料枠（月間配信通数に上限）→超過で有料プランの従量＝最新を要確認。 | ◎ 即着手 |
| **C. note フォロー/メンバーシップ** | note 自体が囲い。サイト → note フォロー導線を強化（既存 funnel と連動）。 | ○ 継続 |
| **D. PWA 過去問アプリ** | **会員登録の本来の置き場**。アプリならログインは自然で web の SEO を傷つけない。登録・同期・プレミアム機能をアプリ側でゲート。 | ○ ロードマップ（[06_PWA過去問アプリ設計方針](../05_プロダクト/06_PWA過去問アプリ設計方針.md)） |

> [!note] リードマグネットの実装イメージ
> 記事末に「リードマグネット CTA ＋ LINE 友だち追加枠」を共通コンポーネント化し、過去問・テキストページの末尾に配置。SEO 本文は一切ゲートしない。配布物（PDF 等）は登録後のサンクスページ/自動応答で渡す。

> [!important] 試験系の捕獲タイミング＝「直前」でなく「試験後の次段階ブリッジ」（2026-07-01 確定）
> リストが空のうちは「直前◯◯」磁石を作っても送る先がなく無効。試験受験者は**受験 → 合格発表 → 次段階（一次→二次／二次→次資格）へ流れる**ので、捕獲窓は**試験後**。磁石は次段階の入口（例: 1級土木「一次おつかれ→二次の始め方」）にし、有料商品へ直結させる。正答速報レースは精度リスクで solo 不採用。資格別の適用は各 `noteコンテンツ計画.md`（1級・2級土木は §3.3）。

## Red Line（やってはいけないこと）

> [!warning] 厳守事項
> - **SEO コンテンツ（過去問解説・テキスト・キーワード）をログイン必須にしない**（クロール可能性を死守）。
> - **A8 アフィリ配信ルール（A8 公式規約・2026-06-27 確認）**: **LINE・個人宛メール・SNS の DM は禁止**（[禁止事項ページ](https://www.a8.net/compliance/prohibited-matter.php)に「個人宛のメールや SNS のメッセージ(LINE など)」と名指し）。**メルマガ（メール）は配信メルマガを A8 にメディア登録すれば掲載可**（メール用素材を使用・広告主ごとの個別媒体条件は各案件で要確認）。→ **LINE で配信してよいのは note・自社商品のみ。A8 アフィリを届けるなら「A8 登録済みメルマガ」経由**。違反＝アカウント停止に直結するので未確認運用はしない。
> - メール収集時は **個人情報保護法（プライバシーポリシー・同意・安全管理）＋特定電子メール法（オプトイン・送信者明記・配信停止）** を満たす。LINE/note はこの負担が相対的に軽い。

## 推奨シーケンス

1. **SEO 記事は無料のまま**、流入＝母数を伸ばす（既存 SEO 施策の継続）。
2. 記事末に **リードマグネット（PDF/予想問題）＋ LINE 友だち追加 CTA** を設置。
3. リストには **note 有料マガジン・自社商品**を配信（A8 アフィリは LINE/個人メール不可・A8 登録メルマガ経由なら可）。
4. 本格的な会員化・登録は **PWA アプリ**で（着手条件はアプリ側ロードマップに従う）。
