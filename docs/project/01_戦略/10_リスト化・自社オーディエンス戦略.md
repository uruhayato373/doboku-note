# リスト化・自社オーディエンス戦略

検索流入（借り物のトラフィック）に依存せず、**メール / LINE / アプリ会員などの「自社で直接届けられるオーディエンス（リスト）」を資産化する**ための方針。リストがあれば note 有料マガジン等の自社商品を直接届けられ、Google アルゴリズム変更のリスクを下げられる。本書は「どうやってリスト化するか／何をしてはいけないか」の横断方針。価格・商品の実行は各 `docs/note/{資格}/noteコンテンツ計画.md`、収益チャネル全体は [04_収益化戦略.md](./04_収益化戦略.md) を参照。

> [!important] 結論（2026-06-27 決定）
> **過去問解説などの SEO コンテンツを「会員登録ゲートで囲う」のは採用しない。**
> 代わりに **「無料で母数を最大化 → おまけ（リードマグネット）で囲う」** を採る。
> リスト化の本丸の会員登録は **PWA 過去問アプリ**（ログインが自然な面）で行う。
> 自社商品（note）はリストへ配信可、**アフィリエイト（ビルドジョブ等）はメール/LINE 配信しない**（ASP 規約・[Red Line](#red-line-やってはいけないこと) 参照）。

## なぜリスト化したいか（狙いは正しい）

- Google 検索流入は **借り物のトラフィック**。アルゴリズム変更 1 つで消える。
- メール / LINE / アプリ会員は **自社資産**。何度でも・直接・無料で届けられる。
- リストがあれば note 有料マガジンの新刊告知、受験期の直前案内、再訪促進などを能動的に打てる。

→ **オーディエンスの資産化という発想自体は正しい。** 論点は「方法」だけ。

## なぜ「SEO コンテンツのハードゲート」は不採用か

過去問解説をログイン必須にする案は、以下の理由でこのサイト（静的・SEO・AdSense・A8 アフィリ構成）に致命的。

| # | 問題 | 内容 |
|---|---|---|
| 1 | **SEO エンジン崩壊（最大）** | Googlebot がゲート内を読めず、インデックス内容が消失 → 順位崩壊 → 流入消滅。**トラフィックを殺してリストは作れない**（ファネルの入口を塞ぐ）。 |
| 2 | **AdSense 収益減** | ゲート＝PV 減＝AdSense 減。現行の収益柱を削る。 |
| 3 | **静的構成と矛盾** | 本サイトは静的（Cloudflare Pages・`output: export`・DB なし）。会員登録は認証基盤＋DB＋個人情報保護法対応が必要で設計思想に反する（[data-storage-decision.md](../../reference/data-storage-decision.md) で D1 不採用を明文化）。 |
| 4 | **ASP 規約違反リスク** | アフィリリンクのメール配信は多くの ASP（A8.net 含む）が禁止。違反＝アカウント停止＝アフィリ収益ゼロ（[アフィリエイト提携状況](../04_運営/02_アフィリエイト提携状況.md)）。 |
| 5 | **摩擦で競合へ離脱** | 検索者は答えを早く欲しい。ログイン壁で「戻る → 無料の競合へ」。小さなリストのために大きな流入を失う。 |

> [!warning] トラフィックが小さい今は特に時期尚早
> カテゴリページの流入は 28 日で 17〜157 ユーザー規模（2026-06 GSC/GA4）。母数がまだ小さい段階でゲートを敷くと、成長エンジンを潰して得るリストはごく少数。**まず母数、囲うのは後**。

## 採用する方法（ファネルを殺さずリスト化）

| 方法 | 概要 | 優先 |
|---|---|---|
| **A. リードマグネット** | 記事は無料・クロール可のまま、**+α をメール/LINE 登録で配布**（印刷用 PDF・予想問題・直前チェックリスト・暗記カード等）。記事＝SEO 維持、特典＝登録動機。 | ◎ 即着手 |
| **B. LINE 公式アカウント** | この受験層に最適。**メールより開封率が高く・特定電子メール法の負担も軽い**。「LINE で直前対策・予想問題を配信」の友だち追加 CTA は摩擦が低く配信チャネル内蔵。 | ◎ 即着手 |
| **C. note フォロー/メンバーシップ** | note 自体が囲い。サイト → note フォロー導線を強化（既存 funnel と連動）。 | ○ 継続 |
| **D. PWA 過去問アプリ** | **会員登録の本来の置き場**。アプリならログインは自然で web の SEO を傷つけない。登録・同期・プレミアム機能をアプリ側でゲート。 | ○ ロードマップ（[06_PWA過去問アプリ設計方針](../05_プロダクト/06_PWA過去問アプリ設計方針.md)） |

> [!note] リードマグネットの実装イメージ
> 記事末に「リードマグネット CTA ＋ LINE 友だち追加枠」を共通コンポーネント化し、過去問・テキストページの末尾に配置。SEO 本文は一切ゲートしない。配布物（PDF 等）は登録後のサンクスページ/自動応答で渡す。

## Red Line（やってはいけないこと）

> [!warning] 厳守事項
> - **SEO コンテンツ（過去問解説・テキスト・キーワード）をログイン必須にしない**（クロール可能性を死守）。
> - **アフィリリンク（ビルドジョブ/GKS 等）をメール・LINE で配信しない**（A8.net 等 ASP 規約で掲載先が登録メディアに限定されるのが一般的。違反は即アカウント停止）。リストへ届けてよいのは **note・自社商品** まで。
> - メール収集時は **個人情報保護法（プライバシーポリシー・同意・安全管理）＋特定電子メール法（オプトイン・送信者明記・配信停止）** を満たす。LINE/note はこの負担が相対的に軽い。

## 推奨シーケンス

1. **SEO 記事は無料のまま**、流入＝母数を伸ばす（既存 SEO 施策の継続）。
2. 記事末に **リードマグネット（PDF/予想問題）＋ LINE 友だち追加 CTA** を設置。
3. リストには **note 有料マガジン・自社商品**を配信（アフィリは配信しない）。
4. 本格的な会員化・登録は **PWA アプリ**で（着手条件はアプリ側ロードマップに従う）。
