# 設計思想

最終更新: 2026-04-03

---

## 核心原則

**doboku-note は「1級土木施工管理技士と技術士（総合技術監理部門）の2試験に特化し、受験者が『ここだけで合格できる』と感じるサイト」に集中する。**

他分野のコンテンツは Obsidian で品質管理し、**別途の条件を満たした段階で Phase 2 以降に段階的に追加**する。

---

## スコープ：2試験特化

| 試験 | 対象 | 優先度 | 状況 |
|---|---|---|---|
| **1級土木施工管理技士** | 1次試験 + 2次試験 | 最高 | 公開済み（30ファイル） |
| **技術士（総合技術監理部門）** | 1次+2次試験 | 最高 | 準備中（100ファイル未公開） |
| **その他試験** | 2級土木・PE他部門・RCCM等 | Phase 2以降 | 封印中 |

この2試験を徹底的に磨き、「ここさえあれば合格できる」という一貫した体験を提供することが最優先。

---

## 3層アーキテクチャ

| 層 | 環境 | 役割 | 状態 |
|---|---|---|---|
| **ステージング** | Obsidian（~/obsidian） | 全分野の下書き・品質管理・体系化 | 非公開 |
| **プロダクション** | doboku-note（本リポジトリ） | 1級土木 + 技術士総監に特化した公開サイト | 公開 |
| **アプリ** | iOSアプリ | 両試験の過去問演習・学習管理 | 開発中（Phase 2） |

### コンテンツの流れ

PDF / 書籍 / 公開情報 → **Obsidian**（下書き・体系化・品質チェック）→ 公開判断（フォーカス試験か確認）→ **doboku-note**（MD→MDX変換・SEO最適化・収益化導線）→ **iOSアプリ**（Phase 2）

### 一方通行の原則

- コンテンツは Obsidian → doboku-note の一方向で流れる
- doboku-note 側で直接コンテンツを作成・編集しない（緊急の修正を除く）
- Obsidian が唯一のソース・オブ・トゥルース

| `construction-management/` | 施工管理・品質・安全・法規（両試験共通） | doboku-note（共通コンテンツ） |

| フォルダ | 対象試験 | 追加条件 |

### ノートの frontmatter 規約

| フィールド | 型 | 説明 |
|---|---|---|
| `title` | string | ノートのタイトル |
| `tags` | list | 分類タグ（例: `#1doboku`, `#pe-cm`, `#concrete`, `#exam`） |
| `source` | string | 出典（PDF名、書籍名、URL等） |
| `status` | string | `draft` / `review` / `ready` / `published` |
| `target` | string | 公開先: `doboku-note` / `note-article` / `ios-app` / `none` |
| `exam-domain` | string | 試験の出題分野（例: `土工`, `コンクリート`, `施工管理`） |
| `date-created` | date | 作成日 |
| `date-modified` | date | 更新日 |

### status の定義

| status | 意味 | 次のアクション |
|---|---|---|
| `draft` | 下書き。内容が不完全 | 執筆を続ける |
| `review` | 内容は書けた。正確性・網羅性の確認待ち | `/audit-staging` で品質チェック |
| `ready` | 品質チェック通過。公開可能 | `/promote-to-site` でdoboku-noteに移動 |
| `published` | doboku-noteに公開済み | 更新がある場合のみ再promote |

## doboku-note（プロダクション）の設計

### 2試験特化の理由

1. **ユーザー体験**: 受験者が「ここだけで合格できる」と感じる一貫した体験
2. **検証速度**: 7月試験（1級一次）・11月試験（技術士一次）に向けた短期フィードバック
3. **資産の集中**: 1級土木（30ファイル公開済み）+ 技術士総監（100ファイル準備中）に最適化
4. **導線の明確化**: サイト→note有料記事→iOSアプリ、全て同じユーザーに向く

### コンテンツアーキテクチャ

フラット URL 設計: すべてのコンテンツは `/docs/{slug}` でアクセス可能。

```
.local/r2/posts/{slug}/article.mdx  →  /docs/{slug}

例：
  .local/r2/posts/civil-construction-1-guide/article.mdx  →  /docs/civil-construction-1-guide
  .local/r2/posts/cem-section-3-1/article.mdx             →  /docs/cem-section-3-1
```

カテゴリ・タグは frontmatter で管理。ナビバーは `src/config/categories.json` で定義。

### サイト構成（2試験特化）

| ナビバー項目 | 対応試験 | 内容 |
|---|---|---|
| **1級土木施工管理技士** | 1級土木 | 試験ガイド・第1次・第2次・土木知識・施工管理 |
| **技術士（総合技術監理）** | 技術士総監 | 試験ガイド・試験セクション・過去問・論文対策 |

#### 現在の非フォーカス試験コンテンツの扱い

| コンテンツ | ファイル数 | 対応 |
|---|---|---|
| 2級土木 | ~20 | ナビバーから除外。SEOインデックスは維持 |
| 技術士（建設部門・他） | ~30 | ナビバーから除外 |
| 河川・水理学 | 67 | 1級土木の出題範囲に関連する部分のみリンク |
| 道路法等 | 98+ | ナビバーから除外 |

**除外 ≠ 削除**。ページは残しSEOインデックスを維持する。ナビバーに表示しないだけ。

## iOSアプリの設計（Phase 2）

### 役割分担

| | doboku-note | iOSアプリ |
|---|---|---|
| 解説 | 詳細な技術解説（テキスト全文） | アプリ内は要約のみ。「詳しくはdoboku-noteで」 |
| 演習 | 過去問を読む（閲覧型） | 過去問を解く（インタラクティブ型） |
| 学習管理 | なし | 正答率、チェック機能、学習記録 |

### 対応する試験

- **1級土木施工管理技士**（第1次・第2次過去問）
- **技術士（総合技術監理部門）**（試験問題）

## 判断基準: Phase 2 を開始するには

1級土木 + 技術士総監で以下の条件を満たした後、**追加試験の公開を検討**します:

| 条件 | 基準値 | 監視指標 |
|---|---|---|
| 月間オーガニック検索流入 | ≥ 10,000 ユーザー | NSM（GA4オーガニック） |
| 2試験のコンテンツ体系化 | 両試験の出題全分野をカバー | インデックス済みページ数 |
| note有料記事 | 月間売上 ≥ ¥30,000 | note.com販売データ |
| iOSアプリ | App Store公開済み + 月間1,000DL達成 | App Store Analytics |

全条件を満たしたら、次の候補（2級土木 or PE建設部門）を Phase 2 として Obsidian から promote する。
