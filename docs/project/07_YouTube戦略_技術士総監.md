# YouTube 戦略 — 技術士（総合技術監理部門）v4

**策定日**: 2026-04-13（v3）
**最終改訂**: 2026-04-26（v4: SNS 量産型への全面転換）
**対象**: 技術士 総合技術監理部門（主）／建設部門（従）
**位置づけ**: **TTS 量産による完全自動 SNS チャネル + doboku-note / note への送客器**
**関連**: [05_収益化戦略.md](./05_収益化戦略.md), [26_instagram-post-automation.md](./26_instagram-post-automation.md), [Umbrella Issue #161](https://github.com/uruhayato373/doboku-note/issues/161)

## エグゼクティブサマリー（v4）

- **YouTube は SNS 量産チャネルに転換**。TTS（VOICEVOX）+ Satori 自動スライド + ffmpeg + YouTube Data API による完全自動投稿。運営者の手作業はゼロを目指す
- **合格体験者ポジションは SNS から撤退**し、note 商品（E-1〜E-4）と iOS アプリに集約する。理由は運営者の受験勉強リソース確保
- **共通基盤 `.claude/scripts/lib/sns-common/` を Instagram と共有**。チャネル独立ではなく、1 ソース → 多チャネル派生の量産型アーキテクチャ
- **立ち上げ時期**: 「7 月試験直後の強制立ち上げ」を撤回。共通基盤整備（Issue #164 SNS-0）完了次第、いつでも稼働。Q2 内に基盤完成、Q3 から週 3 投稿開始の見込み
- **直接収益は補助的**（市場天井が狭い）の位置付けは v3 維持。送客器としての役割が主

### v3 からの変更点（2026-04-26）

| 項目 | v3（撤回） | v4（採用） | 理由 |
|---|---|---|---|
| 音声 | 運営者の肉声 | TTS（VOICEVOX） | 受験勉強の時間を最優先で確保 |
| スライド | Claude 生成 + 手動編集 | Satori 完全自動 | 共通基盤化で人手依存ゼロ |
| 投稿 | YouTube Studio 手動 | YouTube Data API + cron 自動 | 量産・継続性 |
| 顔出し | 任意 | なし固定 | 量産チャネルなので個性を排除 |
| 受験記コンテンツ | YouTube に注入 | note 商品 E-1〜E-4 に集約 | 価値の高い一次情報は有料商品で囲い込む |
| 立ち上げ | 7 月試験直後（強制） | 共通基盤完成次第（任意） | 試験勉強優先の制約下では強制立ち上げが矛盾 |

## 1. 採用フォーマット（v4）

### Shorts（主力・週 3 本）

- 解像度: 1080×1920 (9:16)
- 尺: 30-60 秒
- 内容: 1 動画 = 1 キーワード or 1 過去問
- 音声: VOICEVOX TTS
- スライド: 共通基盤 `slide-render.mjs` で自動生成（5-7 枚）
- 字幕: whisper.cpp で TTS 音声から自動逆生成 → ffmpeg で焼き込み
- 投稿: YouTube Data API v3 (`videos.insert` resumable upload)

### 標準動画（補助・月 4-6 本、Phase 4 以降）

- 解像度: 1920×1080 (16:9)
- 尺: 3-5 分
- 内容: 5 管理別解説（人的資源・情報・安全・社会環境・経済性のいずれか 1 軸 × 複数キーワード束ね）
- パイプラインは Shorts と同一（横長レイアウトを `slide-render.mjs` のテンプレ ID で切り替えるだけ）

### 概要欄テンプレ（共通）

```
{title}（技術士総合技術監理部門）

{description}

▼ 詳細解説（doboku-note）
https://doboku-note.com/docs/{slug}?utm_source=youtube&utm_medium=description&utm_campaign={channel}

▼ 受験記・解答再現（note）
https://note.com/{author}?utm_source=youtube&utm_medium=description

#技術士 #技術士総監 #総合技術監理 #{管理分類} #{キーワード}
```

### v3 から維持する根拠

- 競合不在（特に総監部門特化の SNS は皆無）
- 棚田行政書士チャンネル等の隣接資格事例で「投稿頻度」がアルゴリズム評価の中心
- 量産型は「品質より頻度」のモデルで、リソース制約と整合する

| 建設部門 二次 | 約 1 万名（全部門の 40〜50%） | — |

### 到達可能母集団と天井

- 年間アクティブ受験者: 全部門で **4〜5 万人強**（一次＋二次、重複除く）
- リピート学習者を含めても **実質 5〜6 万人規模**
- **宅建の 1/5〜1/6** の市場サイズ
- 棚田チャンネル 20 万登録を 5 年で到達したペースから単純換算 → **技術士専業の天井は 4〜5 年で登録 3,000〜6,000 人**

### 再生数の相場感

- 1 動画あたり **数百〜数千**
- 1 万再生はスター級・合格発表期の季節動画のみ
- 量産モデルでは「1 動画あたり再生」より「累計再生」を重視する

### 収益性の結論

**広告収益単独では赤字確実**。送客器としての評価が主軸（v3 維持）。

## 3. 競合マップ（v3 維持）

**1 万人超の技術士専業チャンネルは日本に存在しない**。

| チャンネル | 主宰 | フォーカス | 形式 | 弱点 |
|---|---|---|---|---|
| 技術士 Lock-On | 匠習作（機械・総監） | 二次全般／論文／口頭 | 顔出し長尺講義 | 有料講座販促、短尺不在 |
| 技術士合格セオリー | 4 部門技術士ぺんた | 合格ノウハウ／添削経験 | 顔出しなし中頻度 | 更新不定期 |
| 技術士ライトハウス | coolangeng.com | 一次・二次／トレードオフ記事 | 講座抜粋 | 静的・ほぼ休眠 |
| SAT 公式チャンネル | SAT 株式会社 | 現場系資格全般 | プロ制作スライド | 技術士単体ではない |
| Yokosuba 技術士受験講座 | gijyutushijyuken.com | 二次論文の法則 | 顔出し低頻度 | ブログ主体 |

### 空白の度合い

- **総監部門特化**: 事実上ゼロ（Lock-On が部分的に触れる程度）
- **短尺スキマ時間型**: 全チャンネルが「長尺講義」または「有料講座販促」で、3〜5 分の独立コンテンツが皆無
- **音声主体のながら聴取型**: 診断士のダンシ君スタイルが技術士には持ち込まれていない
- **TTS 量産による高頻度投稿**（v4 で確認）: 国内技術士チャンネルでは前例なし

## 5. 参入戦略（v4 全面改訂）

### 基本方針

1. **目的は「note/サイト送客」に固定**（v3 維持）
2. **量産型に振り切る**: 共通基盤からの自動生成を週 3 本（cron）。手動編集禁止
3. **最初の 30 本は総監キーワード Shorts**: 既存資産の転用コストがほぼゼロ。差別化が最も鋭い領域

### KPI 設計（v3 維持）

| 指標 | 採用 | 理由 |
|---|---|---|
| チャンネル登録者数 | ❌ 主 KPI にしない | 市場天井が狭いため無意味 |
| **概要欄クリック率** | ✅ 主 KPI | 送客器としての機能を測定 |
| **doboku-note UTM 流入（YouTube 経由）** | ✅ 主 KPI | 実際の送客効果を定量化 |
| **note 商品ページへの遷移率** | ✅ 主 KPI | マネタイズ貢献度 |
| 1 動画あたりの再生数 | △ 補助指標 | コンテンツ品質の参考値 |
| 視聴完了率 | △ 補助指標 | テンポ改善のシグナル |

### 投稿形式の v4 仕様

- **尺**: Shorts 30-60 秒、標準動画 3-5 分
- **音声**: VOICEVOX TTS（採用キャラは Issue #163 SNS-prereq で決定）
- **スライド**: Satori + @resvg/resvg-js（共通基盤 `slide-render.mjs`）
- **字幕**: whisper.cpp で TTS 音声から逆生成
- **オープニング**: 5 秒以内で結論（離脱防止）
- **概要欄**: doboku-note 該当ページ + note 商品リンク（両方とも UTM 必須）
- **投稿頻度**: 週 3 本（GitHub Actions cron、JST 月水金 07:00）

## 6. リスクと対策（v4 更新）

| リスク | 影響度 | 対策 |
|---|---|---|
| TTS 量産で SEO 評価ペナルティ | 中 | YouTube 説明欄の文章は MDX 由来で品質担保。サムネ・タイトル品質で差別化 |
| YouTube アルゴリズムの初動評価で埋もれる | 中 | 週 3 本の定期投稿を 3 ヶ月以上継続。共通基盤で「途中で止まる」リスクを構造的に排除 |
| Lock-On が「総監×スキマ時間」に参入 | 低 | 有料講座販促モデルとバッティング、参入可能性は低い |
| VOICEVOX の商用利用規約違反 | 低 | Issue #163 で採用キャラのライセンスを事前確認。問題があれば差し替え |
| API レート制限超過 | 低 | YouTube Data API 10,000 units/day で月 60 動画 upload は余裕 |
| OAuth トークン失効 | 中 | 共通基盤 `media-uploader.mjs` で自動リフレッシュ + 失敗時 GitHub Issue 自動起票 |

## 7. 着手判断（v4 全面改訂）

### v4 方針: 共通基盤完成次第の即時稼働

v3 の「7 月試験直後の強制立ち上げ」を撤回。完全自動化により試験勉強との競合がなくなったため、Q2 中に基盤を整備して Q3 早期から運用開始する。

### Q2（4-6 月）: 基盤整備フェーズ

- [ ] Issue #163 SNS-prereq: アカウント・API 認証準備（YouTube ブランドアカウント開設、OAuth トークン取得）
- [ ] Issue #164 SNS-0: 共通基盤 `.claude/scripts/lib/sns-common/` 整備
- [ ] Issue #166 SNS-2: YouTube Shorts MVP（自動生成 + テストチャンネル投稿）
- [ ] Issue #167 SNS-3: GitHub Actions スケジューラ統合

**Q2 で本番投稿はしない**: テストチャンネル or 非公開設定で品質確認のみ。

### Q3（7-9 月）: 本格稼働フェーズ

- [ ] 7 月初: 本番チャンネル運用開始（週 3 本 cron）
- [ ] 7 月中旬: 運営者が技術士総監 2 次筆記を受験（YouTube 運用に影響しない）
- [ ] 7 月下旬: note E-1 を販売開始、YouTube 概要欄から送客
- [ ] 8-9 月: 投稿継続、note E-2/E-3 を YouTube から送客
- [ ] 3 ヶ月で月間再生 5,000 を達成 → 投稿頻度据え置き
- [ ] 未達成 → 投稿は止めない（共通基盤に依存しているため止めるコストの方が高い）

### Q4（10-12 月）: 拡充フェーズ

- [ ] Issue #168 SNS-4: 型拡充（5 管理別解説、トレードオフ動画、IG クロス投稿）
- [ ] 10 月末: 筆記合格発表対応（合格時のみ YouTube に「合格しました」動画 1 本投稿、それ以降は通常運用に戻す）
- [ ] 11 月〜: 1 級土木 2 次・技術士 1 次の季節スポット動画（共通基盤で 1 級土木 MDX も対応可）
