# 合意済み: 現行のリライト設計

## 基本設計

- **Generator/Evaluator 分離**: リライト実行は `keyword-rewriter` エージェント専任。採点（`cem-qa`）とは別エージェント
- **モデル**: keyword-rewriter は **Sonnet**（実行担当）
- **既存尊重原則**: 既存本文を一から書き直さない。**拡張内容を追加** が基本
- **呼出**: `/quality-cycle --mode rewrite` から Task subagent として発火（旧 `/exam-keyword-cycle` Phase 5 は 2026-05-15 退役）

## 2 系統の観点

### 系統 A: 修正候補に付ける「視点タグ」（過去問起点の整理用）

> 旧 `exam-keyword-cycle` スキル（2026-05-15 退役）で使われていた付与体系。退役後も、過去問観点で修正候補を整理する際の語彙として残す。

| タグ | 意味 | 修正例 |
|---|---|---|
| **網羅性** | 過去問で問われた論点が本文に欠けている | 具体例・定義・周辺概念の追加 |
| **正確性** | 事実誤認・OCR エラー・年号間違い | PDF 原文突合による修正 |
| **わかりやすさ** | 構造・表・図で改善可能 | 比較表化・SVG 追加・段落分割 |
| **試験適合** | 誤答選択肢の罠の明示 | ExamPoint に誤答パターンを明記 |
| **関連付け** | インラインリンク・RelatedKeywords 欠落 | 相互リンク追加 |

各修正候補に 1〜3 個の視点タグを付与してユーザーに提示（一括承認）。

### 系統 B: keyword-rewriter の「拡張パターン A-G」

cem-qa の弱点軸に応じて、ページ固有に 800〜1500 字の新コンテンツを追加。

| ID | パターン | 内容 | 弱点軸別推奨 |
|---|---|---|---|
| **A** | 具体例・ケーススタディ | 実務でこの概念がどう使われるか（5 管理トレードオフ観点、特定部門偏重を避ける） | principle / linking |
| **B** | 計算例・ワークスルー | 数式や手順を実数で 1 ステップずつ | （特定キーワード） |
| **C** | 比較・対比表 | 似た概念との 2 軸比較（4 列以上禁止） | structure |
| **D** | 歴史・背景 | なぜこの概念が必要になったか | reference |
| **E** | 試験での問われ方 | 過去問での出題実績・頻出パターン（**架空でなく実データ**） | principle |
| **F** | mermaid 図解 | プロセス系・組織系のフロー・概念図 | structure |
| **G** | モバイル視認性修正 | 4 列以上 / 3 列×長セル超過の表を階層化箇条書きに変換（**追加でなく既存構造の in-place 変更**） | mobile |
| **H** | 標準テキスト由来事実取り込み | 総監標準テキスト md の該当節から定義・成立背景・関連法令・国際合意の事実を抽出し、本文散文に統合。教科書自体は参考資料に書かず、テキストが参照する一次ソース（白書 URL・条約等）を §9 準拠で参考資料に追加 | reference / principle |

#### Pattern H 詳細仕様（2026-05-26 追加）

**入力**:
- `textbook_md_path`（任意）: 標準テキスト md ファイルパス
- `textbook_section_anchor`（任意）: テキスト md 内の該当アンカー（例: `§1 地球的規模の環境問題`）
- 省略時は frontmatter `category` + `section` から自動解決（マッピング: `.claude/config/cem-textbook-mapping.json`）

**処理フロー**:
1. 対応する textbook md を Read し、slug/title をキーワード grep して該当 H3/H4 節を抽出
2. 該当節の事実（定義・成立年・関連条約・対象範囲・主要原則等）を本文の語彙・文体に合わせて要約・再構成
3. 「とは」H2 または「総合技術監理における位置づけ」H2 に統合（新規 H2 追加は最終手段）
4. 教科書が引用している一次ソース（環境省白書 URL / OECD / UNEP 等）を WebFetch で実在確認して参考資料に追加

**禁止事項**:
- ❌ 教科書原文を逐語コピー（本サイト文体に合わせて再構成必須）
- ❌ 「総監標準テキスト 第5章 §1」等の教科書直接引用を本文に書く（読者が所持している前提を作らない）
- ❌ 教科書を `## 参考資料` に書く（content-principles §9 書籍禁止）
- ❌ テキストに記載がないキーワードに H パターンを強引適用（→ 該当節がなければ H をスキップ、cem-qa の類型タクソノミ「歴史政策・概念理論」と同じ判断）

### 1 ページあたりの上限

- 1 ページに **3 つ以上の拡張パターンを詰め込まない**
- ページごとに違うパターン組み合わせを選ぶ（テンプレ感回避）

## やるべきこと

- 既存本文を**尊重**（削除は最小限）
- 拡張は「総合技術監理における位置づけ」と「参考資料」の間に追加
- 新規セクションには H2 を立てる（例: `## 実務での具体例`、`## 試験での問われ方`）
- **散文中心で書く**（§17 準拠）。各 H2 は散文 1 段落以上で導入、表・箇条書きは補足
- **本文薄ページ（< 1000 字）は既存セクション内に散文追加を優先**（新規 H2 は最終手段）
- `<SeeAlso>` は本文中の言及直後に配置（末尾配置は反パターン）
- 法令名・他キーワード概念への内部リンク追加（条文番号には e-Gov リンク）
- Callout でメリハリ（合計 3 個以内、装飾目的禁止）
- frontmatter 更新:
  - `reviewStatus: needs-review`
  - `lastRewrittenAt: ISO 8601 秒単位`
  - `revisionCycle: 1`（既存値があれば +1）

## やってはいけないこと

- ❌ 既存本文を一から書き直す
- ❌ 「実務での観点」など同じセクション名を全ページで使う（テンプレ感）
- ❌ 1 ページに 3 つ以上の拡張パターン
- ❌ frontmatter の他フィールド変更（title, seoTitle, category, section, published）
- ❌ 既存の表・コード・コンポーネントを削除（G パターン例外あり）
- ❌ 既存の関連リンク削除
- ❌ `<ExamPoint>` 新規追加（1 ページ最大 2 個）
- ❌ Callout 合計 3 個超え
- ❌ 「誤り選択肢パターン」等の禁止表現（§5）
- ❌ 過去問判定記号（❌、✅、正答：）を本文に書く
- ❌ セクション見出しで「建設業における〜」（「建設部門/分野/実務における」を使う）
- ❌ 末尾に `<SeeAlso>` + `<ExamPoint>` + `<RelatedKeywords>` の 3 件以上連続配置
- ❌ 散文の代わりに表・箇条書きで概念説明を済ませる
- ❌ `<RelatedKeywords>` の prop 名を `keywords=` にする（正しくは `items=`）
- ❌ `<RelatedKeywords>` の slug にカテゴリ接頭辞を含める（bare slug を渡す）

## 「リライトの 4 視点」との対応

| ユーザーの 4 視点 | 担当 Phase / スキル | 採点軸 |
|---|---|---|
| **1. 構造的ルール**（表配置・h2 階層） | Phase 5（keyword-rewriter の C/G パターン） | 構造 30% + モバイル 25% |
| **2. 文章の内容**（NLM 標準テキスト整合） | Phase 2 で `improve-article --mode improve --deep` 呼出 | コンテンツ原則 20%（**NLM 整合は採点軸外**） |
| **3. deep リサーチ・web 検索** | Phase 3「正確性」タグ、`notebooklm-research` 呼出 | 参考資料 15% |
| **4. SVG 図版** | Phase 3「わかりやすさ」タグから `visual-research` / `illustrate-concept` 呼出 | 構造 30%（**SVG 単体軸なし**） |

## 既存 Orchestrator の使い分け

| Orchestrator | 起点 | 用途 |
|---|---|---|
| `/quality-cycle --profile cem --mode rewrite` | キーワード単体（弱点軸ベース） | バルクリライト |
| `/quality-cycle --profile cem --mode improve` | キーワード単体（NLM 主軸） | 外科的追記＋自動コミット |
| `/improve-article <slug>` | 単一記事 | 対話的に評価→修正→再評価のループ |
| `/audit-exam-mapping` | 過去問⇄キーワード紐づけ | semantic 監査（旧 `/exam-keyword-cycle` Phase 2 を継承） |

> 過去問起点の横断校正（旧 `/exam-keyword-cycle`）は 2026-05-15 退役。視点タグ付与は系統 A として語彙のみ残存。

## リライト後の検証フロー

```
keyword-rewriter で改訂
  ↓
reviewStatus: needs-review に変更
  ↓
quality-cycle --mode verify
  ↓
cem-qa で 5 軸再採点
  ↓
weighted ≥ 2.0 → state: verified
  ↓
quality-cycle --mode review → review-queue.md（人間向け）
  ↓
人間が reviewStatus: approved に書き換え（人間ゲート必須）
```

# 検討中の改善

採点側 [02_採点ルーブリック方針.md](./02_採点ルーブリック方針.md) で 6 軸化議論が進行中。採点軸が確定したら、本 md にも以下の追従が必要:

| 影響箇所 | 必要な対応 |
|---|---|
| 弱点軸→推奨パターン表 | 新軸「内容深掘り」が weak_axes になった場合の推奨パターン |
| 拡張パターン A-G の見直し | NLM 整合・過去問逆引き網羅・散文の論理性に対応するパターンが既存で十分か、新規 H 追加検討 → **Pattern H 実装済み（2026-05-26）** |
| Phase 2.5 連携 | `improve-article --deep` を Phase 2 必須化 or Phase 3 から呼ぶ |

**進め方**: 採点軸の決定を待ってから議論。先取りで本 md を変えない。

# 改善議論のルール

- **議論の場**: 本 md の末尾「議論履歴」セクションに追記
- **議論の昇格基準**: 同じ問題が **2 回以上** サイクルログで浮上したら（誤検知防止）
- **本 md の更新タイミング**:
  - 議論項目を本文に追加: 提案を受けた時点ですぐ
  - 「合意済み」セクションへ移動: ユーザー承認後
  - 真実源 commit 後: 本文の真実源リストにチェック追加
- **GitHub Issue は使わない**（2026-05-11 廃止）
