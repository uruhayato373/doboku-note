# 時点再現バックテスト protocol（R6〜R8）

> [!warning]
> **これは protocol（手順書）であり、まだ結果ではない。** 企画 §9・§13 step 3 の「最優先必須」
> 検証。1件の的中（R8地方創生）は有力なケーススタディだが**予測精度の証明ではない**。
> 販売前に、過年度で「後知恵を排した」再現テストと失敗例を揃える。本書はその実行手順と、
> 後知恵混入を防ぐ設計を定義する。判定基準は `02-match-criteria.md`、証拠は `01-evidence-ledger.md`。

## 1. 目的

「候補抽出→スコアリング→出題予測」のワークフローが、**各年度の試験日前に入手可能だった資料
だけ**で、実際の出題テーマを上位候補に含められたかを検証する。的中率だけでなく、上位候補数K・
カバレッジ・外れ方・見逃しを開示する。

## 2. 検証対象（ground truth・`01-evidence-ledger.md` §6 より）

| 年度 | 試験日(必須科目I) | 実際のI-2テーマ |
|---|---|---|
| R6 | 2024年（要・正確日付確認） | カーボンニュートラル |
| R7 | 2025年（要・正確日付確認） | 少子高齢化 |
| R8 | 2026-07-19（確定） | 地方創生 |

> 各年度の正確な試験日は、日本技術士会の公表情報で確定してから使う（R8のみ確定済み）。

## 3. 後知恵（hindsight）混入を防ぐ設計 — 最重要

このバックテストの信頼性は、**「答えを知っている状態でスコアリングしていない」**ことに全て
かかっている。次を構造的に守る。

### 3-1. 資料カットオフ

- 年度Nの分析には、**試験日前に公表・取得可能だった資料のみ**を入力する。
- 各資料に「公表日・取得日・対象期間」を記録し、試験日以降の資料は物理的に除外する
  （`templates/source-register.yaml` 相当で管理）。
- 白書・基本計画の「版」に注意（試験後に改訂された版を使わない）。

### 3-2. スコアラーの盲検化（human/LLM 双方）

問題は「実行者が既に R6=カーボン・R7=少子高齢化・R8=地方創生 と知っている」こと。知識を
消せない以上、次のいずれかで盲検性を担保する。

- **方式A（推奨・LLMブラインド）**: スコアリングを、対象年度の出題を知り得ないエージェントに
  行わせる。R8（2026年）は多くのモデルの知識カットオフ後のため、出題テーマを事前知識として
  持たないエージェントに、試験日前資料だけを与えて上位候補を出させれば、真にブラインドな
  前向き予測になる。R6/R7は学習データに含まれ得るため方式Aだけでは不十分。
- **方式B（事前登録・pre-registration）**: スコアリング結果（上位K候補・各スコア・除外理由）を
  出題判明**前**にタイムスタンプ付きで固定する。R8地方創生は 2026-06-01 の公開記事が事実上の
  事前登録に相当（`01-evidence-ledger.md` E3）。今後のR9以降はこの方式で毎年積み上げる。
- **方式C（第三者スコアリング）**: 出題を知らない協力者に、資料とルーブリックだけ渡して採点
  させる。R6/R7の遡及テストで後知恵を最も排せる方式。

> [!warning]
> R6/R7 を「いま」スコアリングして「当たっていた」と示すのは、実行者が答えを知っているため
> **後知恵バイアスを完全には排除できない**。この限界を隠さず、R6/R7は方式B（当時の記録が
> あればそれを、なければ方式Cのブラインド遡及）で扱い、方式Aの結果と区別して開示する。

## 4. 手順（年度Nごと）

1. **資料収集**: 試験日前に入手可能だった過去問・白書・政府基本計画・閣議決定を集め、
   source-register に公表日/取得日/対象期間を記録。カットオフ（3-1）を適用。
2. **候補抽出**: 資料から出題候補テーマを列挙。
3. **スコアリング**: `00-product-concept.md` §6 の8軸（政策鮮度・国家スケール・分野横断性・
   5管理適合性・トレードオフ・過去問距離・ペルソナ展開・根拠充足）を0〜3で採点。**上位候補数K
   を先に決めて固定**（例 K=5）。除外理由も残す。
4. **盲検化**: §3 の方式A/B/Cのどれで盲検性を担保したかを明記。
5. **照合**: 実際の出題テーマと上位K候補を `02-match-criteria.md` で一致/部分一致/不一致判定。
6. **開示**: K・カバレッジ・外れ候補・見逃しをセットで記録（的中率単独禁止）。

## 5. 合否ライン（この protocol の完了条件）

`00-product-concept.md` §12 の公開判定のうち本 protocol が担う項目:

- [ ] R6〜R8 の時点再現バックテストを、後知恵排除の方式を明記して完了
- [ ] 「一致/部分一致/不一致」を `02-match-criteria.md` で判定
- [ ] 各年度で K・カバレッジ・外れ候補・見逃しを開示
- [ ] R8ケーススタディに不一致範囲・外れ候補も記載（都合の良い部分だけ見せない）
- [ ] 「候補を増やせば当たるだけ」の設計になっていないことをKの小ささで示す
