# Brain商品企画：Claude Code 出題テーマ分析・国家施策バンク生成スキル

> [!todo]
> **企画段階**。R8総監記述式「地方創生」の事前収録実績をケーススタディにし、白書・政府計画・過去問から出題候補と答案部品を作る再現可能なワークフローを商品化する。商品本体、販売ページ、検証用バックテスト、Brain公開は未実施。

## 1. 結論

商品化する価値がある。ただし、販売するのは「次の出題を必ず当てる予言」や「地方創生の完成答案」ではない。

販売価値の中心は、次の工程をClaude Codeで反復できるようにすること。

1. 過去問題と政策資料を収集する
2. 出題候補テーマを抽出・採点する
3. 総監の5管理と接続する
4. 設問を想定し、国家施策を答案部品へ変換する
5. GeneratorとEvaluatorを分離して検証する
6. 公開日、根拠、更新履歴を保存する
7. 試験後に的中・不的中を同じ基準で検証する

## 3. 商品の位置づけ

### 仮商品名

**Claude Codeで作る 技術士総監「出題テーマ分析・国家施策バンク」スキル**

### 一文説明

過去問、白書、政府基本計画を所定フォルダへ置き、Claude Codeで「候補抽出→スコアリング→5管理への接続→設問案→国家施策答案部品→独立評価→証拠保存」まで行う非公式の分析キット。

### 既存商品との関係

`brain-claude-code-essay-skill` の施工経験記述版とは別商品にする。

| 商品 | 主な対象 | 中核価値 |
|---|---|---|
| 施工経験記述キット | 1級・2級土木 | 本人の工事経験を安全に答案化する |
| 技術士答案設計キット | 技術士建設／総監 | 与えられた問題を分解して答案を設計する |
| 本商品 | 技術士総監 | 出題前に政策テーマを分析し、答案部品を備蓄する |

本商品は専門性と更新負担が高いため、施工経験記述キットの付録ではなく、上位商品または独立商品として扱う。

## 4. 購入者へ提供する成果

購入者が次を自分の環境で再現できる状態を目標とする。

- 政府資料と過去問の出典台帳を作る
- 候補テーマを同一基準で採点する
- 各テーマについて5管理の対立・トレードオフを洗い出す
- 設問(1)～(3)の想定問題を作る
- 国家施策を600字程度の答案部品へ整理する
- 職種・立場別の論点差を展開する
- 根拠不足、古い制度、未確認数値を止める
- 生成物と評価結果をファイルで保存する
- 試験後に予測結果を検証し、翌年度へ改善を戻す

## 5. 中核ワークフロー

```text
公式過去問・白書・政府計画
  ↓
資料台帳（URL／公表日／対象期間／取得日）
  ↓
テーマ候補抽出
  ↓
スコアリングと除外理由
  ↓
5管理・国家スケールとの接続
  ↓
想定設問＋国家施策答案部品
  ↓
Generatorによる草案
  ↓
Evaluator／Fact Checkerによる独立確認
  ↓
人間による承認
  ↓
公開時点の証拠を固定
  ↓
試験後バックテスト
```

## 6. 候補テーマの評価軸

各項目を0～3点で評価し、点数だけでなく根拠と除外理由を残す。

| 評価軸 | 確認内容 |
|---|---|
| 政策鮮度 | 直近の基本方針、白書、閣議決定で重要度が上がったか |
| 国家スケール | 単一組織・単一業界に閉じず、我が国全体の課題として書けるか |
| 分野横断性 | 複数省庁・複数産業・地域をまたぐか |
| 5管理適合性 | 経済性、人的資源、情報、安全、社会環境との対立を書けるか |
| トレードオフ | 複数の合理的選択肢と残余リスクがあるか |
| 過去問距離 | 既出テーマの単純反復か、発展・統合として成立するか |
| ペルソナ展開 | 複数の技術分野・立場で具体例を作れるか |
| 根拠充足 | 一次資料で事実・制度・数値を裏付けられるか |

重みは最初から固定正解とせず、過年度バックテストで調整する。点数の高いテーマだけでなく、落選テーマと理由も保存する。

## 8. 販売導線案

1. 無料note：R8地方創生の事前収録を時系列で検証
2. 無料配布：テーマ採点表の簡易版
3. Brain本商品：スキル、エージェント、テンプレート、検査スクリプト、操作ガイド
4. 上位版：国家施策バンク生成モジュール、複数ペルソナ展開、年度更新
5. 継続版：新年度の白書・政策資料に対応した更新データ

note記事は実績と考え方を伝える入口、Brainは購入者が自分で再現するための実行環境とする。既存の国家施策バンクをそのまま再販売せず、コンテンツ商品と作成ツールの役割を分ける。

## 9. 商品化前に必要な検証

### 最優先：時点再現バックテスト

R6、R7、R8について、それぞれの試験日前に公開されていた資料だけを使って分析を再実行する。

- 未来の資料が混入していないか確認する
- 各年度の上位候補を固定する
- 実際の出題との一致・部分一致・不一致を定義する
- 候補数を増やせば当たるだけの設計になっていないか確認する
- 的中率だけでなく、上位候補のカバレッジと外れ方を示す
- R8地方創生の評価に後知恵が入っていないか検査する

1件の的中は有力なケーススタディだが、予測精度の証明ではない。販売前に過年度バックテストと失敗例を揃える。

### 動作・品質検証

- macOS／Windowsでセットアップを再現する
- Claude Codeの新規利用者が説明書だけで完走できるか確認する
- 出典のない数値をFact Checkerが止められるか試す
- GeneratorとEvaluatorの評価漏れをテストする
- 文字数、必須見出し、未置換プレースホルダを機械検査する
- Claude Codeや外部サービスの最新利用条件を公開直前に再確認する

## 10. 表示・安全上のルール

- 著者属性は「元発注者」「元自治体土木職員」「1級土木施工管理技士」など確認できる範囲に限定する。
- 「添削者」「採点者」「試験委員」「公式」「Anthropic認定」を名乗らない。
- AI出力は参考案であり、人間が一次資料と問題要求を確認する。
- 合格、的中、収益、作業時間を保証しない。
- 政策、制度、統計には基準日と出典を付ける。
- 市販教材、購入者限定資料、有料note本文、試験後に取得した情報を事前分析データへ混入させない。
- 所属先、顧客、個人を識別できる資料をAIへ入力しない。

## 11. 仮の販売単位と価格検証

価格は市場調査とβテスト前の仮説とする。

| 版 | 内容 | 仮価格帯 |
|---|---|---:|
| β版 | スキル、採点表、テンプレート、架空サンプル | 9,800～12,800円 |
| 正式版 | β改善、R8ケーススタディ、検査ツール、動画または詳細ガイド | 14,800～19,800円 |
| 年度更新版 | 新年度資料への更新手順・差分データ | 内容確定後に判断 |

個別の出題予想代行や答案添削は初版へ含めない。サポート範囲を広げる場合は、価格だけでなく対応時間、回答期限、責任範囲を別途定義する。
