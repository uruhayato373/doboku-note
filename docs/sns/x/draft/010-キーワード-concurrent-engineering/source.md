## 1. キーワードの核心

**コンカレントエンジニアリング（CE: Concurrent Engineering）** とは、製品の設計・生産準備・販売準備等の各工程を **同時並行的に進める** ことで、開発期間の短縮と品質向上を図る手法。

従来の逐次的（シーケンシャル）な開発プロセスに対し、各部門が早期に情報を共有し協調して作業を行う。

**位置づけ**: 技術士総合技術監理キーワード集 2026 の **2.1 事業企画**。経済性管理ピラーの設計管理 4 手法のうち **組織・プロセス構造の変革** を担う。

**関連キーワードページ**: [https://doboku-note.com/docs/pe-comprehensive-management-concurrent-engineering](https://doboku-note.com/docs/pe-comprehensive-management-concurrent-engineering)

## 2. 従来型開発との比較

| 項目 | 逐次開発 | CE |
|---|---|---|
| 工程の進め方 | 前工程完了後に後工程を開始 | 各工程を同時並行で実施 |
| 開発期間 | 長い | 短縮される |
| 手戻り | 後工程で発見されやすい | 早期検討により低減 |
| 部門間連携 | 限定的 | 緊密な情報共有 |

## 3. 主な効果

- **開発期間の短縮**: 各工程のオーバーラップにより全体期間を圧縮
- **品質向上**: 製造・保全等の知見を設計段階で反映
- **コスト低減**: 手戻り削減と早期問題発見による無駄の排除

## 4. 設計管理 4 手法における位置づけ

CE は **組織・プロセス構造の変革** を担う。逐次型開発を並行型に組み替えることで工程全体の期間を圧縮し、各工程の重複部分で部門間の情報共有が密になる。

- この情報共有の密度が **フロントローディング** の前倒し検討を実質的に機能させる
- 各工程の節目に **デザインレビュー** を設定することが品質保証の鍵
- **デザインイン** のサプライヤー参画も CE のチーム構成として取り込まれる

## 5. 引っかけポイント（試験で狙われる）

1. **「複数製品の同時開発」と混同**: CE は **1 製品の各工程を同時並行**。複数製品の開発を意味しない。
2. **総監標準テキスト定義**: 「下流の業務担当者を基本設計段階からチームに参画させて、工期の短縮を図る手法」
3. **部門間連携が前提**: CE は緊密な情報共有が前提条件。連携なしでは機能しない。
4. **逐次開発の単純加速ではない**: 工程順序を逆転させるのではなく、オーバーラップさせる。

## 6. 過去問引用

総監キーワード集 2.1 事業企画では、設計管理 4 手法（DR / CE / フロントローディング / デザインイン）が頻出。CE は **組織・プロセス構造の変革** として理解する。
