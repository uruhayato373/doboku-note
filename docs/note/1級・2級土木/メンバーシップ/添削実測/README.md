# 添削実測ゲート（§5.1 ゲート1・ローンチ最優先）

> 会員募集の前に必ず通すゲート。**添削1本に何分かかるか**を実測し、定員（初期10名）の根拠にする。
> 真実源: [noteコンテンツ計画.md §5.1](../../noteコンテンツ計画.md) / 手順: [2級経験記述-添削テンプレ.md](../../2級土木/2級経験記述-添削テンプレ.md)

## なぜやるか

添削層は「週 定員×1本」を運営者が現実的な作業時間に収められて初めて成立する。**1本30分以内**が目安。超えるなら定員を10→6へ、または隔週化する（計画 §1.3）。サンプルを実際に赤入れして測るまで、定員も価格も確定できない。

## このフォルダの中身（実測の入力＝半自動化済み）

添削テンプレの3ステップのうち、**ステップ1（字数）・ステップ2（論点抽出）・ステップ3の下書きまで自動生成済み**（2026-07-16〜 `/keiken-tensaku` スキル＝`civil-keiken-tensaku-drafter` エージェント。旧・手動プロンプト版の AI下書き.md も参考残置）。運営者は**添削下書き.md の取捨選択・トーン調整（最終赤入れ）だけ**を実行して時間を測れる。

|---|---|---|
| 01 安全・公衆災害（お題01対応） | [提出原稿.md](サンプル01_安全公衆/提出原稿.md) | [添削下書き.md](サンプル01_安全公衆/添削下書き.md) |
| 02 品質・コンクリート（お題02対応） | [提出原稿.md](サンプル02_品質コンクリート/提出原稿.md) | [添削下書き.md](サンプル02_品質コンクリート/添削下書き.md) |

以後の本番運用でも、提出1本ごとに `/keiken-tensaku <提出原稿path> --grade N` で同じ下書きを生成する（会員／ココナラ共通）。

## 実測の手順

1. ストップウォッチを開始する。
2. 提出原稿とAI下書きを読み、[添削テンプレ](../../2級土木/2級経験記述-添削テンプレ.md)のチェックリストを埋める。
3. **NG→OK は最重要の1〜2点だけ**に絞って赤入れする（全部直さない＝時間定数化の肝）。
4. 採点者視点の締めを1行書く。
5. ストップウォッチを止め、所要時間を下表に記録する。
