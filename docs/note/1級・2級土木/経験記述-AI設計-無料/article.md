# 施工経験記述をAIに丸投げすると落ちる理由と、自分の現場から組み立てる方法

**この記事でわかること**

- AIに経験記述を丸投げすると危険なのは文章力ではなく事実まで作らせる点にあることがわかります
- 事実は本人・構成と検証はAIという分担で、分からない数値は空欄で止める安全な手順を実践できます
- 現場状況→技術的課題→検討→処置→結果の骨格を、自分の工事の事実だけでつなぐ組み立て方がわかります

施工経験記述をAIに頼むと、文章はそれらしく整います。

でも、そのまま提出すると危ないです。この記事では、なぜ危ないのか、どうすれば自分の現場から安全に組み立てられるのかを書きます。

## AIに丸投げすると落ちる理由

施工経験記述は「あなたが実際に経験した工事」を書く問題です。

AIに「経験記述を書いて」と頼むと、工事名も、工期も、施工量も、あなたの立場も、現場で採った処置も、それらしく埋めてくれます。

でも、それはあなたの経験ではありません。

面接や口頭試問で深掘りされたとき、自分が経験していない工事は答えられません。数値の整合が崩れます。何より、経験していない工事を書くこと自体が本来の趣旨に反します。

つまり問題は「AIが下手」なのではなく、「AIに事実まで作らせてしまう」ことにあります。

## 直し方は「AIに事実を作らせない」

正しい使い方は、事実はあなたが出し、AIは構成と検証を手伝う、という分担です。

- 工事名・工期・施工量・立場・現場条件は、あなたが記入する
- 分からない数値は、AIに埋めさせず空欄で止める
- 設問が求める要素（課題→検討→処置→評価）に、あなたの事実を並べる
- 解答欄に収まる字数か、機械でチェックする
- 書いた文章を、別の視点でレビューする

この分担なら、AIは「作文の速さ」を、あなたは「経験の真実性」を担保できます。

## 落ちない答案の骨格

1級でも2級でも、評価される答案の骨格は共通です。

- 現場状況（固有の条件・数値）
- 技術的課題（なぜ難しいか）
- 検討した内容（複数案・採用理由）
- 採用した処置（具体的に何をしたか）
- 結果・評価（できれば定量的に）

この連鎖が、あなたの実際の工事の事実でつながっていれば、答案は強くなります。逆に、どれか一つでも「借りてきた事実」が混じると、そこから崩れます。

## この手順を、自分の環境で回す

私は元自治体土木職員（発注者側＝採点する側）で、1級・2級土木の経験記述の完成答案や置換ガイドを多数書いてきました。

その「事実は本人・構成と検証はAI」という手順を、あなた自身の環境で再現できるようにまとめたキット（Claude Code用）を用意しています。
