# note コンテンツ段階投下プラン 2026（無料＆有料ラインナップ）

**作成日**: 2026-04-17
**対象**: 技術士総合技術監理部門（運営者本人は合格済み）
**親戦略**: [05_収益化戦略.md](../project/strategy/monetization.md) の E-1〜E-4（合格体験シリーズ）の**実装詳細**にあたる

## Context

書籍市場が年間 3,000〜4,000 人の総監受験者を相手に成立している事実から、note 有料販売のニーズは確実にある。運営者自身が合格済みであるため、**勉強過程と試験本番の経験が一次コンテンツ化**できる構造を狙う。

ただし「合格前に解答のコツを有料販売する」のは**不合格時に信頼が崩壊するリスク**があるため、**段階投下** が必須。本書ではその段階と、各段階で「無料で出すもの」「有料で出して安全なもの」を記事単位で規定する。

---

## Red Line（絶対に守るルール）

以下は受験リスクと信頼リスクを同時に引き上げるため、合格発表まで禁止とする。

1. **合格前に「模範解答」「A評価狙いの論文」「採点基準の解説」を有料販売しない** — 不合格時に虚偽広告相当になる
2. **勉強時間の 30% を超える note 執筆時間を割かない** — 本戦略の土台は合格そのもの
3. **note 執筆のためにサイトの MDX 整備を止めない** — note は sold out したら終わりだが doboku-note は SEO 資産として永続する。**サイト → note への変換** はあっても逆方向はない
4. **不合格時は有料販売を 2 週間以内に停止 or 再編** — 「合格体験」系は即時取り下げ、「不合格体験記」へリブランディング
5. **note と doboku-note に同じ技術解説を両方載せない（重複コンテンツ禁止）** — note のドメインパワーで短期的に検索上位を取れても、同一の技術解説を両方に置くと Google はほぼ確実に note 側を正として doboku-note を低評価化する。noteのドメインパワーは「note記事自体のランキング」には効くが、**doboku-note本体のSEO資産にはほぼ寄与しない**（被リンク1本分のみ）。役割を明確に分離する — **note = 体験談・感情ストーリー・要約（消費完結型）**／**doboku-note = 体系的な技術解説（SEO 本体）**

## サイト（doboku-note） との連携

「サイトが note を売る、note がサイトへ流入を送る」の双方向導線を必ず作る。

### サイト → note

- 各 keyword ページ末尾の `RelatedKeywords` 下に note 商品バナー（P-01 / P-04 への送客）
- `keyword-2026` ハブの冒頭（出典 Callout 直下）に「暗記カード PDF はこちら」リンク
- 過去問ページ末尾に「E-01 解答全文再現」のバナー（R-1 以降）

### note → サイト

**目的**: note のドメインパワーで検索流入を獲得しつつ、読者を doboku-note に誘導して SEO 資産（被リンク・直接訪問・指名検索）を積み上げる。

- **各 note 記事に doboku-note への導線リンクを最低 1〜2 本埋め込む**（必須運用ルール）
  - 冒頭: 「詳細な技術解説は doboku-note にまとめています → [該当ページ URL]」の CTA
  - 本文中: 関連キーワードが登場した箇所に 1〜2 本のインライン内部リンク
- **note 記事本文では技術詳細を要約に留め、深掘りは doboku-note の該当ページへ送る** — note 側で完結させない構成にすることで、検索ユーザーが doboku-note へ流れ、指名検索・リピート訪問につながる
- **note の記事テーマ選定ルール**: doboku-note に既存の技術解説があるテーマを優先し、note はその「導入・体験ベース・要約」として書く。note 発・doboku-note 後追い（逆方向）は Red Line #3 に反するので禁止
- X 1日1キーワード投稿は必ず keyword ページへリンク（サイトの SEO もブーストする）

## 投稿時 SOP（記事ごとのチェックリスト）

`docs/note-drafts/` 配下の各ドラフトを note に実投稿する際の手順。旧 Issue #180 から移譲（2026-05-11）。進捗管理は `.claude/state/task-queue.json` の **T-016（note 商品ラインナップ整備）** を真実源とする。

### 投稿前の準備（全記事共通）

1. **cover.png** — `docs/note-drafts/{N}-*/img/cover.png` を note 記事ヘッダー用にアップロード
2. **インライン PNG** — note は inline SVG 非対応のため、`img/figure-*.png` を本文中の所定位置に配置（該当: 05 / 10 / 14）
3. **タイトル・概要・タグ** — note 内検索 SEO を意識して設定（タグは 5 個まで、関連キーワードを含める）

### 価格・公開形態の設定

| 記事種別 | 対象記事 | 公開形態 | 価格 |
|---|---|---|---|
| 無料 | 02 / 03 / 06 / 11 / 90 | 全文無料 | — |
| 単品有料 | 07 / 09 / 10 / 14 | 有料記事（一部無料公開後にペイウォール） | 07: ¥980 / 09: ¥1,500 / 10: ¥1,200 / 14: ¥1,980 |
| Hybrid | 05 / 08 / 12 / 13 | 「ここからマガジン限定」マーカー設定 | 05: ¥780 / 08: ¥980 / 12: ¥980 / 13: ¥1,200 |

### 投稿後の連携

1. **サイト相互リンク** — 該当キーワードページに「note で深掘り」CTA を追加（[27_5チャネル動線設計.md](../project/sns/channel-funnel.md) の UTM フォーマット準拠）
2. **T-016 の進捗更新** — `.claude/state/task-queue.json` の T-016 の `notes` に投稿済みドラフトを反映（完了したら関連子タスクの `status` を `done` に）
3. **SNS 告知** — X / Instagram で投稿告知（必要に応じて）

### 補足

- **記事末尾 CTA**: 無料記事は記事末尾に有料商品へのバナーを設置（02→A-1 / 10、03→B-1、06→D-1、11→B-1 / 13、90→B-1）
