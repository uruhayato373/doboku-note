## 1. 基本方針（v7）

- **X は補助チャネル（2026-06-12 凍結 → 段階的復帰中）**。かつては主力に置いたが、@dobokunotecom 凍結を受けて一次集客の重みは Instagram・note に寄せた。@doboku373 で 2026-07-07 に予約運用を再開し、**2026-08-13 に S2（1日3本・時間帯スロット A/B/C）へ移行**（段階と後退条件は `.claude/knowledge/reference/x-post-policy.md` §11.6／スロットは §11.2.1）。役割は受験生コミュニティへの信頼形成と note 誘導。執筆は `x-post-writer`、月次計画は `/x-campaign-plan`、予約は `/publish-x`（投入は1週間分ずつ）
- **Instagram が SNS 量産の一次制作チャネル**。`slide-data.json` を起点に、Carousel（4:5 PNG）と Reels（9:16 mp4）を同一データソースから派生生成。Carousel は「保存して試験前日に見返す」ストック教材、Reels は VOICEVOX TTS + ffmpeg で組み立てた音声付き縦動画。**Reels の cover/題材/CTA は Reels 専用テンプレで生成**し、カルーセル流用に起因する「スワイプ」CTA 等の不整合を構造的に排除
- **YouTubeはShortsと通常動画の二層**。1級・2級土木等のShortsはIG Reels派生を維持し、通常動画は検索・信頼・外部送客のストック資産として動画パックから一次制作する。多資格共通のSSOTは [06_動画コンテンツ運用設計](./06_動画コンテンツ運用設計.md)。Shortsは外部URLへ直接送らず、関連通常動画を主導線にする
- **運営者は総監合格済み（土木系公務員〔発注者〕の退職者）**。v5 までの「合格者を名乗れない（受験中）」制約は解消。**X では合格者の視点・思考・受験体験の断片を一次情報として発信**し、信頼と指名検索を作る。フル受験記・解答再現は引き続き note 有料商品（E-1〜E-4）に囲い込む
- **二系統のチャネル設計**: **IG → YT = SEO・カタログ動線**（IG が一次制作 → YT は派生・再リーチ／キーワード・過去問を検索/保存資産として量産 → サイト → note）。**X = 信頼・コミュニティ・マネタイズ動線**（合格者の発信で関係を作り → note 無料記事 → note 有料マガジン）
- 共通基盤 `.claude/scripts/lib/sns-common/` を Instagram・YouTube で共有（1080×1350 と 1080×1920 の両サイズ対応済み）
- NSM（月間オーガニック検索流入ユーザー数）への直接貢献は限定的でも、**指名検索・被リンク・権威性**を通じて間接的に SEO を底上げする

## コンテンツ角度フレームワーク（6 切り口・v7.2）

現状の SNS は過去問パック（IG Carousel B / Reels / YT Shorts 派生）と一部キーワード定義に偏重し、実質「知識チェック型」1 角度 × 「現受験生」1 層しか刺さっていない。一方で note 記事・サイト記事の資産は **すでに 6 切り口（結論／理由／体験／反論／数字／ハウツー）をほぼ網羅して書かれている**のに SNS へ転用されていない。この既存資産を 6 切り口の編集レンズで多媒体へ展開し、TOFU（これから受験する潜在層）・公務員層の取りこぼしを埋める。

- **設計**: 資格を `exam` で横断するのと同じ思想で、編集角度を `angle`（`conclusion` / `reason` / `experience` / `counter` / `number` / `howto`）で横断する。**角度別にエージェント/スキルは新設しない**（媒体 × Generator/Evaluator 分業に直交パラメータを足すだけ）。
- **層別の当て方**: TOFU = `number`/`counter`/`conclusion`（気づきで入口化）／現受験生 = `howto`/`reason`（過去問に上乗せ）／公務員 = `experience`/`conclusion`（公務員クラスター 8 本が既存在庫）。
- **源は手作り note 記事**: 「サイト description の自動要約」は過去に薄すぎて廃止済み。角度が立った既存 note 記事を源にする。
- **Red Line**: `experience` は断片・フックまで（一次情報は note 有料 E-1〜E-4 の囲い込み）／`number` は出典明記・捏造厳禁／verbatim 転記禁止／主角度は 1 投稿 1 つに絞る。

> 真実源は [`.claude/knowledge/reference/content-angle-policy.md`](../../.claude/knowledge/reference/content-angle-policy.md)（6 切り口の定義・資産マッピング・`angle` パラメータ分業設計・パイロット計画）。各 Generator/Evaluator はこれを共通参照する。

  - **試験日カウントダウン・季節リマインダー** — タイムライン適性が高い
  - **受験生との交流** — 引用・リプライ。指名検索と信頼の源泉
- **頻度**: 週数本（1 本の価値を高める）。固定ポスト（pinned）に「サイト紹介 + note マガジン」

- **送客先**: note 無料記事 → note 有料マガジン（主）／サイト（従）。直接「X → 有料」は跳躍が大きいため無料記事を一段挟む
- **KPI**: フォロワー数、プロフィールクリック率、**note への遷移数・有料マガジン経由売上**
- **トレードオフ**: スレッド・体験談は手作りで制作コストが高い。本数より質。投稿が流れやすいため継続が必須

#### 採用フォーマット

**Shorts（二次展開・週 1〜2 本）**

- 解像度: 1080×1920 (9:16)
- 尺: 運用推奨30-60秒（IG Reels 90-110秒からの短縮派生）。プラットフォーム上限ではなくdoboku-noteの推奨値
- 内容: 1 動画 = 1 過去問パック（cover + 1 問 + a1 + cta が原則）または 1 キーワード
- 生成元: **`reels/video.mp4`（gitignore・R2退避＝手元に無ければ R2 取得 or `ig-reel-create` で再生成）を ffmpeg でトリム**
- 字幕: IG Reels 用 ASS を 30-60 秒尺に合わせて再生成 → ffmpeg で焼き込み
- 投稿: YouTube Data API v3 (`videos.insert` resumable upload)
- 導線: 公開済み通常動画をYouTubeの関連動画として設定する。Shorts説明欄・コメントの外部URLはクリック主導線として扱わない
- **MDX 直結モード（旧 `--slug`）は v7 で廃止**。YouTube 単独制作はしない

**通常動画（検索・信頼・送客の核。DN-0110で4本pilot）**

- 解像度: 1920×1080 (16:9)
- 尺: テーマに応じて5-15分を基本とし、聞き流し型だけ別枠で長尺を検討
- 内容: 総監の5管理・記述式、1級・2級土木の施工経験記述など、明確な悩みと商品導線を持つテーマ
- パイプラインは Shorts と同一（横長レイアウトを `slide-render.mjs` のテンプレ ID で切り替え）
- 1動画1悩み・1回答・1主CTA。制作契約は `.claude/knowledge/reference/video-content-policy.md`

**Reels（9:16 mp4・週 3 本・月水金 19:30 JST）— 一次制作**

- 解像度: 1080×1920 (9:16 portrait)
- 尺: 90-110 秒
- 内容: **`slide-data.json` を起点に Reels 専用 PNG を生成 → VOICEVOX TTS → ffmpeg で連結**

**Highlight（プロフィール上部・6 種固定・整備は 1 回）**

- 整備順序: Carousel 4-5 本投稿後（Phase 1 開始から 2 週間後）に **1 回まとめて整備**。以降は四半期に 1 回更新

  1. **まず読む**: 運営者経歴（自治体土木職退職 + 6 資格保有 + 技術士総監筆記合格）と「ここでわかること」

**IG → YT の派生フローが妥当な理由（v7）**

- 共通基盤 `sns-common` は両サイズ（1080×1350 と 1080×1920）対応済み → IG 一次制作で再利用効率最大
- 動画は IG Reels（90-110 秒）の方が YT Shorts（30-60 秒）より長く、**長尺から短尺への派生は ffmpeg トリムで機械化可能**（逆は再撮影相当でコスト高）
- YT は検索流入・IG は Explore/フィード = 視聴者が両方で出会う確率は低く、ザイオンス効果で指名検索強化
- YouTube クロスポスト時のウォーターマーク無し（自家製 mp4 のため）

#### Instagram フォロワー獲得戦術（2026-04-29 追記）

**現実的な目標**

ニッチが狭い（技術士総監受験者 ≈ 年間 5,000-7,000 人）ため、generic IG growth とは別物の戦略を取る。

| 期間 | 目標フォロワー | 達成シナリオ |
|---|---|---|
| 1 ヶ月（5 月） | 30-80 人 | クロスプロモ + ハッシュタグ拾い |
| 3 ヶ月（7 月） | 200-400 人 | 受験期ピーク + 合格体験開始 |
| 6 ヶ月（10 月） | 800-1,500 人 | 合格者ポジション確立後 |
| 1 年（2027.04） | 3,000-5,000 人 | 来年受験者の本格立ち上げ期 |

**1,000 人 = 十分な専門アカウント**。エンゲージメント率（5-10%）の方がフォロワー数より重要。

**効果順 Top 5 戦術**

1. **クロスプラットフォーム流入**（最大効果）
   - doboku-note.com → IG bio リンクで誘導（既存月間 PV を follower 化）
   - X → 同じクイズを「詳細は IG カルーセル」で誘導
   - YouTube Shorts → 関連通常動画、通常動画の概要欄・チャンネルプロフィールからIG/サイトへ
2. **ハッシュタグの 3 階層戦略**（1 投稿 20-25 個 mix）
   - 大 (#技術士 #国家資格): 発見性
   - 中 (#技術士総監 #1級土木施工管理技士): 関連性
   - 小ニッチ (#技術士総監受験 #2026年技術士 #社会人勉強垢): 受験者直撃
3. **競合・関連アカウントへの能動エンゲージ**
   - 技術士関連の中堅アカウント（500-5000 follower）に**質の高いコメント**（専門性ある一言）
   - 1 日 5-10 件 を 30 日継続。「いいね回り」より遥かに効果的
4. **ストーリー活用**（feed と別アルゴリズム）
   - 質問ステッカー・投票ステッカーが**最強のエンゲージメント** → アカウント品質スコア上昇
   - 投稿日: 「新カルーセルあげました」+ 1 枚目スクショ
5. **投稿時間最適化**（受験者向け）
   - 朝 7:00-8:00（通勤）: 最強。火金 07:00 は理想的
   - 昼 12:00-13:00 / 夜 21:00-22:00 も有効

**やってはいけないこと**

| NG | 理由 |
|---|---|
| 1 日複数投稿 | 新規アカウントは reach 分散 |
| follow → 数日後 unfollow | スパム判定、reach 永久低下 |
| 「いいね回り」「フォロワー購入」 | エンゲージメント率低下で永久 reach 抑制 |
| ハッシュタグ毎回同じ | スパム判定。10 個程度ローテーション推奨 |

**doboku-note 固有の最強ムーブ**

- **「合格までの全記録」リアルタイム発信**（差別化の核）
  - 2026.07 受験本番までの 60 日を発信: 模試結果・苦手克服・直前追い込み・試験当日心境・合格発表
  - 同じ立場の受験者が「リアルタイムに並走してくれる人」を見つける希少体験
- **「過去問質問箱」運用**: ストーリーで質問受付 → リールで解説（コミュニティ感 + reach 向上）
- **doboku-note サイトに IG follow ボタン設置**: 月間訪問者を follower 転換

**初月（5 月）の優先 3 アクション**

1. 5/6 火曜の初投稿後、1 時間以内のコメント返信を最優先（IG 初動シグナル）
2. doboku-note サイトのトップに IG リンクを目立つ位置に配置
3. #技術士総監 ハッシュタグの上位投稿に毎日 5 件、質の高いコメント

実行タスクは `.claude/todo/backlog.md` のカードで追跡（IG フォロワー獲得の 30 日チェックリスト）。

## 3. アカウント戦略：独自アカウント vs 個人アカウント

**結論: doboku-note 専用の独自アカウントを作成する。**

### 独自アカウントが望ましい理由

| 観点 | 理由 |
|---|---|
| **ブランド一貫性** | サイト名に寄せたハンドル（IG `@dobokunotecom` 等）で指名検索・認知が積み上がる |
| **フォロワーの文脈** | 受験対策目的でフォローした人にだけリーチが届く。個人アカでは技術・プライベート投稿が混ざりノイズになる |
| **資産性** | 将来 iOSアプリ・note 有料記事をローンチした時、アカウントごと譲渡・共同運用が可能 |
| **分析の純粋性** | GA4 の参照元として `doboku-note-x` を識別しやすく、施策評価が明確 |
| **リスク分離** | 炎上・凍結時の影響範囲を限定できる |

> 当初は全チャネルを `@doboku_note` で統一する計画だったが、実際には空き名・凍結事故で分岐した。**ハンドルの真実源は各チャネルの機械可読 config**（IG は `.claude/config/ig-account.json`）。以下は実態。

## 5. 計測と意思決定

- **GA4 の UTM パラメータ**を全 SNS リンクに付与（`utm_source=x` / `utm_source=youtube` / `utm_source=instagram`）
- **月次レビュー**で SNS 経由セッション数・直帰率・指名検索数を確認
- 3ヶ月継続して NSM への寄与が見えなければ撤退・方針転換（X のみ。YouTube/Instagram は共通基盤依存のため停止コストが高い）

## 6. やらないこと

- **有料広告は当面使わない**。オーガニックと SEO に集中
- **毎日複数プラットフォームを同時運用しない**。Phase ごとに1チャネルずつ立ち上げる（Q2 は X、Q3 で IG 一次制作 + YT 派生）
- **個人的な意見・政治・時事ネタへの言及は避ける**。試験対策アカウントとしての信頼性を守る
- **YouTube に受験記の中身を投稿しない**。一次情報は note 商品で囲い込む
- **YouTube Shorts を Instagram とは別パイプラインで作らない**（v7 で廃止）。MDX 直結モード（旧 `yt-shorts-create --slug`）は再開しない。YT は必ず IG Reels mp4 から派生させる
- **Reels に「スワイプで…」等のカルーセル前提 CTA を流用しない**。Reels モード分岐を `slide-data.json` レンダラで持つ（v7 で構造的に対応）

## 7. フォロワーゼロから立ち上げる1年戦略（X 限定）

X は手動運用前提。資格試験は年サイクル（1次6月・2次10月・合格発表1月）で需要が動くため、試験カレンダーに同期させる。最初の90日が最大の山場なので、年次目標より **90日ごとのマイルストーン** で管理する。

### 90日マイルストーン管理

| 時点 | フォロワー目標 | 主要KPI | 撤退/見直し基準 |
|---|---|---|---|

| Day 180 | 500 | サイト流入月100セッション | 200未満なら固定ポスト・プロフィール改善 |

### 成功の鍵

- **投稿より「返信」が効く**: 受験生コミュニティは狭いので、役立つリプライ10件 > 無反応な投稿10件

- **3ヶ月で諦めない**: X は3ヶ月目までが最も伸び悩む。ここで多くが脱落する

## 8. リスクと対策（Instagram 一次制作 + YouTube 派生チャネル）

| リスク | 影響度 | 対策 |
|---|---|---|
| **IG パイプライン障害が YT も道連れに（v7 単一障害点）** | 高 | YT は IG Reels mp4 から派生するため、IG が止まると YT も発信停止。**フォールバックは IG カルーセル単独運用に縮退**（カルーセルは静止画のみで Reels パイプラインに依存しない）。Reels mp4 さえ復旧すれば YT は同 mp4 から自動派生のため復旧経路は最短 |
| TTS 量産で SEO 評価ペナルティ | 中 | YouTube 説明欄の文章は IG Reels script.json 由来で品質担保。サムネ・タイトル品質で差別化 |
| YouTube アルゴリズムの初動評価で埋もれる | 低 | v7 で「主力 → 二次展開」に格下げのため重要度低下。IG Reels の月水金リーチで補う |
| Lock-On 等が「総監×スキマ時間」に参入 | 低 | 有料講座販促モデルとバッティング、参入可能性は低い |
| VOICEVOX の商用利用規約違反 | 低 | SNS-prereq の事前作業で採用キャラのライセンスを確認済み。問題があれば差し替え |
| API レート制限超過 | 低 | YouTube Data API 10,000 units/day で月 8 動画派生は余裕 |
| OAuth トークン失効 | 中 | 共通基盤 `media-uploader.mjs` で自動リフレッシュ + 失敗時は `scripts/report-automation-failure.mjs`（`automation-failure` ラベル）で記録 |
| Reels CTA とカルーセル CTA の混入バグ | 中 | Reels モード分岐をテンプレレンダラ（`.claude/scripts/sns/templates/quiz-ig.mjs`）で持ち、`ig-reels-qa` の軸 4（音声 ↔ 画面整合）で検証 |
