## 1. 背景と結論

ネイティブ iOS アプリ（`01_iOSアプリ仕様.md`）は「過去問演習」を主用途に設計されていたが、以下の理由から **過去問演習はまず PWA で出す**方針に切り替える。

| 論点 | ネイティブ iOS | PWA |
|---|---|---|
| 初期固定費 | Apple Developer **$99/年（約 ¥15,000）** | ¥0 |
| 手数料 | **30%**（小規模特例 15%） | note 約 10-20% / Stripe 3.6% |
| 着手条件 | **Web 月間収益 ≥ ¥15,000 達成まで着手不可** | なし・今すぐ出せる |
| 審査 | App Store 審査・リジェクトリスク | なし |
| 対象 OS | iOS のみ | iOS / Android 横断 |
| 既存資産 | 同じ問題 JSON を消費 | **同じ問題 JSON をそのまま消費** |

iOS 仕様書自身が「iOS アプリ単独では事業の軸にならない」「初年度売上 ¥50〜95k（手数料後）」と結論づけており、$99/年 の固定費がそれを侵食する。**過去問演習に課金するなら、資本効率は PWA が上**という判断。

> [!note] iOS アプリの扱い
> 過去問演習用途は PWA に移管するため、`01_iOSアプリ仕様.md` の MVP（過去問演習）は事実上 PWA に置き換わる。iOS は将来「キーワード詳細・5 管理トレードオフ・合格体験」など PWA で出しにくい別価値に振り直すか、保留とする。仕様書は破棄せず、再定義候補として残す。

## 2. アーキテクチャ方針：資格別 PWA × 共通エンジン

「複数資格を 1 つのメガ PWA に詰める」のではなく、**資格別に独立した PWA**（独立アイコン・独立スコープ）を、**1 つの共通エンジンから出力**する。

```
共通エンジン（1 コードベース）
  ├ クイズロジック / UI / 進捗保存 / 正規化レイヤー / SW テンプレ
  └ ここを 1 回だけ作る
        │  ↓ 各資格の問題 JSON ＋ 資格設定を差し込む
        ├ /tools/kakomon-quiz/pe-first-stage → 技術士一次（Web アプリ v1 稼働）
        ├ /tools/kakomon-quiz                → 1級土木（Web アプリ v1 稼働）
        └ /tools/quiz/{exam}                 → 将来の資格別 manifest / icon / scope
```

### なぜ資格別か（PWA 固有の理由）

1. **インストール = ホーム画面 1 アイコン = 1 資格であるべき**。「1級土木 過去問」を探す受験者には、その名前・アイコンのアプリの方がインストール率・定着率が高い（App Store の過去問.com / TK office が資格別アプリなのと同じ）。
2. **検索流入が資格別**。資格別ルートなら各々が自分のキーワード（「1級土木 過去問 アプリ」等）で上位を取れる。
3. **受験者層がほぼ重ならない**。1級土木（年 5.1 万人・現場技術者）と総監（年 3-4 千人・上位 PE）は別世界。横断アプリは無関係な面を常に見せてしまう。
4. **収益化が資格別だから 1:1 で噛み合う**。「このアプリ＝この資格の課金で開放」が単純。横断メガアプリは「どの資格に課金したか」の管理が複雑化する。
5. **オフラインキャッシュが軽い**。各 PWA は自分の資格分だけ扱う。

### なぜ共通エンジンか

- エンジニアリングは N 倍にならない。同じエンジンを**設定で N 回出力**するだけ。
- 重複の唯一の管理点は manifest / アイコン → **1 つの資格設定テーブルから自動生成**してドリフトを防ぐ。
- 失う物は「doboku 横断ハブアイコン」1 つだけ。ユーザーは資格別に考えるので不要。資格間回遊は **Web サイト側の相互リンク**で担保する。

### 技術的投資の核心：正規化レイヤー

既存の問題 JSON はスキーマが微妙に違う（`correct` vs `correctNum`、フィールド名差）。**共通スキーマへ寄せる正規化レイヤー 1 枚**が多資格化を安くする唯一の必須投資。ここを最初に作る。

## 3. 配信方針：オンライン先行・インストール任意

PWA の「インストール（ホーム画面アイコン）」と「オフライン動作」は**別機能**。v1 はオンライン先行とする。

| レベル | 内容 | v1 採否 |
|---|---|---|
| (a) ただの Web アプリ | URL で開くだけ | — |
| (b) **インストール可・オンライン前提** | ホーム画面アイコン化、起動はアプリ風。通信は必要 | **v1 採用** |
| (c) 完全オフライン | 電波無しでも全問解ける | Phase で後付け |

**オンライン先行とする理由**:

- 学習の大半は自宅・職場・カフェ（Wi-Fi）。電波無しの電車内は副次的で、(b) で利用の 9 割をカバー。
- (c) は SW のキャッシュ更新・バージョン管理・iOS のストレージ退避という面倒を抱える。v1 で背負う価値が薄い。
- **収益化上もオンラインが有利**：オフラインは全問題を端末に DL する＝バルク抽出が容易。オンラインは都度配信でハードルが少し上がる。
- オフラインは後から SW プリキャッシュを足すだけで段階的に追加できる。

> [!warning] iPhone（iOS）でのインストールのクセ
> - インストールは **Safari の共有 →「ホーム画面に追加」が基本**（iOS の Chrome 等は不安定）。
> - iOS は **自動インストールバナーを出さない**（Android と違う）。→ **アプリ内に手順案内 UI を必ず置く**。
> - **未インストールの Safari タブの保存データは約 7 日放置で消えることがある**（ITP）。インストールするとキャッシュが保護される。
> - **プッシュ通知は iOS 16.4+ かつホーム画面インストール時のみ**。試験直前リマインダーを将来やるならインストール導線が前提。
> - したがって**インストールは「任意のおまけ」**として設計し、未インストールでも全機能が動くこと。必須ゲートにしない。

| 資格 | 構造化済み問題データ | 規模 | PWA への載せやすさ |
|---|---|---|---|
| 技術士総監 択一 | `src/config/exam-questions.json` | **640 問**（16 年） | ✅ 即載せ可 |
| 1 級土木 一次 | `src/config/civil-1-exam-questions.json` | **1,162 問**（12 年） | ✅ 即載せ可（最大の母数） |
| 2 級土木 一次 | `src/config/civil-2-exam-questions.json` | **630 問**（10 年） | ✅ 即載せ可 |
| コンクリート技士・主任技士・診断士 | MDX のみ（`primary-*`） | — | ⚠ MDX→構造化 JSON のパースが必要 |
| 技術士 一次 | `public/quiz/pe-first-stage.json`（公開 MDX から生成） | **1,040 問**（13 年・基礎 390／適性 195／専門〈建設〉455） | ✅ Web 演習へ結線済み |

→ **技術士一次を含む 4 資格で約 3,472 問が構造化済み**。技術士一次は図・KaTeX 数式・表形式選択肢を含むため、MDX から表示用 HTML へ正規化している。平成30年度適性科目 II-14 は公式に全員正解、令和7年度専門科目 III-13 は公式正答番号の掲載がないため、1,040 問に収録しつつ2問を採点母数から除外する。

平成25〜30年度の追加480問は、日本技術士会の問題PDF 18本と正答合冊PDF 1本を `.claude/config/pe-first-stage-historical-sources.json` に固定し、`node scripts/fetch-pe-first-stage-historical.mjs` で SHA-256・ページ数まで再検証できる。画像主体の原典をOCRした後、年度・科目ごとに原典目視突合、正答照合、構造検査を実施して公開データへ統合した。

## 5. 収益化方針

過去問は **commodity**（pejp.net が 25 年分無料公開、過去問.com 系も存在）。「過去問そのもの」ではなく「**弱点分析／復習計画／端末間同期／オフライン**」に値付けする。運営者固有の模範解答・論文再現・経験記述は note 商品に残し、PWA と重複販売しない。詳細・数値は [04_収益化戦略.md](../strategy/04_収益化戦略.md)、リストの横断ルールは [10_リスト化・自社オーディエンス戦略.md](../strategy/10_リスト化・自社オーディエンス戦略.md) を真実源とする。

> [!important] 2026-08-22 の決定
> サイト全体へログインを付けず、SEO 記事と無料演習は匿名で使える状態を維持する。ログインは **PWA の購入権限・端末間同期・購入復元**だけに使う。既に全 1,098 問を無料公開している 1 級土木は、問題アクセスを後から有料化せず、学習管理機能を買い切りで販売する。

### 現在地（無料 v1）

- `/tools/kakomon-quiz` に 1 級土木 1,098 問、年度別・ランダム 20 問・間違い復習、`localStorage` 進捗、結果画面の note CTA が実装済み。
- `/tools/kakomon-quiz/pe-first-stage` に技術士一次 1,040 問、年度別・科目別・ランダム 20 問・間違い復習、図・数式・全選択肢解説、元解説記事／note PDF への CTA が実装済み。
- `quiz_start / quiz_complete / quiz_cta_impression / quiz_cta_click` を資格別に送る。技術士一次は 1,038 問を採点し、公式に全員正解の1問と正答番号が掲載されていない1問を学習用の採点対象外として表示する。
- 現在の「全問無料」という公開約束と検索入口は維持する。ログイン、決済、端末間同期、manifest / Service Worker は未実装。
- 無料からの収益は、資格・結果に合った **note 自社商品**への送客のみ。学習導線へ講座／教材アフィリエイトを再導入しない。

### 買い切り Premium の価値境界

| 無料・匿名 | Premium・ログイン |
|---|---|
| 全過去問、即時採点、選択肢解説 | 分野・年度別の弱点分析 |
| 年度別、ランダム、間違い復習 | 忘却を考慮した復習スケジュール |
| 1 端末内の `localStorage` 保存 | 端末間同期・購入復元 |
| オンライン時のみ利用可 | オフライン利用（PWA キャッシュ） |
| 結果画面から note 送客 | 模試履歴・学習計画・結果出力 |

- 初期価格仮説は **資格ごと買い切り ¥980〜¥1,480**。価格は販売実績ではなく検証値で、CTA 意向と少数の有料 pilot を見て確定する。
- 「全問を見られる」だけでは課金価値にしない。過去問単体の月額も採用しない。継続課金は、予想問題・添削・新規モートを継続供給できる段階だけで検討する。
- Premium は 1 級土木で先に検証し、総監・2 級へ同時実装しない。

### 決済・認証・権限

```text
SEO 記事・note・SNS
  → PWA 無料演習（ログイン不要）
  → 2 回目の完了／間違い蓄積時に Premium 案内
  → Stripe Checkout / Payment Links
  → 決済 Webhook で entitlement を付与
  → メールのマジックリンクでログイン
  → Premium 機能・端末間同期
  → 記述式／模範答案は note へ送客
```

- note はドキュメント商品、Stripe は PWA 機能権限に分ける。note 購入コード＋`localStorage` フラグは、共有・購入復元・自動失効・端末間同期に弱いため本番方式にしない。
- 認証はメールのマジックリンクを第一候補とし、無料演習前の会員登録、パスワード管理、サイト全体のログインは作らない。
- `users / entitlements / progress / consent` を分離する。購入権限とマーケティングメール同意を同じ真偽値にしない。
- Stripe、認証 SaaS、メール配信基盤、Webhook、顧客データ保存は外部状態・個人情報を伴うため、候補・料金・保存項目・削除方法を提示してユーザー承認後に作る。

### メールと LINE の役割

| チャネル | 役割 | 取得タイミング | v1 方針 |
|---|---|---|---|
| **メール** | PWA 会員 ID、マジックリンク、購入通知、端末同期、学習リマインド、新商品案内 | Premium 購入時／任意の学習レポート受取 | **主チャネル** |
| **LINE 公式** | 試験直前・合格発表・一次→二次など期限性の高い通知 | 結果画面や次段階ブリッジで任意追加 | **補助チャネル** |
| **note フォロー** | note 新刊・メンバーシップ内回遊 | note 側 | 継続 |

- メールは購入権限と同じ識別子を使えるが、販促配信は**別チェックボックスの明示同意**を取る。送信者、配信停止 URL、問い合わせ先を必須にし、同意日時と取得面を記録する。
- LINE はメールの代替 DB やログイン手段にしない。メールと LINE の両方を初回に要求せず、LINE は緊急性のある少数配信だけに使う。
- LINE 公式の無料コミュニケーションプランは 2026-08-22 時点で月 200 通。友だち数 × 配信回数で消費するため、無料枠を「大規模リスト」と見なさない。
- メールアドレス、LINE 識別子、Stripe customer ID、同意ログを Git、GA4、CI artifact に保存しない。分析は匿名の集計値だけを残す。

### 実装前の検証ゲート

1. Phase 1 前は `quiz_start / quiz_complete / premium_view / premium_intent / email_interest / line_interest` を資格・配置別に計測する。実リスト開始後だけ `email_opt_in / line_add_click` を追加する。
2. 実機能を作る前に、Premium の価値・価格仮説を示す案内面と購入意向 CTA を置く。未実装機能を販売済みのように表示しない。
3. 1 級土木で PWA 利用者 100 人以上、Premium CTA 率 5%以上、重複除外した購入希望 10 人以上を満たしたら、メールリスト pilot と決済・認証の ADR へ進む。
4. 未達ならログイン基盤を作らず、到達面・価値提案・利用継続率を見直す。

### 条件成立後：メンバーシップとの接続

> [!important] 小出し（drip）の対象を取り違えない
> **過去問演習は小出ししてはいけない**。受験者は試験日までに全部解きたい（直前詰め込み型）。月 1 小出しは「試験に間に合わない」解約を生む。
> - **小出しする = エバーグリーンなモート**（論文再現／月次キーワード解説／5 管理トレードオフ／受験記）。毎月更新が継続課金の理由。
> - **一括開放する = 過去問 PWA フル演習**（試験前に全部使える特典）。

- 既存の買い切りマガジン購入者は **永久アクセスのまま grandfather**（月額化で不信を生まない）。
- メンバーシップの形：**過去問 PWA Premium を特典として含め、読み物（モート）は資格別トラック**が自然。Stripe 買い切り購入者の権利は維持する。
- 戦略は過去に「資格系アプリのサブスク」を一度否定（`04_収益化戦略.md` v3.1）。否定されたのは「過去問アプリ単体の月額」であり、**モートを継続価値にしたメンバーシップは別**。詰め込み 1 ヶ月解約に負けないよう、買い切り（前段）の受け皿も残す。

## 6. 段階ロードマップ（Phase 0 → 4）

> [!warning] 過剰スコープが最大リスク
> 戦略リスク表の筆頭は「実行リソース不足（高/高）」。**多資格化・課金・メンバーシップ・データ構造化を同時にやらない**。Phase 0 → 1 → 2 → 3 → 4 を順番に進める。

| Phase | 内容 | 前提・データ | 状態 |
|---|---|---|---|
| **Phase 0（実装済み）** | 共通クイズエンジンで、1 級土木 1,098 問と技術士一次 1,040 問を無料演習化。技術士一次は科目別・図・数式・元解説導線にも対応 | 資格別 JSON | 稼働 |
| **Phase 1（計測開始）** | GA4 の演習／CTA イベントを取得。Premium 案内面、メール任意登録、LINE 任意 CTA は需要を見て追加し、課金・認証はまだ作らない | 現行 Web 演習 | 一部実装 |
| **Phase 2** | Stripe買い切り、マジックリンク、entitlement、端末間同期、弱点分析、広告非表示。1 級だけで pilot | Phase 1 成功基準 | 未着手 |
| **Phase 3** | 共通エンジン化して総監・2 級土木へ展開。manifest / SW / オフラインを資格別に結線 | Phase 2 有料実績 | 未着手 |
| **Phase 4** | 継続モートが供給できる場合だけメンバーシップと接続。買い切り権利は維持 | 継続価値・運用実績 | 未着手 |

## 7. 次の実装チェックリスト

1. 1 級土木・技術士一次の `quiz_start / quiz_complete / quiz_cta_*` を GA4 で計測し、資格・モード・CTA 別のファネルを比較する。
2. Premium 価値・価格仮説・未実装表示を備えた案内面を作る。
3. メール任意登録と LINE 任意追加を別 CTA とし、同時要求しない。
4. 成功基準を満たした場合だけ、認証／決済／メール基盤の ADR とデータ保護設計を作る。
5. Stripe test mode、Webhook 署名、冪等な entitlement、購入復元、退会／削除を実装する。
6. 弱点分析・端末間同期・広告非表示の最小 3 機能で有料 pilot を行う。
7. `npm run build`、認証 E2E、Webhook fixture、権限テスト、個人情報非混入検査を通す。

> [!note] 未確定事項
> - アプリアイコンは資格別に新規生成が必要（デザイン方針：資格名タイポ主体／資格カラー分け — 未決）。
> - 認証・メール・データ基盤の製品選定は未確定。外部サービス登録前に費用・ロックイン・削除／export・SMTP・障害時の購入復元を比較する。
> - Phase 2 以降の着手タイミングは Phase 1 の利用・意向データで決める。
