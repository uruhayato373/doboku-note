# 商品制作ロードマップ

## Phase 0：権利・スコープ確定

1. 初版を「1級・2級土木 施工経験記述」に限定する
2. 配布可能な自作ロジックと、配布不可の内部資料を一覧化する
3. 字数上限の一次資料・確認日を記録する
4. サンプル問題文を自作するか、再配布可能な公開資料を選ぶ
5. ライセンスと免責の方針を決める

成果物：権利台帳、初版スコープ、サンプル方針。

## Phase 1：最小スキル

1. 出力先を決める
2. skill-creatorの `init_skill.py` で初期化する
3. SKILL.mdを書く
4. `civil-1.md`／`civil-2.md`／`evidence-policy.md`／`rubric.md`を書く
5. 入力・答案・レビューのテンプレートを作る
6. 字数・必須項目・プレースホルダ検査を実装する
7. `quick_validate.py`を通す

成果物：ローカルで動く最小スキル。

## Phase 2：サンプルと前方テスト

1. 架空工事の正常ケースを作る
2. 入力不足ケースを作る
3. 機密情報ケースを作る
4. 1級／2級取り違えケースを作る
5. 字数超過ケースを作る
6. 新しいClaude Codeセッションで、答えを教えずに各ケースを実行する
7. 失敗をSKILL.md／scriptsへ戻す

前方テストはファイル生成を伴うため、実施時にユーザーへテスト範囲を提示して了承を得る。

成果物：テスト記録、修正版スキル。

## Phase 3：購入者向け教材

1. `START-HERE.pdf`を作る
2. インストール動画を作る
3. 正常ケースを最初から最後まで実演する
4. よくある失敗をまとめる
5. Windows／macOSの差を確認する
6. サポート対象・対象外を確定する

成果物：PDF、動画、FAQ原稿。

## Phase 4：販売準備

1. ZIPを作る
2. secrets・内部URL・絶対パスを横断検査する
3. 商品ページと同梱物を突合する
4. サムネイルを作る
5. 販売価格・紹介設定を決める
6. Brain販売者情報を整える
7. 審査へ提出する

成果物：審査提出可能な商品一式。

## Phase 5：β販売

1. 少人数へ案内する
2. 導入完了率を確認する
3. 質問を匿名化して記録する
4. 答案内容の個別添削へ範囲が膨らまないようにする
5. 重大な誤りは購入者へ通知する
6. 正式版へ反映する

## 必要なユーザー判断

実制作へ進む前に、次の4点を決める。

1. 初版を1級・2級土木版に限定してよいか
2. スキル本体の作成先
   - このリポジトリ内の販売準備ディレクトリ
   - 別の非公開リポジトリ
   - 個人のClaude Code skillsディレクトリ
3. サンプル問題を完全自作にするか、公開過去問を参照させるか
4. β版に動画と質問対応を含めるか

推奨は、別の非公開リポジトリで商品本体を作り、このリポジトリには設計・参照元・公開記録だけを残す方式。
