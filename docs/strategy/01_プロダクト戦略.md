# プロダクト戦略

## 事業の方向

**図で理解し、過去問で確かめ、答案に活かす。** 受験者が理解・演習・答案作成をつなげられる試験対策ハブを育てる。教材の正確さと、継続可能な収益・運営負担を両立させる。「ここだけで合格できる」は体験設計の目標であり、合格の保証や実測済みの効果を意味しない。

この文書は判断理由の正典。**重点資格・提供価値・指標の定義は [business-direction.json](../../.claude/config/business-direction.json)** を唯一の機械設定とし、管理画面、SEO選定、週次・月次レビュー、戦略エージェントが参照する。価格・公開状態・販売実績は各商品カタログと計測台帳を参照し、この文書に件数や売上を複製しない。

## 誰の、どの課題を解くか

重点は1級土木施工管理技士、技術士総合技術監理部門、技術士建設部門。資格名だけでなく「理解する・問題を解く・答案を書く」の学習段階で検索意図と教材を設計する。

- **1級土木**: 施工の構造・手順・用語の違いを理解し、選択肢の正誤理由や経験記述へつなげる。
- **総監**: 5管理の関係、比較、トレードオフを整理し、択一の判断と記述式の論理へつなげる。
- **建設部門**: 原因、対策、適用条件、残留リスクを整理し、専門分野の課題・解決策・留意点を組み立てる。

重点外の既存資格も正確さを保つ。新資格の追加は既存の学習体験・需要・収益・保守余力から判断する。単に検索順位を上げやすい一般用語へ改善枠を流さない。資格名を含まない専門語でも、対象受験者と次の学習行動が明確なら候補になる。

## 図解をどう強みにするか

図解単体は他者も提供できる。差別化の仮説は、**正確な図解と体系的な説明、過去問の判定理由、答案への使い方を一続きにすること**にある。運営者の実体験は経験した範囲を明示し、他分野の技術的根拠を代替しない。「競合ゼロ」「唯一」「模倣不可能」とは断定しない。

図は構造・比較・因果・手順など、文章だけでは把握しにくい関係に使う。全記事への図の追加や図数増加を目的にしない。スマートフォンで読めるか、矢印や尺度が正しいか、出典・権利を満たすかを既存の図版・教材品質規約で確認する。

コンテンツの改善単位は「対象資格／読者の課題／現物で確認した不足／変更／評価指標／再確認日」。図から関連説明、過去問、答案へ進める次の行動を設け、SEO目的だけの内部リンクを増やさない。

## 無料・有料の役割

無料サイトは理解と演習の入口を担う。noteは体系化した教材、まとめて使える模範解答などを提供する。ココナラは本人の事実に基づく診断・添削・答案作成など個別支援を担う。各商品が実際に約束する内容・公開状態を確認して案内する。

note・ココナラ内の検索や回遊による売上も事業の成果。サイトの送客数だけで両チャネルを評価しない。YouTube、PWA、Kindle、アフィリエイト等も同じ顧客価値と運営余力の基準で評価し、チャネル追加そのものを成長とみなさない。個別の公開・着手条件は既存の商品戦略を参照する。

## KPIの役割

事業成果は受取額・費用・運営時間と販売実績で確認する。手数料控除前の販売額を利益と言わず、未記録の費用・時間を0にしない。教育価値は学習行動と教材品質を見て検証する。NPSは推奨意向であり、合格率への貢献ではない。

| 観点 | 確認すること | 次の判断 |
|---|---|---|
| 集客 | 資格別の自然検索人数・Googleクリック、順位と需要 | 対象受験者へ届いているか |
| 学習 | 演習開始・完了など、実装済みの行動と範囲 | 次の学習へ進めるか |
| 販売 | note記事PV・販売数、ココナラ閲覧・相談・購入、商品別販売額 | 入口・商品説明・支援内容のどこを実査するか |
| 運営・品質 | 実受取・費用・作業時間・教材不備 | 継続・集中・縮小の判断 |

既存NSMの自然検索ユーザー数は**集客の継続指標**として保持する。GA4 Organic Search（日本、全検索エンジン）の期間全体の人数であり、Googleのみの人数ではない。日別や資格別の人数を足して月間ユニーク人数にしない。検索表示数×CTRはクリックであり、ユーザー数ではない。

将来の中心指標候補は「理解から演習・答案確認まで進んだ学習者」。資格横断の計測範囲・重複排除・同意と品質を検証してから採否を判断する。現状の一部イベントだけで達成済みとしない。目標は対象・期間・実測基準・根拠・見直し日を記録して設定し、過去の仮目標を現在の約束へ流用しない。

## 計測の解釈

同じ期間・資格・商品範囲で比較する。GSCは太平洋時間、運用レビューは日本時間であることを示す。試験日までの距離や前年同時期も確認し、前月増減だけで施策の因果効果を断定しない。

note新ダッシュボードの記事PVとインプレッションは旧「全体ビュー」と別系列。PVはマガジンページ閲覧を含まず自己閲覧を含む。マガジン販売数を記事PVで割らない。ココナラの過去30日値を週次の増分として足さない。マスク値・未取得・対象外は欠測として扱う。

同一対象の販売数÷閲覧数を使う場合も参考の販売効率であり、購入者単位のCVRではない。サイトCTAクリックと販売数を割ってサイト経由購入率にしない。売上は起きたことを示すが、売れた・売れない理由は商品説明や導線の実物と照合して仮説にする。

## 継続改善の責任分担

- **日次**: SEO Rank Watchの期限・測定鮮度を確認。1回1キーワード、本番反映後7日間は観察し再改善しない。専用の延長・1位判定条件を守る。
- **週次**: 前の完了した月曜〜日曜の集客・学習・販売・欠測と、既存実験の期日を確認。実測／未確認／判断を分け、次の一手を選ぶ。実験枠を空けるために未評価の施策を完了にしない。
- **月次**: 前の完了した暦月の資格・商品・費用・時間と試験季節性を確認。重点と目標、続ける・変更する・保留する施策を最大3件に絞る。SEOの28日方針レビューは別の期日を保持し、月次開催だけで確認済みにしない。

レビューは計測スナップショット・判断・次の一手・実験ID・次回日を追記保存する。改善の状態は既存 [experiments.json](../../.claude/state/experiments.json)、単発実装はbacklog、週次・月次計画はその参照だけを持つ。記録の重複は期間キーで検出し、訂正は前の記録を指す追記とする。

運用コマンド・データ契約は [事業計測とレビュー](../../.claude/knowledge/reference/business-review.md)。管理画面は `/metrics/business`。スキルは `weekly-review` → `weekly-plan` と `monthly-review` → `plan-weekly`、統括は `strategy-advisor`。定期実行は既存ルーティンへ結線し、同じ役割の監視を増やさない。
