# KPI ツリー — 受取額から逆算する資格別の指標と目標

最終更新: 2026-09-27

## 結論

- 頂点は **月の受取額**（手数料控除後）。そこから **チャネル別**（note・ココナラ・KDP・サイト経由）に分け、各チャネルの中だけで「入口 → 購入」を追う。チャネルをまたいで割り算しない（[01_プロダクト戦略.md](./01_プロダクト戦略.md)「計測の解釈」）。
- 資格は同じツリーを **資格別** に持つ。目標は資格 × 試験の季節で置き、前月比ではなく **前年同期と試験日までの距離** で読む。
- 今の NSM「自然検索ユーザー」は **大半が Bing**（2026-08-21〜09-03 の GA4 監査で Bing 2,683 人・Google 82 人。[measurement-incidents.md](../../.claude/knowledge/reference/measurement-incidents.md)）。Google 検索は月 100 クリック前後で、売上の主な入口ではない。集客指標は **Google と Bing を分けて** 見る。
- 売上の大半は **note の中の検索・回遊** で起きている（サイトからの note CTA クリックは 8 月 221 回、note の記事 PV は 7,455）。サイトの SEO は「note と自社商品の入口のひとつ」として位置づけ、ツリーの頂点側に置かない。

## ツリー

```
月の受取額（控除後）  ← 頂点
├─ note 受取
│   ├─ 販売額 = 販売件数 × 単価（マガジン・単品・会員）
│   ├─ 入口: note 内インプレッション・記事 PV・フォロワー
│   └─ 外部入口: サイトの note CTA クリック・X / IG（参考）
├─ ココナラ受取
│   ├─ 販売額 = 購入件数 × 単価（＋差額・おひねり）
│   ├─ 入口: 閲覧 → 購入前相談 → 購入（同じ 30 日窓の中だけで比べる）
│   └─ 信用: 評価平均・評価件数・返信までの時間
├─ KDP ロイヤリティ
│   └─ 販売冊数・既読ページ（KENP）・公開冊数
└─ サイト（無料の入口・学習）
    ├─ インデックス: 登録済み URL ÷ サイトマップ URL（資格別）
    ├─ 検索: クラスター別の 1 桁順位の検索語数・表示（16_検索キーワード戦略.md）／Google クリック／Bing ユーザー
    ├─ 学習: 演習開始・完了・答案確認
    └─ 送客: note CTA・ココナラ CTA クリック

運営（ツリーの横に置く制約）
├─ 費用・作業時間 → 時間あたり受取額
└─ 品質: 重大な教材不備・返金・苦情
```

## 目標の置き方

**全体の目標は月の受取額 ¥100,000**（2026-09-27 運営者決定・NSM を `organicUsers` から `netReceipts` へ切り替え）。`target` 記録は完全な実測基準（受取額の月次計測）を残してから置く。資格別の配分は季節差を見て別途決める。


- 目標を置くのは **受取額（全体・資格別）** と、各チャネルで最も打ち手が効く 1 段だけ（note＝販売件数、ココナラ＝購入件数、サイト＝インデックス率と Google 表示回数）。全段に目標を置かない。
- 目標には対象・期間・実測の基準・根拠・見直し日を付ける（`business-direction.json` の `metrics[].target`）。値は運営者が決める。
- 判断の基準（下回ったら原因を調べる線）は、前年同期の実績があれば前年同期、無ければ直近 3 か月の同じ季節帯で置く。

## 追加する KPI

既存の 22 指標に無く、判断に効くもの。

| 指標 | 段 | 理由 | 元データ |
|---|---|---|---|
| インデックス率（全体・資格別） | サイト | 表示の前提。今は機械が見るだけで判断に使っていない | GSC URL 検査・index-coverage |
| Google 表示回数・平均順位（資格別） | サイト | クリックが小さい間は、表示と順位の方が改善の効きを早く示す | GSC |
| Bing ユーザー | サイト | 自然検索の大半。Google と混ぜない | GA4 source 別 |
| ココナラ評価平均・評価件数 | ココナラ | 購入の決め手が実績と評価（競合調査） | orders-log・プロフィール |
| 差額・追加購入の件数 | ココナラ | 客単価を上げる型（2 テーマ → 全 5 テーマ）の実績 | orders-log |
| KDP 既読ページ | KDP | 読み放題の収益はロイヤリティ明細だけで追えない | KDP レポート |
| 時間あたり受取額 | 運営 | 手間の割に稼げない商品を見分ける | 受取額 ÷ 作業時間 |
| 返金・苦情の件数 | 品質 | 教材不備を購入者側から拾う | note・ココナラ |
| リスト（LINE 友だち等）の人数 | 資産 | 検索に依存しない直接の届け先（[10_リスト化・自社オーディエンス戦略.md](./10_リスト化・自社オーディエンス戦略.md)） | LINE 公式 |

## 欠けている計測

目標を置く前に埋める。

- **受取額・費用・作業時間**: 全期間で未計測。頂点が測れていない。
- **演習開始・完了が 0**: イベントの発火か集計範囲の不具合を疑う。
- **ココナラ閲覧**: 30 日窓のため暦月の値が無い。暦月へ換算せず、30 日窓のまま別枠で持つ。
- **note の購入経路**: 購入が note 内の検索・回遊・外部のどこから来たかは分からない。月次の流入元（`note-traffic-fetch`）で記事 PV の経路までは見られる。
- **インデックス率**: 取得はしているが、資格別の率として集計していない。
