#### ③メンバーシップ 具体化構想（2026-06-09 / 2027 検証・まず建設部門で）

v6 の「③来年メンバーシップ ¥1,000/月」を具体化する構想。**検証スコープは技術士建設部門（1次＋2次）に限定**して小さく回し、成立確認後に資格横断（PWA 共通エンジンの総監ほか）へ広げる。3 本柱で構成する。

> [!important] 1級・2級土木は本節の対象外（非重複二刀流）
> 1級・2級土木の note 有料商品は、**買い切りマガジン（過去問・完成答案）とメンバーシップ「土木セコカン合格ラボ」（予想問題＋添削）の非重複二刀流として [content/note/1級・2級土木/noteコンテンツ計画.md](../../content/note/1級・2級土木/noteコンテンツ計画.md) に確定済み**（2026-06-12）。過去問＝買い切り／予想・添削＝会員で内容が重複しないため価格逆転が起きない。本節の「週1予想ドリップ＋PWA」概念のうち 1級・2級土木分は同書の会員ベース層に吸収した。本節は建設部門先行の cross-exam 概念を扱い、1級・2級土木向けの独立メンバーシップをここで再定義しない。**v6「買い切りの受け皿も残す」原則は 1級・2級土木でも維持**（過去問＝買い切り・同書 §2.2/§2.3）。PWA 演習基盤（資格別 PWA × 共通エンジン）自体は総監・1級・2級土木を横断する（柱2）。

- **柱1：週1回 予想問題ドリップ（drip エンジンの正体）** — v6 原則「小出し＝エバーグリーンなモート読み物」を**週次配信**として具体化。1次（基礎・適性・建設部門専門）＋ 2次必須Ⅰの予想問題を毎週 1 本。月4本で月額が構造的に正当化され、年間約50本がストック資産化する。既存の予想問題生成スキル資産を AI 生成＋運営者レビューの週次パイプラインに乗せる（1対多の build-once＝スケールする。添削の人的労働とは別物）。
- **柱2：過去問 PWA アクセス（一括開放）** — v6 原則「一括開放＝過去問 PWA」を会員特典に内包。会員は PWA を包含 or 会員クーポンで開放。通年利用される演習ツールが継続課金のフックになる。
- **柱3：1次試験を入口に（季節解約対策）** — 1次は受験者数が桁違い（技術士1次 約1.4万人、参考: 1級土木1次 約5.1万人）で通年学習。「1次→2次→部門→（将来）総監」の長期ファネルで会員 LTV を複数年に伸ばし、2次の7月一斉解約への依存を緩和する。専門 2次のフル模範解答は買い切り（科目パック ¥4,980）に据え置き、会員は分野横断で全員に効く部分（予想＋1次基礎＋PWA）に集中させる。

**この型が「メンバーシップ見送り」判断を覆す理由**: 過去の見送り理由（月額が乗る構造がない／季節一斉解約／科目排他で breadth が無駄／添削は非スケール）を、週1予想 drip（継続価値）・1次包含（通年＋長期ファネル）・予想＋PWA の分野横断性・build-once 供給（スケール）が一つずつ解消する。

**詰めるべき設計論点（2027 着手前）**:
1. **PWA の認証・権限基盤（最大の技術ボトルネック）** — 決済は Stripe、ログインは購入・同期時のメールマジックリンクまで確定。残るのは認証／DB／メール基盤の製品選定、Webhook の冪等性、購入復元、返金・削除である。無料演習とサイトの SEO 面は匿名のまま維持する。
2. **週次供給の持続性** — 52本/年を solo で回す予想問題パイプラインの確立（AI 生成＋運営者レビュー）。週次 cadence が切れると会員価値が崩れる。
3. **価格** — v6 既定 ¥1,000/月 を基準に、週1予想＋PWA＋1次の厚みで ¥1,480〜1,980 を再検討。買い切り（科目パック ¥4,980）とは grandfather（買い切り客は永久アクセス）で棲み分ける。
4. **着手順序の維持** — 今年は物販（科目パック）の実売 → 稼働済み PWA v1 の利用・購入意向計測 → 学習管理機能の買い切り pilot → 継続モートが成立した場合だけメンバーシップ、の順序を崩さない。

**検証ゲート（建設部門で先行）**: PWA v1 + 買い切り（②）が回り、週次予想パイプラインが 4〜8 週連続で破綻なく供給できることを確認してから ③ を起動する。

## 合格体験者ポジションの活用戦略

### なぜ決定的な差別化になるか

- 総監を受験する層は「合格した人のリアルな体験」を強く求める（情報整理記事より信頼される）
- 論文再現（特に自分の解答の全文公開）は**競合が絶対に作れないコンテンツ**（他人の論文は再現できない）
- サイト運営者＝**総監合格者**（土木系公務員〔発注者〕の退職者）という構造は E-E-A-T（経験・専門性・権威性・信頼性）の全軸を一気に埋める

### コンテンツ価値（運営者は総監合格済み）

> **2026-05-22 改訂（v4）**: 旧版は運営者が受験中で「受験前 → 試験直後 → 筆記合格発表後 → 最終合格後」と段階的に権威性が上がる前提だった。運営者の合格判明により全段階が完了済み。**「総監合格者による解説」が全コンテンツに適用可能**であり、解答再現・論文全文・受験記もすべて合格者の成果物として今すぐ提供できる。公開タイミングのみ買い手（受験生）の試験季節に合わせる。旧「失敗時のリスク管理」（筆記不合格時の不合格体験記へのピボット／合格を前提にしない運用）は、運営者合格により失効。

## 各チャネルの詳細

### 1. AdSense（Q2 即実装）

- AdSenseUnit コンポーネントを新規作成し、記事末尾に1箇所配置
- **実装状況**: layout.tsx にスクリプト追加 + コンポーネント作成が必要
- **CVR計算**: 月間3,000 PV × RPM ¥150 / 1,000 = ¥450/月（現時点）。UU成長に比例して増加
- **予想収益**: 悲観 ¥300/月 → 標準 ¥2,250/月 → 楽観 ¥15,000/月
- **備考**: 技術士総監 743 ファイルの公開化は完了済み。ポリシー審査の懸念は緩和されている

### 3. note 有料記事（基礎）: Q2 テスト販売

## 収益化戦略に対するフィードバックと改善案（2026-06-17）

### 1. 最大の技術的ボトルネック：「note決済 ⊗ PWA連携」のUXと手数料
* **懸念点**: noteはサードパーティへのリアルタイム決済Webhookや認証APIを公開していないため、PWAの演習権限を自動連動させるのが困難です。手動対応は運営負荷を高め、離脱の原因になります。
* **対策**: Stripe Payment Linksなどを直接PWAに埋め込む方が、手数料も安く（約3.6%）、購入直後に即アプリがアンロックされるシームレスなUXを提供できます。

### 2. 「TTS/自動量産SNS」と「合格者ブランド」のトーン＆マナーの不一致
* **懸念点**: YouTube/Instagramに無機質なTTS解説を大量投下すると、初見の受験生に「量産型アフィリエイトアカウント」と誤解され、運営者本人の信頼（E-E-A-T）が薄まるリスクがあります。
* **対策**: 自動生成動画であっても、「総監・建設部門合格の元公務員技術者が監修」といった看板（ロゴ、冒頭コピー、合格者のキャラクターアイコンなど）を前面に押し出し、デザインシステムをサイト同様「モダンシック」に統一して信頼性を担保します。

### 3. 「週次予想問題ドリップ」の持続性に対するバッファ設計
* **懸念点**: AI生成＋運営者レビューとはいえ、毎週その場で問題を作って出すのは、本業や生活の中で非常に高い負荷となります。配信の遅延は会員離脱に直結します。
* **対策**: あらかじめ最低8週分（2ヶ月分）のコンテンツストックを作り、予約投稿で自動配信する運用モデルを採用します。また、試験直前期（4〜7月）は頻度を上げ、試験後は下げるなどの可変頻度型にすることで、負荷を平準化します。

### 4. 資格別（土木 ⇄ 建設部門）のマネタイズモデル多様化による管理負荷
* **懸念点**: 土木（買い切りマガジン＋添削会員）と建設部門（週次ドリップ＋PWA）で課金・配信システムが異なり、個人での維持・管理負荷が乗算で増えてしていきます。
* **対策**: 建設部門で先行してモデルの有効性を確認した後は、決済プラットフォームや会員管理基盤（PWA共通エンジン、Stripe等）を共通化し、システムの分岐を避けるロードマップを意識します。

### 5. note決済 ⊗ 自前決済（Stripe）のハイブリッド住み分け戦略（追加検討）
* **ドキュメント系（模範解答、再現論文、PDF教材）**
  👉 **引き続き note で販売（推奨）**
  受験生（ゼネコンや公務員といったお堅い職種）にとって個人の直接決済サイトは心理的障壁が高いですが、noteであれば圧倒的な信頼感があり、キャリア決済やPayPayなどの手軽な決済手段によって高いCVR（コンバージョン率）を期待できます。また、特商法表記の義務や事務コスト（決済エラー対応等）も回避できます。
* **アプリ・ツール系（過去問PWAの機能アンロック、継続課金メンバーシップ）**
  👉 **自前決済（Stripe等）でアンロックする（2026-08-22 決定）**
  決済完了と同時にPWAのアカウント権限を自動でアンロックさせる必要があるため、API連携の難しいnoteではなく、PWAに直接Stripeチェックアウト等を埋め込む方がシームレスなUXと柔軟なサブスクリプション設計が可能です。
* **ハイブリッド運用の連携方法**:
  - PWAの無料ユーザーには、PWA内から直接noteの模範解答・解説へリンクを貼って送客します。
  - note 購入者への PWA 優待は、有料 pilot 成立後に別施策として検証する。共有可能なプロモコードを本番の購入権限に使わない。
