## 核心原則

**doboku-note は「土木・建設系の実務資格試験対策ハブ」として、受験者が『ここだけで合格できる』と感じるサイトを資格ごとに積み上げる。**

- **現在の整備対象**: 技術士総監（主力）・技術士建設部門・1 級/2 級土木
- **下書き整備中／将来候補**: コンクリート主任技士 / コンクリート診断士 / 行政書士（建設業許可等の法務系）

他分野のコンテンツは Obsidian で品質管理し、**別途の条件を満たした段階で Phase 2 以降に段階的に追加**する。拡張の判断は「現フェーズの資格で『ここだけで合格できる』体験が成立しているか」を前提とする。

### ★v3 追加原則（2026-04-13）: 合格体験者ポジション

**運営者本人が技術士総監 2 次筆記試験に合格済み**。学習過程・解答再現・論文構成が「他人が絶対に書けない一次情報」となり、情報整理屋中心の競合との決定的差別化を形成する。

- サイトの全コンテンツは「合格体験者による」という権威性で支えられる
- note 高単価商品（総監 ¥1,980〜9,800・建設部門 ¥2,480〜4,980）、SNS 送客、PWA 過去問アプリ（合格者設計・凍結中）は全てこのポジションを前提にする
- 運営者の試験勉強と doboku-note のコンテンツ整備は**一体運用**された（学習の副産物が無料記事、完成物が有料商品）

## スコープ：土木・建設系試験対策ハブ（段階的拡張）

| 試験 | 対象 | 優先度 | 状況（2026-07） |

## 4層アーキテクチャ

| 層 | 環境 | 役割 | 状態 |
|---|---|---|---|
| **ステージング** | Obsidian（~/obsidian） | 全分野の下書き・品質管理・体系化 | 非公開 |
| **プロダクション（Web）** | doboku-note（本リポジトリ） | 総監・建設部門・1 級/2 級土木を整備、段階的に拡張 | 公開 |
| **プロダクション（動画/SNS）** | YouTube / IG / X（TTS 量産） | 送客器（流入寄与は実測 1% 未満・要再評価） | 稼働 |
| **アプリ** | PWA 過去問アプリ | 各資格の過去問演習・学習管理（iOS から移管） | **凍結中**（着手条件 Web ¥15k は達成済み） |

### コンテンツの流れ

```
PDF / 書籍 / 公開情報 / 運営者の学習記録
  → Obsidian（下書き・体系化・品質チェック）
  → 公開判断（フォーカス試験か確認）
  → doboku-note（MD→MDX変換・SEO最適化・収益化導線）
  → SNS（TTS 量産による解説・送客）
  → note 有料記事（模範解答・論文・パック）
  → PWA 過去問アプリ（凍結中）
```

各層は相互送客する設計。SNS は doboku-note 記事への送客器、doboku-note は note 有料商品への送客器、PWA アプリは全レイヤの演習プラットフォーム。

### 一方通行の原則

- コンテンツは Obsidian → doboku-note の一方向で流れる
- doboku-note 側で直接コンテンツを作成・編集しない（緊急の修正を除く）
- Obsidian が唯一のソース・オブ・トゥルース

### ノートの frontmatter 規約

| フィールド | 型 | 説明 |
|---|---|---|
| `title` | string | ノートのタイトル |
| `tags` | list | 分類タグ（例: `#1doboku`, `#pe-cm`, `#concrete`, `#exam`） |
| `source` | string | 出典（PDF名、書籍名、URL等） |
| `status` | string | `draft` / `review` / `ready` / `published` |
| `target` | string | 公開先: `doboku-note` / `note-article` / `ios-app` / `none` |
| `exam-domain` | string | 試験の出題分野（例: `土工`, `コンクリート`, `施工管理`） |

| `date-modified` | date | 更新日 |

### status の定義

| status | 意味 | 次のアクション |
|---|---|---|
| `draft` | 下書き。内容が不完全 | 執筆を続ける |
| `review` | 内容は書けた。正確性・網羅性の確認待ち | `/check-mdx --rules staging` で品質チェック |
| `ready` | 品質チェック通過。公開可能 | `/promote-to-site` でdoboku-noteに移動 |
| `published` | doboku-noteに公開済み | 更新がある場合のみ再promote |

## doboku-note（プロダクション）の設計

### Phase 1（1級土木 + 技術士総監）に集中する理由

1. **ユーザー体験**: 受験者が「ここだけで合格できる」と感じる一貫した体験
2. **検証速度**: 7月試験（1級一次）・11月試験（技術士一次）に向けた短期フィードバック
3. **資産の集中**: 技術士総監（743 ファイル）を中核に、建設部門・1 級/2 級土木へ最適化
4. **導線の明確化**: サイト→note有料記事→iOSアプリ、全て同じユーザーに向く

### コンテンツアーキテクチャ

公開 URL は検索意図別に `/exam/`・`/practice/`・`/standards/`・`/topics/` へ分ける。一方、原稿の論理 slug と2つのファイル命名規約は維持し、既存 1,100 ページ超を機械的に移動しない。公開経路への変換は `src/lib/content-routes.ts` が一元管理する。

#### Convention A: 個別ファイル名（civil-construction-1 で使用）
```
content/site/civil-construction-1/guide/strategy.mdx
  → /exam/civil-construction-1/guide/strategy

content/site/civil-construction-1/textbook/schedule-management/article.mdx
  → /exam/civil-construction-1/textbook/schedule-management
```

#### Convention B: article.mdx（pe-comprehensive-management で使用、新規コンテンツ推奨）
```
content/site/pe-comprehensive-management/followership/article.mdx
  → /exam/pe-comprehensive-management/keywords/followership
```

カテゴリ・タグは frontmatter で管理。ナビバーは `src/config/categories.json` で定義。

### サイト構成（Phase 1）

| ナビバー項目 | 対応試験 | 内容 |
|---|---|---|
| **1級土木施工管理技士** | 1級土木 | 試験ガイド・第1次・第2次・土木知識・施工管理 |
| **技術士（総合技術監理）** | 技術士総監 | 試験ガイド・試験セクション・過去問・論文対策 |

#### Phase 1 外コンテンツの扱い

| コンテンツ | ファイル数 | 対応 |
|---|---|---|
| 技術士（建設部門） | ~30 | Phase 2 候補。ナビバー非表示で SEO インデックスは維持し、Phase 2 着手時に整備 |
| 2級土木 | ~20 | Phase 3 以降候補。ナビバー非表示で SEO インデックスは維持 |
| 河川・水理学 | 67 | 1級土木の出題範囲に関連する部分のみリンク |
| 道路法等 | 98+ | ナビバー非表示 |

**非表示 ≠ 削除**。ページは残し SEO インデックスを維持する。Phase 2 着手時に該当コンテンツをナビバーへ昇格させる。

## コンテンツ作成ガイドライン

### URL設計：検索意図別の領域 URL

公開コンテンツは利用目的で分ける。資格合格を目的とするページは `/exam/`、施工実務の解説は `/practice/`、公的仕様書と参考資料は `/standards/`、複数領域をつなぐハブは `/topics/` とする。時事性のある運営記事を追加する場合に限り `/blog/` を使う。

```
試験ガイド       → /exam/{qualification}/guide/{slug}
過去問           → /exam/{qualification}/primary/{slug}
施工実務         → /practice/{slug}
公的仕様書       → /standards/{agency}/{document}/{part}
横断トピック     → /topics/{topic}
```

原稿内では従来の論理 `/docs/{slug}` を互換参照として使用でき、レンダリング時に正規 URL へ変換する。旧公開 URL も同じ正規 URL へ 1 対 1 の 301 リダイレクトを設定し、リンク評価とブックマークを継承する。詳細は [05_情報アーキテクチャ.md](./05_情報アーキテクチャ.md) を参照。

### frontmatter 必須フィールド

```yaml
---
title: "ページタイトル"
description: "50〜160文字の説明"
category: "civil-construction-1"  # 試験または分野
tags: ["guide", "primary"]         # 分類タグ
published: true                    # false=下書き
---
```

### category の値（Phase 1）

| category | 説明 |
|---|---|
| `civil-construction-1` | 1級土木施工管理技士 |
| `pe-comprehensive-management` | 技術士総監 |
| `civil-general` | 両試験共通の土木基礎 |
| `construction-management` | 両試験共通の施工管理・法規 |
| `keywords-law` | 補助用キーワード |

### tags の例

- `guide` — 試験ガイド・学習方法
- `primary` — 第1次試験対策
- `secondary` — 第2次試験対策
- `past-questions` — 過去問
- `keyword` — キーワード解説

### slug 命名規則

- 英数字 + ハイフンのみ
- 試験を prefix に: `civil-construction-1-{topic}`, `cem-{topic}`
- 深さ最小限: `posts/{slug}/article.mdx`（img/配下のみ例外）
