# 自治体の土木担当・コンクリート シリーズの方針（2026-10）

最終更新: 2026-10-13（骨子と根拠の配線・法令を起点にした回遊を追加）

## 結論

資格試験・教科書とは別の軸で、読み物のシリーズを `/practice/` に置く（2 つと、コンクリートから分けた建設材料の骨組み）。`/blog/` は時事だけの置き場なので使わない（[05_情報アーキテクチャ.md](./05_情報アーキテクチャ.md)）。

- **A「自治体の土木担当」**: 自治体に土木職で入った人・異動した人に向けて、道路・河川の管理と、発注者としての事業の進め方を書く。運営者の経験（元自治体の土木職）がいちばん生きる領域で、競合にも空白がある（[13_土木公務員SEO戦略2026-08.md](./13_土木公務員SEO戦略2026-08.md)「会計検査／設計変更／臨時協議」の行）
- **B「コンクリートの実務」**: コンクリートに関わるすべての人（発注者・設計者・生コン工場・施工者・維持管理者）に向けた 33 章。手元の 5 冊（コンクリートの基本・主任技士の教科書 2 冊・診断士の教科書・建設材料の基本）の全項目を論点として使い、章立ては doboku-note 独自に組む。既存の試験の教科書記事と実務記事をつなぎ、空いている章だけを足す（2026-10-13 運営者判断で入門から全体へ広げた）
- **建設材料**: 建設材料の基本のうちコンクリート以外の章（鋼材・アスファルト・高分子・木材と石材）の行き先。骨組み（5 項目）だけを置く

> [!important] 着手の条件
> A は 13 番「非受験層を受験者へ育てる導線」の ① 入口記事に当たる。入口記事を増やすかは EXP-012 の判定（事後窓の終わり 2026-11-26）で決めると決めてある。それまでは目次（DN-0719）と参考文献の台帳への登録だけにする（2026-10-13 運営者判断）。B の新しい記事も同じ時期にまとめて判断する。
> 2026-10-15 運営者判断で、A の第 1 波（A-08 占用・A-14 河川区域の許可・A-19 里道と水路）は判定を待たずに書き、同日に公開した。39 章の骨子を一次資料で照合し確認済みにしたため。続けて同日、第 2 波（道路・河川の管理 8 章）と第 3 波（事業を進める 8 章）も判定を待たずに書くと決め、同日に 16 本を公開した。さらに同日、残りの第 4 波（新規 16 章・補強 4 章）も書いて公開し、シリーズを完結させると決めた（DN-0742）。EXP-012 の判定と公開 28 日の計測は、シリーズの改善と B の判断に使う（DN-0719）。

> [!warning] 経験を書く記事

## 構成の方針

記事の一覧（目次・計画・根拠の参考文献 id・第何波か）はシリーズ企画の台帳 `config/content-series.json`（シリーズ id `municipal-civil-engineer`・`concrete-practice`・`construction-materials`）が持ち、状態（公開・下書き・未着手）は記事の実体から出す。管理画面はサイト＞シリーズ企画（`/content/series`）、検査は `npm run check-content-series`（[todo-standards.md](../../.claude/knowledge/reference/todo-standards.md) §1-2）。着手の判断は backlog の DN-0719。公開した記事のシリーズでの並びは `src/config/category-curriculum.json`（`civil-practice`）が正本になる。本書には一覧を写さない。

- **A**: 入口 → 仕事の土台（法令の読み方・国と自治体の役割・予算と財源）→ 道路を管理する → 川と海岸を管理する → 法定外公共物（里道・水路）→ 事業を進める（計画と事業評価から会計検査まで、事業の進む順）→ まちをつくる（都市計画・開発許可・区画整理・公園・下水道）→ 災害に備える → 仕事の進め方、の順に、運営者の業務の流れから組む。配属直後に窓口で当たる公物の管理を先に、法令の読み方と財源をその前提に置く（2026-10-13 に土木行政の教科書の目次で抜けを洗い出し、42 章へ組み直した）。市販の解説書や、着想のきっかけになった市販書（『自治体の土木担当になったら読む本』・土木行政の教科書）の章立て・項目の並びは写さない（[reference-sources-policy.md](../../.claude/knowledge/reference/reference-sources-policy.md) §5）。入口はハブ記事 1 本と、工種別ノートに足すブロック。既存の発注者実務の記事（発注方式・入札・工事検査・設計変更・会計検査・供用開始など）は書き直さず、シリーズに組み込んで足りない側面だけを補う
- **B**: 部を「誰が何を決めるか」で分ける（入口 → 知る〔材料と性質〕→ 決める〔発注者・設計者〕→ つくる〔生コン工場・製品〕→ 打つ〔施工者〕→ 確かめる〔検査〕→ 守る〔維持管理〕→ これから）。5 冊はどれも「材料 → 製造 → 施工 → 劣化」か試験の分野の順なので、どの本の章立てもなぞらない。教科書記事と同じ内容を入門の名前で書き直さず、既存記事で足りる章はリンクで組み込む。入口はハブ記事と、工種別ノートの既存ブロック `concrete` を読む順に並べ替えたもの。市販の本を下調べに使うときも、原文を渡さない brief 方式（[content-taxonomy.md](../../.claude/knowledge/reference/content-taxonomy.md) §7）で書き、逐語の検査を通す

## 章の骨子と根拠の配線（A）

A は本から出発しない。章（仕事の場面）から出発し、**章 → 論点 → 根拠** の向きでつなぐ（2026-10-13 運営者判断）。B の「本の全項目を章へ仕分ける」台帳（下の節）は A には使わない。試験の記事への展開（書籍の網羅）とも関係させない。

- **骨子**: 章ごとに、読者と場面・論点（自分の言葉で 30 字以内）・既存記事との分担・図の候補を 1 ファイルに書く。置き場は `content/sources/series/<シリーズ id>/<項目 id>.md`（制作の入力の置き場）。市販書籍の見出し・文は入れない（本の項目は id だけで指す）。運営者が確かめたものを「確認済み」とし、執筆はそれを brief として使う
- **根拠**: 論点ごとに 1 つ以上ぶら下げる。集め方は Web の検索（e-Gov・国交省・白書・都道府県や市の公開資料）を先にし、本は補助にとどめる（2026-10-13 運営者判断。手元に無い市販書の PDF は取り寄せない）。種類と指し方は次のとおり
  - 法令の条: 参考文献の台帳の id ＋ 条（`road-act#第32条`）。リンクは e-Gov の条（法令 ID は台帳の `egov.lawId`）
  - 国の通知・要領・指針、白書・統計: 台帳の id（無ければ URL）＋ 版・頁
  - 都道府県・市の公開資料: URL。記事では「例として ◯◯市の手引き」と書き、全国の決まりのようには書かない
  - 本の項目: Drive の候補表がある本の `本 id/項目 id`。補助の扱いで、同じ項目を複数の章で使ってよく、使わない項目があっても問題にしない
  - 土木奥義: 上の「根拠資料の扱い」の 3 区分に従う（公開の法令・基準だけを根拠にする）
- **検査**: どの論点にも一次資料（法令・要領・白書）が 1 つ以上あること、台帳の id と本の項目 id が実在すること、URL だけの根拠の数（記事を書く前に台帳へ入れる）を `check-content-series` が見る。管理画面のシリーズ企画に、章ごとの論点の数・一次資料のある割合・確認済みかを出す
- **事実**: 確かめた資料と値はシリーズの事実ファイル（`.claude/knowledge/reference/` にシリーズごとに 1 つ）へ貯め、執筆担当はまずそこを読む

## 法令を起点にした回遊

記事は条文へ、条文から記事へ行き来できるようにする。法令の分類はタグで作らず、記事の e-Gov へのリンクから集める（タグは付け忘れと手入れが要る）。

- 法令 ID・条・改正の施行日の正本は `config/egov-laws.json`（e-Gov 法令 API の写し）。`npm run egov-laws` が記事のリンクと台帳の法令を照合し、`--drift` が写しより後の改正とリンクする記事を出す
- 記事の末尾に「この記事の根拠法令」を、リンクから自動で並べる
- 法令ページ（法令の説明・よく引かれる条・資格試験と実務に分けた記事の一覧・最新の改正の施行日）は新しい領域 `/laws/<参考文献の id>` に置き、5 本以上の記事が引く法令のうち説明を書いたものだけを公開する（2026-10-13 運営者判断・[05_情報アーキテクチャ.md](./05_情報アーキテクチャ.md)「法令ページ」）

## 書籍の全項目の割り当て

5 冊の全項目（1,075 項目＝書籍の網羅の候補表の単位）を、シリーズの章（`シリーズ id/項目 id`）か、シリーズの外の記事（試験の小論文・出題傾向のページなど）か、使わない理由（前付け・索引・図の説明文・本の中の重複・過去問の設問）に割り当てる。台帳は `config/content-series-basis.json` で、項目 id だけを持ち、市販書籍の見出しは持たない（見出しは Drive の候補表）。

- 件数は書籍の網羅の要約（`.claude/state/book-coverage.json` の textUnits）と一致させる。Drive がある端末では、候補表の id とちょうど一致するかも `npm run check-content-series` が見る
- 試験の範囲外として判定した項目（工事の段取り・生コン工場の経営・セメントの歴史・これからの技術・品質意識の移り変わりなど）も、このシリーズでは章に入れる。著者の意見は論点だけを使い、意見そのものはなぞらない
- 本の判定をやり直したら（`audit-reference-book-coverage`）、割り当ても見直す

## 図と写真

図と写真は、本の頁の上で文章と並んでいる。そこで、文章（章）と図を**本の頁**でつなぐ（2026-10-13 運営者判断）。

- **つなぎ方**: 書籍の全項目の割り当て（`config/content-series-basis.json`）が、項目ごとに本の頁（`pages`・書籍の台帳 book-manifest の頁 id）を持つ。項目 → 章の割り当てと合わせて、章 → 頁 → その頁の図がたどれる。図の一覧は別に写さない
- **画像は本から切り出す（クロップ）**: 頁の画像（Drive vault の `<書籍>/pages/`）から図・写真を切り出し、`<書籍>/crops/<頁>_<図の id>.png` に置いて `npm run record-reference-book-artifacts` で書籍の台帳へ登録する。図の無い頁は `cropStatus` を `not-needed` にする。章ごとの状態（頁の数・切り出し待ち・切り出した図）は `npm run check-content-series` と管理画面のシリーズ企画に出る
- **Codex への渡し方**: `npm run check-content-series -- --crop-jobs --series concrete-practice` が、切り出しの終わっていない頁の一覧（頁の画像の場所・置き場の名前・登録のコマンドつき）を出す。同じ頁を複数の章で使うときも作業は 1 回
- **写真は、切り出した写真を元に AI で描き直す**（運営者の指示・2026-10-13。条件は 2026-10-15 に決定）。元の写真を AI に渡して描き直すが、構図・画角・背景・配置はなぞらず、元の文字・図番・注記は写さない。元は `provenance` の `basedOn` に記録し、監査で元と見比べる。条件と手順の正本は [image-policy.md](../../.claude/knowledge/reference/image-policy.md)「本の写真を元に描き直す」
- **図**: 書籍の図は流用しない。切り出した図は、自作の SVG（create-svg）の題材・下敷きとしてだけ使う
- **計画**: 項目の `visuals` に「図か写真か・何を見せるか・元にした切り出し図（`crop`）・置き場（`figKey`）」を書く。使わない切り出し図は `skip` に理由を書く
- **進み具合（画像ごと）**: 段階は手で書かず、切り出し図・画像の実体・AI 画像の台帳・記事の本文から出す。切り出し済み・未作成 → 作成済み・未監査（写真）→ 作成済み・記事に未配置 → 記事に配置済み（ほかに未着手・切り出し図が無い・監査で不合格・使わない）。章の頁にあるのにどの計画にも結びついていない切り出し図は「未対応」として数える
- **管理画面**: サイト＞シリーズ企画の各章の「画像」の列（頁・切り出し図・段階ごとの数）と、`?item=<シリーズ id>/<項目 id>` の詳しい画面（計画ごとの段階・元の切り出し図の縮小画像・章の頁の切り出し図・切り出し待ちの頁の画像へのリンク）。Drive の画像は `/media/book/` から出す（Drive の台帳に載る頁画像・切り出し図だけ）
- **Codex への渡し方（作成から配置まで）**: `-- --visual-jobs` が、記事に配置済み・使わない以外の計画を、段階ごとの次の作業つきで出す

## やらないこと

- 県の内部資料や、公開を確かめられない資料を根拠にする
- 市販の解説書・市販書の章立てや項目の並びを写す
- 試験・教科書の記事と同じ内容を、入門の名前で書き直す（B は既存記事へのリンクで足りる）
- `/blog/` に置く
