# 領域モデル

収益を広げる打ち手（計測と改善、SEO、note などの商品展開、動線、品質、SNS、アフィリエイト）は視点が多く、並べるだけでは優先順位がつかない。そこで事業を 8 つの**領域**に分け、管理画面のサイドバー、バックログ、スケジュール、スキルとエージェント、文書を同じ領域で束ねる。領域の一覧の正本は `.claude/config/domains.json`（機械が読む）で、この文書はその考え方を人向けに書く。

## 8 つの領域と並び

役割は「決める → 売る → 集める → つくる → 支える」の5つで、サイドバーもこの順に並ぶ（管理画面の 戦略 ＞ 事業の分類 に一覧）。

| 領域 | 役割 | 管理するもの |
|---|---|---|
| 戦略 | 決める | 方針と KPI、資格ポートフォリオ、週次・月次の判断、競合 |
| 計画 | 決める | 年間ロードマップ、スケジュール、バックログ |
| 商品 | 売る | 品揃えと販売チャネル（note・ココナラ・Kindle・アプリ）、売上、商品品質、商品への動線 |
| アフィリエイト | 売る | 成果、掲載先（サイト・note・SNS）、提携と案件 |
| サイト | 集める | 記事と過去問の品質、SEO、サイト内の動線、計測（GSC・GA4・PSI）、図版と OGP |
| SNS | 集める | 投稿、各 SNS、動画、キャラクター素材 |
| 教材 | つくる | 教材から記事・図解・SNS・商品への展開、原典の正確さ |
| 管理 | 支える | 文書、品質検査、エージェントとスキル、自動化、CI |

> [!note] 横断する視点は領域に割り振る
> 「計測・記録・改善」「品質」「動線」は独立した領域にしない（持ち主が曖昧になる）。数字は各領域で見て判断は戦略の週次・月次レビューで行う。品質は対象の領域（商品品質は商品、記事品質はサイト、原典は教材）、検査の仕組みは管理。動線は送客先の領域（サイト→note は商品、サイト→アフィリエイトはアフィリエイト）。

## 何を領域で束ねるか

| 対象 | 領域の書き方 | 検査 |
|---|---|---|
| バックログのカード | タグ行の `[領域:商品]`（全カード必須） | `npm run check-backlog-schema` |
| スキル・エージェント | frontmatter の `domain: product` | `npm run check-domains` |
| 文書（`docs/`・作業マニュアル） | `domains.json` の `documents`（パス接頭辞） | `npm run check-domains` |
| スケジュール | 予定の領域（バックログの予定はカードの領域） | `schedule-events.mjs` |
| 管理画面 | サイドバーのグループ＝領域。グループ名から領域の概要へ | — |

ファイルの置き場は動かさない。スキルのディレクトリやバックログの既存タグは「作業の種類」で、領域とは別の軸として残す。

## 管理画面のサイドバー（全領域共通の規則）

サイドバーは「その領域で人が判断するときに開く画面」だけを置く。画面の一覧・種類・規則の正本は `domains.json` の `nav`・`navKinds`・`navRules` で、管理画面はそこから描く（Nav に直書きしない）。

| 種類 | 何のための画面か | 例 |
|---|---|---|
| 品揃え・一覧 | 何があり、何が足りないか | 商品ラインナップ、掲載先、記事、教材一覧 |
| 成果・計測 | 効いたか | 売上、アフィリエイトの成果、GSC・GA4 |
| 要対応・状態 | 人が手を打つもの | 販売状態、投稿状況、提携・案件、バックログ |
| 方針 | 判断の基準 | 事業方針と改善、共通方針 |
| 素材 | 作業に使うもの | 記事図版、OGP、キャラクター素材 |

- **チャネル・SNS はサイドバーの枝にしない**。note・ココナラ・Kindle は「販売状態」、X・Instagram・YouTube は「投稿状況」のタブ（節）にする。資格は「商品ラインナップ」の枝、教材は「教材一覧」の棚。
- **原稿・画像・ファイルの作業場はサイドバーに出さない**。判断画面の上のリンクか、管理 ＞ すべて から開く。
- 既存の URL は変えない（ブックマーク・手順書の参照を壊さない）。新しい画面は `/<領域 id>/…` に作る（例: `/product/status`）。
- 画面の種類が navKinds に無い、または URL の画面が実在しない項目は `npm run check-domains` が止める。

## 優先順位とスケジュール

優先順位は「収益への近さ × 試験の時期」で決める。売れる時期は試験日の前なので、年間の骨組みは資格ごとの試験期（日付の正本は `exam-calendar.json`）から逆算し、年間（試験期 × 領域）→ 月間（領域ごとの重点 1〜3 件）→ 週間（バックログのカード）の順に落とす。年間計画は `.claude/todo/annual.md`。
