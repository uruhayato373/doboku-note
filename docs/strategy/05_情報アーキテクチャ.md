# 情報アーキテクチャ

> [!important] 真実源
> 公開 URL、旧 URL の扱い、公的資料のインデックス方針、タグ回遊の設計は本書を真実源とする。ルート変換の機械可読な実装は `src/lib/content-routes.ts`、公的資料の索引は `src/lib/standards.ts`、横断トピックは `src/config/topics.json` に置く。

## 目的

doboku-note を「資格試験対策だけのサイト」から、資格学習・土木施工実務・公的基準を相互に行き来できる土木技術者向け知識基盤へ拡張する。同時に、検索エンジンと利用者がページの目的を URL だけで判断できる構成にする。

## 公開領域

| 領域 | URL | 主な検索意図 | 掲載内容 |
|---|---|---|---|
| 資格試験 | `/exam/` | 合格したい、過去問を解きたい | ガイド、教科書、過去問、キーワード |
| 施工実務 | `/practice/` | 現場判断や施工方法を知りたい | 土木技術者の基礎知識、施工実務解説 |
| 公的基準 | `/standards/` | 原文を確認したい | 共通仕様書、土木工事必携、実務参考資料、解説ガイド |
| 横断トピック | `/topics/` | ある技術テーマをまとめて学びたい | 試験・実務・基準を束ねる編集ハブ |
| ブログ | `/blog/` | 更新情報や時事解説を読みたい | 将来の時事性・運営性コンテンツだけ |
| ツール | `/tools/` | 計算・判定を行いたい | 現場支援・受験支援ツール |

`/blog/` は汎用記事の逃げ場所にしない。長期利用する技術解説は `/practice/`、資格固有の解説は `/exam/` に置く。

## URL の生成規則

```text
/exam/{qualification}/{group}/{slug}
/practice/{slug}
/standards/guides/{slug}
/standards/{agency}/{document}/chapters/{編-章}
/standards/{agency}/{document}/{part}
/topics/{topic}
```

原稿ファイルは `content/site/` に維持し、既存の論理 slug を変更しない。論理 slug から公開 URL への変換は `src/lib/content-routes.ts` に集約する。これにより、1,100 ページ超の本文・画像参照・バックリンクを一括改名せず、公開 URL だけを安定して管理できる。

旧 `/docs/{slug}` と `/category/{slug}` は、対応する新 URL へ 1 対 1 の 301 リダイレクトを置く。リダイレクト連鎖を作らず、正規 URL・OG URL・構造化データ・内部リンク・RSS・sitemap はすべて新 URL を直接出力する。

## 公的資料の公開方針

国土交通省各地方整備局等の公開資料は、取得元 URL・資料名・対象年度・ページ対応を保持した全文文字起こしとして公開する。原 PDF は Git に収録せず、検証済み Markdown と索引だけを公開資産へ生成する。

公開は 2 層に分ける。**原典照合用の逐語文字起こし**（`content/site/standards-library/`・PDF 50 ページ単位の分冊・紙面の改行と空白とページ番号を保持）は不変データとして残し、そこから生成した**構造化章記事**（`content/site/standards-articles/`・`/standards/{agency}/{document}/chapters/{編-章}`）を読者と検索の主導線にする。章は PDF の分冊位置ではなく原本の編・章で切る（分冊境界をまたぐ章があるため、全分冊をページ順に結合してから解析する）。逐語分冊のページは削除せず「原典PDFページで確認する」導線として残し、章記事を公開した文書では `noindex, follow` へ下げてサイト内検索の対象からも外す（同じ内容で 2 系統のインデックスを作らない）。生成と検査は `npm run build-standard-articles` と `npm run check-standard-articles`、設計の真実源は `scripts/lib/standards-structure.mjs` 冒頭。

同一の共通仕様書を 9 機関が公開しているため、章記事を検索インデックス対象にするのは 1 機関だけとする（既定は近畿・機械可読な真実源は `.claude/config/standards-structure.json` の `canonical.commonAgencyId`）。他機関の章記事は読める状態を保ったまま `noindex, follow` にし、原本 SHA-256 が完全一致する重複文書には章記事を生成しない。

各ページには次を表示する。

- 出典機関と原資料へのリンク
- 公共データ利用規約に基づく出典表示
- 文字起こし・整形を行った二次著作物である旨
- 原資料との差異があり得ること、実務では最新版原本を確認する旨
- 判読不能箇所を推測で補わない注記

地域間で本文がほぼ同一の共通仕様書は、近畿地方整備局版を代表的なインデックス対象とし、重複する他地域版の全文パートは `noindex,follow` とする。地域固有の必携・提出様式・施工管理資料はインデックス対象にする。資料索引と資料概要は常にインデックス対象とし、原本への到達性を確保する。

## タグと回遊

タグから無制限に一覧ページを生成しない。検索需要と記事群が確認できる編集済みトピックだけを `/topics/{topic}` として公開する。各トピックは次の三方向を結ぶ。

1. 資格試験の教科書・過去問
2. 施工実務の解説
3. 公的仕様書・必携の該当資料

記事フッターの関連記事とタグ導線も正規 URL を使う。ページ数だけを増やす薄いタグページや、パラメータ付きのファセット URL は生成しない。

## sitemap・GSC 移行規約

サイトマップには正規 URL とインデックス対象ページだけを掲載する。旧 `/docs/*`、301 転送元、`noindex` の文字起こし重複ページは掲載しない。公開前後は次を検証する。

1. 全旧 URL に 1 回で正規 URLへ到達する 301 がある
2. 正規 URL の canonical・OG URL・構造化データが一致する
3. sitemap に転送元・404・`noindex` が混入していない
4. 内部リンクが旧 URL を経由しない
5. GSC では新 sitemap を送信し、移行後の 404・リダイレクト・クロール済み未登録を継続観測する

GSC の URL 検査やインデックス登録リクエストは、サイト側の検証が完了した後に承認ゲートを通して行う。流入が少ない段階でも、旧 URL の評価継承を捨てず、恒久転送と canonical を維持する。

## 変更時の完了条件

- `npm run build-public-redirects` が Cloudflare Pages の上限内で完了
- `npm run build` が成功
- MDX・SEO meta・sitemap・内部リンク検査が成功
- 主要領域を desktop/mobile と light/dark で目視確認
- 公開後に本番 SSR と主要 301 を確認
