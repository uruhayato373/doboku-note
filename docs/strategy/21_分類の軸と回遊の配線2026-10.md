# 分類の軸と回遊の配線（2026-10）

最終更新: 2026-10-22

## 結論

記事を「資格」「分野・工種」「施工管理・マネジメント」「法令」「読み手・立場」の 5 つの軸で引けるようにし、どの記事の末尾からも、同じテーマ・同じ法令を**ほかの資格や実務がどう扱うか**へ移れるようにした。規則・検査・運用の正典は [content-taxonomy.md](../../.claude/knowledge/reference/content-taxonomy.md) §6。

| 軸 | 何で表すか | ハブ | 記事の末尾 |
|---|---|---|---|
| 資格 | カテゴリ（`categories.json`） | `/exam/{資格}`（記事一覧の後ろに「テーマから探す」） | カテゴリのナビ・もくじ（既存） |
| 分野・工種 | テーマ（`topics.json` の `facet: field`）11 件 | `/topics/{slug}` | 「この記事のテーマ」 |
| 施工管理・マネジメント | テーマ（`facet: management`）9 件 | `/topics/{slug}` | 「この記事のテーマ」 |
| 法令 | 法令ごとのページ（`/laws/{法令}`・24 本）と、法令の解説を兼ねる記事（`explainsLaw`・61 本）と、テーマ「関係法令」（`facet: law`）と、本文の e-Gov へのリンク | `/laws`（テーマ別の法令ページと「法令と分野の対応」）・`/topics/safety-laws` | 「この記事の根拠法令」に、法令ページ・同じ法令を扱う記事・関わるテーマ |
| 読み手・立場 | テーマ「自治体の土木職」（`facet: audience`・タグ `地方公共団体`） | `/topics/municipal-civil-engineers` | 「この記事のテーマ」 |

法令と分野・立場は多対多で結ぶ。記事が本文で引く法令と記事のテーマを掛け合わせ、そのテーマの記事の 2 本以上が引く法令とテーマを結ぶ（道路法 → 自治体の土木職 25・関係法令 13・道路 11、河川法 → 自治体の土木職 14・河川 12）。テーマのページには「このテーマの記事が引く法令」を、関係法令のページには法令ごとに関わるテーマを並べる。

法令ページは、法令の仕組みの解説（一次資料で照合済み）の後に、関わるテーマ・関係する国の計画・施策・審議会・よく引かれる条・この法令を扱う記事（実務と資格別）を自動で並べる。最初の 7 本は道路（道路法・道路交通法）と河川・砂防（河川法・水防法・特定都市河川浸水被害対策法・急傾斜地法・土砂災害防止法）。2026-10-22 に、5 本以上の記事が引く法令を 17 本足した（労働安全衛生法・建設業法・地方自治法・入契法・品確法・労働基準法・測量法・環境基本法・環境影響評価法・都市計画法・下水道法・建設リサイクル法・災害対策基本法・土地収用法・技術士法・地方財政法・個人情報保護法）。法令名の行き先は、法令ページ → 法令の解説を兼ねる記事（総監の用語「大気汚染防止法」・1級のテキスト「港則法」など、frontmatter の `explainsLaw`）→ e-Gov の順に決まる。

国の計画・施策・審議会（道路の中長期計画、社会資本整備審議会 道路分科会・河川分科会の答申、流域治水など）は、1 件ずつのページを作らず、台帳 `config/policy-registry.json`（79 件・全 22 テーマに 2 件以上）に「所管・決定日・期間・根拠法令・テーマ・一次資料の URL」を持たせ、法令ページとテーマのページの「制度の地図」に載せる。計画の名前だけで検索する読み手は少なく、法令・分野の文脈で読むほうが役に立つため。

テーマのページには、そのテーマ（分野・立場）に合う有料教材を資格をまたいで並べる（`topics.json` の `products`。例: 道路＝建設部門 道路・総監 自治体道路担当・道路橋梁コンサル・1級／2級の経験記述・RCCM 道路）。

## なぜこの形か

- **資格はテーマの軸にしない**。資格はすでにカテゴリとして URL・ナビ・もくじを持つ。テーマのページが記事を資格ごとに区切って見せることで、「同じ技術を別の資格ではどう問うか」を 1 枚で読める。
- **法令はタグにしない**。記事が引く法令は本文の e-Gov へのリンクから機械で集まる（2026-10-21 時点で 264 本・214 法令）。タグにすると付け忘れと手入れが要る（[05_情報アーキテクチャ.md](./05_情報アーキテクチャ.md)「法令ページ」）。
- **分野のテーマは基準を満たすまで検索に出さない**。2026-09 の棚卸しで港湾・鉄道などをテーマ外にした理由（実務・基準の記事が無い）は、薄いハブを検索に出さないためだった。今回はテーマを作って記事末の回遊には使い、検索に出すかは昇格基準（三方向のうち 2 方向）で分けた。基準を満たした 5 つ（橋梁・鋼構造／港湾・空港・海岸／ダム・電力土木／上下水道／都市・地域計画）を公開ハブ、実務・基準が 0 の鉄道を育成中（noindex）にした。
- **立場はテーマの軸にし、実務記事の本文には有料教材を出さない**。自治体の土木担当シリーズ（実務 50 本）と、試験側の土木公務員向けの記事（9 本）と、総監の自治体ペルソナの模範論文（10 マガジン）は、同じ読み手に向けたものなのに互いにつながっていなかった。タグ `地方公共団体` を試験側にも付けて 1 つのテーマに束ね、テーマのページに有料教材を並べた。実務記事の本文に試験文脈を入れない規約と、記事末の橋渡しカードを 1 枚にする方針（13_土木公務員SEO戦略）は守る。記事末の橋渡しカードは、自治体の土木担当シリーズでは施工会社向けの選択肢を技術士に替え、立場のテーマへのリンクを添えた（EXP-012 の計測中だが、運営者の判断で配線を優先した）。
- **法令ページは、多くの記事が引く法令から作り、解説は AI が書いて一次資料で照合する**（2026-10-21 運営者の判断。05_IA「法令ページ」）。法令の名前だけのページは薄いハブになるので、解説（目的・仕組み・管理者・許可や届出・試験と実務での出方）を書いた法令だけを公開し、まず道路・河川で型を作ってから広げる。
- **法令ページと同じ法令を解説する記事は作り分けない**。総監の用語には「男女雇用機会均等法」「労働契約法」のように法令そのものを 1 本で解説する記事が 50 本以上ある。同じ法令の法令ページを別に作ると検索で食い合うので、法令ページを作らず、その記事を法令名の行き先にした（`explainsLaw`）。法令ページを作らない法令（民法・日本国憲法など）は、理由を `content-taxonomy.json` の `lawPages.skip` に残し、月次の報告の候補から外す。
- **主題タグは必ず行き先を持つ**。テーマに属さない主題タグが 27 種あり、付けても回遊に乗らなかった。15 種をテーマへ入れ、2 種は class を直し（専門土木→資格・科目、参考資料→学習の型）、残る 10 種には属さない理由（読み手・組織・出典・手法・広すぎる語）を書いた。新しい主題タグは、行き先を決めないと登録できない。

## 数字（2026-10-21・公開 1,430 本）

| 項目 | 前 | 後 |
|---|---|---|
| テーマ | 15 | 22（公開ハブ 21・育成中 1。有料教材の枠つき 21） |
| テーマへの所属が要る記事（993 本）のうち所属なし | 21 本（判定の仕組みが無く、数えていなかった） | 0 本（ラチェットで増やさない） |
| 記事型のタグ（guide など）しか持たない記事（過去問・キャリアを除く） | 12 本 | 0 本（ラチェットで増やさない） |
| 関連記事のうち他の資格・実務の割合 | 2% | 34% |
| 関連記事のどこからも選ばれない記事（過去問・キャリアを除く） | 705 本 | 38 本 |
| 関連記事が出る記事 | 1,271 本 | 1,296 本 |

関連記事が同じ資格に偏っていたのは、資格・年度・学習の型（試験対策など）のタグを技術テーマと同じ重みで数えていたため。どこからも選ばれない記事が多かったのは、同点を更新日の新しい順に並べ、どの記事からも同じ新しい記事が選ばれていたためと、資格のタグを付け忘れた記事（総監のキーワード 43 本）が同点の勝負で毎回負けていたため。資格のタグは関連度に数えず（総監の 5 管理のように科目名がテーマを兼ねるタグはテーマの共有で数える）、記事型のタグしか持たない試験の手続きのガイドにはタグを補った。残る 38 本は、記事の多いテーマ（総監の 5 管理など）の中で共有する主題タグが少ない記事で、テーマのページと資格のナビからは届く。

## 運用

- 毎週: 点検 `npm run check-taxonomy-wiring` が、所属なし・行き先の無いタグ・昇格の食い違いなどを要対応として出す。公開ハブなのにテーマのページに法令の節が出ない（そのテーマの記事 2 本以上が引く法令が無い）テーマも要対応に挙げる。
- 毎月: `npm run report-taxonomy-wiring` で、昇格の判断、取りこぼし（どこからも選ばれない記事、記事の多い理由付きのタグ）、回遊の質と `internal_nav_click` のラベル別のクリックを読む。
- 計画・施策の台帳は、一次資料で確かめてから 180 日を超えた行を週次の点検（`check-taxonomy-wiring`）が要対応として挙げる（計画の改定・答申の更新を取りこぼさない）。
- テーマのページはこれまで検索のクリックが 0 だった。記事末からの送客（`topic-hub:hub`）とテーマのページからの回遊（`topic-page`）が増えるかを先に見て、検索の評価はその後に読む。

## 残っていること

- 法令ページの候補は月次の報告が「5 本以上の記事が引くのに法令ページも解説記事も無く、作らない理由も無い法令」として挙げる（2026-10-22 時点で 0 本）。新しい記事が法令を引き始めたら、法令ページを作るか、解説記事に `explainsLaw` を付けるか、`lawPages.skip` に理由を書く（DN-0731）。
- EXP-012 の交絡: 記事末のカード（同じ法令の記事・関わるテーマ・この記事のテーマ）と橋渡しカードの出し分けは、EXP-012 の事後の計測期間（2026-11 下旬まで）にデプロイする。デプロイした日を EXP-012 の actions に記録し、判定ではデプロイ前後を分けて読む。
- どのテーマとも結べない法令（3 本以上が引くのに、どのテーマでも 2 本に満たず、法令ページも解説記事も無い）は、月次の報告で記事のタグを見直す（2026-10-22 時点で 0〜1 法令）。
