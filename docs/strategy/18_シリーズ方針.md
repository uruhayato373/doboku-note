# シリーズ方針（自治体の土木担当・コンクリートの実務・建設材料・測量・情報化・建設業の経営と法務）

資格試験・教科書とは別の軸で、読み物のシリーズを `/practice/` に置く。`/blog/` は時事だけの置き場なので使わない（[05_情報アーキテクチャ.md](./05_情報アーキテクチャ.md)）。旧 18（自治体の土木担当・コンクリート）・19（測量・情報化）・20（建設業の経営と法務）を 1 本にまとめた。

## 制作物の置き場

記事の一覧（目次・計画・根拠の参考文献 id・第何波か）は `config/content-series.json`（シリーズ企画の台帳）が持ち、状態は記事の実体から出す。章の骨子は `content/sources/series/<シリーズ id>/<項目 id>.md`、本の項目の行き先は `config/content-series-basis.json`、公開後の並びは `src/config/category-curriculum.json`（`civil-practice`）。管理画面はサイト＞シリーズ企画（`/content/series`）、検査は `npm run check-content-series`、手順は [book-coverage-expansion.md](../../.claude/knowledge/reference/book-coverage-expansion.md)。本書には章の一覧・骨子を写さない。

## シリーズの方針

| シリーズ | 読者 | 方針 |
|---|---|---|
| 自治体の土木担当（A） | 自治体に土木職で入った人・異動した人 | 道路・河川の管理と、発注者としての事業の進め方。運営者の経験（元自治体の土木職）がいちばん生き、競合にも空白がある（[13_土木公務員SEO戦略2026-08.md](./13_土木公務員SEO戦略2026-08.md)）。窓口で先に当たる公物の管理を先に、法令の読み方と財源をその前提に置き、運営者の業務の流れで組む |
| コンクリートの実務（B） | 発注者・設計者・生コン工場・施工者・維持管理者 | 「誰が何を決めるか」で部を分ける。試験の教科書記事と同じ内容を入門の名前で書き直さず、足りる章は既存記事へのリンクで組み込む |
| 建設材料 | コンクリート以外の材料に関わる人 | 建設材料の基本のうちコンクリート以外の章の行き先 |
| 測量・情報化 | 地図・測量・3 次元・台帳・センサのデータを扱い始めた技術者（自治体・コンサル・施工会社）。測量士の受験者にも入口になる | 工種別ノートの工種の 1 つとして置き、名前は「測量・情報化」にする。GIS・空間情報だけでは読者の名前になり、工種別ノートの意味が崩れるため。書籍の網羅で別の区分に埋もれていた既存記事は、シリーズの区分へ移して束ね、穴を新規の章で埋める |
| 建設業の経営と法務 | 建設業の許可・経審・取引・紛争・監督に関わる人 | 主な根拠は建設業法の解説書の許可・経審・紛争・監督の項目。既存記事を束ね、穴を新規の章で埋める |

自治体の土木担当には、景観計画・バリアフリー・都市の緑化・水道事業・多自然川づくりと水辺・気象情報の読み方の章も足す方針（根拠は土木技術の基本と気象災害の基本の本）。

> [!important] 着手の条件
> A は 13 番「非受験層を受験者へ育てる導線」の ① 入口記事に当たる。入口記事を増やすかは EXP-012 の判定（事後窓の終わり 2026-11-26）で決める。2026-10-15〜16 の運営者判断で、各シリーズは判定を待たずに書いて公開した。以後の改善は、各シリーズの公開 28 日の計測（DN-0844）で行う。

| EXP-012 の判定 | 次の対応 |
|---|---|
| 継続（クリック 20 件以上かつクリック率 1.5% 以上） | 新しい題材を書く。選び方は、管理実務で検索の表示が出た語に近く、自治体の外（占用する事業者など）も検索する題材 |
| 文言・位置を変えて再計測（0.5〜1.5%） | 再計測の結果を待つ |
| 入口記事の追加を止める（0.5% 未満・表示 200 件未満） | A・B とも新しい記事は作らない |

第 1 波は公開から 28 日で、GSC の表示・平均順位と、記事末カードのクリック（`qualification_bridge_click`）を見る。

## 教材からの展開とシリーズ展開

本の全項目の割り当て（`config/content-series-basis.json`）が、書籍の網羅（教材からの展開）とシリーズ展開の両方をつなぐ。項目は「シリーズの章」「ほかの記事」「使わない（理由）」のどれかに置き、`check-content-series` が欠けと古い割り当てを止める。

| | 教材からの展開（書籍の網羅） | シリーズ展開 |
|---|---|---|
| 出発点 | 本の側（項目の取りこぼしをなくす） | 読者の側（読む道筋をつくる） |
| 単位 | 本の項目 → 既存記事への追記・新規記事 | 読者と仕事の場面 → 章 → 記事 |
| 手順 | book-coverage-expansion.md §0〜3 | 同 §4 |

- 範囲外は 2 種に分ける。目次・索引・本の中の重複・過去問・答案例は記事にしない。それ以外の範囲外（「当時のサイトの範囲の外」）には `revisit` を付け、シリーズを作るときに判定し直す。判定し直す候補は 0 にしてある。
- 試験の範囲外の項目も、このシリーズでは章に入れる。著者の意見は論点だけを使い、意見そのものはなぞらない。本の判定をやり直したら（`audit-reference-book-coverage`）、割り当ても見直す。
- A は本から出発しない。章（仕事の場面）から出発し、**章 → 論点 → 根拠** の向きでつなぐ（2026-10-13 運営者判断）。B の「本の全項目を章へ仕分ける」台帳は A には使わない。

### 使わないと決めた項目の型

| 型 | 例 | 理由 |
|---|---|---|
| 歴史・沿革・個別事業の紹介 | 古墳・新幹線の延伸・海外の大型案件 | 実務の判断に使う一次資料が無く、時点の値はすぐ古くなる |
| 経営論・営業論・著者の意見 | 建設業 AI 経営の大半 | 一次資料で確かめられない |
| 特定の製品の操作手順・料金・プロンプト例 | Claude Code の導入ガイドの大半 | 変わりやすく、製品の宣伝になる |
| 土木の外の業種 | 屋根・電気・リフォーム・エアコン・住宅瑕疵 | 土木の実務記事の対象外 |
| 引用・書式・名簿 | 条文の引用・提案理由・審議会の部会 | 原典を引けば足りる |
| 数式やアルゴリズムの導出 | 連立方程式の解法・誤差逆伝播・遺伝的アルゴリズムの実装 | 実務の判断に使わない |

生成 AI の本から残すのは、社内に広げる段階・つまずき方・専用サービスとの使い分けの項目だけ。導入のルールは国の AI 事業者ガイドラインを根拠にする。

## 根拠の集め方

- **根拠は論点ごとに 1 つ以上**。Web の検索（e-Gov・国交省・白書・都道府県や市の公開資料）を先にし、本は補助にとどめる（2026-10-13 運営者判断。手元に無い市販書の PDF は取り寄せない）。どの論点にも一次資料（法令・要領・白書）が 1 つ以上あることを `check-content-series` が見る。
- 法令の条は参考文献の台帳の id ＋ 条で指す。都道府県・市の公開資料は「例として ◯◯市の手引き」と書き、全国の決まりのようには書かない。確かめた資料と値はシリーズの事実ファイル（`.claude/knowledge/reference/` にシリーズごとに 1 つ）へ貯め、執筆はまずそこを読む。
- 市販書籍の見出し・文は骨子にも記事にも入れない（本の項目は id だけで指す）。市販の解説書や着想のきっかけになった市販書の章立て・項目の並びは写さない（[reference-sources-policy.md](../../.claude/knowledge/reference/reference-sources-policy.md) §5）。市販の本を下調べに使うときは、原文を渡さない brief 方式（[content-taxonomy.md](../../.claude/knowledge/reference/content-taxonomy.md) §7）で書き、逐語の検査を通す。

### 自治体の資料（A の下調べ）

A の下調べには、マイドライブ直下の「土木奥義」を使う。Drive vault の外にあり、兵庫県の土木部局の資料が中心。3 つに分けて扱う。

| 種類 | 扱い |
|---|---|
| 公開の法令・基準 | 参考文献の台帳に `external-primary` で登録し、記事の `sources` はこの id で書く |
| 市販の解説書 | 第 1 波の根拠にしない。使うときは `commercial-book` として台帳に載せ、Drive vault に書籍の束（bookBundle）を作り、逐語の検査（`check-reference-sources --deep`）を通せる状態にしてから |
| 公開を確かめられない県の資料（「職員用内部資料」と明記されたものなど） | 記事の根拠にしない。県の Web で公開版を確かめられたものだけを台帳に足して使う |

> [!warning] 経験を書く記事
> 地元説明会・議会対応などの記事も、ほかの章と同じく一般論で書く（公開の指針・法令から。2026-10-13 運営者判断）。体験談は書かず、団体名・個人・案件が特定できる書き方をしない。

## 法令を起点にした回遊

記事は条文へ、条文から記事へ行き来できるようにする。法令の分類はタグで作らず、記事の e-Gov へのリンクから集める（タグは付け忘れと手入れが要る）。

- 法令 ID・条・改正の施行日の正本は `config/egov-laws.json`。`npm run egov-laws` が記事のリンクと台帳の法令を照合し、`--drift` が写しより後の改正とリンクする記事を出す。
- 記事の末尾に「この記事の根拠法令」を、リンクから自動で並べる。法令ページがある法令は法令ページへ、無い法令は e-Gov へ（content-taxonomy.md §6-3）。
- 法令ページは領域 `/laws/<参考文献の id>` に置く。解説を書いた法令だけを公開し、AI が一次資料で照合して書く（[05_情報アーキテクチャ.md](./05_情報アーキテクチャ.md)「法令ページ」）。

## 図と写真

図と写真は、本の頁の上で文章と並んでいる。そこで、文章（章）と図を**本の頁**でつなぐ（2026-10-13 運営者判断）。

- **つなぎ方**: 書籍の全項目の割り当てが項目ごとに本の頁を持つ。項目 → 章と合わせて、章 → 頁 → その頁の図がたどれる。図の一覧は別に写さない。
- **画像は本から切り出す**: 頁の画像から図・写真を切り出し、`npm run record-reference-book-artifacts` で書籍の台帳へ登録する。図の無い頁は `cropStatus` を `not-needed` にする。切り出しの未了の頁は `npm run check-content-series -- --crop-jobs`、作成から配置までの次の作業は `-- --visual-jobs` が出す。
- **写真は、切り出した写真を元に AI で描き直す**（運営者の指示・2026-10-13。条件は 2026-10-15 に決定）。構図・画角・背景・配置はなぞらず、元の文字・図番・注記は写さない。元は `provenance` の `basedOn` に記録し、監査で元と見比べる。条件と手順の正本は [image-policy.md](../../.claude/knowledge/reference/image-policy.md)「本の写真を元に描き直す」。
- **図**: 書籍の図は流用しない（`commercial-book` は `figureReuse: false`）。切り出した図は、自作の SVG の題材・下敷きと、写真の描き直しの元にだけ使う。

## やらないこと

- 県の内部資料や、公開を確かめられない資料を根拠にする
- 市販の解説書・市販書の章立てや項目の並びを写す
- 試験・教科書の記事と同じ内容を、入門の名前で書き直す（B は既存記事へのリンクで足りる）
- `/blog/` に置く
- 本の図を流用する
