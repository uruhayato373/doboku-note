# コードの拡張性 負債の棚卸しと優先順位

> [!note]
> 2026年10月20日の点検。読むだけで、コードは変えていない。同じ日に一度、件数を数えただけの棚卸しを書いたが、既存のカード・検査・実ファイルと障害の履歴を照合していなかったため、照合したうえで全面的に書き直した。git の履歴は 2026-08-22 に 1 コミットへ切り詰められているので、git から出した数字は 08-22〜10-20 の 59 日分。CI の数字は 07-22 から取れた。

## 最初の棚卸しの誤り

| 最初の主張 | 照合した結果 |
|---|---|
| 計測の入力に型の無い JSON が 8 件 | 7 件は台帳で planned になっていて、ファイルが 1 つも無い。実物があるのは cloudflare.zone だけ。型は「実データ全件で違反 0 を確かめたものだけ足す」規約なので、7 件には今は書けない |
| 報告のみの検査で読み手の無いものが 4 本 | 3 本は読み手が書いてある。実体は env-inventory の 1 本だけ。読み手を強制するテストが、複数行の定義のコメントを拾って env-inventory を検査から外していた |
| 呼ばれないスクリプト 44 本を退役 | render-figure-* の 34 本は、svg-figure-rewriter が図を作り直すときに使う元。手順書が「写して作る」と指示している。消してよいのは、済んだ移行と一回きりの作業の 11 本 |
| 重複関数を寄せる検査を新しく置く | `tests/script-helpers-ratchet.test.mjs` が既にある。集約は 10 月前半に 3 回進めている |
| スクリプトへの型付けを最初にする | 障害の修正 20 件を読むと、型の欠如が原因だったのは 2 件。管理画面の tsc は lib の 66 モジュールを既に型検査している。依存ゼロの lib に zod の型を書くと、`workflow-zero-dependency` のテストとぶつかる |
| quality-audit の検査は 171 本 | 183 本（ci 145・ops 20・報告のみ 18）。1 行で書いた定義しか数えていなかった |

## 実際にコストを生んでいる所

**CI の信号**
- develop の CI は、07-22 以降の時間の 37% で赤だった。1 回の赤の中央値は 1 時間、最長は 138 時間。
- 09-14 以降の赤 63 回を、最初に落ちた検査で分けた。コンテンツ品質のゲート（本来の役目）が 23 回。製品の欠陥ではないものが 36 回（57%）で、内訳は次のとおり。
  - 台帳・参照・登録の整合: 16 回
  - 分類表への追加漏れ: 8 回・28 時間
  - 生成物のコミット漏れ: 4 回
  - 実データに依存するテスト: 4 回・20 時間
  - 順序・並行: 4 回
  - 外部状態: 2 回・44 時間
- 追跡している生成物が変更を膨らませている。2 か月で tag-dictionary.json が 235 回、cross-exam-keywords.json が 172 回変わった。変わったのは、作った日時と件数だけ。

**事故の類型**（measurement-incidents.md の 64 件）
- 最も被害が大きいのは「黙って 0 件、または一部だけ取れたのを成功として扱った」11 件。A8 の 1 か月分のデータが消え、導入以来一度も鳴らないアラートがあり、.md の 38% が走査されていなかった。
- 次いで「同じ判定が 2 か所にあってずれた」6 件、「データの形が変わっても検査が止めなかった」5 件。
- 障害の修正 20 件を読んで分けると、重複のずれ 6、黙って 0 件 6、パスの直書き 3、並行作業 3、型 2、外部仕様の変更 1。

**資格を足す手間**
- 資格の名前は `config/qualification-registry.json` に一本化され、検査も 0 件で通っている。しかし、サイトの構造は registry からも categories.json からも決まっていない。サイトの構造とは、ビュー・記事型の並び・色・/exam に出すかどうか・並び順のこと。
- RCCM の立ち上げでは、仕組みの側で 52 ファイル・88 か所を手で直した。registry から自動で決まった箇所は 0 で、その後も追随の修正が 5 コミット続いた。
- registry を入れた後に足した測量士・舗装でも、OGP の対応表から漏れた。今も枠色なしで出ている。
- src の中で資格 id を直接比べている箇所は約 63 ある。そのうち 4 割強は、記事の分類（doc-classifier.ts）とカテゴリページのビュー選択（CategoryPage.tsx）。
- /exam に出すかどうかは civil|pe の二値で決めているので、行政書士はこのままでは出ない。
- 並び順は registry・categories.json・トップのカード・/links で 4 通りある。
- categories.json の groups とコード側の並びは照合されておらず、2級土木で既にずれている。
- コンクリート系のビューは 3 種類の記事型しか描かないので、新しい記事型は黙って消える。
- 商品の資格は id の接頭辞から推定していて、知らない接頭辞は総監として扱われる（`src/lib/exam-brand.ts:34-49`）。products.json は商品ごとに資格を持っているので、同じ事実が 2 か所にある。

**判定の二重実装**
- 経験記述の字数は、サイトの字数ツールとスクリプトで数え方が違う。目印【〇〇】の括弧を、サイトは数え、スクリプトは数えない。コメントには「一致」と書いてある。
- MDX のパスから slug を導く処理は 7 か所以上にあり、見出し ID は 2 か所にある。

## 観点ごとの結論

| 観点 | 結論 |
|---|---|
| 型定義 | スクリプトへの @ts-check は見送る。型を入れるのは事故が起きる層だけにする。frontmatter（記事で使うキー 42 種のうち 13 種しか検査していない）、商品の資格、カテゴリの構造 |
| ディレクトリ構成 | 再編しない。探しやすさは接頭辞の命名で既に得られている。読み手の無い生成物は追跡から外す |
| 関数 | 統合するのは「判定」の二重実装だけ（字数・slug・見出し ID）。sleep・sha256 のような純関数は、ずれても害が無いので追わない |
| 記録・計測・改善 | CI の信号を直す。速い台帳検査を pre-commit で先に止める。PR の差分以外で赤になる検査は、差分だけで決まる形にするか ops へ移す |
| エージェント・スキル | 呼び出しを 4 週間記録してから、統合・退役を決める。根拠が既にあるもの（呼び出し元の無い content-planner、撤退を決めたメンバーシップ一式）は先に片付ける |
| サイトの拡張性 | カテゴリの表示構造を categories.json に持たせ、資格ごとの手書き分岐を消す。行政書士を展開するかを決めた後、最初の制作の前に行う |

## 進める順番

backlog では、タイトルの末尾を「（拡張性・第N波）」でそろえている。

1. **第0波（10 月）: 今出ている不具合と、利用記録の開始。** 小さいので並行できる。
   - 測量士・舗装の OGP の枠色
   - 字数の数え方の統一
   - Convention A の古い記述・読み手のテスト・退役表
   - 呼び出しを記録する hook
2. **第1波（11 月前半）: CI の信号。** 赤の時間を最も減らせる。
   - 速い台帳検査を pre-commit で止める
   - PR の差分以外で赤になる検査を移す
   - 生成物を追跡から外す
   - あわせて、develop の必須検査に build だけでなく audit も含める
3. **第2波（11〜12 月・行政書士の判断の後）: 資格・記事の型を足す手間を減らす。**
   - カテゴリの表示構造
   - 商品の資格を products.json から引く
   - 試験日の直書き
   - frontmatter の未知のキー
4. **第3波（12 月）: 判定の重複、エージェントの整理、後片付け。**
   - slug と見出し ID の共有
   - エージェント・スキルの統合と退役
   - 一回きりのスクリプト 11 本の削除
   - データ台帳の警告

効果は 12 月の月次レビューで、11 月の develop の赤を同じ分類で数え直して確かめる。

## やらないこと

| やらないこと | 理由 |
|---|---|
| スクリプトへの @ts-check と、スクリプト用の tsconfig | 事故の原因と合わない。依存ゼロの検査ともぶつかる |
| 検査の登録先（package.json・commands.md・quality-audit）を 1 か所から生成する | `check-gate-parity` が意図して結んでいる。赤の原因はこの 3 点ではなく、別の台帳群 |
| 「黙って 0 件」の共通の出口を全検査に強制する | 192 本の移行になる。大きな事故が起きたのは取得とアラートの側で、検査を移しても効かない。共通部品（`cli-run`・`inconclusive-gate`）は既にある |
| 収益導線の配置（magazine-placement など）をすべて設定へ移す | 到達性の検査が既にあり、10/17 に実際に止めている。直すのは日付の直書きだけ |
| `scripts/` の再編と、render-figure の共通部品化 | 参照の書き換えが大きいわりに、得るものが少ない |
| 会話記録の保存期間（cleanupPeriodDays）を延ばす | ディスクの方針（7 日）とぶつかり、30 日で約 6GB 増える。記録は hook で取る |
| 4 週間の記録だけで SNS 系のスキルを退役させる | SNS は保留中なので、使われていないのは当然 |
