## なぜ2事業か

| 捨てたもの | 捨てた理由 |
|---|---|
| 書籍（KDP） | 人間の判断が大きい。校正・構成・プロモーションは自動化困難 |
| Udemy講座 | 顔出し・声出し・動画編集が必須。Claude Codeの恩恵ゼロ |

| 残したもの | 残した理由 |
|---|---|

| iOSアプリ | コード100%をClaude Codeで生成可能。既存過去問データを転用 |

**判断基準: Claude Codeで自動化できる割合が高い事業に集中する。**

## iOSアプリ技術設計

### 基本情報

```
アプリ名: 1級土木施工管理 過去問マスター（仮）

技術スタック:
  - Swift + SwiftUI（ネイティブ）
  - SwiftData（ローカルDB、学習記録保存）
  - JSON（問題データ、バンドル同梱）
  - Google Mobile Ads SDK（AdMob広告）
  - StoreKit 2（サブスク課金）
```

### UI設計方針（独学TODAY 1,000万DLから学ぶ）

| 原則 | 理由 | 実装 |
|---|---|---|
| **一問一答を基本画面** | ○×が最速。4択は集中モードで | ホーム → タップで即出題 |
| **文字を大きく** | 現場作業員はスマホ片手操作 | 本文16pt以上、選択肢18pt以上 |
| **即時フィードバック** | 正解/不正解を音+色で | 緑=正解、赤=不正解、触覚フィードバック |
| **10問単位のミニテスト** | スキマ時間（通勤・昼休み）対応 | デフォルト10問、設定で変更可 |
| **チェック機能** | 苦手を繰り返し → 定着 | ブックマークとは別に「要復習」フラグ |
| **余計な機能を入れない** | MVP最優先。v1.0はシンプルに | 弱点分析・グラフはv1.1以降 |

### 画面構成

```
v1.0（MVP）:
  ├── ホーム（今日の学習状況 + クイックスタート）
  ├── 出題モード選択
  │   ├── 年度別（H26〜R02 × 問題A/B）
  │   ├── 分野別（土工/コンクリ/施工管理/法規/...）
  │   └── ランダム10問
  ├── 出題画面（問題 → 選択 → 正解表示 → 解説）
  ├── チェック問題一覧（要復習マーク）
  └── 設定（問題数、通知、プレミアム購入）

v1.1（プレミアム機能）:
  ├── 弱点分析（分野別正答率レーダーチャート）
  ├── 学習記録（日別グラフ、連続学習日数）
  ├── 模試モード（本番形式65問、タイマー付き）
  └── doboku-note連携（解説からSafari表示）

v2.0（2次試験対応）:
  ├── 2次試験モード（記述式の過去問 + 模範解答）
  └── 経験記述テンプレート
```

### データ設計

```
問題JSON:
{
  "id": "r02-a-01",
  "year": "R02",
  "exam": "primary",         // primary | secondary
  "section": "A",            // A | B
  "number": 1,
  "category": "earthwork",   // 分野タグ
  "subcategory": "soil",
  "question": "問題文...",
  "choices": [
    {"id": "a", "text": "選択肢1"},
    {"id": "b", "text": "選択肢2"},
    {"id": "c", "text": "選択肢3"},
    {"id": "d", "text": "選択肢4"}
  ],
  "answer": "b",
  "explanation": "解説文...",
  "dobokuNoteUrl": "/docs/exam/civil-construction-1/guide/earthwork-key-points"
}

学習記録（SwiftData）:
- QuestionResult: 問題ID, 正誤, 回答日時, 回答時間
- StudySession: 日付, 問題数, 正答率, 学習時間
- BookmarkedQuestion: 問題ID, チェック日時
```

## Pre-Mortem（この計画が失敗するとしたら）

### 1. 「アプリ開発が楽しくてサイト収益化を忘れた」
→ **4月第1週はAdSense配置のみ。アプリは4月第2週から。**

### 2. 「機能を盛り込みすぎてリリースが遅れた」
→ **MVP = 出題 + 正解表示 + チェック機能のみ。グラフ・分析はv1.1以降。**

### 3. 「7月の試験に間に合わなかった」
→ **6月末TestFlight必須。間に合わなければ10月の2次試験をターゲットに切替。**

### 4. 「ダウンロードされない」
→ **無料+全問解説でDL障壁を最小化。doboku-noteの全試験ページにCTA。ASO最適化。**

### 5. 「サブスク課金されない」
→ **無料版でもAdMob収益がある。課金率0%でも広告だけで月1〜3万円は確保。**

### 6. 「TK office（累計60万DL）に勝てない」
→ **勝つ必要はない。市場の5%を取れば十分。差別化はモダンUI + サイト連携 + 2次試験対応。**
