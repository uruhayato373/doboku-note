doboku-note のコンテンツ現状・検索パフォーマンス・試験日程・競合状況・収益化戦略を総合的に分析し、期間指定のコンテンツ拡充ロードマップを生成する。

## 引数

```
/content-roadmap [--horizon HORIZON] [--focus FOCUS]
```

- `--horizon`（任意）: 計画期間（デフォルト: `90d`）
  - `30d`: 1ヶ月
  - `60d`: 2ヶ月
  - `90d`: 3ヶ月
  - `6m`: 6ヶ月
- `--focus`（任意）: 重点カテゴリ（デフォルト: `all`）
  - `general`: 一般（土木工学・施工管理・アセットマネジメント・空間情報）
  - `road`: 道路
  - `river`: 河川
  - `low`: 法律
  - `all`: 全カテゴリ

## プロジェクトコンテキスト

| 項目 | 値 |
|---|---|
| コンテンツ配置 | `docs/general/`, `docs/road/`, `docs/river/`, `docs/low/` |
| サイドバー定義 | `sidebars/` |
| レビュー保存先 | `docs/reviews/` |
| 作成方法 | PDF変換（インポートスキル）/ 手書き / アフィリエイト記事 |
| 工数目安 | S=2-4時間, M=4-8時間, L=8-16時間 |

## 手順

### Phase 1: 現状把握（並列サブエージェント）

4つのサブエージェントで並列にデータを収集する。

#### Agent A: コンテンツインベントリ

```
調査項目:
- docs/ 配下の全 .mdx ファイル数をカテゴリ別に集計
- 各ファイルの行数・frontmatter タイトル
- sidebars/ のサイドバー定義との整合性確認
  - サイドバーに定義があるがファイルがないもの（欠損）
  - ファイルがあるがサイドバーに未登録のもの（孤立）

出力形式: カテゴリ別のファイル数・行数・整合性の問題点
```

#### Agent B: 検索パフォーマンス

```
調査項目:
- GSC データ取得を試行（サービスアカウント鍵があれば /fetch-gsc-data 相当）
- GSC が利用不可の場合、以下のフォールバック:
  - docs/reviews/keyword-gap/ の最新レポートを読み込み
  - docs/reviews/seo-audit/ の最新レポートを読み込み
- 上位クエリ・ページ別パフォーマンス
- 高インプレッション低クリックのクエリ

出力形式: 検索パフォーマンス概況、成長機会のあるキーワード群
```

#### Agent C: 試験カレンダーと季節性

```
調査項目:
- 今日の日付から直近の資格試験日程を確認:
  - 1級土木施工管理技士（学科: 7月, 実地: 10月）
  - 2級土木施工管理技士（前期: 6月, 後期: 11月）
  - 技術士一次試験（11月）
  - 技術士二次試験（筆記: 7月, 口頭: 12月）
  - コンクリート技士/主任技士（11月）
  - 測量士/測量士補（5月）
- 各試験までの残り日数
- 季節性に基づくコンテンツ需要の優先度調整
  - 試験3ヶ月前 = 学習需要ピーク開始
  - 試験1ヶ月前 = 最終追い込み需要

出力形式: 試験カレンダー表、季節性に基づく優先度評価
```

#### Agent D: 既存レビューの読み込み

```
調査項目:
- docs/reviews/keyword-gap/ の最新レポート
- docs/reviews/competitor-audit/ の最新レポート
- docs/reviews/affiliate-plan/ の最新レポート
- docs/reviews/monetization/ の最新レポート

出力形式: 各レポートの要点サマリー、未対応の推奨事項リスト
```

### Phase 2: コンテンツ候補の統合と優先度付け

Phase 1 の全データを統合し、コンテンツ候補を洗い出す。

#### 2.1 候補の収集元

| ソース | 候補の種類 |
|---|---|
| キーワードギャップ | 未カバーの検索需要に対応するコンテンツ |
| 競合調査 | 競合がカバーし自サイトにないトピック |
| アフィリエイト企画 | 収益化可能な商材比較・おすすめ記事 |
| 試験カレンダー | 試験日程から逆算して必要なコンテンツ |
| サイドバー欠損 | 定義済みだが未作成のページ |

#### 2.2 優先度スコアリング

各コンテンツ候補に対して優先度スコアを算出:

```
優先度スコア = 検索需要(1-5) × 競合の弱さ(1-5) × 作成容易性(1-5) × 収益化ポテンシャル(1-3) × 季節緊急度(1-3)
```

| 要素 | 評価基準 |
|---|---|
| 検索需要(1-5) | GSC インプレッション or 推定検索ボリューム |
| 競合の弱さ(1-5) | 競合コンテンツの品質・量が低いほど高評価 |
| 作成容易性(1-5) | PDF変換可能=5、既存知識転用=4、調査必要=2-3、専門知識必要=1 |
| 収益化ポテンシャル(1-3) | アフィリエイト直結=3、AdSense収益期待=2、間接的=1 |
| 季節緊急度(1-3) | 試験1ヶ月以内=3、3ヶ月以内=2、それ以外=1 |

#### 2.3 作成方法の分類

| 分類 | 説明 | 該当スキル |
|---|---|---|
| **PDF変換** | 既存インポートスキルで半自動化可能 | `/river-design-import`, `/common-specs-import`, `/design-manual-import`, `/fishery-port-import`, `/civil-law-import`, `/tech-management-import` 等 |
| **手書き** | 独自の解説・まとめ・試験対策記事 | `/pdf-to-mdx`（部分利用） |
| **アフィリエイト記事** | 商材比較・おすすめ記事 | `/plan-affiliate` で企画済みのもの |

### Phase 3: ロードマップ設計

指定された `--horizon` に合わせてフェーズを分割する。

#### 3.1 フェーズ分割ルール

| horizon | フェーズ数 | フェーズ単位 |
|---|---|---|
| 30d | 2 | 2週間 |
| 60d | 3 | 約3週間 |
| 90d | 3-4 | 約1ヶ月 |
| 6m | 6 | 1ヶ月 |

#### 3.2 配置ルール

1. **試験日程から逆算**: 試験関連コンテンツは試験3ヶ月前までに公開完了を目標
2. **技術コンテンツ先行**: 収益化コンテンツ（アフィリエイト記事）は関連する技術コンテンツの後に配置（自然な導線確保）
3. **PDF変換は効率重視**: 同一ソースからの連続変換でスキル習熟度を活かす
4. **1週間あたりの作業量**: 個人開発の制約を考慮し現実的に設定
   - 目安: 週あたり S×2 + M×1 程度（= 8-16時間）

#### 3.3 各フェーズの定義

各フェーズに以下を設定:
- テーマ（例: 「河川・水理学の基盤整備」「試験対策コンテンツ充実」）
- 期間
- 具体的なコンテンツ一覧（タイトル、パス、作成方法、推定工数）
- フェーズ終了時の達成指標

### Phase 4: 依存関係と並行作業の整理

#### 4.1 依存関係の特定

- どのコンテンツが他のコンテンツの前提条件か（例: 基礎理論 → 応用 → 演習）
- サイドバー定義の更新タイミング（新カテゴリ追加時はサイドバー更新が先）

#### 4.2 並行作業の特定

- 異なるカテゴリのコンテンツは並行可能
- PDF変換と手書き記事は並行可能
- 同一PDFからの連続変換は直列が効率的

### Phase 5: 出力

`docs/reviews/content-roadmap/YYYY-MM.md` に保存する。

## 推奨実行頻度

- **月次**: フルロードマップ更新
- **四半期**: `/competitor-audit` + `/keyword-gap` の結果を反映した大規模見直し

## 注意事項

- コンテンツ拡充は収益化の前提条件。技術コンテンツの質を最優先する
- 「PDFの壁」を崩す領域（公的資料のHTML化）を優先する戦略
- 個人開発の制約を考慮し、1週間あたりの作業量を現実的に設定（S=2-4時間、M=4-8時間、L=8-16時間）
- 長時間の作業では自然な区切りごとに `/compact` の実行を提案する
