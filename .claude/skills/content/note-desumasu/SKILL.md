## 用途

`docs/note-drafts/{NN-タイトル}/article.md` の note 下書きを、親しみやすい ですます調 に変換する。v3 合格体験者ポジション戦略（運営者が 2026-07 受験予定）と note 媒体の特性（個人の体験・思考の共有が期待される）を踏まえ、「伴走者」トーンを演出する。

## 引数

```
/note-desumasu <article path>
```

| 引数 | 必須 | 説明 |
|------|------|------|
| article path | 必須 | 変換対象の article.md パス（例: `docs/note-drafts/06-4フェーズ学習法/article.md`） |

## 適用判断（書き始める前に必ず確認）

本スキルは **「受験戦略・学習指南系」「技術リファレンス系」の両方** に適用できる。サイト本体（doboku-note.com の MDX）とは文体ポリシーが異なる:

| コンテンツ | 文体 | 参照ガイド |
|---|---|---|
| サイト本体の教科書・キーワード・過去問解説 | だ・である調 | [.claude/content-principles.md](../../../content-principles.md) |
| note 下書き（有料販売予定の戦略・学習法）| **ですます調（本スキルで変換）** | 本スキル |
| note 下書きの企画書（00_企画立案 等）| 対象外 | 変換しない |

**理由**: note は読者が「この著者と一緒に合格したい」と感じる距離感が購買に直結する。サイト本体（SEO 流入の網羅的リファレンス）とは異なる体験が必要。

## 変換ルール

### ですます化する対象

- 地の文（通常の段落）
- 箇条書きの説明文（項目自体は体言止めなら維持）
- H2/H3 配下の本文
- 締めの段落

### そのまま残す対象

- `# H1` タイトル
- 引用ブロック `> この記事でわかること` 内の体言止めリスト
- コード・URL・数値・英字・数式・年度表記（R07, H30 等）
- 体言止めで終わる箇条書き項目（無理に「〜です」を付けない）
- 引用ブロック内の専門用語の引用・条文
- 公式・定義（「A とは B である」が専門用語定義の場合は許容。「〜のことです」「〜を指します」への置換は可）
- 数学記述・計算式

### 変換パターン例

| before | after |
|---|---|
| 〜だ。 | 〜です。 |
| 〜である。 | 〜です。 |
| 〜だった。 | 〜でした。 |
| 〜なければならない。 | 〜する必要があります。 |
| 〜してはならない。 | 〜しない方がいいでしょう。 |
| 〜するべきだ。 | 〜するのが現実的です。／〜することをおすすめします。 |
| 〜することだ。 | 〜することです。 |
| 〜と考えた。 | 〜と考えました。 |
| 〜してほしい。 | 〜してみてください。 |
| 〜ではない。 | 〜ではありません。 |

### 親しみやすさの表現

押し付けを避け、伴走感を演出する語尾を混ぜる（**多用すると冗長になるので 1 記事に 5〜10 箇所程度**）:

- 〜していきましょう
- 〜してみてください
- 〜してみましょう
- 〜おすすめします
- 〜が現実的です
- 〜ではないでしょうか
- 〜と感じています（個人の経験を語る場面）

### 記事タイプ別の追加配慮

**受験戦略系（学習計画・指南・解答戦略）**:
- 積極的に「〜しましょう」「〜してみてください」を混ぜて伴走感を出す
- 個人の経験を「〜と感じました」「〜がおすすめです」で語る

**技術リファレンス系（分析・体系整理・計算パターン）**:
- 情報密度を保つため「〜します」「〜です」の基本形を中心に
- 専門用語の定義や公式・条文引用はそのまま
- 「〜しましょう」は手順の要所のみ（毎節ではない）

**再受験者向け**:
- 「〜べき」「〜しなければならない」等の断定を避け、寄り添うトーン
- 過剰な同情表現（「頑張ってください」「つらいですよね」）は避ける

## 作業手順

1. **Read**: 対象ファイルを読み込む
2. **Write で上書き**: 既存構造・見出し階層・箇条書き・改行構造は維持し、地の文のみ置換
3. **検証**:
   - `grep -cE "だ。|である。"` が 0 件（意図的引用を除く）
   - `grep -E "なければならない|してはならない"` が 0 件
   - `grep $'\uFFFD'` が 0 件（文字化け U+FFFD 無し）
4. **例外の報告**: 意図的に残した箇所（条文引用・公式定義）があれば、完了報告で理由を明記

## 完了報告テンプレート

```
## 変換完了: {article path}

### 主な文末変更例（5 件）
- 「〜だ。」→「〜です。」
- 「〜である。」→「〜です。」
- ...

### 意図的に残した箇所
- L{line}: {reason}（例: PERT LF の定義）

### 検証結果
- だ。/である。: 0 件
- なければならない / してはならない: 0 件
- U+FFFD: 0 件
```

## 一括変換（複数記事）

3〜6 記事をまとめて変換する場合、`general-purpose` サブエージェントに 2 記事ずつ割り当てて並列実行すると効率的。1 エージェントあたり 3 分程度で完了する。親エージェントはエージェント起動後に完了通知を待ち、検証結果をまとめて報告。

## ハーネス設計上の位置づけ

- **Generator（model: sonnet）** — テキスト変換は定型作業
- **別エージェント（`civil-construction-qa` 等）による評価は不要** — 機械的検証（grep）で十分
- **サイト本体の MDX には適用しない** — サイトは [.claude/content-principles.md](../../../content-principles.md) の文体ルールに従う
