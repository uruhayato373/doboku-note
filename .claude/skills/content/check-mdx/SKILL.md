MDX ファイルの構文チェックを行い、Docusaurus ビルドエラーを未然に防ぐ。

## 引数

```
/check-mdx <対象パス>
```

- ファイルパス: 単一の MDX ファイルをチェック
- ディレクトリパス: 配下の全 MDX ファイルを一括チェック
- 省略時: `git diff --name-only` で変更された MDX ファイルを対象

## チェック項目

### 1. frontmatter

- `---` で囲まれた YAML ブロックが存在するか
- `title` が設定されているか
- `sidebar_position` が数値か
- `description` が 120 文字以内か

### 2. MDX 構文（Docusaurus 3.x / MDX v3）

- `{` `}` がコンテンツ内にエスケープなしで存在しないか（JSX 式として解釈されビルドエラーになる）
  - 許容: コードブロック内、JSX コンポーネント内
  - 修正例: `\{` `\}` にエスケープ、または `` `{` `` でインラインコード化
- `<` `>` がタグとして解釈されないか
  - 許容: `<div>`, `<img>`, Docusaurus コンポーネント（`:::note` 等）
  - 不正: `A < B`（数式外の不等号）→ `A &lt; B` or `$A < B$`
- インポート文の構文が正しいか

### 3. 見出し構造

- h1 (`#`) が使われていないか（Docusaurus では title が h1 になる）
- 見出しレベルが飛んでいないか（h2 → h4 等）

### 4. リンク・画像

- 内部リンク `[text](./path)` の参照先ファイルが存在するか
- 画像パス `./img/xxx` のファイルが存在するか
- `static/` への絶対パス (`/images/...`) を使っていないか（相対パスを推奨）

### 5. 数式（KaTeX）

- `$$...$$` ブロック数式の前後に空行があるか（ないとレンダリングが崩れる）
- `$...$` インライン数式内に改行がないか
- KaTeX 未対応コマンドがないか（基本的なもののみ）

### 6. テーブル

- ヘッダー行とセパレーター行（`|---|`）があるか
- 列数が一致しているか

### 7. Docusaurus 固有

- `:::note`, `:::tip` 等のアドモニションが正しく閉じているか
- `<div className="...">` が閉じタグとペアになっているか
- Mermaid コードブロックが正しい記法か（`` ```mermaid ``）

## 出力形式

```
=== check-mdx: <ファイルパス> ===

[ERROR] L42: エスケープされていない `{` があります
  → 修正案: `\{` にエスケープするか、コードブロック内に移動

[WARN]  L15: 見出しレベルが h2 → h4 に飛んでいます

[OK] 他に問題はありません
```

- **ERROR**: ビルドエラーになる問題（必ず修正）
- **WARN**: レンダリングに影響する可能性がある問題
- **INFO**: 推奨事項

## 手順

### Step 1: 対象ファイルの特定

引数に基づいて対象ファイルを特定する。省略時は `git diff --name-only` で変更 MDX を取得。

### Step 2: 各ファイルを Read で読み込み

対象ファイルを読み込む。大きなファイルは分割して読む。

### Step 3: チェック実行

上記チェック項目を順に検証する。

### Step 4: 結果出力

問題をファイル別・重要度別に一覧表示する。

### Step 5: 自動修正（オプション）

ユーザーの確認後、自動修正可能な項目を修正する:
- `{` `}` のエスケープ
- 数式前後の空行追加
- `static/` パスの相対パスへの変換
