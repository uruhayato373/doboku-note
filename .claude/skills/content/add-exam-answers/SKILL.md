## 用途

択一式過去問の MDX ファイルに、未作成の解答・解説（`<details>` ブロック）を追加するスキル。
正答 PDF の正答番号に基づき、各選択肢の正誤を検証する解説を生成する。

## 引数

```
/add-exam-answers <MDXファイルパス> [正答PDFパス]
```

| 引数 | 必須 | 説明 |
|------|------|------|
| MDXファイルパス | ✅ | 対象の択一式過去問 MDX（例: `.local/r2/posts/pe-comprehensive-management/r07-primary/article.mdx`） |
| 正答PDFパス | 任意 | 正答表 PDF。省略時は `docs/textbook/技術士（総監）/` から年度を推定して自動選択 |

## 実行手順

### Step 1: 状態把握

1. MDX ファイルを読み込み、全設問の見出し（`## Ⅰ-1-XX`）を列挙
2. `<details>` ブロックの有無を Grep で確認し、**解答済み / 未解答** を分類
3. 正答 PDF を読み込み、全設問の正答番号を取得
4. 未解答の設問一覧と正答番号をユーザーに提示し、作業範囲を確認

### Step 2: 解答ブロックの追加

各未解答設問に対し、以下のテンプレートに従って `<details>` ブロックを追加する。

**挿入位置**: 各設問の選択肢リスト末尾と次の `## Ⅰ-1-XX` の間（またはファイル末尾）。

#### 確定テンプレート

```mdx

<details>
<summary>解答・解説</summary>

**正答：N**

1. 解説文（1〜2文で簡潔に） ✅
2. **不適切な理由の解説文 ❌**
3. 解説文 ✅
4. 解説文 ✅
5. 解説文 ✅

<ExamPoint
  summary="試験対策上の要点（1文）"
  items={[
    "ポイント1",
    "ポイント2",
    "ポイント3",
  ]}
/>

<RelatedKeywords items={[
  { label: "関連キーワード", slug: "keyword-slug" },
]} />

</details>
```

#### スタイル規約（厳守）

**① 正答行**
- `**正答：N**`（番号のみ。選択肢テキストの繰り返しは不要）
- 正答行と選択肢リストの間に `---` 区切り線を入れない

**② 選択肢解説（番号付きリスト）**
- テーブル形式は使わない（スマホで見にくいため）
- 各選択肢を `1.` 〜 `5.` の番号付きリストで記載
- 各行は解説文の後に `✅`（適切）または `❌`（不適切）で終わる
- 正答の選択肢（不適切/適切な方）の行を `**太字**` で囲む
- 解説文は簡潔に（1〜2文）。選択肢テキストの繰り返しは不要

**③ ExamPoint コンポーネント**
- 試験対策上のポイントを `<ExamPoint>` で記載
- `summary`: 1文で要点をまとめる
- `items`: 3〜5個のポイント
- スタイル: 灰色ボーダーボックス + 青ラベル「試験対策ポイント」が左にはみ出し（`mx-5`, `-left-8`）

**④ RelatedKeywords コンポーネント**
- 関連キーワードを `<RelatedKeywords>` で記載
- slug が存在するキーワード → リンク付きテキスト（青）
- slug が不明 → slug 省略で灰色テキスト
- スタイル: 左ボーダーライン（ティール色）+ テキストリンク（`mx-5`, `border-l-4`）

**⑤ 全体の区切り**
- 正答行と選択肢リストの間に `---` を入れない
- 選択肢リストと ExamPoint の間に `---` を入れない
- 各要素は空行で自然に区切る

### Step 3: 問題タイプ別の対応

**「最も不適切なものはどれか」の場合:**
- 正答の選択肢が不適切 → その行を `**太字 ❌**`
- 他の選択肢は適切 → `✅`

**「最も適切なものはどれか」の場合:**
- 正答の選択肢が適切 → その行を `**太字 ✅**`
- 他の選択肢は不適切 → `❌`

**計算問題の場合:**
- 計算過程を数式（KaTeX `$$...$$`）で示す
- 最後に番号付きリストで各選択肢の正誤をまとめる

**組合せ問題の場合:**
- 各用語・概念のマッチング根拠を個別に説明
- 正答の組合せが一意に定まる論理を示す

### Step 5: バッチ処理とコンテキスト管理

- 未解答が 10 問以上ある場合は **6〜7 問ずつのバッチ** に分割
- 各バッチ完了後にユーザーへ進捗報告
- 大量の設問がある場合はバッチ間で `/compact` を提案

### Step 6: 検証

**タグ数チェック:**
1. `<details>` タグ数が全設問数と一致することを Grep で確認
2. `</details>` タグ数も同数であることを確認

**構成順序チェック（必須）:**
全設問の `<details>` 内で、以下の要素が正しい順序で並んでいることを確認する。
```
grep -n "正答：\|ExamPoint\|RelatedKeywords\|</details>" article.mdx
```
で出力し、各設問ブロックが以下の順序になっていることを目視確認:
```
正答：N
  ↓
（番号付きリスト or 計算解説）
  ↓
ExamPoint
  ↓
RelatedKeywords
  ↓
</details>
```

**NG パターン（過去の実例）:**
- RelatedKeywords が ExamPoint より前に出ている
- 正答行の直後に RelatedKeywords がある（解説より先に来ている）
- `---` 区切り線が残っている

**構文チェック:**
3. `/check-mdx` で MDX 構文エラーがないことを確認（ユーザーに提案）

## 絶対ルール

1. **正答 PDF の正答番号を最優先**: 解説の論理と正答番号が矛盾する場合は、正答番号に合わせて解説を調整する
2. **details 内に H2/H3 見出しを使わない**: `**太字**` で代替（TOC汚染防止）
3. **既存解答のスタイルを踏襲**: 同一ファイル内でフォーマットを統一
4. **選択肢テキストを改変しない**: 問題文・選択肢は元のまま保持
5. **`toc_max_heading_level: 2`** が frontmatter に設定されていることを確認（未設定なら追加）

## 正答 PDF の配置場所

```
docs/textbook/技術士（総監）/過去問/
  R01/R01_試験問題_択一式_正答.pdf
  R02_試験問題_択一式_正答.pdf
  ...
  R07_試験問題_択一式_正答.pdf
```

年度の推定ルール: MDX ファイルパスの `r01`, `r02`, ... `r07` から `R01`, `R02`, ... `R07` に変換。
