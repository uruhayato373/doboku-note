## 文書の特徴

### テキスト抽出

PyMuPDFで抽出可能だが、**表のレイアウトが崩壊しやすい**。

- **散文ページ**: 良好。見出し・本文がクリーンに取れる
- **表ページ**: 表のセル内容が混在・順序が崩れる → 画像抽出 or PDFページ画像を見ながら手動再構成
- **図ページ**: テキスト少なく、キャプションのみ

```python
import fitz, sys, io
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')

doc = fitz.open('第１章_道路一般.pdf')
for i in range(start_page, end_page):
    text = doc[i].get_text()
    print(f'--- Page {i+1} ---')
    print(text)
```

### ページフッタ

`X-NN` 形式のページ番号（例: `1-5`, `1-31`）→ 除去する

### 出典注記

右欄外に「出典：文献名 pXX」形式の注記がある。

**変換方針**: 設計便覧と同様、MDXでは `:::note` ブロックに変換:

```mdx
:::note[出典]
道路構造令の解説と運用 p287～
:::
```

重要な出典のみ記載。連続する場合や本文理解に不要な場合は省略可。

### 見出し体系

```
第X章 タイトル        → ファイル先頭の frontmatter title
X. or X－X 大見出し   → h2: ## X. タイトル
X－X 中見出し         → h3: ### X-X タイトル
(X) 小見出し          → h4: #### (X) タイトル
```

### 兵庫県独自基準

本文中に「【兵庫県独自基準】」のラベルがある箇所がある。以下のように変換:

```mdx
:::info[兵庫県独自基準]
独自基準の内容
:::
```

### 表

- **単純な表**: Markdownテーブル（`<div className="table-wrapper">` で囲む）
- **複雑な表**（セル結合、斜線ヘッダ等）: PNG画像として抽出
- **表タイトル**: `<p className="table-title">表X-X-X タイトル</p>`
- **テキスト抽出が崩壊する表**: PDFページを画像化して確認し、手動でMarkdown表を構成

### 図

- PDFページをPNG化（150 DPI） → PILでトリミング → R2にアップロード
- **R2パス**: `content/general/tech-management/img/{編略号}-fig-{連番2桁}.png`
- **MDXでの参照**: `<img src="/content/general/tech-management/img/{編略号}-fig-01.png" />`
- **図キャプション**: `<p className="text-center">図X-X-X タイトル</p>`
- **命名**: `{編略号}-fig-{連番2桁}.png`（例: `road1-fig-01.png`, `river-fig-01.png`）
- **表画像命名**: `{編略号}-tbl-{連番2桁}.png`
- **画像はGitに含めない** — R2 (`storage.doboku-note.com`) から配信

### 数式

- ブロック数式: `<div className="scroll-equation">$$...$$</div>` + `\tag{}`
- インライン数式: `$...$`
- 道路I編・河川編ではほぼなし。橋梁編・砂防編の設計部分に集中

## 変換手順

### Step 1: PDFパスの確認

章別PDFがある場合はそれを使用。ない場合は統合PDFの該当ページ範囲を使用。

### Step 2: テキスト抽出

PyMuPDFでテキスト抽出。同時にページをPNG化して図・表の位置を確認。

**統合PDF（道路II編、トンネル編等）の場合**:
1. 最初に目次ページを抽出して章構成・ページ範囲を特定
2. このSKILL.mdの該当テーブルを更新
3. 章ごとにページ範囲を指定して変換

### Step 3: MDX変換

テキストをMDX形式に変換。見出し階層・表・図・数式のルールに従う。

### Step 4: 図の抽出 → R2アップロード

PDFページをPNG化（150 DPI） → PILでトリミング → `/tmp/` に一時保存 → R2にアップロード。

```bash
# R2アップロード（S3 API、20並行）
node scripts/upload-images-to-r2.mjs --prefix general/tech-management
```

**R2キー**: `content/general/tech-management/img/{編略号}-fig-{連番2桁}.png`
**参照URL**: `/content/general/tech-management/img/{編略号}-fig-{連番2桁}.png`

> **注意**: 画像はGitに含めない。`content/**/img/` は `.gitignore` 対象。R2のみが正とする。

### Step 5: 構文チェック

`/check-mdx` でMDX構文を検証。

### Step 6: ビルド確認

`npm run build` で全体のビルドが通ることを確認。

### Step 7: 進捗更新

このスキルファイルの状態欄を更新。

## エージェント戦略

### 基本原則

- **1章（or 1編） = 1エージェント**（章別PDFがある場合）
- 40ページ超は**節単位で分割**する
- 最大**3エージェント並列**起動

### 分割基準

| ページ数 | 分割 | エージェント数 |
|---|---|---|
| 1-40P | 分割なし | 1 |
| 41-80P | 節単位で2分割 | 2 |
| 81-150P | 節単位で3分割 | 2-3 |
| 150P超 | 目次で章分割してから上記を適用 | 3+ |

### 統合PDF（道路II編 833P 等）の対処

1. まず目次を抽出して章構成を特定（1エージェント）
2. 章ごとにページ範囲を確定し、SKILL.md を更新
3. 以降は章単位で通常の変換フローを実行

### 図の抽出・R2アップロードエージェント

- 1エージェントあたり最大6図
- 150 DPI でレンダリング
- 一時ファイル: `/tmp/tech-management-{編略号}/page-{NNN}.png`
- 抽出後に `content/general/tech-management/img/` に保存
- 全図完了後にまとめてR2アップロード: `node scripts/upload-images-to-r2.mjs --prefix general/tech-management`
- MDXでは最初からR2 URL (`/content/...`) で参照する
