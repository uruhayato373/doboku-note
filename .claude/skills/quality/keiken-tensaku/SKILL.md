## 用途

添削サービス（合格ラボ「添削つきプラン」週次添削／ココナラ単発添削）の**1本あたり工数を定数化**する。
添削3ステップ（[2級経験記述-添削テンプレ.md](../../../../docs/note/1級・2級土木/2級土木/2級経験記述-添削テンプレ.md)）のうち、ステップ1（字数）・ステップ2（論点抽出）・ステップ3の**下書きまで**を `civil-keiken-tensaku-drafter` が自動化する。

```
/keiken-tensaku <提出原稿path> [--grade 1|2] [--theme 安全|品質|工程|施工計画|環境]
```

## フロー

1. **入力検証**: 提出原稿の実在を確認。工事概要＋設問構造が読み取れない場合は不足項目を報告して停止（ヒアリングシートの再送を依頼する運用）。
2. **Generator 起動**: `civil-keiken-tensaku-drafter` に path / grade / theme を渡す。
3. **出力**: 提出原稿と同じディレクトリに `添削下書き.md`。
4. **運営者への引き継ぎ表示**: 以下のチェックリストを表示して終了。
   - [ ] ストップウォッチ開始（実測ゲート中は所要時間を [添削実測/README.md](../../../../docs/note/1級・2級土木/メンバーシップ/添削実測/README.md) の実測ログへ記録）
   - [ ] NG→OK は**最重要の1〜2点だけ**採用（全部直さない）
   - [ ] 採点者視点の一言のトーンを自分の言葉に
   - [ ] 返却（会員: note メンバーシップ掲示板／ココナラ: トークルーム）
   - [ ] 共通の誤りは「今月の重点」へ転記、匿名化して添削事例アーカイブへ

## 入力フォーマット（顧客への依頼形式）

ヒアリングシート（[ココナラ展開キット.md](../../../../docs/note/1級・2級土木/ココナラ展開キット.md) §ヒアリングシート）のテキストをそのまま .md 保存すれば入力になる。会員は週次お題への提出テキストをそのまま使う。

## ガードレール

- **代筆はしない（Red Line #2）**: 本スキルの成果物は「本人答案への赤入れ下書き」まで。原稿の代作依頼はサービス対象外として断る文面が展開キットにある。
- **返却前に必ず人が最終赤入れ**: 添削下書き.md をそのまま顧客へ送らない（末尾の AI 下書き注記が残っていたら未完成）。
- 提出原稿・下書きは商用の顧客情報。リポジトリ管理する場合は `docs/note/1級・2級土木/メンバーシップ/添削事例アーカイブ/` へ**匿名化してから**置く（生原稿はコミットしない）。

## 完了条件

- 添削下書き.md が返却フォーマット（字数判定表・チェックリスト・NG→OK 2点・一言2案）を満たして出力される。
- 運営者の最終赤入れが30分以内（超過が続く場合は定員10→6 or 隔週化を検討＝計画 §5.1）。
