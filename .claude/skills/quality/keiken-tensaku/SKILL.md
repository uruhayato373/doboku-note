## 用途

添削サービス（合格ラボ「添削つきプラン」週次添削／ココナラ単発添削）の**1本あたり工数を定数化**する。
添削3ステップ（[2級経験記述-添削テンプレ.md](../../../../content/note/1級・2級土木/2級土木/2級経験記述-添削テンプレ.md)）のうち、ステップ1（字数）・ステップ2（論点抽出）・ステップ3の**下書きまで**を `civil-keiken-tensaku-drafter` が自動化する。

```
/keiken-tensaku <提出原稿path> [--grade 1|2] [--theme 安全|品質|工程|施工計画|環境]   # 添削（既定）
/keiken-tensaku <ヒアリングシートpath> --grade 1|2 --mode kosshi                      # 骨子シート（ココナラ S3 指導の1段目）
/keiken-tensaku <下書きpath> --grade 1|2 --mode shindan                               # 診断（ココナラ S1）
```

**骨子モード（`--mode kosshi`）**: ココナラ S3「指導」の1段目。指導用ヒアリングシート（[ココナラ展開キット.md](../../../../content/note/1級・2級土木/ココナラ展開キット.md) §4b）の回答を、設問ごとに「何を・どの順で・どの数値で書くか」に並べた `骨子シート.md` を出す。事実は回答からの「」引用だけで示し、**答案の文章は書かない**（2026-09-25 に答案ドラフトを納品する作成サービスがココナラ運営に「学校の課題の代行」として取り下げられたため）。宣誓チェック未記入なら生成しない。回答が足りない箇所は `〇〇` と「確認したいこと」の質問にする。機械ゲートは `check-kosshi-sheet`。

**指導の2段目以降**: 本人が骨子をもとに書いた答案は、通常の添削（`--mode tensaku`）で添削する。書き直した答案の再添削（1回）も同じ。全テーマ版は、ヒアリングシートを書けたテーマから順に受け取り、骨子→添削をテーマ単位で回してよい。

**診断モード（`--mode shindan`）**: 下書き1テーマから **A/B/C 総合判定＋減点ワースト3（該当箇所→なぜ→方向性）＋字数チェック**の診断下書きを生成。**書き換え文（NG→OK の OK例本文）は出さない**＝S1 は診断のみの商品定義。出力は `診断下書き.md`（キット §4c「S1 診断 返却テンプレ」の型）。

## フロー

1. **入力検証**: 提出原稿の実在を確認。工事概要＋設問構造が読み取れない場合は不足項目を報告して停止（ヒアリングシートの再送を依頼する運用）。
2. **Generator 起動**: `civil-keiken-tensaku-drafter` に path / grade / theme / mode を渡す。
3. **出力**: 入力と同じディレクトリに `添削下書き.md`（添削）／`骨子シート.md`（骨子）／`診断下書き.md`（診断）。骨子は `node scripts/check-kosshi-sheet.mjs <骨子シート> --source <ヒアリングシート>` が exit 0 であること。
4. **返信文を作る**: 下書きから顧客へ送る文面を同じディレクトリに `返信文.txt` として作る（採用する指摘は最重要の1〜2点、書き換え例の見出し末尾に `（N字）` を付ける）。骨子は、返信文（短い送付文）＋骨子シートを送る。骨子シートが 3000 字を超えるならファイル添付にする（`check-kosshi-sheet` の出力に表示される）。
5. **返信文の検証（Generator/Evaluator 分離）**: `civil-keiken-tensaku-qa` に reply / source / draft / grade / mode を渡す（骨子は draft に骨子シートを渡し、`check-kosshi-sheet` も QA が実行する）。機械ゲート `node scripts/check-tensaku-reply.mjs <返信文> --source <原稿> [--grade N]` はこのエージェントが実行する。**PASS になるまで親が返信文を直して再検証する**（FAIL・BLOCKED のまま運営者へ渡さない）。
6. **運営者への引き継ぎ表示**: QA の判定と「未確認のまま残る点」を添えて、以下のチェックリストを表示して終了。
   - [ ] ストップウォッチ開始（実測ゲート中は所要時間を [添削実測/README.md](../../../../content/note/1級・2級土木/メンバーシップ/添削実測/README.md) の実測ログへ記録）
   - [ ] NG→OK は**最重要の1〜2点だけ**採用（全部直さない）
   - [ ] 採点者視点の一言のトーンを自分の言葉に
   - [ ] 返却（会員: note メンバーシップ掲示板／ココナラ: トークルーム）
   - [ ] 共通の誤りは「今月の重点」へ転記、匿名化して添削事例アーカイブへ

## 入力フォーマット（顧客への依頼形式）

ヒアリングシート（[ココナラ展開キット.md](../../../../content/note/1級・2級土木/ココナラ展開キット.md) §ヒアリングシート）のテキストをそのまま .md 保存すれば入力になる。会員は週次お題への提出テキストをそのまま使う。

## ガードレール

- **捏造はしない（Red Line #2 再定義）**: 添削は原稿の事実の範囲・骨子はヒアリング回答からの引用のみ。**経験していない工事・事実・数値を創作しない**（欠落は追加質問 or `〇〇` プレースホルダ）。骨子モードは宣誓チェック（実経験工事のみ）未記入なら生成しない。
- **代筆しない**: 骨子シートに答案の文章を書かない。答案を書くのは本人（ココナラの取り下げ理由「学校の課題の代行」に当たるため）。
- **返却前に必ず人が最終赤入れ**: 添削下書き.md をそのまま顧客へ送らない（末尾の AI 下書き注記が残っていたら未完成）。
- 提出原稿・下書きは商用の顧客情報。リポジトリ管理する場合は `content/note/1級・2級土木/メンバーシップ/添削事例アーカイブ/` へ**匿名化してから**置く（生原稿はコミットしない）。

## 完了条件

- 添削下書き.md が返却フォーマット（字数判定表・チェックリスト・NG→OK 2点・一言2案）を満たして出力される。骨子は `骨子シート.md` が `check-kosshi-sheet` exit 0（引用・数値の実検査件数を確認）。
- 返信文.txt が `check-tensaku-reply` exit 0（書き換え例・数値の実検査件数を確認）かつ `civil-keiken-tensaku-qa` PASS。
- 運営者の最終赤入れが30分以内（超過が続く場合は定員10→6 or 隔週化を検討＝計画 §5.1）。
