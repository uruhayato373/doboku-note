管理画面（tools/admin-app）は人が見る画面として、必要な値だけを適切な密度で出す。ページ見出しの説明（正本のパス・判定の説明）、照合記録・出典・未確認の理由・データ上の長いラベル・id は出さない。それらはエージェントが正本（JSON）とレポート（例: `npm run exam-ssot-status`）で管理する。グルーピングはスクロールを減らすためタブ（`.filterbar a.chip`）にする。KPI カードはラベルと値だけ（アイコン・装飾線なし）。警告は正本の不整合など人が動く必要があるときだけ出す。カード（`.card`）の中にカードや枠付きの折りたたみを入れない（枠はページの区切りだけ。中は区切り線・余白・左罫で整理）。詳細はトップに折りたたまず別ページへ「詳しく見る」カードで送る。

**Why:** 2026-09-26、資格一覧画面に説明文・照合列・出典・注記を並べたら「冗長・人には不要・スクロールが多い」と指摘され、KPI のアイコンも「意味がない」と言われた。2026-09-27 にはカード内カードを「やめた方が良くない？」と指摘された。2026-10-25 には、新しく作った `/ops/mac`・`/ops/ci` に正本のパス・コマンドの説明・「何をするか」「読み手」の長い列を並べて「情報が多すぎる」と言われた（この記憶を読まずに作った）。2026-11-02 にも `/strategy/channels` に手数料の割合の数字カード・節ごとの注記・KPI の理由の文・承認の列を並べ、「スタッツカード不要・データテーブルが煩雑・説明文はいらない」と言われた（4 回目・やはり読まずに作った）。数字・4P と 4C・SWOT をタブに分け、値だけにして直した。

**How to apply:** 新しい管理画面を作る・既存に節を足す前にこの記憶を読む（作ってからでは遅い）。数字カードは判断に使う値だけ（料率や根拠の値は出さない）、表の列は判断に要るものだけ、説明・理由・注記は正本と docs に置く。まず「人がこの画面で判断すること」に要る列だけを決め（状態の一覧なら名前・状態・最終の 3 列で、問題のある行を上に）、エージェント向けの情報は正本とレポートに置く。関連: [[feedback_ssot_no_hand_copies_self_verify]]
