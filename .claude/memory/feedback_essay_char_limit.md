## 字数制約を最初の評価軸にする
総監記述式模範論文をレビュー・新規執筆するときは**字数制約を最初の評価軸として提示**し、内容質・専門度・散文性・事実誤認の評価は字数制約に整合してから着手する。
- 設問(1): 答案用紙1枚以内＝**600字以内**。設問(2)・(3): 各組合せ1枚以内×2施策＝**各施策600字以内／計1,200字**。**合計3,000字以内**。
- 「答案用紙1枚以内」は厳密な上限（許容範囲なし）。マージン確保のため**目標585〜600字**。参考実測（R7 A案）: 設問(1)619／設問(2)施策1 578・施策2 618／設問(3)施策1 624・施策2 657／合計3,153。R7 A案は超過例であって基準にしない。
- **Why:** 2026-05-25 の R8予想問題集レビューで「R7 A案も660字程度なので同水準まで許容」としたのは誤り。「本番では書ききれない量」を公開しかけた。AI社会記事の初版は各施策860〜920字で大幅圧縮が必要、残5記事も設問(3)で600字超過のため再圧縮した。
- **How to apply:** レビュー時の最初の出力は字数表（各設問・各施策別・上限との差）。600字超があれば「まず圧縮、その後に内容質を議論」と宣言。計測スクリプト（Python）:
  ```python
  import re
  def count_between(path, start, end):
      with open(path, encoding='utf-8') as f:
          text = f.read()
      s = text.find(start); e = text.find(end, s+1) if end else len(text)
      body = re.sub(r'[#*`\-|\[\]()>]+', '', text[s:e])
      return len(re.sub(r'\s+', '', body))
  ```

## 設問(2)は散文化（箇条書き禁止）
設問(2) 5年以内の施策に「**内容**: … **根拠**: … **効果**: …」の bold ヘッダ＋箇条書きを使わず、R7 同ペルソナ模範論文（`docs/note/magazines/総監模範論文-*/R07/article.md`）と同じ流れる散文段落へ統合する。
- **Why:** 本番答案は手書き散文で、箇条書き提示は読者の答案構造の参考にならない。2026-05 R8予想問題集「AI社会」記事で「R7 と比べて品質が落ちている」と指摘された。
- 各施策は「内容として〜。〜することで〜（根拠）。効果として〜（経済性管理）、〜（情報管理）。」の1段落。「**障害と克服策（トレードオフ）**」も「障害として〜（**A × B** のトレードオフ）。克服策として〜」と段落で。設問(3)も同様。

## 設問(3)は一般技術者レベル
事業・組織の枠を超えた国レベル施策は、**一般技術者なら自分の言葉で書けるレベル**に揃える。EU AI Act・第三者認証制度・AI-SBOM・サプライチェーンリスク評価・基盤モデル等の法制度設計/ICT サプライチェーン専門用語は避ける。
- **Why:** 専門知識を前提にすると「自分には書けない論文」になる。R7 A案（自治体道路担当）の設問(3)は「労働力人口確保」「社会保障制度の持続可能性」という一般市民でも理解できる施策。2026-05 R8「AI社会」で設問(3)を「EU AI Act 準拠の用途別リスク AI 認証制度」「AI-SBOM」で書いて「専門的すぎる」と指摘され案β（規制制度設計＋人材育成＋社会受容性）へ書き直し。
- **How to apply:** 書く前に同ペルソナの R7 模範論文の設問(3)を Read して語彙レベルを揃える。制度設計は「リスクに応じた規制」「定期見直し条項」「監督権限の集約」など一般語彙（固有制度名・専門用語は撤去）。人材・社会受容性側の施策（人材育成・代替チャネル維持・救済制度・透明化）を必ず1施策入れ規制と社会の両輪で。トレードオフは 経×情・人×経・社×経 など5管理間の一般的対立軸。

## 立場ラベルは越権施策を生まないシンプルな肩書きに
立場ラベル（例: 道路維持課 課長補佐）に「(情報化・DX 担当)」「(サイバーセキュリティ統括)」等の兼務を付与すると所掌外の施策（CIO 部局のゼロトラスト移行・全庁ネットワーク整備）を立ててしまい「自分が監理できる範囲」を逸脱する。総監記述式は受験者の業務経験が起点で、採点者から「監理対象が曖昧」「役職と施策のスケールが合っていない」と判断される。
- **Why:** 2026-05 R8「AI社会」記事で「道路維持課 課長補佐（情報化・DX 担当）」と兼務付与し、施策2で「ゼロトラスト移行」を自前実施する越権施策を書いて書き直した。
- **How to apply:** R7 同ペルソナ模範論文の肩書きと同水準に揃える。他部局の所掌に踏み込む施策は「CIO 部局と連携して〜」「情報政策課と協議のうえ〜」と所掌調整の枠組みで書く（自前実施にしない）。立場ラベルを盛る必要があるなら施策スケールを役職に合わせて縮小するかラベルを見直す。

## 答案テンプレは「○○管理軸」で固定しない（2026-04-29）
論文骨子テンプレートを「安全管理軸」「経済性管理軸」のように5管理のうち1つで固定しない。試験構造は **テーマ（出題側が決める: 少子高齢化/DX/働き方改革/カーボンニュートラル/インフラ老朽化 等）× 5管理（経済性/人的資源/情報/安全/社会環境・普遍）× 専門部門（受験者が持ち込む: 建設部門の道路・河川・コンクリート…/機械/電気電子）の3Dマトリクス**で、評価軸は「テーマに対し5管理を横串で書く」こと。管理を1つ固定してもテーマがそのズレた瞬間に機能しない。
- 骨子テンプレ・答案構成は「テーマ非依存・5管理均等扱い」を基本に。1つの管理を題材にした具体例は OK だが「軸」と呼んで商品化しない。細分化は「テーマ別マッピング」＋「専門部門別具体例」の方向（管理軸並列ではない）。出典: 2026-04-29、14ドラフト「論文骨子テンプレ」を「安全管理軸」→「テーマ駆動5管理横串」に全面リライトした事例。
