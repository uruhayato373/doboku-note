2026-06-12 に運用 X アカウント（@dobokunotecom）が「platform manipulation and spam」（日本語通知では「偽装行為」＝同一カテゴリの訳ぶれ）で凍結された。これを踏まえ X 投稿基盤に凍結回避ガードレールを新設した（真実源 `docs/reference/x-post-policy.md` §11）。

**続報（同日 異議申し立て却下）**: 異議申し立て（文面審査）は「当初の決定を撤回する正当な理由はない」として却下。ただし通知末尾に「ログイン → 画面手順を完了して違反を解決」とあり、**異議とは別系統の自助解除パス（ロック/機能制限状態の SMS・電話番号認証/captcha）が残る**＝却下＝終わりではない。解除手順は**メール内リンクから辿らず必ず自分で x.com/公式アプリを開いて**完了する（凍結通知を装うフィッシングが常態。受領通知に "witter" 等の崩れあり）。対応として `publish-x`（Playwright 自動投稿）を当面停止し、戦略上 X を「主力」から外して IG/note へ重みを移した（SNS戦略 v7.3）。**2026-06-19 追記**: 凍結は解除されないまま技術士二次試験シーズン（2026-W25）を迎えたため一旦 X 投稿を断念、todo から除外。**2026-06-21 更新（断念は撤回）**: ユーザーが**新 X アカウントで再開**を決定（技術士建設7/20・総監7/19 の1ヶ月前カウントダウン、1日2投稿）。`§11.3` のとおり凍結回避目的の新アカ量産は ban evasion 判定リスクがあることを surface した上での判断。再発防止に **`npm run x-schedule-guard`（予約前ゲート・§11.5）** を新設＝同時刻衝突／near-dup／1日上限／古い予約残存を機械 BLOCK。旧アカ status は `docs/sns/x/draft/_archive-old-account/` へ隔離（`_`接頭辞でスキャン除外＝新アカはクリーン台帳）。詳細は [[project_x_account_reboot_2026_06]]。

主なルール:
- 文面のユニーク性: near-duplicate なテンプレ骨格を反復しない。各ツイートでフック・語順・CTA を変える。同一 URL を連投の何本にも貼らない（一部だけに付ける）。
- 頻度/間隔: 1 日 3〜5 本（新規期 2〜3）、同時刻一括予約を避け時刻ジッタ、バースト連投せず 60〜90 分間隔、数十本を一度に予約キューへ積まない。
- 自動化フットプリント最小化: 自動投稿より writer 半自動生成＋人手投稿/リプライが基本。自動フォロー/いいね/リプライ禁止。凍結時は SMS 等正規手順で解除し ban evasion しない。

実装箇所: policy §11（SSOT）/ `x-post-writer`（執筆時の自己点検＋品質ガード）/ `x-post-qa`（重大減点ゲート、5 軸に薄まらないブロッキング判定）/ `publish-x` SKILL（投稿頻度・間隔の警告節）/ `docs/sns/x/README.md`（やってはいけない/やるべき）。

**Why:** Playwright 自動投稿・1問1答パック・angle-slice は重複/自動化臭の高い投稿を量産しうる。文字数やリンク 404 と同格のブロッキングリスクとして扱わないと再凍結する。

**How to apply:** X 投稿を書く/予約する前に policy §11 を読む。writer 出力は `x-post-qa` の凍結リスク・ゲートを通す。`publish-x` の日時引数は同時刻で並べずジッタを入れ、1 回数本に留める。関連: [[feedback_publish_x_false_success]]（予約偽成功の実査）。
