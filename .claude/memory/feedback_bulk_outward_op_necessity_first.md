外向きの一括操作は、本数・間隔・順番の案を出す前に、やらない場合に何が壊れるかを実測する。そのうえで「必須」と「任意」を分けて出す。

**Why:** 2026-09-24、PR #598（note 原稿 675 本のリンク張り替え）の後、`check-note-republish` の「要再公開 674 本」をそのまま受け取り、674 本の全文置換を段階的に流す案を出した。実際には旧 `/docs/` は本番で 301 転送され UTM も残るため、必須だったのは 404 を直した 1 本（配合計算-実戦演習）だけだった。ユーザーに「なぜ必要？」と聞かれて初めて絞った。さらに「転送 1 回分だけ」と説明したが、#598 の PR 本文には「Google が旧 URL を正規に選ぶ（重複 18 件）」という SEO 上の理由が書かれていて、それを読み落としていた。データで確かめると、17 件のうち 7 件は note から張られていないのに同じ状態で、note の寄与は未検証だった（DN-0298 で追跡）。全文置換は有料境界・画像・PDF を壊しうる（[[feedback-platform-only-artifacts-destroyed-by-bulk-ops]]）ので、不要な分まで流すのは害になる。
さらに逆方向の誤りもした。「必須は 1 本」と絞った根拠は #598 の差分だけで、同じ drift に 9/23 18:47 の表示崩れ修正（太字が `**` のまま出る 149 か所・重複画像）が混ざっていたのを見落とした。DN-0297 で drift を分類して初めて、要再公開 128 本の大半が live で実際に崩れていると分かった（公開 API で `**` を確認）。

**How to apply:**
- surfacer の件数（drift・要対応 N 件）をそのまま作業量にしない。まず「現状のまま放置すると読者・計測・SEO のどれが実際に壊れるか」を実物で確かめる（curl で 301 と UTM、ライブの 404 など）。
- 起点になった PR やカードの「なぜ」を読み、主張された効果はデータで裏を取ってから必要度を判断する。裏が取れなければ「未検証」と書く。
- drift の中身は 1 つの PR の差分で代表させない。記録時の版と現原稿を実際に比べ、変更の種類ごとに数える（`check-note-republish` の 301 等価判定・`note-republish-plan` の分類）。
- 案は「必須（壊れているもの）」と「任意（等価・将来のため）」に分け、任意分は次の改稿時に反映する、あるいはデータで条件がそろったら実行する、を既定にする。
