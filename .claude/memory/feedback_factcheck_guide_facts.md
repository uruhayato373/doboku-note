## ガイド記事の試験統計・制度は公開前に一次情報照合
ガイド記事（`group: guide`）に加筆した検証可能な事実（合格率・合格基準・受験資格・試験構成・制度改正・試験日程・年収/手当・法令）は LLM が高頻度で誤る。Opus でも外す（2026-06-21、Opus版 guide-textbooks 自身に「応用能力＝令和6（正：令和3）」「第1次合格＝5年有効（正：無期限）」の誤り）。32本検査で**43件の suspicious**を検出・是正。
- **Why:** 試験制度は年度改正が多く（令和3＝技士補/応用能力・無期限化、令和6＝受験資格/経験記述見直し）LLM は年度の帰属を混同し、合格者数（1次=技士補 vs 2次=技士）や試験回数（1次=年2回/2次=年1回）も取り違える。受験者が依拠する核心情報で実害。
- **How to apply:** 加筆・リライトしたガイドは公開前に `guide-fact-checker`（Evaluator・WebSearch・sonnet）で一次情報照合（国交省 `tochi_fudousan_kensetsugyo`・全国建設研修センター JCTC・日本技術士会・文科省・JCI・e-Gov・厚労省）。suspicious は `guide-rewriter`（Generator）が正値で是正。特に pe/総監は運営者の専門外でハルシネーション最大。fact-check を省いて「lint清浄・3000字達成」だけで公開しない。品質サイクル（guide-qa→guide-rewriter→guide-fact-checker）は agents-registry の「ガイド品質サイクル」行が真実源。関連: [[feedback_content_structure]] [[feedback_opus_sonnet_split]] [[feedback_workflow_orchestration_gotchas]]

## 白書を出典にする前に章構成と原表現を確認
「令和7年版情報通信白書によれば〜」と書く前に WebSearch で白書の章構成と原表現を確認する。ハルシネーション・ランサムウェア・サプライチェーン攻撃・生成AI悪用といった耳慣れた用語を出典確認なしに白書由来として書くと事実誤認。
- **Why:** 2026-05、R8予想問題集「AI 社会」記事で「令和7年版情報通信白書で…ハルシネーション・偽情報の大規模拡散・サイバー攻撃の高度化（ランサムウェア・サプライチェーン攻撃・生成AI悪用）が論点化」と書いたが、原文には「偽・誤情報」「AI の爆発的な進展」はあっても「ハルシネーション」「ランサムウェア」「サプライチェーン攻撃」「生成AI悪用」は明示的に登場しない、または別文書（サイバーセキュリティ 2025）の表現と混在していた。
- **How to apply:** 白書名・特集タイトル・章番号・章タイトルは公式 HTML（総務省・文科省・NISC）の概要ページで先に確認。「白書に〜と書かれている」と書くならその単語が原文か公的サマリーに登場するか WebSearch で1回確認。確認できない単語はより広い概念語に置換（ハルシネーション→偽・誤情報の流通）。NotebookLM が使えるなら `notebooklm-research` で本文照合（認証期限切れは `notebooklm login` をユーザーに依頼）。数値検証は `.claude/scripts/whitepaper-grep-check.mjs`。

## 参考資料 URL は WebSearch→WebFetch で実在確認（推測・パターン補完禁止）
新規 URL を参考資料・Callout reference・本文リンクに書く前に必ず実在確認。
- **Wikipedia（2026 前）**: 「デザインイン」の URL を推測で書いたが正式項目名は「デザイン・イン」（中黒あり）で404。中黒・漢字/カタカナ表記ゆれで別ページになるため、WebSearch で正確な項目名→WebFetch で200と関連内容を確認。content-principles.md 原則12に反映済み。
- **連番 URL の捏造（2026-05-27、エネルギーキーワード分割・commit c7f5aa167）**: EMIRA `pedia/{数字}/` パターンを3件パターン補完で書き全て404。cem-qa 並列評価で発見、修正 commit 646d2461f で民間ソースを差し替え。lint MDX PASS + HTTP 200 だけで品質保証されたと誤判定し、cem-qa 起動前に commit したのが直接原因。民間解説サイトの `{site}/pedia/{番号}/`・`{site}/article/{連番}/`・`{site}/category/{id}/` 系は特に危険。「他の番号で存在するから」「いつもこの形式だから」を理由に未確認 URL を書かない。候補は WebFetch で実在確認→404/redirect なら別 URL→見つからなければ削除。新規キーワードページは commit 前に必ず cem-qa Evaluator（5軸）を起動（lint だけで済ませない）。
- ガード公式化: `content-principles.md §12`（連番 URL 捏造リスク）／`cem-qa.md`「参考資料 URL 捏造の検出」節（HIGH 違反）／`keyword-rewriter.md`（新規 URL の WebFetch 必須＋cem-qa 起動）。

## 運営者の合格科目外の分野は独立 QA 必須（2026-08-20）
運営者が合格していない分野（建築施工・設計コンサル・試験検査機関・発注者としての主任技士実務など）の商品は、Generator/Evaluator 分離と WebSearch ファクトチェックを省略しない。自分の科目内なら誤りに気づけるが科目外は「読んで違和感がない」ため素通りする。機械ゲート（note-lint・字数・ハッシュタグ）は体裁のみで内容の正しさは検出しない。
- **捕捉した実例（DN-0095・コンクリート主任技士32本）**: ①法令と逆向き: 支保工の「盛替え」を計画的に実施する場面として記述（**昭和46年建設省告示第110号 第二は大ばりの支柱等の盛替えを禁止**・JASS 5 も「原則として行わない」）。②技術的に成立しない機構説明: W/C 上限を課す理由を「単位セメント量を増やして強度を満たしながら W/C は高いままという配合が成立しうるから」と書いた（水量一定でセメントを増やせば W/C は下がる。正しくは同一呼び強度が材料・混和材・判定材齢によって複数の W/C で成立しうる、が理由）。③裏取りできない断定: ASR の「水分がなければ膨張が進行しない」（実務は相対湿度の閾値・部材内部は外気が乾いていても高湿）、「更新1回の環境負荷 > 補修の積み上げ」（構造物種別と評価期間で逆転）、打放し色むらの原因列挙（系統実験と寄与度が逆転）。
- **How to apply:** ①執筆と採点を別エージェント ②Evaluator に「断定が強すぎないか」「一次資料で確認できるか」を明示的に問わせる ③数値・条番号は原則 `〇〇` プレースホルダにし確信のあるもの以外を書かせない。QA が「WARN 4件」程度で済んだ回でも BLOCK は別の立場の記事から出た＝全立場・全テーマを通す。関連 [[feedback_essay_persona_authentic_seat]]
