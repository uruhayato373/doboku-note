# note 記事 構成テンプレート（売れる9型）

note 記事を「読まれて・買われる」状態に組み上げるための**記事内部の構成（本文の型）**の真実源。資格を問わず共通で使える。外部の note 販売実績に基づく構成論を、本プロジェクト（土木・建設系試験対策 note）向けに翻案したもの。9 型は note が主戦場だが、下の**強化コンポーネント**はチャネル横断（note 有料記事／Brain LP／ココナラ出品文面）で使える共通部品として、Brain・ココナラの出品文面からも本書を参照する。

> [!important]
> **真実源の責務分担**（混同しない）
> - 本書 = **記事内部の構成**（1 本の記事の中で、読者の悩みをつかみ → 購入理由を作る本文の型）の SSOT
> - [note-funnel-architecture.md](note-funnel-architecture.md) = **記事間の回遊・購入動線**（どの記事からどこへ送るか／L1-L2-L3 の CTA 配線）の SSOT
> - [note-publish-enhancement.md](note-publish-enhancement.md) = 公開レベルへ引き上げる**作業工程**（網羅性・図版・段落分割等）
> - [note-essay-review-checklist.md](note-essay-review-checklist.md) = 模範論文の**字数・散文性レビュー**手順
>
> 本書は「記事の中身をどう並べるか」、funnel は「記事から記事へどう送るか」。両方を満たして初めて売れる。

## 大原則 — 5 ステップの骨格

型は 9 つあるが、土台は 1 つ。**売れる記事は文章の美しさではなく、この流れの有無で決まる。**

1. **読者の悩みをつかむ** — 読者の言葉で悩みを名指しする（綺麗な導入より、自分の悩みに名前をつけてほしい）
2. **原因を言語化する** — 「うまくいかないのは〇〇が原因」と読者が気づいていない真因を見せる
3. **解決策を見せる** — この記事（商品）で何が変わるかの方向性を提示
4. **読後の変化を約束する** — Before → After。読者が「自分も行けそう」と思える未来
5. **次の行動へつなげる** — 無料部分なら有料へ、無料記事なら回遊先へ（[funnel](note-funnel-architecture.md) L3 と連結）

> [!note]
> 読者が欲しいのは「情報」ではなく「変化」。試験対策 note でも同じで、過去問解説そのものより「**この型を覚えれば本番で書ける／取りこぼさなくなる**」という変化を冒頭で約束する。

## 9 型

各型は「ねらい → 型（ステップ）→ 本プロジェクトでの例」で示す。1 記事に複数型を重ねてよい（例: 冒頭=悩み直撃型、本文=ロードマップ型、末尾=販売導線型）。

### 1. 悩み直撃型

- **ねらい**: 読者の悩みをそのまま冒頭に置き「これ、自分のことだ」と感じさせる。初心者が最初に覚える基本型。
- **型**: 悩みを書く → 「でもそれは〇〇が原因ではない」とズラす → この記事で解決すると宣言。
- **例（試験対策）**: 「過去問は解けるのに、本番の記述で手が止まる」「経験記述が毎年 C 判定で理由が分からない」を冒頭に置く。

### 2. 勘違い破壊型

- **ねらい**: 読者が信じている間違いを壊す。「自分が間違えていたかも」と感じた瞬間に続きを読みたくなる。
- **型**: 多くの人は〇〇だと思っている → でも本当の原因は〇〇 → だからまず〇〇を直す。
- **例**: 「総監は知識量で決まる」と思われがちだが、本当の差は**5 管理のトレードオフを自分の言葉で語れるか**。「精読すれば受かる」ではなく**頻出論点の取りこぼしを潰す**。

### 3. Before → After 型

- **ねらい**: 情報でなく**変化**を見せる。読者が未来に自分を重ねられると読み進める。
- **型**: 昔の状態 → 何が原因だったか → 何を変えたか → 変わった後の未来。
- **例**: 「テーマが決まらない」→「品質管理で 1 つ書き切れる」。「経験記述を晒すのが怖い」→「自分の現場に置換して 1 本完成」。

### 4. 失敗談 → 教訓型

- **ねらい**: 失敗談は黒歴史でなく、読者の未来の失敗を減らす素材。「つらかった」で終わると日記、行動に変えれば商品。
- **型**: 失敗を書く → なぜ失敗したか分解 → 学んだ教訓 → 読者が同じ失敗を避ける方法。
- **例**: 減点された答案・不合格年の答案を提示し、どこで落としたかを分解 → 改善の型へ。**施工経験記述商品と相性が最良**（減点回避を売りにできる）。

### 5. ロードマップ型

- **ねらい**: 「何から始めればいいか分からない」読者に順番を見せる。初心者は正解より**順番**が欲しい。
- **型**: ゴールを示す → 手順を分ける → 各ステップでやること → 今日やる一歩まで落とす。
- **例**: 「合格答案を 14 日で 1 本」「必須 I を 3 ステップで組む（課題抽出 → 解決策 → リスク）」。模範解答集・予想問題集の導入に強い。

### 6. チェックリスト型

- **ねらい**: 読者が自分で診断できる。保存されやすい。迷っている読者に「自分はどこで詰まっているか」を理解させる。
- **型**: 売れない（受からない）原因を提示 → チェック項目 → 当てはまる項目ごとの改善策 → まず直す 1 つを指定。
- **例**: 「経験記述 減点チェック 7 項目」「II-1 が書けない人の確認 5 項目」。案内記事・もくじでの自己診断にも有効。

### 7. 比較型

- **ねらい**: 売れる人／売れない人（受かる人／落ちる人）を並べ、読者に現在地を理解させる。差が見えると行動が変わる。
- **型**: ダメな側の行動 → なぜダメか → 良い側の行動 → 今日から変える行動。
- **例**: 「落ちる答案は施工内容を羅列、受かる答案は課題→対応→効果で語る」。**案内記事・もくじ（L2）で商品選びの軸を作る**のに最適。

### 8. ケーススタディ型

- **ねらい**: 抽象論だけだと読者が動けない。1 事例を分解し、真似できる形まで落とす。
- **型**: 具体例を出す → うまくいった理由を分解 → 読者が真似できる形に変える → 自分の場合への置き換え方。
- **例**: 「R07 道路 III をどう組んだか」を設問読解 → 骨子 → 肉付けの順で分解。予想問題集の予想根拠提示にも使える。

### 9. 販売導線型

- **ねらい**: 書いた後に売るのでなく、**書く前から購入理由をどこで作るか**を設計する。無料部分が前置きになっていると売れない。
- **型**: 無料部分で悩みを言語化 → 原因を見せる → 解決の方向性を見せる →（paywall）→ 有料部分で具体手順を渡す → 最後にもう一度買う理由を整理。
- **例**: 無料部分で「なぜ毎年 C 判定か」を言語化し、有料部分に「完成答案＋置換ガイド」を置く。**note の無料部分は読ませる場所でなく、購入理由を作る場所**。[funnel](note-funnel-architecture.md) の paywall 直前 CTA と連結する。

## 資格・記事タイプ別の「かき分け」

どの記事でどの型を主に使うかの早見表。1 記事に複数型を重ねる前提で「主に効く型」を示す。

| 記事タイプ | 主に効く型 | 使いどころ |
|---|---|---|
| 案内記事・もくじ（L1/L2） | 比較型(7)・チェックリスト型(6)・ロードマップ型(5) | 「どれを買えばいいか」読者の現在地を診断し該当商品へ送る |
| 無料 SEO 記事（サイト／note 無料） | 悩み直撃型(1)・勘違い破壊型(2) | 検索流入の悩みを冒頭で名指し → 本文・回遊へ |
| 有料記事の無料部分（導入〜paywall 手前） | 悩み直撃型(1)・Before→After 型(3)・販売導線型(9) | 無料部分で購入理由を作る（前置きで終わらせない） |
| 施工経験記述 商品 | 失敗談→教訓型(4)・Before→After 型(3) | 減点された答案 → 改善の型をフックにする |
| 模範解答集（建設部門・総監） | ロードマップ型(5)・ケーススタディ型(8)・勘違い破壊型(2) | 「合格答案はこう組む」を手順・具体例で分解 |
| 精読ガイド | 勘違い破壊型(2)・チェックリスト型(6) | 「精読＝合格」の常識を壊し、頻出論点の取りこぼしを潰す |
| 予想問題集 | ケーススタディ型(8)・ロードマップ型(5) | 予想根拠を事例分解で見せ、対策手順に落とす |

## 強化コンポーネント（型に載せる 6 部品）

9 型が「本文の流れ」なら、こちらは**どの型にも載せられる部品**。2026-07 の Brain 売れ筋（Claude×パワポ・200 部超）分析から抽出し、Brain 2 商品の LP で実適用した。**構成の逐語コピーはしない**——骨格を借りて、自分の言葉・自分の実績で書く。

1. **冒頭の社会的証明** — タイトル・冒頭に「なぜ信じてよいか」を置く。ただし**本物の検証可能な実績のみ**（公開日で検証できる事前収録・発注者＝採点する側の経験・技術士 2 部門など）。**部数・的中・合格率の捏造は Red Line 違反**（下の warning）。
2. **価値 3 点先出し** — 導入直後に「この商品が用意する 3 つのこと」を箇条で先に見せる。読者が読む前に価値を把握できる。
3. **中身の数え上げ** — 「スキル 1＋エージェント N 体＋テンプレ M 種＋検査 K 本＋サンプル」のように具体的に数える。抽象的な「充実の内容」より、数えられる具体が信頼を生む。
4. **「やることは、たった 3 つ」** — 使い始めの簡単さを 3 ステップで提示（例: 展開 → 入力 → 実行）。「難しそう」の離脱を防ぐ。
5. **インライン FAQ** — 購入前の不安を Q&A で先回り（動作環境・代筆でないか・向かない人）。反論処理を本文に内蔵する。
6. **図版で実物を見せる** — フロー図・3 ステップ図・Before/After を挿入し「動く実物」を想像させる。Brain 実例: `.claude/config/brain/assets/figures/`（SVG 源＋PNG・note/サイト/SNS 再利用可）。

> [!note]
> **チャネル適合**（部品は共通だが効き方が違う）
> - **情報商材型（note 有料記事／Brain DL キット／ココナラ C 系 PDF）**: 6 部品を直適用してよい。
> - **ココナラ人力サービス（S1 診断／S2 添削／S3 作成）**: 買い手の関心は「作り手の信頼・何が届くか・受注の流れ」。**FAQ・社会的証明（権威）・数え上げは効くが、「たった 3 つ」は「ご購入後の流れ」へ翻案**し、DIY ツールの手順提示にしない。
> - 部品はメニュー。全部を機械的に詰めると金太郎飴化する——記事・商品タイプに合うものだけ選ぶ（9 型と同じ思想）。

---

> [!warning]
> **試験対策 note 特有の制約と両立させる**
> - 誇大表現・断定的な合否約束はしない（型は「読者の現在地理解」までで、過剰なセールスにしない）
> - フックは過去問・出題傾向・基準など**検証可能な事実**に立脚させる（[note-fact-checker](../../agents/note-fact-checker.md) 連携）
> - 無料部分で売り切ろうとして本編（解答・解説）の信頼を損ねない。冒頭 CTA は[funnel 原則 2](note-funnel-architecture.md)「冒頭=軽く・末尾=回遊」に従う
> - 外部の販売実績エピソード（金額・体験談）は**運営者自身の経験座でない限り本文に流用しない**（一人称で語れるかを確認）

## 適用のしかた（どの経路から参照されるか）

note 記事の**作成・リライト経路**ごとに、本書がどこから参照されるかを示す。記事タイプに合う型は上の早見表で選ぶ。**解答・答案・論文の本文そのもの**（中身）は各経路の既定ルール（字数・網羅・誠実表記・論述メソッド）が優先で、本書はその「外枠（フック〜無料部分〜導線）」にだけ適用する。

| 経路 | 担当 | 参照のされ方 |
|---|---|---|
| 建設部門 模範解答（過去問／予想） | `pe-secondary-exam-writer`（Generator）・`/pe-secondary-yosou` | エージェント定義から本書を参照（導入・無料部分・販売導線） |
| 1級2級 施工経験記述 | `civil-keiken-essay-writer`（Generator）・`/civil-keiken-magazine` | エージェント定義から本書を参照（導入・無料部分・販売導線） |
| 総監 記述式 模範論文（note・persona/R8予想/設問3バンク/クロストレードオフ） | `cem-essay-writer`（Generator）・`cem-essay-qa`（Evaluator） | Generator が定義＋ランブック [note-essay-review-checklist.md](note-essay-review-checklist.md) から型を選ぶ。QA は Red Line・散文性を見る（型そのものは採点しない） |
| 総監テキスト精読ガイド（note） | 親駆動（専任 writer なし） | [note-publish-enhancement.md](note-publish-enhancement.md) B1 から橋渡し |
| 全 note 下書きの公開前ゲート | `/note-prepublish-review` | Phase 1 で無料部分の5ステップ骨格を report-only 観点喚起（自動判定・BLOCK しない） |
| Brain キット LP（brain-market） | `brain-operator`・`/brain-publish`（`--replace-body`） | [brain-operations.md](brain-operations.md) §4 から本書「強化コンポーネント」を参照（LP 本文の型）。誠実表現は brain-operations 安全弁6 |
| ココナラ 出品文面 | `coconala-operator`・`/coconala-publish` | [ココナラ展開キット.md](../../../docs/note/1級・2級土木/ココナラ展開キット.md) §3 から本書「強化コンポーネント」を参照（C系PDF=直適用／S系人力=翻案） |

- **対象外（意図的）**: サイトの無料 SEO／参考ページ（キーワードページ・`/pe-essay-draft` の総監模範論文**サイト**ページ・過去問 MDX・textbook）。これらは販売ファネルでないため自動配線しない。検索流入の悩み直撃・勘違い破壊を SEO 記事の導入にも効かせたい場合は、別途その判断で早見表「無料 SEO 記事」行を適用する。
- 新しい記事タイプ・経路を増やすときは、上表と早見表に 1 行追記してから書く（その場のアドリブで型を増やさない）。
