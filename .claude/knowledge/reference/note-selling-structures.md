# note 記事 構成テンプレート（売れる9型）— doboku-note での適用

**本文の型そのもの（5 ステップ骨格・売れる 9 型・強化 6 部品・制約）の正本は Obsidian vault `memos/note記事構成SSOT.md`** で、このリポには [`.claude/shared-policy/STRUCTURE.md`](../../shared-policy/STRUCTURE.md) として配布される（2026-09-15 に本書から移設。写しは手編集しない・配布の規約は [shared-business-policy.md](../../rules/shared-business-policy.md)）。

本書に残るのは **doboku-note 固有の適用**——記事タイプ別にどの型を主に使うか・有料記事の機械ゲート・どの経路から参照されるか。型の中身を読むときは STRUCTURE.md へ。

> [!important]
> **真実源の責務分担**（混同しない）
> - 本書 = **記事内部の構成**（1 本の記事の中で、読者の悩みをつかみ → 購入理由を作る本文の型）の SSOT
> - [note-funnel-architecture.md](note-funnel-architecture.md) = **記事間の回遊・購入動線**（どの記事からどこへ送るか／L1-L2-L3 の CTA 配線）の SSOT
> - [note-publish-enhancement.md](note-publish-enhancement.md) = 公開レベルへ引き上げる**作業工程**（網羅性・図版・段落分割等）
> - [note-essay-review-checklist.md](note-essay-review-checklist.md) = 模範論文の**字数・散文性レビュー**手順
>
> 本書は「記事の中身をどう並べるか」、funnel は「記事から記事へどう送るか」。両方を満たして初めて売れる。

## 機械ゲート: 有料記事は「わかること」を無料部分に置く（2026-07-28 新設）

ステップ 3〜4（解決策・読後の変化）は、有料記事では **paywall より前**に無い限り読者に届かない。無料部分は購入判断のすべてで、そこに「何が得られるか」が無い記事は、読者が代金に見合うか判断できないまま買うか離脱するかになる。

```bash
npm run check-note-intro-benefit    # pre-commit（--staged）＋ CI 全量（r2-audit.yml）
```

published かつ `notePricing: paid` の記事に `**この記事でわかること**` が**有料境界より前**にあるかを検査し、無ければ exit 1。導入の並びは `**こんな人のための記事です**`（誰向けか）→ `**この記事でわかること**`（何が得られるか）→ 地の文。

**実測（2026-07-28）**: 有料 593 件のうち 580 件が境界前に配置、**境界より後ろは 0 件**、欠落は 5 件だけで、しかもそれが**最高価格帯の PDF 商品**（¥1,980 / ¥1,480×2 / ¥980×2）だった。例外のない慣行なので機械ゲートにできる。無料記事は対象外（もくじ・索引・「はじめに」など、構造的に benefit 節を持たないものが正当に存在するため）。構造的な例外は `.claude/config/note-intro-benefit-allow.json` に**理由つきで**登録する。

## 資格・記事タイプ別の「かき分け」

どの記事でどの型を主に使うかの早見表。1 記事に複数型を重ねる前提で「主に効く型」を示す。

| 記事タイプ | 主に効く型 | 使いどころ |
|---|---|---|
| 案内記事・もくじ（L1/L2） | 比較型(7)・チェックリスト型(6)・ロードマップ型(5) | 「どれを買えばいいか」読者の現在地を診断し該当商品へ送る |
| 無料 SEO 記事（サイト／note 無料） | 悩み直撃型(1)・勘違い破壊型(2) | 検索流入の悩みを冒頭で名指し → 本文・回遊へ |
| 有料記事の無料部分（導入〜paywall 手前） | 悩み直撃型(1)・Before→After 型(3)・販売導線型(9) | 無料部分で購入理由を作る（前置きで終わらせない） |
| 施工経験記述 商品 | 失敗談→教訓型(4)・Before→After 型(3) | 減点された答案 → 改善の型をフックにする |
| 模範解答集（建設部門・総監） | ロードマップ型(5)・ケーススタディ型(8)・勘違い破壊型(2) | 「合格答案はこう組む」を手順・具体例で分解 |
| 精読ガイド | 勘違い破壊型(2)・チェックリスト型(6) | 「精読＝合格」の常識を壊し、頻出論点の取りこぼしを潰す |
| 予想問題集 | ケーススタディ型(8)・ロードマップ型(5) | 予想根拠を事例分解で見せ、対策手順に落とす |

## 適用のしかた（どの経路から参照されるか）

note 記事の**作成・リライト経路**ごとに、本書がどこから参照されるかを示す。記事タイプに合う型は上の早見表で選ぶ（型の中身は STRUCTURE.md）。**解答・答案・論文の本文そのもの**（中身）は各経路の既定ルール（字数・網羅・誠実表記・論述メソッド）が優先で、本書はその「外枠（フック〜無料部分〜導線）」にだけ適用する。

| 経路 | 担当 | 参照のされ方 |
|---|---|---|
| 建設部門 模範解答（過去問／予想） | `pe-secondary-exam-writer`（Generator）・`/pe-secondary-yosou` | エージェント定義から本書を参照（導入・無料部分・販売導線） |
| 1級2級 施工経験記述 | `civil-keiken-essay-writer`（Generator）・`/civil-keiken-magazine` | エージェント定義から本書を参照（導入・無料部分・販売導線） |
| 総監 記述式 模範論文（note・persona/R8予想/設問3バンク/クロストレードオフ） | `cem-essay-writer`（Generator）・`cem-essay-qa`（Evaluator） | Generator が定義＋ランブック [note-essay-review-checklist.md](note-essay-review-checklist.md) から型を選ぶ。QA は Red Line・散文性を見る（型そのものは採点しない） |
| 総監テキスト精読ガイド（note） | 親駆動（専任 writer なし） | [note-publish-enhancement.md](note-publish-enhancement.md) B1 から橋渡し |
| 全 note 下書きの公開前ゲート | `/note-prepublish-review` | Phase 1 で無料部分の5ステップ骨格を report-only 観点喚起（自動判定・BLOCK しない） |
| ココナラ 出品文面 | `coconala-operator`・`/coconala-publish` | [ココナラ展開キット.md](../../../content/note/1級・2級土木/ココナラ展開キット.md) §3 からSTRUCTURE.md「強化コンポーネント」を参照（C系PDF=直適用／S系人力=翻案） |

- **対象外（意図的）**: サイトの無料 SEO／参考ページ（キーワードページ・`/pe-essay-draft` の総監模範論文**サイト**ページ・過去問 MDX・textbook）。これらは販売ファネルでないため自動配線しない。検索流入の悩み直撃・勘違い破壊を SEO 記事の導入にも効かせたい場合は、別途その判断で早見表「無料 SEO 記事」行を適用する。
- 新しい記事タイプ・経路を増やすときは、上表と早見表に 1 行追記してから書く（その場のアドリブで型を増やさない）。
