# 共同開発の実装と引き継ぎ

役割の正典は [codex-division-of-labor.md](./codex-division-of-labor.md)。通常は担当 AI が調査から検証・記録まで完結する。別 AI 向け指示書を作るためだけの工程は挟まない。

## plan と引き継ぎが必要なとき

plan の要否・frontmatter は [todo-lifecycle.md](./todo-lifecycle.md) に従う。plan が必要でも担当 AI の交代は不要。別環境で続ける場合や独立した作業を委任する場合は、既存 plan に次の情報を揃えて引き継ぐ。

- 対象 DN-ID・目的・受入条件・対象ファイル
- 作業ブランチとコミット、既存差分、残作業
- 実行済みの検証コマンド・対象コミット・結果、未検証事項
- 必要な認証・承認と停止条件

引き継ぎ先は既存結果を使い、変更箇所・未検証事項・失敗の原因に調査と検証を絞る。追加変更や前提の変化があれば関連検査を再実行する。既存の commit・CI ゲートは省略しない。

## plan の置き場

`.claude/plans/{DN-ID}-{slug}.md` に 1 案件 1 ファイルを置く。複数フェーズも同じファイルにまとめ、短い起動プロンプトは末尾に置く。目的・範囲・確定設計・手順・検証・抽出先・削除条件を必要な分だけ書く。

残作業と完了条件は backlog、実行中の担当は既存 claims、検証実績は git と dispatch-log を参照する。plan に status 欄や作業日記を作らない。

## 終了処理

担当 AI が恒久ルールを SSOT へ、残件を backlog へ抽出する。plan は全受入条件を満たし、指定検証が成功し、必要な抽出と参照更新を済ませてから削除する。完了記録は git 履歴に残し、completed/ や archive/ は作らない。未達なら plan と残件を維持する。

公開・課金・削除等はユーザーの承認範囲と各操作の既存 gate に従う。
