# note 記事の誤りを指摘されたときの手順

読者（購入者のコメント・ココナラの購入者のメッセージなど）から、note の記事の誤りや誤解を招く書き方を指摘されたときの手順。2026-11-27 に、総監の2本（「再受験対策」の成績通知の誤り・「トレードオフ思考」の採点基準のような言い切り）で回した流れを型にした。

## 手順

1. **一次情報で確かめる**: 試験制度の事実は、日本技術士会・文部科学省など実施機関の公表ページで確かめる。手元の記事・サイトの記事を根拠にしない。採点の中身は、採点基準が公表されているかを先に確かめる（公表されていなければ、断定した書き方そのものが誤り）。
2. **原稿を直す**: `content/note/**/article.md` を直す。図に同じ誤りがあれば図も直す。有料記事と、読者が誤解して判断した恐れのある記事には、冒頭（「この記事でわかること」の後）に「お詫びと訂正」を入れる。中身は、日付・何が誤りだったか・どう直したか。以前の書き方を引用する行は、行末に `<!-- overclaim-ok: お詫びと訂正の引用 -->` を付ける。
3. **公開ページを更新する**: `npm run note-update-body -- --article <md> --commit`（会員マガジンの無料記事は `--trial-line-bottom`）。反映は note の API（`https://note.com/api/v3/notes/<id>`）の本文で、直した語が消えたことを確かめる。`updated_at` だけで判断しない。
4. **指摘者へ伝える**: 何を直したかと、お詫びを伝える。ココナラでは note やサイトの名前・URL を書かない（外部誘導の禁止）。送るのは運営者。
5. **同じ型の誤りを探す**: 同じ語・同じ事実を grep で全記事から探し、見つかったものは直すか台帳に起票する（`npm run todo:add`）。
6. **機械で止められる型なら検査に足す**: 言い切りの語は `scripts/checks/check-note-overclaim.mjs` の一覧に足す。試験制度の事実は機械で判定できないので、`note-fact-checker` のスコープ F（公開前の一次情報の照合）で止める。

## 書き方の目安

- 「鉄則」「必ず」「減点必至」「採点上きわめて重要」「採点者は〜を評価します」は、採点基準のように読める。「〜は問題文の求めに沿った書き方です」「読み手に伝わりやすくなります」など、理由を述べる言い方にする。
- 模範答案の「採点者視点」の節は、節の最初に「採点基準は公表されていません。以下は、筆者が読み手の立場で見た自己点検の観点です。」を置く。
