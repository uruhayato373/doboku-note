# SNS 投稿画像 ポリシー

`docs/sns/{x,instagram,youtube}/` に出力する SNS 用画像（IG カルーセル / X 投稿 / YT Shorts）の真実源。`.claude/knowledge/reference/note-svg-policy.md` の SNS 版。

## 適用範囲

- `docs/sns/instagram/**/{carousel,reels}/img/**/*.{svg,png}` — IG スライド画像
- `docs/sns/x/draft/**/img/*.{svg,png}` — X 投稿用画像（1 ツイート 1 枚）
- `docs/sns/youtube/**/*.{mp4,png}` — YT Shorts 動画・サムネ
- 生成スクリプト: `.tmp/gen-sns-{NNN}.mjs`

note 用図解（`docs/note/**/img/figure-*`）は対象外、`.claude/knowledge/reference/note-svg-policy.md` 参照。doboku-note 本体（`.local/r2/posts/**/img/*.svg`）も対象外。

## なぜ SNS 専用ルールが必要か

媒体ごとに表示仕様・UX が異なり、note ポリシーをそのまま流用すると不整合を起こす:

| 媒体 | アスペクト比 | スワイプ方向 | フィード縮小率 |
|---|---|---|---|
| **IG カルーセル** | 4:5 (1080×1350) | **横**（左右） | フィード = 約 343×429（約 32%） |
| **IG リール** | 9:16 (1080×1920) | **縦**（上下） | フル画面 |
| **X 投稿画像** | 16:9 (1200×675) | フィードは縦スクロール、リプライツリーは下展開 | フィード = 約 600×335（約 50%） |
| **YT Shorts サムネ** | 9:16 (1080×1920) | **縦**（上下） | フル画面 |

特に IG カルーセル と Shorts でスワイプ方向が逆なので、矢印記号は媒体ごとに切り替える必要がある。

## 1. キャンバスサイズ

| 用途 | サイズ | 備考 |
|---|---|---|
| IG カルーセル | **1080×1350** (4:5) | 縦長、最も情報密度高い |
| IG リール / Stories | 1080×1920 (9:16) | 縦長、フル画面 |
| **X 投稿画像** | **1200×675** (16:9) | フィード in-feed 表示で読まれることを優先 |
| YT Shorts サムネ | 1080×1920 (9:16) | 縦長 |

**禁止**:
- IG カルーセル を 1:1（正方形）にしない（縦長の方が情報量も滞留時間も多い）
- X で 4:5 を使うと in-feed 表示で上下が大きく切れて読めなくなる

## 2. スワイプ方向の表記ルール

**最重要**: 矢印記号と媒体の UX を一致させる。誤ると「このアプリはこの方向にスクロールできない」と読み手を困惑させる。

| 媒体 | 矢印 | 例 |
|---|---|---|
| IG カルーセル（次のスライドへ） | **`→`** | 「→ スワイプで答えを見る →」 |
| IG リール / YT Shorts（次の動画へ） | **`↑` / `⬆`** | 「↑ スワイプで次の動画」 |
| X（リプライツリー展開） | **`↓`** | 「↓ 答えはリプライツリーに ↓」 |
| 方向に依存しない表現（推奨） | なし | 「次のスライドで答え合わせ」 |

**禁止**: IG カルーセル で `↓` を使う（縦スワイプは存在しない、横スワイプ UX と矛盾）。

## 3. 記号の文体統一

問題と答えの記号は同一系統で揃える。`(N)` ASCII と `①②③④` Unicode を混在させない。

| 用途 | 記号 | 出典 |
|---|---|---|
| 4 択選択肢の番号 | **`①②③④`**（U+2460〜U+2463）または SVG 円 + 白数字 | UI / SVG どちらでも視覚的に円形 |
| 正答記号（IG 答えスライド中央） | **`②`** など Unicode 囲み数字 | 質問側と統一 |
| 順序付き手順 | `1.` `2.` `3.` 番号付きリスト | 選択肢ではないため別系統 OK |

**禁止**:
- 質問が `①②③④` なのに答えで `(2)` 形式
- 質問が `1)` `2)` なのに答えで `①②③④`

font: `'Hiragino Sans, Hiragino Kaku Gothic ProN, Yu Gothic, Noto Sans JP, sans-serif'` で Unicode 囲み数字は正常レンダリング。サイズは ASCII の同等表現より **約 1.3 倍大きく** すると視覚的インパクトが揃う（U+2460 系はグリフが小さめ）。

## 4. 装飾 badge の節度

「頻出」「引っかけ」「R7 出題」等の装飾 badge は、解説文中で同じ意味を表現できる場合は削る。視覚ノイズを増やすだけで読み手の理解は深まらない。

**badge を付けてよい場合**:
- カバースライドの「シリーズ N/5」のような構造的メタデータ
- 解説文に書いていない情報を補う（例: 「公式発表」「速報」）

**badge を付けてはいけない場合**:
- 解説文末に「...頻出の引っかけ！」と書いてあるのに、別途「引っかけ」badge を表示する（重複）
- スライドのアクセントだけが目的（純粋な装飾は別の手段で）

## 5. テキスト折り返し（wrapJa 算法）

長文の自動折り返しは以下のパラメータで安定動作することを確認済み:

```javascript
function wrapJa(text, maxChars) {
  const breakChars = /[、。！？「」『』（）\s→\/]/;
  // 1. cur.length >= maxChars でチェック開始
  // 2. lookback 12 文字以内で breakChars を探す
  // 3. 見つかれば breakIdx + 1 で push
  // 4. 見つからず cur.length >= maxChars + 4 で強制改行
}
```

**maxChars の目安**（fontSize と canvas 幅から逆算）:

| キャンバス幅 | フォントサイズ | 推奨 maxChars |
|---|---|---|
| 1080 (IG) | 40px (本文) | **20** |
| 1080 (IG) | 34px (補足) | **24** |
| 1080 (IG) | 36px (選択肢) | **22** |
| 1200 (X) | 30px (質問) | **32** |
| 1200 (X) | 24px (選択肢) | **14** |

**なぜ 12 文字 lookback が重要か**: 「Engineering」のような英単語が 11 文字あるため、6 文字 lookback だと単語の途中で切れる。12 文字確保すれば英単語の前にあるスペース or `/` まで遡れる。

**なぜ force-break threshold は maxChars + 4 か**: それ以上にすると 1080 幅 + fontSize 34 で 32 文字超 → 約 1000px 超 → canvas からはみ出す。+4 なら最大 28 文字 ≒ 840px で安全。

## 6. 長文選択肢の自動レイアウト切替（X 投稿）

X 投稿画像は 1200×675 で in-feed 読み取りを優先するため、選択肢が長いと 2×2 グリッドに収まらない。次の自動切替を実装する:

```javascript
const longestChoice = Math.max(...q.choices.map(c => c.length));
const useVertical = longestChoice > 14;  // 14 文字超は縦 1 列
```

| longest | レイアウト | 例 |
|---|---|---|
| ≤ 14 文字 | **2×2 グリッド** | 「640,000 円」「23日経路1本のみがCP」など |
| > 14 文字 | **縦 1 列** | 「リサイクル→リデュース→...→処分」（22 文字）など |

縦 1 列モードのとき:
- vCellW = W - 120 (フル幅近く)
- vCellH = 70
- vGap = 10
- vStartY = 250

これで 4 cell が y=250 〜 570 に収まり、フッター y=655 と 30px 程度の安全マージンを確保できる。

## 7. レイアウト規約

### 余白・マージン（IG カルーセル基準）

| 項目 | 最低値 |
|---|---|
| 質問本文 → 選択肢の余白 | 60px（動的計算） |
| 選択肢間の gap | 18px |
| 答えスライド「正答」と中央 ② の余白 | 60px 以上 |
| フッター hint と最終要素の余白 | 50px 以上 |

**ブランド識別は右下の `doboku-note.com` テキストのみで担保**。左端の brand stripe（縦帯）は使わない（管理色 badge / 5 管理 chip 等の図内要素と視覚的に競合するため）。

### 答えスライドの安全レイアウト

```
[A1 経済性管理]                       <- top label badge (60-124)
損益分岐点                            <- topic (200-240)
✓ 正答                                <- headline (280-340)

  ┌─────────────────────────┐
  │     ②                     │     <- big number (380-660 box)
  │   640,000 円              │
  └─────────────────────────┘

─── divider ───                       <- (740)
解説                                  <- label (770-820)
解説本文 4-5 行...                    <- body (880-1100)

      doboku-note.com                 <- footer (1318)
```

円ボックスは fontSize 160 の Unicode ② が y=540 中心で box (380-660) に収まる。

## 8. 検証手順（生成後の必須チェック）

```bash
# 1. 全 PNG 生成
node .tmp/gen-sns-{NNN}.mjs
# → "✅ Generated N PNG files" を確認

# 2. サンプル目視チェック（最低 5 枚）
# - cover (1 枚): タイトル・5 管理 chip
# - question (1 枚): フッター矢印・選択肢収まり
# - answer (1 枚): 中央 ② が正常レンダリング
# - 長文選択肢 X tweet (1 枚): 縦レイアウトに切替されているか
# - CTA (1 枚): リンク URL に UTM が入っているか

# 3. 改行コード等は SVG/PNG なので無関係
# 4. wrap 検証: 各 PNG の右端でテキスト切れがないか
```

## 9. 失敗パターン早見表（教訓）

| パターン | 兆候 | 防止策 |
|---|---|---|
| 矢印方向ミス | IG カルーセルに `↓` を使う | section 2 のテーブル参照 |
| 記号文体不一致 | 質問が `①` で答えが `(2)` | section 3 の統一ルール |
| Badge 装飾過多 | 解説文と意味重複する badge | section 4 の節度ルール |
| 英単語途中で切れる | 「Engineeri\nng」 | wrapJa の lookback を 12 文字以上 |
| 右端からテキストはみ出す | force-break threshold 高すぎ | maxChars + 4 までで強制改行 |
| 長文選択肢が cell 外にはみ出す | X 投稿で 2×2 固定 | longestChoice > 14 で縦切替 |
| 中央数字 + ヘッドラインが重なる | 「正答」と「(2)」が縦に近い | 60px 以上の vertical gap |
| 最終要素がフッターと重なる | choices と「↓ スワイプ」テキスト | choicesEndY + 50px = footerY 以上 |
| 中央寄せテキストが chip の中心からズレる | `dominant-baseline="central"` 付き text の y がチップ中心と一致しない（y を見栄えで決めると外す） | **必ず `y = chipY + chipH/2` で計算**（ハードコード禁止）。例: chip y=380, h=180 → text y=470。複数箇所で再発しやすい（cover title chip、X answer block 等） |
| 答え画像で管理色が消える | 答えスライド/画像の stripe/badge を成功色（positive 緑）固定にすると、質問画像との視覚連続性が切れタイムライン上で「同じシリーズ」と認識されない | 質問・答え両方で **stripe/badge は m.color（管理色）を維持**、成功シグナルは「✓ 正答」テキストや ②③④ 数字を positive 緑で表現 |
| 解説テキストが右端ギリギリ | wrap maxChars が広すぎ（フォント幅 × maxChars が canvas 使用領域の 95% 超） | maxChars × fontSize ≦ 使用幅の 85% を目安。例: 1200 幅 / margin 60×2 / font 26 → maxChars=36（行幅 ≈ 900px = 83%） |

## 11. 修正サイクル

既存画像の修正時:

1. SVG ソース or 生成スクリプトを編集
2. `node .tmp/gen-sns-{NNN}.mjs` で再生成（全枚数を一括再生成して整合性を保つ）
3. `git status -s docs/sns/` で変更ファイルを確認
4. サンプル PNG を Read で目視チェック
5. 問題があれば 1 へ戻る

PNG だけ修正することは絶対にしない（再生成で消える）。SVG ソースも併置しているので、再編集時は SVG 経由で。

## 12. 試験識別レイヤー（多資格展開）

複数試験（技術士総監 / 1級土木 / コンクリート主任技士 等）を同一アカウントで展開する際、フィード/グリッドで「どの試験の投稿か」を即判別させるためのルール。設計の真実源は [docs/project/03_SNS/03_多資格SNS展開設計.md](../../../docs/project/03_SNS/03_多資格SNS展開設計.md)。

### 12.1 2軸の色設計（試験＝色相 / サブテーマ＝アクセント）

- **第1軸＝試験**：パレット真実源 `.claude/knowledge/design-system/note-cover-tokens.json` の `exams` から **base 色を解決**（総監=navy / 1級土木=azure / コンクリ主任=teal / コンクリ診断=plum）。これがカバーの**上部色帯＝試験識別**。
- **第2軸＝サブテーマ**：総監の 5 管理色は原則として試験色帯を侵さず内部アクセントに置くが、**過去問パックのカバーは管理分野を主役にするため上部色帯を 5 管理別色にする**（2026-06-17。管理色は淡色のため帯上テキスト〔試験名・ページ番号〕は暗色へ切替えて可読性を確保）。試験識別が主のサムネ等は従来どおり試験色帯を優先。
- note カバー・IG・X・Shorts は**同じ token を解決**してチャネル間で色を統一する。

### 12.2 カバー（slide 1 / サムネ）の必須要素

- **試験名は正式名称のみ**（略称併記は不要）。長い「技術士／総合技術監理部門」は2行、他は1行で auto-fit。
- **過去問パック（総監・5 管理）は「管理分野」を主役（大）** に置く（パックは 1 管理 × 4 問でグルーピング＝管理分野がそのパックの一貫テーマ。利用者は年度より分野・テーマに関心が高い）。年度＋形式（択一式 過去問 等）は従（小）に降格する（2026-06-17 変更）。YT Shorts は管理分野を主役にしたうえで「この動画の論点」として個別テーマも併記する。
- 管理分野を持たない試験（1級/2級土木 等、年度が主識別子）は従来どおり**年度を主役（大）** に置く。形式＋種別（第一次検定 過去問 / 四肢択一 過去問）は従（小）。
- タグ（過去問/予想問題/解説/クイズ）は**実際の中身に合わせる**（資格に固定しない）。

### 12.3 セーフゾーン（プロフィールグリッドの正方クロップ対策）

- IG カルーセル 1080×1350 は、**プロフィールグリッドで中央 1080×1080 にクロップ**され**上下 135px がカットされる**。
- **文字情報（試験名・タグ・年度・ブランド）は必ず y∈[135, 1215] のセーフゾーン内**に置く。**上部色帯はカットされて良い**（色だけ）。
- 検証: 生成 PNG に中央 1080×1080 の枠を重ねるか、上下 135px を除いた領域に主要文字が収まるか目視する。

## 13. figure-*.svg の Stories / Reels 静止画流用

サイト図版（`.local/r2/posts/**/img/figure-*.svg`）は 4:5（viewBox 400×500）で設計されており、**SVG 本体を修正せずに** IG Stories / Reels の静止画スライドとして流用できる。

### 9:16 キャンバス上の配置レイアウト

```
9:16 キャンバス (1080×1920)
┌─────────────────────────────┐
│  上部 UI 領域  約 250 px    │  ← Stories: プロフィール名・時間バー
│  （背景色で埋める）          │    Reels: プロフィール・フォローボタン
├─────────────────────────────┤
│                             │
│   figure-*.svg              │  ← 4:5 相当（1080×1350）
│   SVG をそのまま配置         │    figure の viewBox 比率と一致
│                             │
├─────────────────────────────┤
│  下部 UI 領域  約 320 px    │  ← Reels: いいね/コメント/シェアボタン
│  （背景色で埋める）          │    Stories: 返信ボックス
└─────────────────────────────┘
```

### ルール

- **背景色**: ブランドカラー（`#1a3a5c`）または黒（`#111`）。白背景は UI との境界が消えるので避ける。
- **figure-*.svg の修正不要**: キャンバス変換スクリプト側で 9:16 の中央に配置するだけでよい。
- **セーフエリア**: Stories/Reels ともに上下の UI 領域は端末・OS バージョンで若干変動する。コンテンツを上下各 250〜320px 以内に収めない設計でよい（figure が 4:5 相当なので自然に中央に収まる）。
- **CTA テキスト**: 下部 UI 領域が隠れるため、「プロフィールのリンクから」など UI に依存しない誘導文を figure 外の上部余白エリアに小さく入れる（オプション）。
- **動画化**: 静止画を ffmpeg 等で mp4 に変換する場合も同じ 9:16 配置を適用する。
