# note 記事用 図解 SVG ポリシー

note.com に PNG 化して掲載する図解（`content/note/{slug}/img/figure-*.png`）を作るときの真実源。doboku-note 本体の inline SVG とはルールが異なるため、本ドキュメントを優先する。

## 適用範囲

- `content/note/**/img/figure-*.svg` および `figure-*.png`（cover.png は除外、`scripts/generate-note-covers.mjs` 専用）
- `.tmp/gen-figures-*.mjs` 等で生成する note 用図解スクリプト

doboku-note 本体（`content/site/**/img/*.svg`）は本ポリシー対象外。SVG inline 配信なので別ルール。

## cover.png のセーフティゾーン（参考）

`content/note/**/img/cover.png` は `scripts/generate-note-covers.mjs` が `.claude/skills/conversion/ogp-create/scripts/lib/ogp-templates.mjs` のテンプレで生成する。サイズは note 推奨の 1280×670。frontmatter に `cover:` ブロックがあれば **note-cover-g2**（試験色分け・全幅バナー帯）、無ければ **mono-tag** にフォールバック（仕様は `.claude/knowledge/design-system/note-cover.md`）。

**セーフティゾーン**: 中央 **630×630** 厳守（SAFE_L=325〜SAFE_R=955）。G2 ではバナー帯テキスト・強調キーワード(HiBox)・リード文がこの内側（バナーは自動で 590px 幅にフィット）。mono-tag ではタイトル・カテゴリチップ・ワードマーク・下部メタがこの内側。装飾（グリッド・同心円・ロゴ・右上メタ・両端チップ）は全幅 OK（クロップで欠けても問題なし）。

note の記事一覧・SNS 自動共有は中央正方形クロップのケースが多いため、**主要コンテンツが中央 630×630 から外れると意味が伝わらなくなる**。テンプレ実装はこの制約を満たすよう設計されているので、独自に SVG/PNG を作る場合も同じ範囲を踏襲する。

## なぜ note 専用ルールが必要か

note は **inline SVG が使えず、PNG 必須**。さらに以下の制約がある:

| 環境 | 表示幅 | 縮小率 |
|---|---|---|
| PC ブラウザ | 約 690px | 1280px → 約 54% |
| モバイル | 約 343px（375 デバイス） | 1280px → 約 27% |

つまり SVG 内で 14px のテキストは PC で 7.5px、モバイルで 3.8px となり、**読めない**。doboku-note の感覚で SVG を作ると失敗する。

## 1. キャンバスサイズ

| 用途 | 推奨サイズ | 理由 |
|---|---|---|
| 標準横長図 | **1200×720** | note 推奨アスペクト比、Retina 解像度 |
| 縦長要素多め | 1200×800〜1000 | 縦に伸ばす場合 H を増やす（W は変えない） |
| 表（行数多） | 1200×（200 + 行数 × 80）| 高さは内容に応じて拡張 |

**禁止**:
- W を 1280 超にしない（note の最大幅基準を超える）
- 同一記事で W を揃える（読みやすさ、リズム）

## 2. フォントサイズ規約

note PC 表示で **最低 11px 相当** が読める下限。SVG 内のフォントサイズは以下を目安とする。

| 役割 | SVG font-size | note 表示時 (PC/Mobile) |
|---|---|---|
| メインタイトル | **32〜36** | 17px / 9px |
| サブタイトル・列ヘッダ | **22〜26** | 12px / 7px |
| **本文・ラベル（必須読み取り）** | **22 以上** | 12px / 6px |
| 補足・キャプション | **18 以上** | 10px / 5px |
| **絶対禁止**（読めない） | **16 未満** | 9px / 5px |

読者が**モバイルで必ず読めないと困るテキスト**（著者オーソリティ・バナー等）は、上表の下限では足りない。1280px 基準で **52px 以上**（モバイル約343pxで ≒14px）を確保する——上表の下限は PC 表示（690px 換算）の可読性のみを保証しており、モバイル最優先の要素には別基準が要る（詳細: [author-authority-banner.md](author-authority-banner.md)「レイアウト」）。

検証: `grep -o 'font-size="[0-9]*"' figure.svg | sort -u` で値を全洗い出し、**16 未満が含まれていれば修正必須**。

例外: 注釈・凡例の補足のみは 16〜17px まで許容（短い単語限定）。

## 3. レイアウト規約

### 余白・マージン

| 項目 | 最低値 |
|---|---|
| 要素間の隙間 | **24px** |
| カード内パディング | **20px** |
| テーブル行高 | **60px**（テキスト高 22px + 上下パディング 19px ずつ） |
| 中央配置の円・図形と他要素の距離 | **40px** |
| **タイトル下〜コンテンツ上** | **40px 必須** |
| **ヘッダ→データ行（表/マトリクス）** | **40px 必須** |
| **データ行→凡例** | **40px 必須** |
| **行間 gap（複数行カード）** | **16px 以上** |
| 列ヘッダ・行ラベル内のテキスト上下 padding | **対称配置（差 ±2px 以内）** |

セクション境界（タイトル↔本体、ヘッダ↔本体、本体↔凡例）は 40px を強く推奨し、24px に下げない。「セクション内の同種要素間」は 24px を最低値とする。

### 情報密度

1 図あたりの密度は以下を上限とする。超える場合は **2 枚に分割**:

- **表**: 8 行 × 4 列まで（10 行 × 4 列は失敗例 → 10 figure-1）
- **散布図ラベル**: 5 個まで（重なり防止）
- **放射状図の周辺要素**: 5 個まで（中央円とのマージン 40px 確保）

### 要素配置の禁止パターン

過去事例から、以下は必ず避ける:

| 禁止パターン | 失敗例 | 対策 |
|---|---|---|
| 横並びラベルとカードの x 座標重複 | 04 figure-2 (16〜20問正解 vs 本文重なり) | ラベル幅を確定後、本文の x を `labelX + labelW + 24` から開始 |
| 中央円と他ボックスの座標重複 | 05 figure-2 (中央円が経済性ボックスを隠す) | 中央円半径 + 40px 以上離した位置に周辺要素を配置 |
| 散布図の近接ラベル | 07 figure-2 (パターン1 vs 5 重なり) | 同一 y 座標 ± 40px 以内なら一方のラベルを上下にオフセット |
| キャプションとカード ヘッダーの y 重複 | 10 figure-2 (キャプションが ALARP/LCA に被る) | キャプション高さ + 40px をカードの y に確保 |
| キャンバス高さ不足 | 11 figure-1 (凡例と R07 行重なり) | 高さは「行数 × rowH + ヘッダ + 凡例 + 余白 80px」で計算 |

## 4. デザイントークン

CLAUDE.md / `src/styles/globals.css` と整合。SVG にはリテラル hex でコメント併記推奨。

| トークン | hex | 用途 |
|---|---|---|
| brand | #2e6da4 | アクセント・主要バー・列ヘッダ |
| brand-fill | #e8f0fe | 強調背景・キャプション帯 |
| brand-deep | #1a3a5c | 行ラベル・見出し |
| ink-strong | #222222 | 本文太字 |
| ink-body | #555555 | 本文 |
| ink-muted | #8a8a8a | 補足・キャプション |
| danger | #b22234 | 警告・最頻出・注意喚起 |
| warn | #d4a017 | 中レベル注意 |
| positive | #3a7d44 | 良好・推奨 |
| 表面背景 | #ffffff / #f3f4f6 / #f8fafc | カード・行交互 |

その他:
- フォント: `'Hiragino Sans, Hiragino Kaku Gothic ProN, Yu Gothic, Noto Sans JP, sans-serif'`
- 角丸: `rx="6"` 〜 `rx="8"`
- **ブランド識別は右下の `doboku-note.com` テキスト（ink-muted 18px）のみで担保**。左端の brand 色アクセント縦線は使わない（同系統色の図内要素と「二重縦帯」を作って冗長になるため）

## 5. 検証手順（生成後の必須チェック）

スクリプト実行後、PR / commit 前に以下を確認:

```bash
# 1. フォントサイズ規約違反チェック
for f in content/note/{slug}/img/figure-*.svg; do
  echo "=== $f ==="
  grep -o 'font-size="[0-9]*"' "$f" | sort -u
done
# → 16 未満が出たら修正

# 2. PNG を Read で目視確認
# → レイアウト重なり・密度過多をチェック

# 3. 縮小プレビュー（任意・厳密チェック）
# Playwright または ブラウザで幅 690px に縮小して読めるか確認
```

## 6. 失敗パターン早見表（教訓）

| パターン | 兆候 | 防止策 |
|---|---|---|
| テキスト重なり | 横並びレイアウトで x 座標を独立計算 | 「次の要素の x = 前要素の x + width + マージン」を機械的に守る |
| 中央円が周辺を隠す | 放射状図で中央円を後から拡大 | 中央円半径を最初に固定、周辺要素位置は半径 + 40px から計算 |
| 凡例見切れ | キャンバス H をコンテンツ上限ぴったりにする | H 計算時に末尾余白 80px を必ず加算 |
| 文字が読めない | font-size を 13〜15px で多用 | 本文は 22px、補足は 18px を最小ライン |
| 表が密集 | 全データを 1 表に詰め込む | 6 行超は分割または上位サマリ + 詳細別表 |
| ラベル衝突（散布図） | 全点に一様にラベル配置 | 近接点は上下交互配置 or リーダー線 |

## 7. 雛形リファレンス

良い参考実装:
- `scripts/render-figure-soukan-analysis.mjs` — 総監択一式17年分分析の生成スクリプト（横棒均等配分・タイムライン）
- `content/note/一般部門との違い/img/figure-{1,2,3}-*.svg` — 完成 SVG（比較表・横棒・マトリクス 3 種）

## 8. 修正サイクル

既存図解の修正時:

1. SVG ソースを編集（PNG ではなく）
2. `node .tmp/gen-figures-{NN}.mjs` で再生成
3. 上記「5. 検証手順」を実行
4. 問題があれば 1 へ戻る

PNG だけ修正することは絶対にしない（再生成で消える）。
