# キャラクターPOP画像の共通制作方針

2026-09-27、公開中のココナラ18商品で承認された意匠を、note・SNSの新規表紙／サムネイルへ展開する制作方針。呼出しは `/create-pop-image`。本文の図解・問題・解答画面には各媒体の学習用レイアウトを使う。

## 見せる順序

1. **対象資格と主題**を最も大きくする。「1級土木」「経験記述」「添削」など、一覧でも何の商品か読める短い言葉を使う。SNSの学習投稿は問い・論点も主役にする。
2. **何が得られるか**を一つ示す。テーマ数・冊数・内容は販売カタログ／原稿に照合し、競合の数字や実績を流用しない。
3. **総監の専門性**を黄色などの強調帯に置く。正式表記は「技術士（総合技術監理部門）」、短縮は「総監」。対象資格と著者の保有資格を別の領域に置き、総監教材と誤認させない。
4. **先生キャラクター**を添える。答案の確認は赤ペン・答案、比較は両手で見比べる、判断は考える、聞き流しはヘッドホンなど、動画の内容が伝わるポーズを使い分ける。同じポーズへの固定や、順番だけのローテーションにしない。顔・髪・メガネ・ひげ・作業服の同一性は [キャラクター素材ポリシー](./character-asset-policy.md) を守る。

資格別の主色は1級土木＝青、2級土木＝緑、コンクリート主任技士＝紫。その他の資格は媒体の既存資格色を引き継ぐ。白／黄の太字、必要な輪郭、少量の赤で強調する。空白は減らして文字と人物を大きくするが、文字間隔・輪郭・媒体の切り取り安全域は削らない。細かな説明を詰め込まない。

「ココナラと同じ意匠」は色と文字帯だけで判断しない。原本と媒体別の実画像を並べ、顔と主題の大きさ、極太の縁取り、文字と背景の動きを確認する。特にShortsは人物を小さくして上下の空白を埋めただけの構成へ戻さない（2026-10-11の表紙修正で確認）。

ブランド名・URL・価格・無関係な肩書きは既定で省く。この意匠ではヘルメットも無地でよい（プロフィール等の標準ロゴ入り素材は継続）。競合から学ぶのは情報の優先順位・視認性であり、固有のキャラクター・文言・構図を複製しない。

## 総監訴求の使い分け

| 提供内容 | 表記例 |
|---|---|
| 本人が担当する添削／指導 | 総監が直接添削／総監が直接指導 |
| 本人が制作した教材・PDF | 総監が制作 |
| 本人が設計したキット | 総監が設計 |

既製PDFへ「直接添削」を付けない。無料の解説投稿は内容に応じ「総監が解説」等に調整する。「唯一」「最高峰だから合格」「必ず合格」や未確認の合格率は使わない。保有資格だけで指導実績を推定しない。

## 原本と媒体別の派生

- 承認済みココナラ原本の対応・SHA-256は [承認画像台帳](../../../data/coconala/thumb-approved.json)。画像と生成時のプロンプトは `content/coconala/assets/pop-20260927/` のPNGと `generation-manifest.json`。Drive vaultの `coconala-asset` に保存済み。復元は [アセット置き場](./asset-storage-policy.md) と `/asset-route` を使う。
- 新規生成の前に該当資格の原本を実画像で見る。ファイルが無ければ復元する。原本未確認の状態で「同じ意匠」と扱わない。
- 同一商品・同一媒体の再出力は承認PNGをそのまま使う。ココナラは `node scripts/coconala-thumb.mjs --service coconala-tensaku-set` のように既存CLIでSHA照合してコピーできる。
- 横長・縦長への展開は原本を参照して再配置する。完成PNGの引き伸ばし・文字や顔が切れる中央クロップで済ませない。noteの表示領域、SNSの操作UIと重ならない安全域は媒体側の正典に従う。
- noteは [noteカバー](../design-system/note-cover-character-v5.md)、SNSは [SNS画像](./sns-image-policy.md)、ココナラは [運用](./coconala-operations.md) を参照する。寸法・公開コマンドをここへ重複管理しない。
- 方針の適用と既存レンダラーの実装状況は別。既存CLIを実行するだけでPOP版になるとは扱わない。対応していなければ画像生成ツールで媒体別原稿を作るか、依頼された範囲でテンプレートを改修する。

## 通常動画・Shortsの承認見本

| 内容とポーズ | 原稿・生成履歴（revisionsのキー） |

ヘッドホン等の用途に合う装備へ変えてよい。顔・服装の同一性を保ち、ポーズを単なる順番で割り当てない。今回の全面画像生成版は `pop-poster-v3`。従来の `pop-v2` 一括レンダラーは3ポーズの別組版であり、この見本の再生成器ではない。

## 保存と引き継ぎ

新規制作は対象記事／商品／投稿の制作ディレクトリに `pop-image.json` を置き、下記を記録する。本文コピーは既存frontmatter等が正典ならその参照も残す。PNGを唯一の文字原稿にしない。

- `policy`: この文書のパス、`designVersion`: `pop-20260927`
- `source`: 商品ID／記事パス、`channel`、`format`: 実際の幅・高さ
- `copy`: 資格名・主題・補足・総監訴求、`evidence`: 数字やサービス内容の根拠パス
- `references`: 参照画像のパスとSHA-256、`prompt`: 実際に送った全文
- `output`: 出力パス・SHA-256、`review`: 確認日・実画像の判読／文字切れ／事実整合の結果
- `storage`: Drive/R2の既存台帳を引く識別子、`publication`: 未公開／反映済みとURL（未確認なら未確認）

編集可能な文字・参照・プロンプトをGit、原画像と完成PNGを用途に応じDrive/R2へ保存する。共用する人物素材はキャラクター台帳へ登録し、商品固有の背景付き完成画像を人物ポーズとして登録しない。保存方法は `/asset-route` に従い、新しい独自保管先を増やさない。承認後の差し替えは原本を残し、新版のパスとSHAへ更新する。

新規に日本語込みで画像生成した場合は原寸と幅360pxの表示で文言を読み、誤字・文字切れ・顔の変形を修正する。生成モデルへの同じプロンプトは同じ画素を保証しない。完全再現は保存済みPNG、内容変更は新しい派生版として扱う。既存予約・公開物の差し替えは各媒体の公開手順で実体確認する。

動画表紙の完成PNG・生成途中の原本は `content-media` としてDrive vaultの「制作物/コンテンツ」へ保存する（[設定](../../../config/drive-vault.json)）。Gitには `pop-image.json` のコピー・参照SHA・生成指示・実寸・承認範囲を残す。R2はCIへ渡す採用画像の一時転送用で、Drive原本の代替ではない。復元・SHA照合・R2転送は [動画生成手順](../../../content/sns/youtube/VIDEO-RENDER.md) を使う。`revisions` の画像は、保存しただけでは `approvedImage` や動画へ採用されない。
