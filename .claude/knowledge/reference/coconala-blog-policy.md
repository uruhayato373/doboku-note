# ココナラブログ運用ポリシー（真実源）

ココナラブログ（記事型）の**戦略・構成・採点・ハードゲート**の単一真実源。
`/coconala-blog` スキルと `coconala-blog-writer` / `coconala-blog-qa` はここを参照するだけで、
ルールを各ファイルに写経しない。プラットフォーム仕様（URL・セレクタ・ダイアログ構造）は
[coconala-operations.md §9](coconala-operations.md) が真実源で、ここには重複させない。

- 記事本文の SoT: `content/coconala/blog/{slug}/article.md`
- 価格・出品状態の SoT: `src/lib/coconala-services.ts`（**本ファイルにも記事本文にも価格を書かない**）
- 偵察データ: `.claude/state/coconala/blog-competitors.json`（`npm run scout-coconala-blogs`）
- 機械ゲート: `scripts/lib/coconala-blog-guards.mjs` ／ `npm run check-coconala-blog`

---

## 1. 位置づけ — ココナラ内の第4面

サイト（SEO）／note（有料コンテンツ）／ココナラ出品（受注）に続く4番目の面。
**役割はココナラ内の検索・回遊から自出品へ送ること**に限定する。

**外部誘導は禁止**（投稿エディタが常時表示する規約文。詳細と原文 → operations.md §9.1）。
note・doboku-note.com の URL は書かない。**URL でなくてもサービス名の言及すら書かない**
（検索誘導になり外部誘導と見なされうる）。違反はアカウント制限に直結するため、
これは採点軸ではなく**ブロッキングゲート**として機械で止める（§7）。

**送客は「サービスカード」で行う。** 本文に `https://coconala.com/services/{id}` を置くと、
エディタが画像・タイトル・**ライブ価格**つきのカード（`div.c-blogBody_service`）へ自動変換する。
価格はココナラ側が描画するので、**本文に金額を書かない**のが既定（書けば価格改定で嘘になる）。

## 2. カニバリ境界（これを外すと自分の商品を殺す）

ブログは**無料**で、しかも自分の有料商品と同じ土俵の話題を扱う。境界を先に決めておく。

| 出せる | 出せない |
|---|---|
| 減点の**型**・失敗パターンの列挙 | 完成答案の**全文**（＝C系PDF・note有料の中身） |
| 自己診断の**観点**を数点 | 診断チェックリストの**全項目**（＝S1 の商品価値） |
| 書き方の手順・考え方 | 想定工事バンク・テーマ別の答案素材（＝有料の在庫） |
| 過去の添削で頻出した傾向（匿名・一般化） | 顧客の答案そのもの（守秘） |

**深さの上限 = note 無料リードマグネットと同じ**。note 無料記事より深い内容をココナラブログに
置かない（note 側の集客資産を自分で無効化するため）。**note 有料記事の内容は転載しない**。

> 判断に迷ったら「これを読んだ人が S1/S2 を買う理由が残るか」で決める。残らないなら出しすぎ。

## 3. 資産マップ（source → angle → funnel）

angle の語彙は [content-angle-policy.md](content-angle-policy.md) と共通（結論/理由/体験/反論/数字/ハウツー）。
**資格ごとにエージェントを増やさない**（`exam` パラメータで横断）。

| # | 論点 | source（書き直しの素材） | angle | funnel |
|---|---|---|---|---|
| 1 | 落ちる経験記述の型 | note 無料「経験記述-落ちる答案診断」 | 体験 | S1 診断 |
| 2 | 独学添削の限界 | note 無料「経験記述-独学添削の限界」 | 理由 | S2 添削セット |
| 3 | 予想問題で書く練習 | note 無料「経験記述-予想問題で書く練習」 | ハウツー | C8/C9 模試 |
| 4 | 品質管理の書き方 | サイト `civil-construction-{1,2}-secondary-experience-writing-guide` | ハウツー | S3 作成 / C10・C11 |
| 5 | 総監の出題テーマ | 総監テーマ分析（sokan-bunseki） | 数字 | sokan-bunseki |

**source は素材であって原稿ではない。** `stripNoteFunnel()` で外部導線を落としてから**書き直す**。
逐語転載は note 側の重複コンテンツになり、どちらの資産価値も下げる。

**資格の配分（2026-08-12 決定）**: 土木（1級・2級）中心＋総監は少数。
理由は実需の実測 —「経験記述」646件に対し「総合技術監理」は**16件**しかない
（「技術士」1,100件は部分一致のノイズ）。総監は当面 #5 の1本に留め、
「サービス・ブログ分析」で閲覧が付いてから増やす。

## 4. 記事構成（競合の型を踏まえた標準形）

競合実測（2026-08-12・`blog-competitors.json`）で分かった型:

- **連載が上位を独占**する。たくえい（経験記述特化・9本）が「経験記述」検索の1位/7位、
  小泉士郎（技術士）が「技術士」上位をほぼ占有。**単発より連番**が回遊を作る
- カテゴリは **「学び」** が主流（一部「ビジネス・マーケティング」「コラム」）
- タイトルは **問いかけ＋数字**（「なぜ重要？」「NG例5選」「3ステップ」）
- **お気に入り数は総じて 0〜10**。バズる面ではない＝**積み上げと検索一致**で戦う面
- **有料ブログも存在する**（500円・1,500円の実例）。無料で始め、実績が出てから検討

標準構成（[note-selling-structures.md](note-selling-structures.md) の**失敗談→教訓型**を基底に翻案）:

1. **リード**（3〜5行）— 読者の詰まりを名指しする。連載なら位置づけを1行
2. **本題**（見出し2〜4個）— 型・手順・失敗例。§2 の境界内で具体を出し切る
3. **まとめ** — 要点3つを**散文で**（「1つ目は〜。2つ目は〜。3つ目は〜。」）。
   **箇条書きにはできない**（エディタに機能が無い＝装飾は 見出し / 太字 / 位置 / 引用 の4つだけ・operations.md §9.4）
4. **CTA** — サービスカード**1枚**（`funnel` 先）＋ 「ご購入後の流れ」を2〜3行
   - S 系（人力サービス）では「たった3つ」型を使わない → 「ご購入後の流れ」に翻案（同 §強化6部品）
   - **合格保証は書かない**。実績は検証可能な事実のみ（発注者＝審査する側の経験・技術士2部門）

**見出しは選択ツールバーで作る**（markdown `#` は変換されない）。見出しを付けると目次が自動で付く。

## 5. タイトルと検索

- ココナラのブログ内検索は**部分一致**。ターゲット語（経験記述／施工管理技士／1級／2級）を
  **タイトル前半**に置く
- 連載は `【第N回】` を先頭に付け、後半に論点を書く（競合の上位型）
- **プラットフォームの文字数上限は未到達**（200字を投入して切り詰めなし・operations.md §9.4）。
  上限は運用側で決める＝**全角 45 字以内**（一覧カードでの視認性から）
- ハッシュタグは公開設定で **2〜4個**（画面推奨値）

## 6. カデンス

| 項目 | 値 | 理由 |
|---|---|---|
| 公開 | **1日1本まで** | 収益アカウントの bot 検知回避（§8 出品と同じ低頻度原則） |
| 初回 | 1本公開 → ライブ実査 → 24〜48時間観察 → 以降日次 | 段階ゲート |
| 通常運用 | 週1本 | 連載を切らさない最小ペース |
| 競合偵察 | 四半期（`cadenceDays: 90`） | read-only・礼節 |

## 7. ハードゲート（ルーブリック平均で薄めない）

**1つでも該当したら公開しない。** 実装は `scripts/lib/coconala-blog-guards.mjs`（**例外で停止**＝
呼び出し側が握り潰せない）。`npm run check-coconala-blog` が pre-commit と週次で同じ判定を回す。

| # | ゲート | 実装 |
|---|---|---|
| G1 | 外部リンク・外部プラットフォーム言及がゼロ | `assertNoExternalLinks`（note.com / doboku-note はテキストも不可） |
| G2 | 外部連絡先（メール・電話・LINE・外部SNS）がゼロ | `assertNoContactInfo` |
| G3 | funnel 先がカタログに実在し **listed** | `assertFunnelTargets`（休止・廃止先へ送らない） |
| G4 | 本文の金額がカタログ価格と一致（既定は金額を書かない） | `assertPriceClaims` |
| G5 | タイトルが非空・上限内 | `assertTitle` |
| G6 | **偽成功検証** — 公開後に**ログアウト状態で**ライブ URL を取得し、タイトル・冒頭段落が描画され、外部リンクが0であることを DOM で実査 | `coconala-blog-publish.mjs`（「投稿した」というログを成功と呼ばない） |

> G6 の根拠: x-post-policy §9 と同じ思想。UI の完了表示は成功の証拠にならない。

## 8. 5軸ルーブリック（`coconala-blog-qa` が採点・各 0〜3・平均 2.0 以上で合格）

| 軸 | 3 | 0 |
|---|---|---|
| ①検索適合 | ターゲット語がタイトル前半と冒頭にあり、検索意図と本文が一致 | 検索語が本文にしか無い／タイトルが抽象的 |
| ②論点の的確さ・捏造なし | 具体的で、事実は検証可能（経験・公開情報の範囲） | 経験していない工事・数値・実績の創作がある |
| ③カニバリ境界 | §2 の境界内で、読後に購入理由が残る | 完成答案の全文や診断全項目を出している／note 有料の転載 |
| ④導線整合 | funnel 1本にカードで接続し、購入後の流れが具体的 | 導線が無い／複数に散る／記事内容と無関係な出品へ送る |
| ⑤構成準拠 | §4 の構成に沿い、見出しで読み下せる | 段落が壁になっている／CTA が唐突 |

**捏造禁止は §5 安全弁1（Red Line #2）と同じ**。運営者の真正な立ち位置＝
**発注者（審査する側）**であって採点者ではない（2026-08-12 訂正済み・author-authority-banner.md）。

## 9. 計測

マイページ「サービス・ブログ分析」を**月次で目視**。数値が動いたら `kpi-log.json` へ。
v1 では自動収集しない（ダッシュボードのスクレイプは §4 の方針どおり手動貼付が正）。

判断:
- 3ヶ月で閲覧が付かない → 記事型（§3 #1〜#4）を止め、コンテンツマーケット（operations.md §9.3）へ振る
- 閲覧はあるが出品クリックが無い → CTA（§4-4）の位置と文面を見直す
