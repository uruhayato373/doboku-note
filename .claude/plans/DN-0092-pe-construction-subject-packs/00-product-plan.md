# 技術士 建設部門「選択科目まるごと合格パック」全科目展開計画

> [!important] 決定
> 道路で実証した「必須科目I＋選択1科目」の商品型を、建設部門の全11選択科目へ展開する。道路は既存商品を維持し、残り10商品を順次作成・公開する。優先順位は公開順を決めるものであり、下位科目を中止する基準ではない。

## 1. 目的

建設部門の受験者が、本番で実際に解く次の組み合わせを1商品で購入できるようにする。

```text
必須科目I 模範解答集
＋
本人が選択した1科目の模範解答集
```

道路パックは2026-07-06〜08-17に7件、売上¥34,860を記録した。道路単科5件と合わせたマガジン級購入12件のうち、パックが7件を占める。商品型として実売検証できたため、残りの選択科目にも同じ購入体験を提供する。

## 2. 商品原則

- 商品単位は「必須科目I＋選択1科目」。複数選択科目を混ぜない。
- セット価格は当面すべて`¥4,980`。
- 標準科目は単品合計`¥6,460`（必須I ¥3,480＋選択科目 ¥2,980）に対し約23%OFF。
- 道路は単品合計`¥6,960`に対し約28%OFF。
- 既存単科マガジンは廃止しない。パックを主商品、単科を低価格の選択肢として併存させる。
- 公開URL、記事本文、単品価格、有料境界、PDF添付をパック作成のために変更しない。
- noteはマガジンを別マガジンへ入れ子にできないため、必須Iと選択科目の公開記事を新パックへ個別再収録する。

## 5. 実行順序

1. `01-local-preparation.md`で10商品のローカルSSOT・カバー・検査を完成させる。
2. Batch Aを1商品ずつ作成・収録・検証する。
3. Batch Aがすべて正常ならBatch Bへ進む。
4. Batch Bがすべて正常ならBatch Cへ進む。
5. `03-wiring-and-measurement.md`でサイト・noteもくじ・計測を接続する。
6. `99-finalize-and-delete.md`の全条件を満たした場合だけ本手順書bundleを削除する。

同じbatch内でも並列作成しない。1商品について作成→カバー→1件収録試験→全件収録→API検証→SoT反映まで完了してから次の商品へ進む。

## 6. リポジトリ再編との順序

`.claude/plans/repository-information-architecture/`が未完了の場合、コンテンツルート移行と本商品の制作を同時実行しない。

実行時のnoteルートは次で決める。

```text
content/note/ が存在する     → content/note を使用
docs/note/ だけが存在する    → docs/note を使用
両方に同じ資産が存在する     → 二重SSOTとして停止
どちらも存在しない           → 停止
```

本計画中の`{NOTE_ROOT}`は、上記で確定したルートを示す。

## 7. 成功指標

実装完了は公開・配線・実体検証まで。販売評価は別途4週・8週で行う。

| 指標 | 定義 |
|---|---|
| パック販売数 | `sales-log.json`の商品ID別件数 |
| パック比率 | パック件数 ÷（パック＋同科目単科） |
| 科目売上 | パック＋同科目単科＋関連単品記事の売上 |
| 増分 | 公開前後の同期間における科目売上差 |

パック販売数だけで成功判定しない。単科からの置換でもパック件数は増えるため、科目全体の売上を主指標にする。

## 8. 非スコープ

- 各記事本文のリライト。
- 単品価格の変更。
- 道路パックの値上げ。
- 総監商品との混合パック。
- 新しいPlaywrightセレクタの盲目的追加。
- note以外の販売チャネルへの同時展開。

## 9. 停止条件

- accountが`dobokunote`ではない。
- 必須Iまたは対象選択科目の公開マガジンが取得できない。
- noteライブ価格とローカルSoTが一致しない。
- ソースマガジンの記事union件数を説明できない。
- タイトル、説明、価格の読み戻しが一致しない。
- 作成後のマガジンkeyを取得できない。
- カバーがdefaultのまま。
- 収録missが0にならない。
- note APIで価格、記事数、公開状態を実測できない。

停止時は後続商品を作らず、作成済みマガジンのkeyと実状態を記録して重複作成を防ぐ。本bundleは削除しない。
