# 設定・記録を台帳に沿って移し、型を揃え、JSON を減らす

判断と基準の正本は `.claude/knowledge/reference/data-storage-decision.md`「設定・記録の構成と型の正本」。ここは実行の順番と受入れ条件だけを書く。

## 順番（前の段が済むまで次へ進まない）

1. **CI の書き戻しをパスに依存させない**: ワークフローの「一時退避 → 最新の develop に戻す → 書き戻す → 決まったパスだけ git add」を、変わったファイルを git から拾う共通スクリプトに置き換える（DN-0497 もここで直す）。develop に入れたあと、ワークフローの YAML だけを main に入れる（サイトは data/ を読まないので、本番サイトに未公開の変更を出さない）。手動起動で 1 本ずつ書き戻しを確かめる
2. **型**: 全データセットに zod の型を付ける（API の取得物は実物から作った緩い型、売上・台帳・実験など人と CI が書き足すものは意味つきの strict）。読み書きを台帳経由の関数にする
3. **移動と統合**（取得元ごとに 1 PR）: 写しと読み手の無い出力を消す → 取得元ごとに `data/<取得元>/` へ移す → business・analysis を分ける → GA4・GSC を 1 回の取得＝1 ファイルに、rank-watch を月ごとの jsonl にまとめる（`.claude/state/` に残る外部サービスの記録は動かさない＝ADR）。中身を変えない台帳と、名前で引かれるファイルは `MOVED_PATHS`・`RESTRUCTURED_PATHS` で読み替える
4. **config/**: 同じ主題の小さな設定をまとめ、計画・作業記録を正しい置き場へ移す

## 受入れ条件

- `npm run check-datasets` が全ファイルを台帳に当て、型のあるデータセットは全ファイルが型に合う
- 各段のあとで、週次・月次・管理画面が読む結果が移動前と同じ（移動前後で報告スクリプトの出力を比べる）
- ワークフローの手動起動で、書き戻しが新しいパスで成功する
- git 管理の data/ のファイル数が ADR の見込み（約 280）に近づく
