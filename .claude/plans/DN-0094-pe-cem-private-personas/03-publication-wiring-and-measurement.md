# Phase 3：公開、導線、計測

## 1. 公開原則

- noteへの外向き操作は1商品ずつ実行する。
- account=`dobokunote`を毎回assertする。
- 新規マガジンはdraft-firstで作り、タイトル、説明、価格、有料種別、カバーを読み戻してから記事を収録する。
- 最初の1記事で収録経路を検証し、その後に残りを追加する。
- note APIまたは既存検証器で公開状態、価格、記事数、URLを確認できるまで`published:true`にしない。
- CAPTCHA、アカウント不一致、UIドリフト、保存結果不明では後続商品へ進まない。

## 2. 商品ごとの公開手順

1. ローカル原稿・`note掲載文.txt`・カバー・期待記事一覧を確定する。
2. 既存のnote公開スキル／CLIをdry-runする。
3. ユーザーが外向き公開を承認した範囲で1マガジンを作成する。
4. カバー、価格、説明、有料種別を設定し、画面またはAPIで読み戻す。
5. 1記事だけ収録し、公開範囲と有料境界を確認する。
6. 残りを収録し、期待集合との差分が0であることを確認する。
7. `note-magazines.ts`へnoteUrl、価格、記事数説明、`published:true`を反映する。
8. ペルソナレジストリを`published`へ更新する。
9. 売上正規化がproductIdを認識することをテストする。
10. 選択UIと対象記事のCTAへ配線し、誤ペルソナが出ないことを確認する。

## 3. 選択UI

50カードの平面一覧は禁止する。次の3段階で1商品へ着地させる。

```text
組織系統
├─ 自治体
├─ 建設コンサルタント
└─ ゼネコン・施工会社
    ↓
専門分野
    ↓
担当業務・プロジェクト類型
    ↓
推奨ペルソナ1件 + 最近傍1〜2件
```

要件:

- URLまたはクエリで選択状態を共有できる。
- 既存14商品のURLを壊さない。
- モバイルで3タップ程度で推奨へ到達できる。
- 各結果に「この立場が合う理由」「想定した権限」「2つの業務類型」を表示する。
- 未公開商品は購入リンクを出さず、公開済みの最近傍商品または横断コア教材を案内する。
- Admin画面では全50件の制作・QA・公開・売上状態を一覧できる。

## 4. パック再設計ゲート

新規36商品を現行完全パックへ無条件で追加しない。Batch A公開後に次を比較して決定する。

| 案 | 長所 | リスク |
|---|---|---|
| 単品のみ | 自分の1冊が明確 | 客単価上限が低い |
| 組織別ファミリーパック | 自治体／コンサル／施工で選びやすい | 他分野の水増し感 |
| 全部入りライブラリ | 網羅保証が強い | 記事数過大、価格・既購入者対応が複雑 |

決定前に、現行完全パックのライブ収録数、価格、販売数、既購入者影響を確認する。決定結果は移行後の総監`noteコンテンツ計画.md`へ反映する。

## 5. 計測

公開日を基準に4週・8週で評価する。

| 指標 | 定義 |
|---|---|
| 商品販売数・売上 | productId別の件数・金額 |
| 組織系統売上 | municipality / consultant / contractor別合計 |
| 選択UI利用 | 系統・分野・結果クリックの分布 |
| 既存商品への影響 | 同期間の既存14商品の件数・売上差 |
| カニバリ | パックと単品を合わせた総売上で判定 |
| 品質事故 | 返金、問い合わせ、誤り修正、公開停止件数 |
| 制作効率 | 1商品あたり人間レビュー時間とQA差戻し回数 |

販売0件だけで削除しない。タイトル・導線・分類を一度改善し、8週後も反応がなければ「単品公開維持／ファミリーパックへ統合／非表示」の判断を記録する。
