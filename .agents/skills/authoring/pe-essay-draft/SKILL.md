# /pe-essay-draft — 総監記述式 模範論文 ドラフト Generator

総監記述式の **模範論文ページ**（`r0X-essay-{attr}/article.mdx`）をドラフトする Generator スキル。Evaluator は `/pe-essay-review`。両者を分離する AGENTS.md ハーネス原則に従い、このスキルは「作る」だけ・評価はしない。

## 引数

```
/pe-essay-draft --year R0X --attr <attr> [--mode draft|revise] [--review <report-path>]
```

| 引数 | 必須 | 説明 |
|---|---|---|
| `--year` | 必須 | 年度（`R03`〜`R07` 等） |
| `--attr` | 必須 | 受験者属性キー（下表 3 種） |
| `--mode` | 任意 | `draft`（既定・新規）/ `revise`（添削反映） |
| `--review` | revise で必須 | `pe-essay-review` の出力レポートパス |

| 属性キー | 日本語 | ハブ |
|---|---|---|
| `general-contractor` | ゼネコン土木支店 | `pattern-essay-general-contractor` |
| `river-consultant` | コンサル 河川・砂防 | `pattern-essay-river-consultant` |
| `road-municipality` | 地方公共団体 道路担当（発注者） | `pattern-essay-road-municipality` |

出力先: `.local/r2/posts/pe-comprehensive-management/{year-lower}-essay-{attr}/article.mdx`（例 `r07-essay-general-contractor`）

## 実行手順（draft モード）

### Step 1: 入力資料を読む

1. **設問**: `r0X-secondary/article.mdx`（過去問ページ）の問題文全文 — 設問構造（何部構成か）はここに従う。年度で構成が異なる
2. **共通ペルソナ**: `pattern-essay-{attr}/article.mdx` の「共通ペルソナ（管理対象の統一設定）」表 — 事業名・規模・業務領域・立場・主要顧客・強み・弱みをそのまま流用
3. **構造の手本**: 同属性の既存年度（例 `r07-essay-{attr}/article.mdx`）があれば構造の参照に
4. **トレードオフの引き出し**: `management-tradeoffs/article.mdx`（解決フレーム: ALARP・LCA・段階的実施・合意形成・リスクベース）

### Step 1.5: 設問制約リストを作る（書き始める前に必須）

`r0X-secondary/article.mdx` の問題文から以下を箇条書きで抜き出し、執筆中の照合基準にする。**この手順をスキップしてはならない。**

```
【設問制約リスト — 例: R06 二次試験】
(1) 枚数: 1枚以内
    ①  名称・目的・成果物
    ②  施策を【1つ】取り上げ（内容・理由・課題）   ← 必ず 1 施策のみ
    ③  施策の問題点（2管理以上明記）
(2) 枚数: 各施策1枚以内
    ②  「脱炭素経営や社会貢献等の観点から期待できる効果を理由とともに記せ」← 両観点に触れる
    ③  5管理2つ以上・分野名明記・異なる総合技術監理分野のトレードオフ
(3) 枚数: 各施策1枚以内
    スコープ: 「事業や組織の枠を超え、我が国が解決すべき課題と施策」← 国家スケール（後述の必須ルール参照）
    ①  取り上げる課題と有効と考える施策
    ②  有効性・実現性（世界情勢・技術革新・経済財政政策・厚生労働政策の動向・予算制約等の背景を含む）
    ③  最も重大な障害と克服策（複数の視点に留意。総監の視点に限らず我が国が直面する重要課題の視点も可）
特殊制約: 「データ利用可能性に関するリスクは対象外」等があれば追記
評価方針: 前文で明示される評価軸（視点の広さ・記述の明確さ・論理的なつながり・まとまり）も抽出する
```

抽出した制約は MDX の各設問セクションを書く前に必ず照合し、取りこぼしがないか確認する。**形式制約（枚数・必須項目①②③）だけでなく、設問3 の「スコープ／視点要件」（『〜の枠を超え』『我が国が』『国レベル』『課題を限定せず』等の文言）を必ず抽出する。** 視点の広さは試験委員会が「特に重視する」評価軸であり、ここの取りこぼしが最も減点に直結する。

### Step 3: 必須ルール

- **三層構造**: 設問（２）以降は「現在 → 近い将来（5 年以内）→ 我が国施策」など年度設問の時間軸に沿う。ただし時間軸・スコープは年度ごとに異なる（R06 設問3 は「2050年」を含むが R07 設問3 は時点指定なし）。前年 essay の三層構造をコピーせず、必ず当該年度の `r0X-secondary` で確認する
- **ペルソナの一貫性**: 事業名・規模・組織体制・予算・主要顧客を `pattern-essay-{attr}` から固定流用。年度間でブレさせない。**ただし設問3（次項）は意図的な例外**
- **設問3はペルソナ一貫性の例外＝国家スケールで書く**: 近年（R06・R07〜）の必須科目 設問3 は「事業や組織の枠を超え、我が国が解決すべき課題と施策」を要求する。ここでは設問1・2 で固定したペルソナ（事業・組織・業界）の視点を **意図的に離れ**、我が国＝国家レベルの課題と施策を論じる。少子高齢化等のテーマの進行そのものを広く課題として設定してよい。
  - 特定業界に閉じた施策（例: 建設業界の構造改革、業界 DX 共通基盤、道路インフラ集約、流域カーボン会計）は「事業の枠 → 業界の枠」へ一段広げただけで要求スケールに届かず、最重視される「視点の広さ」で減点される
  - 施策は当該年度の **テーマそのものに対する国家政策レバー** で立てる。ペルソナの業界・所管インフラではなく、我が国全体の政策として通用する施策にする。全属性版が設問3でほぼ同じ国家施策に収束してよい。**テーマ別の代表例**:
    - **カーボンニュートラル（R06 等）**: 再生可能エネルギーの主力電源化／カーボンプライシング（GX-ETS・炭素賦課金）／運輸部門の脱炭素（次世代自動車の普及）／需要側の電化・省エネ／吸収源対策（森林・ブルーカーボン）
    - **少子高齢化（R07 等）**: 労働力人口の確保（女性・高齢者・外国人材）／出生率対策／全産業の生産性革命／社会保障の持続可能性
    - **判定基準**: その施策が、エネルギー・税制・労働・社会保障など **複数省庁にまたがる国家政策** として説明できるか。ペルソナの業界・所管インフラの話で完結するなら不合格（CN 年度で「建設業界の CN 標準化」「道路インフラの CN 化」「流域カーボンマネジメント」を挙げるのは業界・流域の枠にとどまり減点。「再エネ主力電源化」「カーボンプライシング」まで広げる）
  - ②は世界情勢・経済財政/厚生労働政策の動向・予算制約・技術革新の進展の背景に、③は総監5管理に限らない国家的重要課題の視点（エネルギー安全保障・国際競争力・地方の人口減少等）に触れる
  - **この「枠を超え」指示があるかは年度ごとに `r0X-secondary` で必ず確認する**（指示のない年度はこの限りでない）
- **施策数は設問の指定に完全一致させる**: 「施策を1つ取り上げ」ならその設問に書く施策は必ず1つだけ。複数施策を「関連施策」として列挙するのも違反とみなす
- **設問サブ要件を全量カバーする**: 設問内に①②③等の箇条書き要件がある場合、各項目を独立した段落で必ず論じる（Step 1.5 の制約リストと照合）
- **文体は である調 で統一する**: 模範論文の設問解答本文（設問1・2・3 すべて、A案/B案 併記の場合は両方）は **である調（だ・である調）** で書く。技術士記述式の答案作法に従う。リード文・採点者視点・`<Callout>` 等の地の文は ですます調 でよい（読者への語り）。**設問3 を後から revise で書き直す際も である調 を厳守し、設問1・2 と文体が割れないようにする**（設問3 だけ ですます調 になる混在が起きやすい）
- **5管理の正式名称と禁止語**:
  - 正式名称（この5つ以外は使わない）: 経済性管理 / 安全管理 / 人的資源管理 / 情報管理 / 社会環境管理
  - **禁止語**: 品質管理・QCD・コスト管理・リスク管理（これらは 5 管理外。「経済性管理」「安全管理」に言い換える）
- **施策間でトレードオフ軸ペアを変える**: 設問(2)の施策1と施策2で同一の「○○管理 × △△管理」ペアを繰り返してはならない。各施策で異なる管理分野の組み合わせを選ぶ
- **数値は年度固有にする**: 論文内の定量数値（人員削減率・投資額・削減量等）は当該年度の設問テーマと事業規模から導出する。他年度の論文で使用した数値をそのまま転用してはならない（同じペルソナで同一数値が複数年度に出ると「テンプレ流用」として採点評価を下げる）
- **固有用語の正確性**: i-Construction 2.0・CCUS・流域治水・ブルーカーボン等の制度・数値は事実確認する
- **frontmatter**: 新規は `published: false` ＋ `reviewStatus: needs-review`（人間ゲート）
- **書き込みは `.Codex/scripts/lib/mdx-io.mjs` の `transformMdxFile` 経由**（CRLF 保持）。書き込み後 `U+FFFD` チェック
- **既存 `*-secondary` の Callout 方針とは別**: 模範論文（`*-essay-*`）は guide 系のため `<Callout type="tip">` を使ってよい

## 実行手順（revise モード）

1. `--review` のレポート（`.Codex/state/pe-essay-review/{slug}-*.md`）を読む
2. 「致命的問題」と修正優先度 **High / Med** の指摘を反映（Low は任意）
3. **Evaluator の指摘を Generator が反映する** — これが Gen/Eval 分離の受け皿。`pe-essay-review` 自身は改変しない
4. `dateModified` を今日に更新、`reviewStatus: needs-review` のまま（再評価へ）
5. 書き込み後 `U+FFFD` チェック

## 例

```bash
# R06 河川・砂防コンサル版を新規ドラフト
/pe-essay-draft --year R06 --attr river-consultant

/pe-essay-draft --year R06 --attr river-consultant --mode revise --review .Codex/state/pe-essay-review/r06-essay-river-consultant-20260514.md
```

## トラブルシューティング

- **設問構造が年度で違う**: 必ず該当年度の `r0X-secondary/article.mdx` の問題文を正とする。3 部構成とは限らない
- **前年度の設問構造をそのまま流用してしまう**: 設問の時間軸・スコープは年度ごとに異なる（R06 設問3 ＝「2050年 CN」、R07 設問3 ＝時点指定なしの「我が国の課題」）。前年 essay の見出し・三層構造をコピーせず、当該年度の `r0X-secondary` を読み直して設問構造を確定する
- **設問3を書くとペルソナの話に戻ってしまう**: 設問3に「事業や組織の枠を超え」指示がある年度では、設問1・2 のペルソナ視点を引きずらない。業界内施策ではなく国家政策で 2 施策を立てる（必須ルール「設問3はペルソナ一貫性の例外」参照）。設問3はペルソナ非依存で、全属性版がほぼ同じ国家施策に収束してよい
- **ペルソナが思いつかない**: `pattern-essay-{attr}` の共通ペルソナ表が唯一の正。新規創作しない
- **施策数を増やしたくなる**: 「1つ取り上げ」制約は絶対。別の施策を「補足」「参考」として書くのも違反。1施策を深く論じることに集中する
- **トレードオフが同一管理内になっている**: QCD・CIA 等は総監の主問ではない。5 管理の垣根を越える対立に組み替える
- **施策1と施策2でトレードオフの管理軸が同じになる**: 施策1で「情報管理 × 経済性管理」を使ったなら、施策2では「安全管理 × 人的資源管理」等まったく異なるペアを選ぶ。「× 経済性管理」が両施策に入り込むことは許容するが、主軸が同一になってはならない
- **数値が思い浮かばない**: 設問テーマ（DX・脱炭素・少子高齢化等）と事業規模（正社員数・予算・対象規模）から逆算する。他年度論文の数値を参照しない
- **published を true にしてよいか**: 不可。AI ドラフトは必ず `false` ＋ `needs-review`。公開は人間判断
