# 保全性（Integrity）

## 保全性とは

保全性（Integrity）とは、システムが保持するデータやプログラムが、意図しない変更・破壊・消失から保護され、完全かつ一貫した状態が維持される性質を表す指標であり、RASISの4番目の要素である。

情報セキュリティの3要素（CIA）における「完全性（Integrity）」と同義の概念であり、データが正確で改ざんされていないことを保証する。

保全性が損なわれると、業務判断の誤り・法的問題・システム障害の連鎖など深刻な影響を及ぼすため、情報システムにおいて信頼性と並ぶ重要な品質特性である。

### 保全性を脅かす要因

| 脅威カテゴリ | 具体例 | 影響 |
|---|---|---|
| **人為的ミス** | 誤入力・誤削除・設定ミス | データの不整合・消失 |
| **不正アクセス** | 外部攻撃・内部不正による改ざん | データの信頼性喪失 |
| **ソフトウェア障害** | バグ・競合状態によるデータ破損 | 一貫性の崩壊 |
| **ハードウェア障害** | ディスク故障・メモリエラー | データの物理的消失・破損 |
| **災害・環境要因** | 地震・水害・停電 | 大規模なデータ消失 |

### 保全性を確保する手法

| 手法 | 概要 | 対応する脅威 |
|---|---|---|
| **アクセス制御** | 権限に基づくデータの読取・書込制限 | 不正アクセス・人為的ミス |
| **デジタル署名** | データの改ざん検知・送信者の証明 | 不正アクセス（改ざん） |
| **ハッシュ関数** | データの同一性を検証（SHA-256等） | 改ざん・通信エラー |
| **トランザクション管理** | ACID特性による一貫性の保証 | ソフトウェア障害 |
| **バックアップ** | データの定期的な複製保管 | ハードウェア障害・災害 |
| **RAID** | 複数ディスクによる冗長化 | ディスク故障 |
| **監査ログ** | データ操作履歴の記録・追跡 | 不正アクセス・人為的ミス |
| **入力チェック** | バリデーション・ダブルチェック | 人為的ミス |

### ACID特性（トランザクション管理）

データベースの保全性を支える基本原則として、ACID特性がある。

| 特性 | 英語名 | 内容 |
|---|---|---|
| **原子性** | Atomicity | トランザクションは全体として成功か失敗かのいずれか |
| **一貫性** | Consistency | トランザクション前後でデータの整合性が保たれる |
| **独立性** | Isolation | 複数トランザクションが互いに干渉しない |
| **永続性** | Durability | 完了したトランザクションの結果は永続的に保持される |

## 総合技術監理における位置づけ

総合技術監理キーワード集では「**4.4 情報通信技術動向**」に位置づけられる。

保全性は安全性（Security）と密接に関連し、両者を合わせて情報セキュリティの根幹を構成する。
信頼性（Reliability）が「壊れにくさ」を示すのに対し、保全性は「正しさが守られること」を示す点で、RASISにおいて異なる品質側面を担う。
