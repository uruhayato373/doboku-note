# 暗号化・電子署名

## 暗号化・電子署名とは

暗号化とは、平文（ひらぶん）のデータを第三者が読めない形式（暗号文）に変換する技術であり、情報の**機密性**を確保するための基本手段である。

電子署名（デジタル署名）とは、電子文書の作成者の本人性と内容の改ざんがないことを証明する技術であり、情報の**真正性**と**完全性**を保証する。

暗号化と電子署名は、いずれも**公開鍵暗号方式**を基盤技術として利用するが、鍵の使い方が逆である点に注意が必要である。

### 共通鍵暗号方式と公開鍵暗号方式

| 項目 | 共通鍵暗号（秘密鍵暗号） | 公開鍵暗号 |
|---|---|---|
| 鍵の種類 | 暗号化と復号に**同じ鍵**を使用 | **公開鍵**で暗号化、**秘密鍵**で復号 |
| 処理速度 | 高速 | 低速 |
| 鍵配送問題 | あり（事前に安全な経路で共有が必要） | なし（公開鍵は公開可能） |
| 鍵の管理数 | n人間で n(n-1)/2 個 | n人間で 2n 個 |
| 代表的アルゴリズム | AES、ChaCha20 | RSA、楕円曲線暗号（ECC） |
| 主な用途 | 大量データの暗号化 | 鍵交換、電子署名 |

### ハイブリッド暗号方式

実際の通信では、共通鍵暗号と公開鍵暗号を組み合わせた**ハイブリッド暗号方式**が広く用いられる。

公開鍵暗号で共通鍵（セッション鍵）を安全に交換し、その共通鍵でデータを高速に暗号化する方式である。

SSL/TLS通信（HTTPS）はハイブリッド暗号方式の代表的な実装例である。

### 電子署名の仕組み

電子署名では、暗号化とは逆に**秘密鍵で署名し、公開鍵で検証する**。

1. 送信者が文書のハッシュ値を計算する
2. 送信者が自分の**秘密鍵**でハッシュ値を暗号化（＝署名）する
3. 受信者が送信者の**公開鍵**で署名を復号し、ハッシュ値を取得する
4. 受信者が文書のハッシュ値を再計算し、3の結果と一致すれば改ざんなしと確認する

### PKI（公開鍵基盤）

PKI（Public Key Infrastructure）は、公開鍵の正当性を**認証局（CA: Certificate Authority）**が電子証明書で保証する仕組みである。

| 構成要素 | 役割 |
|---|---|
| 認証局（CA） | 電子証明書の発行・失効管理 |
| 登録局（RA） | 証明書発行の申請受付・本人確認 |
| 電子証明書 | 公開鍵と所有者の対応を証明（X.509形式） |
| CRL / OCSP | 失効した証明書の確認手段 |
| リポジトリ | 証明書・失効情報の公開場所 |

PKIにより、電子署名の信頼性が担保され、電子商取引や行政手続きのオンライン化が実現されている。

## 総合技術監理における位置づけ

総合技術監理キーワード集では「**4.5 情報セキュリティ**」に位置づけられる。

暗号化は[VPN](/docs/pe-comprehensive-management-vpn)における通信の秘匿性確保、電子署名は[アクセス制御](/docs/pe-comprehensive-management-access-control)における本人認証の基盤技術として、多くのセキュリティ対策と関連する。

[ISMS（ISO/IEC 27001）](/docs/pe-comprehensive-management-isms-iso27001)の管理策においても、暗号化ポリシーの策定や鍵管理が要求事項として含まれている。
