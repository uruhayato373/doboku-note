# クラウドコンピューティング／オンプレミス

## クラウドコンピューティングとは

クラウドコンピューティングとは、サーバ・ストレージ・ネットワークなどのITリソースを、インターネット経由でオンデマンドに利用できるサービス形態である。

利用者は自らハードウェアを保有・管理する必要がなく、必要な分だけリソースを確保し、従量課金で利用できる。

NIST（米国国立標準技術研究所）の定義では、クラウドの本質的特徴として、オンデマンド・セルフサービス、幅広いネットワークアクセス、リソースプーリング、迅速な弾力性、計測されたサービスの5つが挙げられている。

### クラウドのサービスモデル

| サービスモデル | 概要 | 利用者の管理範囲 | 代表例 |
|---|---|---|---|
| **IaaS** (Infrastructure as a Service) | 仮想マシン・ストレージ等のインフラを提供 | OS以上すべて | AWS EC2, Azure VM |
| **PaaS** (Platform as a Service) | アプリ実行環境・開発基盤を提供 | アプリケーションとデータ | AWS Lambda, Azure App Service |
| **SaaS** (Software as a Service) | 完成したアプリケーションを提供 | データと設定のみ | Microsoft 365, Google Workspace |

### クラウドの配置モデル

| 配置モデル | 概要 | 特徴 |
|---|---|---|
| **パブリッククラウド** | クラウド事業者が一般に提供 | 低コスト・高い拡張性 |
| **プライベートクラウド** | 特定組織専用に構築 | セキュリティ・カスタマイズ性が高い |
| **ハイブリッドクラウド** | パブリック＋プライベートの組み合わせ | 柔軟な使い分けが可能 |
| **マルチクラウド** | 複数のパブリッククラウドを併用 | ベンダーロックイン回避 |

### オンプレミスとの比較

オンプレミスとは、自組織内にサーバやネットワーク機器を設置・運用する従来型の方式である。

| 評価項目 | クラウド | オンプレミス |
|---|---|---|
| **初期コスト** | 低い（従量課金） | 高い（設備投資が必要） |
| **運用コスト** | 利用量に応じて変動 | 固定費中心（人件費・保守費） |
| **拡張性** | 需要に応じて即座にスケール | 物理的な増設が必要 |
| **カスタマイズ性** | サービス仕様の制約あり | 自由度が高い |
| **セキュリティ統制** | 事業者のポリシーに依存 | 自組織で完全管理 |
| **データ所在** | 事業者のデータセンター | 自組織内に保管 |
| **災害対策** | 地理的冗長化が容易 | 自前でDR環境を構築 |

### クラウド移行の判断基準

クラウドとオンプレミスの選択にあたっては、以下の観点から総合的に判断する。

**クラウドが適する場合**: 需要変動が大きい、初期投資を抑えたい、迅速なサービス立ち上げが必要、グローバル展開を想定している。

**オンプレミスが適する場合**: 機密性の極めて高いデータを扱う、既存システムとの密結合がある、通信遅延が許容できない、法規制上データの国内保管が必須である。

## クラウドコンピューティングの歴史的背景

クラウドコンピューティングという概念の萌芽は1960年代に遡る。コンピュータ科学者ジョン・マッカーシーは1961年のMITの講演で「コンピューティングはいつか公共事業（utility）として提供されるかもしれない」と予言した。しかし実現には40年以上を要した。

1990年代のインターネット普及とともに、アプリケーションサービスプロバイダー（ASP）モデルが登場した。これはSaaSの前身であり、インターネット経由でソフトウェアを提供する方式であったが、帯域・コスト・信頼性の問題から普及は限定的であった。

転機は2000年代初頭に訪れた。2002年にAmazonが内部の分散コンピューティング基盤を整備し、2006年にこれを外部向けサービスとして公開したのがAmazon Web Services（AWS）の始まりである。同年Googleのエリック・シュミットCEOが「クラウド」という用語を現在の意味で広く使い、以後この言葉が定着した。

2009年以降、米国政府の「クラウド・ファースト」政策や、スマートフォンの普及によるモバイルデータの爆発的増加がクラウド移行を加速した。日本では東日本大震災（2011年）後のBCP対策として、地理的冗長化が容易なクラウドの採用が急速に進んだ。

日本の行政分野では、2021年策定の「政府情報システムのためのセキュリティ評価制度（ISMAP）」により、政府が利用するクラウドサービスのセキュリティ評価が制度化され、官公庁のクラウド移行に法的根拠が与えられた。
