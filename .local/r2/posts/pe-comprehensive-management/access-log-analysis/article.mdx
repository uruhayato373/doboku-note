# アクセスログ分析

## 定義

**アクセスログ分析**とは、情報システムやネットワーク機器が記録するアクセス履歴（ログ）を収集・蓄積・分析し、不正アクセスの検知、セキュリティインシデントの調査、システムの利用状況の把握を行う活動である。

ログはシステムの「行動記録」であり、「いつ」「誰が」「何に」「どのような操作を」行ったかを事後的に追跡するための基盤となる。

近年は大量のログを統合的に分析する**SIEM（Security Information and Event Management）** の導入が進んでおり、リアルタイムでの脅威検知と迅速なインシデント対応を実現している。

## 仕組み

### ログの種類

| ログの種類 | 記録内容 | 主な用途 |
|---|---|---|
| **認証ログ** | ログイン・ログアウト、認証成功・失敗 | 不正ログイン試行の検知 |
| **アクセスログ（Webサーバ）** | アクセス元IP、リクエストURL、ステータスコード | 不正アクセス・攻撃の検知 |
| **操作ログ** | ファイルの作成・編集・削除、設定変更 | 内部不正・誤操作の追跡 |
| **通信ログ（ファイアウォール）** | 送信元・宛先IP、ポート番号、許可・拒否 | 不正通信の検知、C2通信の発見 |
| **アプリケーションログ** | アプリケーション固有のイベント・エラー | 障害分析、不正利用の検知 |
| **データベースログ** | SQL実行履歴、データ変更履歴 | 情報窃取・改ざんの追跡 |
| **メールログ** | 送受信記録、添付ファイル情報 | 情報漏洩の追跡、マルウェア配送の調査 |

### ログ分析の基本プロセス

| 段階 | 内容 |
|---|---|
| **1. 収集** | 各システム・機器からログを一元的に収集（ログ転送・エージェント方式） |
| **2. 正規化** | 異なるフォーマットのログを統一形式に変換 |
| **3. 蓄積・保管** | タイムスタンプ付きで改ざん防止措置を施して保管 |
| **4. 分析・相関付け** | 複数ログ間の関連性を分析し、単一ログでは検知困難な脅威を発見 |
| **5. アラート・対応** | 異常検知時のアラート発報、インシデント対応チームへのエスカレーション |

## 種類・比較

### SIEM（Security Information and Event Management）

**SIEM**は、組織内の多様なシステムからログを一元的に収集・統合し、リアルタイムの相関分析・脅威検知・アラート発報を行うプラットフォームである。

| SIEMの機能 | 内容 |
|---|---|
| **ログの一元管理** | サーバ・ネットワーク機器・セキュリティ機器のログを統合 |
| **相関分析** | 複数の異なるログを横断的に分析し、複合的な攻撃パターンを検知 |
| **リアルタイム監視** | 定義したルールやAIに基づくリアルタイムのアラート発報 |
| **ダッシュボード** | セキュリティ状況の可視化、レポート生成 |
| **インシデント調査** | 過去ログの検索・フォレンジック分析の支援 |
| **コンプライアンス対応** | 監査証跡の保存、規制要件への適合レポート |

### SIEM・SOC・CSIRTの関係

| 組織・ツール | 役割 |
|---|---|
| **SIEM** | ログ分析・脅威検知を行うツール（プラットフォーム） |
| **SOC（Security Operation Center）** | SIEMを運用し、24時間体制でセキュリティ監視を行う組織 |
| **CSIRT（Computer Security Incident Response Team）** | SOCが検知したインシデントに対応する専門チーム |

### フォレンジック調査

**デジタルフォレンジック**は、セキュリティインシデント発生後にログやデータの保全・分析を行い、原因究明・証拠保全・再発防止策の策定を行う調査手法である。

| フォレンジックの工程 | 内容 |
|---|---|
| **証拠保全** | ログ・ディスクイメージの改ざん防止措置（ハッシュ値の記録等） |
| **分析** | タイムライン分析、マルウェア解析、通信先の特定 |
| **報告** | 調査結果の文書化、法的手続きへの証拠提出 |

## 導入時の留意点

| 留意点 | 内容 |
|---|---|
| **ログ保存期間の設計** | 法令・社内規程に基づく保存期間の設定（一般に1年以上を推奨） |
| **改ざん防止** | ログの完全性を保証するためのWORM（Write Once Read Many）ストレージや暗号化 |
| **プライバシーへの配慮** | 従業員のアクセスログ取得にあたり、個人情報保護法やプライバシーに配慮 |
| **運用コスト** | 大量のログ保管・分析に要するストレージ・計算資源・人件費の見積もり |
| **アラート疲れの防止** | SIEMのルールを適切にチューニングし、誤検知（False Positive）を削減 |
| **ログの時刻同期** | NTPによる全機器の時刻同期（相関分析の精度確保に不可欠） |

## 総合技術監理における位置づけ

総合技術監理キーワード集では「**4.5 情報セキュリティ**」に位置づけられる。

アクセスログ分析は、情報管理（インシデント検知・証跡管理）の基盤であると同時に、経済性管理（SIEM導入・運用の費用対効果）、人的資源管理（SOC・CSIRT要員の確保・育成）、社会環境管理（個人情報保護法への対応）と関連する。

ログの保存・分析に要するコストとセキュリティ水準のバランスを、組織のリスク評価に基づいて最適化することが、総合技術監理の視点では重要となる。
