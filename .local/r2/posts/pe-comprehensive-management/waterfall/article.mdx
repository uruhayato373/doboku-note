# ウォーターフォール

## ウォーターフォールモデルとは

ウォーターフォールモデル（Waterfall Model）とは、システム開発を上流工程から下流工程へ順番に進め、原則として前の工程に戻らない逐次型の開発プロセスモデルである。

水が上から下へ流れ落ちるように工程が一方向に進むことから、この名称がつけられた。

1970年にウィンストン・ロイスの論文で体系化され、大規模な業務システムや公共系システムの開発で長年にわたり標準的に採用されてきた。

### ウォーターフォールモデルの工程

| 工程 | 内容 | 主な成果物 |
|---|---|---|
| 要件定義 | システムに求められる機能・性能の明確化 | 要件定義書 |
| 基本設計（外部設計） | システム全体の構造・画面・帳票の設計 | 基本設計書 |
| 詳細設計（内部設計） | モジュール単位の処理手順の設計 | 詳細設計書 |
| 実装（プログラミング） | 設計に基づくソースコードの作成 | ソースコード |
| 単体テスト | モジュール単位の動作確認 | テスト報告書 |
| 結合テスト | モジュール間の連携確認 | テスト報告書 |
| システムテスト | システム全体の機能・性能確認 | テスト報告書 |
| 運用・保守 | 本番稼働後の運用とメンテナンス | 運用手順書 |

### Vモデル

Vモデルとは、ウォーターフォールモデルの各設計工程と対応するテスト工程をV字型に対応付けたモデルである。

| 設計工程 | 対応するテスト工程 |
|---|---|
| 要件定義 | 受入テスト（ユーザーテスト） |
| 基本設計 | システムテスト |
| 詳細設計 | 結合テスト |
| 実装 | 単体テスト |

各テスト工程では、対応する設計工程の成果物を検証基準として用いることで、品質を体系的に確保する。

### メリット・デメリット

| 観点 | メリット | デメリット |
|---|---|---|
| 計画性 | 全体の工程・工数・コストが見積もりやすい | 要件変更が発生すると大幅な手戻りが生じる |
| 品質管理 | 各工程の成果物をレビュー・承認で品質を確保 | テスト工程まで動作確認できない |
| 管理のしやすさ | 進捗が明確で大規模プロジェクト向き | 要件が曖昧な段階では適用が困難 |
| ドキュメント | 各工程で成果物が整備される | ドキュメント作成の工数が大きい |

### ウォーターフォールとアジャイルの比較

| 比較項目 | ウォーターフォール | アジャイル |
|---|---|---|
| 開発の進め方 | 工程を順番に一巡（逐次型） | 短期間の反復（イテレーション）で繰り返し |
| 要件の確定時期 | 開発初期に全要件を確定 | 開発中に優先順位に応じて段階的に確定 |
| 変更への対応 | 変更は手戻りとなりコスト大 | 変更を歓迎し柔軟に対応 |
| 成果物の提供 | 全工程完了後に一括リリース | 各イテレーションで動作するソフトウェアを提供 |
| 顧客の関与 | 要件定義時と受入テスト時が中心 | 各イテレーションでフィードバックを取得 |
| 品質保証 | 工程ごとのレビュー・テストで保証 | 自動テスト・継続的インテグレーションで保証 |
| 適した案件 | 要件が明確・大規模・ミッションクリティカル | 要件が不確実・中小規模・短納期 |

## 総合技術監理における位置づけ

総合技術監理キーワード集では[**4.4 情報通信技術動向**](/docs/pe-comprehensive-management-keyword-2026#44-情報通信技術動向)のシステム開発プロセスに位置づけられる。

プロジェクト管理（工程管理・品質管理）と密接に関連し、アジャイルとの使い分けが出題ポイントとなる。
