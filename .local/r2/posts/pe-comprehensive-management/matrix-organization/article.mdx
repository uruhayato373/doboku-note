# マトリクス組織

## マトリクス組織とは

マトリクス組織（matrix organization）とは、**職能別の縦軸**と**事業・プロジェクト別の横軸**を交差させ、メンバーが2つの指揮命令系統に属する組織形態である。

1960年代にNASAの宇宙開発プロジェクトで採用されたことが契機とされ、複雑な技術課題と多部門連携を両立する手法として広まった。

組織の「命令一元化の原則」を意図的に崩す構造であり、運用には高度なマネジメント能力が求められる。

### マトリクス組織の3類型

| 類型 | 特徴 | 権限のバランス |
|---|---|---|
| **ウィーク・マトリクス** | 職能部門の権限が強い。プロジェクトマネージャーは調整役にとどまる | 職能 ＞ プロジェクト |
| **バランス・マトリクス** | 職能部門長とプロジェクトマネージャーが対等の権限を持つ | 職能 ＝ プロジェクト |
| **ストロング・マトリクス** | プロジェクトマネージャーの権限が強い。専任メンバーを確保できる | 職能 ＜ プロジェクト |

### メリットとデメリット

| 区分 | 内容 |
|---|---|
| **メリット** | |
| 資源の柔軟な活用 | 専門人材を複数プロジェクトで共有でき、稼働率が向上する |
| 専門性と事業対応の両立 | 職能部門で専門性を深めつつ、プロジェクト目標にも対応できる |
| 部門横断の情報共有 | 縦横の交点で多様な情報が集まり、イノベーションが促進される |
| 環境変化への対応力 | プロジェクト単位で編成を変えることで柔軟に対応できる |
| **デメリット** | |
| 二重権限の混乱 | 2人の上司から異なる指示を受け、メンバーが板挟みになる |
| 調整コストの増大 | 職能部門長とプロジェクトマネージャー間の調整に時間を要する |
| 責任の曖昧さ | 権限が分散し、問題発生時の責任の所在が不明確になりやすい |
| パワーバランスの崩壊 | 一方の軸が強くなりすぎると実質的に職能別または事業部制に退化する |

### 適する環境

| 条件 | 理由 |
|---|---|
| **高度な技術と多様な事業** | 専門性と事業対応を同時に求められる |
| **プロジェクト型の業務** | 有期・部門横断の業務が頻繁に発生する |
| **不確実性の高い環境** | 固定的な組織では対応できない変化が多い |
| **資源が限られている** | 専門人材を複数の事業で共有する必要がある |

### 主要組織形態の比較

| 比較項目 | 職能別組織 | 事業部制組織 | マトリクス組織 |
|---|---|---|---|
| **指揮命令** | 単一（職能部門長） | 単一（事業部長） | 二重（職能＋事業） |
| **専門性** | 高い | 分散しやすい | 高い |
| **事業対応力** | 低い | 高い | 高い |
| **調整コスト** | トップに集中 | 事業部間 | 二軸の交点で発生 |
| **資源効率** | 高い | 重複あり | 高い（共有） |

## 総合技術監理における位置づけ

総合技術監理キーワード集では「**3.1 人の行動と組織**」に位置づけられる。

マトリクス組織は建設業界のプロジェクト管理と親和性が高い。

安全管理では二重の指揮命令による責任の曖昧さが事故リスクとなりうるため、権限と責任の明確化が不可欠である。

人的資源管理では複数プロジェクトへの人材配置と育成のバランスが、経済性管理では資源の効率的配分が論点となる。
