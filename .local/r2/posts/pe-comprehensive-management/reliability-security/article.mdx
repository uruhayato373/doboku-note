# 信頼性（Reliability）

## 信頼性とは

**信頼性（Reliability）** とは、情報システムが意図した動作および結果を一貫して提供できる特性である。

JIS Q 27001（ISO/IEC 27001）では「意図した動作及び結果に一致する特性」と定義される。

信頼性が確保されていないシステムでは、処理結果の誤りや予期しない動作が発生し、業務の正確性やセキュリティが損なわれる。

### 信頼性と可用性の違い

| 特性 | 定義 | 焦点 |
|---|---|---|
| **信頼性** | 意図した通りに正しく動作する | 動作の正確性・一貫性 |
| **可用性** | 必要な時にアクセスできる | アクセスの継続性 |

信頼性はシステムが「正しく動く」ことに焦点を当て、可用性はシステムが「止まらない」ことに焦点を当てる。

両者は密接に関連するが、同一ではない。

### 信頼性を確保する主な手法

| 分類 | 手法 | 内容 |
|---|---|---|
| **設計段階** | フォールトトレランス | 障害が発生しても正常に動作し続ける設計 |
| **設計段階** | フェールセーフ | 障害発生時に安全側に停止する設計 |
| **設計段階** | フェールソフト | 障害発生時に機能を縮退して動作継続 |
| **テスト** | 単体・結合・総合テスト | 各段階での動作検証 |
| **テスト** | 負荷テスト | 高負荷時の動作安定性確認 |
| **運用** | パッチ管理 | ソフトウェアの不具合修正の適用 |
| **運用** | 構成管理 | システム構成の変更管理と整合性維持 |
| **品質管理** | CMMI・ISO 9001 | ソフトウェア開発プロセスの成熟度管理 |

### 信頼性に関する設計思想

| 設計思想 | 内容 | 例 |
|---|---|---|
| **フォールトトレランス** | 障害が起きても動作継続 | RAID構成、冗長電源 |
| **フェールセーフ** | 障害時に安全側へ移行 | 信号機の赤点滅、ガス遮断弁 |
| **フェールソフト** | 機能を縮退して継続 | 一部機能停止で主要業務のみ継続 |
| **フールプルーフ** | 人為的ミスを防止する設計 | 入力値の自動チェック、確認ダイアログ |

### 具体的な信頼性侵害の例

- ソフトウェアのバグによる計算結果の誤り
- メモリリークによるシステムの不安定化
- 設定ミスによる予期しない動作（意図しないデータの上書き等）
- 並行処理における競合状態（レースコンディション）

### 信頼性と他の要素との関係

信頼性は完全性・可用性の前提条件となる。

システムが意図した通りに動作しなければ（信頼性の欠如）、データの正確性（完全性）もサービスの継続性（可用性）も保証できない。

また、信頼性の確保にはソフトウェア品質管理やテスト手法の充実が不可欠であり、経済性管理における品質コストの概念とも関連する。
